# iOS 附件拖出

2026-11-11 用户要求从提问的附件列表与预览页拖到其他 App，并明确提出在 item provider 内异步下载。

## 行为

- 图片缩略图、非图片文件行与预览中的附件均可长按拖出，提供原文件、原文件名及匹配的系统类型；图片不使用缩略图替代原文件。
- 拖拽预览立即出现；目标 App 向 `NSItemProvider` 请求文件时才异步读取缓存或从 Mac 下载，通过 `Progress` 报告下载进度和取消。无需先打开附件，也不预下载整份附件列表。
- 复用既有 10 MiB 上限、Mac 在线检查、分块传输和校验；超限附件不可拖出，失败交给系统文件加载错误，不伪造空文件或路径文字。
- 导出任务由 provider 持有，与页面任务分开；关闭预览、换题或切 App 不提前删除交付文件。接收方得到文件副本。取消与失败清理临时文件，成功文件由 provider 持有至系统结束使用。
- 实际加载期间申请有期限的系统后台执行时间；仅该导出需要时允许 MQTT 在后台继续。后台在线不冒充用户前台阅读，不改变推送的前台判定；结束后恢复普通后台断连。系统不给时间或时间耗尽时取消并报告失败。
- 图片查看器保持双指缩放、双击放大、单指平移和翻页；长按后拖出。原有点击预览与分享保留。
- 本次不增加从其他 App 拖入、不改历史附件保留策略，也不扩大到回复草稿附件。拖拽不改已结束页倒计时的既有规则。

## 验证

- Provider：创建时不下载；请求时下载、命中缓存、原文件名／类型／字节、进度、取消、失败与临时文件生命周期。
- 引擎：后台导出保留连接但 `fg=0`；最后一份导出结束才断连；取消、失败与前台返回不误关连接；普通后台行为保持。
- 界面：列表图片与文件、图片放大预览与文件预览均能拖出；缩放、平移、翻页与点击不回归。
- 跨 App 实测：「文件」、备忘录和可用的聊天 App；包含缓存与未下载文件，核对文件名、类型、字节和取消。
