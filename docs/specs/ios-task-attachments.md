# iOS 新建任务的附件

2026-10-31 用户要求实施，并确认：仍需任务文字或待办；手机附件可与待办附件合并；全部上传成功后才创建，上传失败保留草稿。

## 使用

新任务表单复用现有附件菜单和附件行，支持拍照、相册图片／视频和文件；可移除，显示准备与上传进度。
手机新增最多 5 个、每个不超过 10 MiB，视频沿用 [现有压缩规则](../plans/ios-video-attachments.md)。
附件不能代替任务指令：仍须填写文字或选待办。待办自带附件继续由 Mac 读取，与手机新增附件一并传给 Agent。
任务进度页列出本次手机新增的附件名称。
导入、压缩或上传时禁止开始；上传时锁定表单。失败不丢失文字和附件，取消有内容的草稿需确认。
切换 Mac／Agent 保留本机附件；目标 Mac 不支持时提示更新，可移除附件或换 Mac，不能静默丢弃后启动。

## 协议与执行

`task.options.attachmentsSupported` 是可选能力字段；旧 Mac 缺失时隐藏添加入口。
`upload.begin.scope.taskId` 绑定手机与本次任务 `clientMsgId`，与提问／插话 scope 分开，不能跨手机或任务引用。
`task.create.files` 只含上传 ID，缺省不发送，旧消息和旧任务身份不变。所有文件完成后才发送创建消息；
文件 ID 列表参与幂等身份，同一 ID 重试只能复用同一正文和附件。上传完成后若创建消息的发布结果未知，进入进度页并按同一 ID 重试，不能生成新任务再发；迟到的 Mac 回执仍可纠正本机网络失败状态。网关先处理重放，再消费附件，避免重复启动或重复取件。

Mac 校验数量、重复 ID、归属、完整上传及文件存在后，交给共享任务启动管线；Codex App、CLI 及其他已支持 Agent
沿用已有附件路径交付。手机不提供 Mac 路径。手机新增文件与待办交付副本合并，不改待办原附件。
新增内容均为可选字段，不新增消息类型，不提高线协议或本机 IPC 版本号。

手机草稿临时文件在移除／关闭草稿时释放。未使用上传沿用 30 分钟过期与已有暂存配额；已消费文件沿用现有
24 小时磁盘清理，避免任务提交结果未知时过早删除 Agent 可能仍需读取的文件。

## 验证

覆盖无文字门控、准备门控、数量与大小、草稿清理、旧 Mac、待办合并、上传失败不创建、同 ID 重试、
跨手机／跨任务／错误 scope／不完整上传拒绝、CLI 与桌面文件交付；Rust、Swift 共用新旧线夹具。
中英文模拟器检查菜单、附件行、失败保留与任务进度。修改后执行主工作树安装，不启动真实 Agent 或产生模型费用。
