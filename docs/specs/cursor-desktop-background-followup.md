# Cursor Desktop 后台完成自动续跑控制

状态：2026-10-16 已按用户授权恢复默认关闭的实验功能，加入原生行为预检并完成安装与六窗口验证。
恢复实施与安装验证见 [恢复计划](../plans/cursor-desktop-restoration.md)；先前的撤回决定与理由保留于
[可靠性复审](../investigations/cursor-background-reliability.md)。本机偏好保持关闭。

## 1. 目标与已确认决策

Cursor 的后台 Shell 或子代理结束后，可以通过完成通知重新启动模型，即使用户已点击 Stop，
或通过 AskHuman 同意结束本轮。调查与原型证据见
[`../investigations/cursor-background-followup.md`](../investigations/cursor-background-followup.md)。

用户已确认：

- 采用全局策略：阻止所有后台完成通知自动启动新一轮模型，包括尚未明确结束的会话。
- 不维护逐会话的结束、恢复状态，不识别人类输入来解除会话静音。
- 增加独立开关，默认关闭；仅 Cursor 的 AskHuman 自动集成为 CLI/MCP 时运行。
  切至 None 停止接入，保留该开关偏好。
- 首版正式范围为 **macOS Cursor Desktop 的 Cursor Agents 和普通 IDE 窗口**，两条运行路径
  都必须通过验收，不能用一条路径的结果替代另一条。
- 普通启动自动接入；按实用优先，不为消除启动、重载期间的短暂接入过程增加启动接管机制。
- 用户随后授权按本规格开始实现；Cursor CLI 仅作静态分析，禁止实测。

这里的 CLI/MCP 是 **AskHuman 的提问集成模式**，不表示该功能支持终端里的 Cursor CLI。

## 2. 行为契约

| 输入或动作 | 开关开启且已接入时的行为 |
|---|---|
| 后台 Shell 成功、失败或被中断 | 正常记录真实结果与输出，确认完成通知，不自动启动模型 |
| 后台子代理完成 | 正常维护完成状态与原生确认台账，不因通知自动启动父会话模型 |
| 已排队、尚未进入模型的后台完成通知 | 通过原生完成处理收敛，不重排，不产生模型请求 |
| 模型正在显式 Await 的任务完成 | 正常返回该工具调用的结果，不能破坏等待者或挂死当前轮次 |
| 用户点击 Stop / 在 AskHuman 同意结束 | 沿用原有停止语义；已生效的全局策略持续阻止后台完成续跑 |
| 主动发送新消息，或选择 AskHuman 的继续 | 沿用原有提交与 continuation，不被此开关阻断 |
| 开启前已经进入模型的一轮请求 | 不追溯取消；原生 Stop 仍可停止它 |
| 关闭开关或切至 None | 恢复原生后续行为；不回放此前已确认的通知 |

全局范围覆盖接入 Cursor Desktop 进程中的所有本地工作区和会话，不要求会话使用过 AskHuman，
也不依赖它是否打开、位于前台、属于当前项目或显示过结束标记。

不终止后台命令或子代理，不改变其输出文件、退出状态和权限审批；不归档、隐藏、删除聊天。
正常工具结果不能伪装成成功：原型中的 `completed` 是“完成通知已处理”的内部返回值，
任务本身的 success/error/aborted 状态仍取原生结果。

本开关只控制后台完成通知。Goal、订阅、定时任务、用户设定的自动化及远端 Cloud Agent 自身的
调度不在范围内；不得将 UI 文案写成“禁止一切自动运行”。本地父会话收到子代理完成时，仍需
按本节契约处理，不能借 Cloud Agent 的非目标范围遗漏本地完成通知。

## 3. 设置、状态与偏好

- 设置入口位于 Cursor 自动集成卡，建议文案为 **“禁止后台完成后自动续跑”**。
- 简短说明：**“对所有本地 Cursor Desktop 会话生效。后台任务照常执行，完成后需主动发消息
  才会让模型继续处理；不影响当前轮次的 Await。”**
- 与“结束时确认”、生命周期追踪分开保存和启停，不增加第二条 Stop Hook，也不更改现有
  Stop / whats-next 输出协议。
- 偏好使用现有配置保存机制，建议字段为
  `cursorDesktop.suppressBackgroundCompletionFollowUp`，缺失时为 `false`。
  具体字段归属在实现时按配置约定确定，不形成第二份配置真值。
- macOS 且 CLI/MCP 集成有效时可开启；None 隐藏运行开关但保留偏好。Windows/Linux 显示
  暂不支持，不执行 macOS 接入逻辑。
- “偏好已开启”与“当前已生效”分开表达。沿用设置页现有状态样式，简要显示等待 Cursor、
  正在接入、已生效或接入失败；失败原因进入现有诊断入口，不增加日常弹窗。
- 只有目标运行路径的契约检查及挂载均成功，才能显示已生效；部分窗口失败不能显示全局成功。

## 4. 运行与接入边界

### 4.1 所有权与普通启动

由 Daemon 独占管理接入；GUI/CLI 只读状态、保存偏好和发出既有 IPC 管理请求。
不要求用户改变 Cursor 的日常启动方式、手工加调试参数、打开 DevTools 或修改安装包。

运行约定：

- 开关有效时，Daemon 保持运行并发现后续启动的 Cursor；关闭后恢复既有闲退规则。
  不改写用户的 `general.daemonLifecycle`，登录启动沿用现有设置。
- AskHuman 尚未运行时不宣称保护有效；开启开关会启动所需 Daemon。
- 覆盖 Cursor 先启动、AskHuman 先启动、Cursor 重启、新窗口和窗口重载。
- 接入时点为 `发现 Cursor 进程 → 等待窗口内部服务就绪 → 安装拦截 → 后续完成通知不再启动模型`。
  Cursor 已运行时开启开关，当场接入已有窗口；开关有效后发现新进程便开始接入，新建或重载窗口
  自动重新挂载。Stop 或 AskHuman 结束不是接入触发点，正常工作时拦截应已就绪并持续有效。
- 已接入窗口的拦截能独立处理完成通知，不把每次通知转交 Daemon 等待，不依赖短命 Ask 进程。
  Daemon 换新时优先接管已有接入，避免主动拆掉仍有效的拦截。手动停止 Daemon 不作为还原
  开关；已有保护可继续驻留，关闭能力开关或切至 None 才明确还原。
- 启动或重载后先等待运行环境就绪，再自动挂载；允许短暂的重新接入过程。
  失败有界重试并给出状态，不阻止正常对话，不自动杀任务，也不自动重启 Cursor。

### 4.2 适配契约

- 将后台工作结果更新、完成通知确认和“启动新一轮模型”分开。
  首选保留原生账务与队列处理，只跳过自动进入模型的步骤。
- Cursor Agents 的 legacy runtime 与普通 IDE 的 Agent Host 分别检测、分别验收。
  不能仅拦截共用提交入口、Stop Hook 或一段提示词来声称完成支持。
- 接入需覆盖窗口内已存在和后来创建的工作区服务实例，不只覆盖前台或已加载聊天。
- 同一进程、窗口和服务代际只挂载一次；重载后替换旧代际，过期回调不能修改新代际。
- 定位依赖经过检查的服务与行为契约，不依赖压缩类名、源码行号或整堆扫描。
  记录 Cursor 版本、构建和适配器版本；契约不匹配时停止该路径的修改并报告不可用。
- 结构检查后，先解除 provider 调试暂停，再创建隔离的原生 store / service 和虚拟 composer
  运行行为预检。预检不接触真实队列、聊天和文件服务，模型调用边界一律拒绝；验证原生同步
  ACK / nack、六种任务结果标识、Await 排除、活跃轮次排队和停止后的结算。存在 paired inbox
  时还检查原生游标排序和缺口保护；3.14 的直接 ACK 契约需明确匹配，不无条件跳过检查。
- 每次窗口代际的激活必须先通过预检。调用次数与等待时间有界，超时 / 还原会取消激活并释放
  隔离资源；晚到的 Promise 不能重新安装 guard。只有预检通过、当前原型未变且 owner / revision /
  lease 一致，才修改真实原型。任何窗口未验证都不能报告全局 active。

### 4.3 接入资源与恢复

初始候选沿用已验证的 macOS 进程附加方式，具体实现仍需审查：临时连接主进程 Inspector，
建立用户私有的有限控制桥，再关闭仅由 AskHuman 打开的 Inspector。

- 确认进程属于当前用户及目标 Cursor 安装，并核对端点所有者；端口冲突不能误连或操控其它进程。
- 控制桥仅接受固定管理操作，要求随机认证；目录/端点使用用户私有权限，不能暴露任意代码执行入口。
- 不关闭用户已有的调试连接，不遗留公开调试端口，不读取认证 token 或用户消息正文作诊断。
- 重复接入、Daemon 重启及旧端点清理必须校验进程身份与所有权，不能误清其它实例资源。
- 显式关闭开关、None 或卸载时还原自己的拦截、释放资源；还原前确认当前包装仍归自己所有，
  不覆盖后来安装的其它包装。Cursor 已退出时清理对应记录即可。
- 稳态不调用模型，不反复扫描大文件或堆，不做高频忙轮询；重试和诊断日志有界。

## 5. 验收标准

### 5.1 不消耗模型 Token 的自动化验证

| 类别 | 必须覆盖 |
|---|---|
| 配置 | 默认关闭；旧配置兼容；CLI/MCP 切换保持偏好；None 停止；重新集成恢复偏好；保存失败可见 |
| 独立性 | 生命周期和 Stop 开关任意组合不改变本能力；现有单一 Stop handler 与输出协议保持 |
| 队列 | Shell/子代理的 success/error/aborted；批次、重复、在途回收、重试与原生确认台账 |
| Await | 等待期间成功/失败结果正常返回；已消费结果不再唤醒；并发等待与完成不死锁 |
| 会话范围 | 多聊天、多工作区、多窗口、旧待处理通知、新建空白聊天触发重扫仍不续跑 |
| 生命周期 | 两种运行路径的普通启动、窗口新增/重载、Cursor/Daemon 重启与版本换新；幂等挂载和还原 |
| 故障 | 端口占用、身份不匹配、服务暂未就绪、契约漂移、桥接断开；状态准确且正常任务可继续 |
| 卸载 | 关闭开关/None/卸载后无自有包装和临时调试资源；已确认通知不回放；未运行任务不被杀 |
| 回归 | 主动消息、AskHuman 继续、普通工具结果、权限审批及明确不在范围内的其它调度正常 |

### 5.2 真实 Desktop 验收

功能实现后按项目要求运行相关检查和 `./scripts/install.sh`，再使用新安装的 AskHuman 继续确认。
两种运行路径分别建立可追溯记录，不能只凭 UI 停转、最终文本或等待一段时间判为通过：

1. 按普通方式启动 Cursor，在空临时工作区确认模型为 **Grok 4.7**，尽量减少消息和 Token。
2. 让一个真实 Shell 在主轮次结束后完成，证明拦截收到了完成事件、原生状态/输出正确、
   通知已确认且队列清空，并用请求日志证明没有自动模型请求。
3. 至少一条极短的主动消息证明仍可正常继续；不用重复对照组复现已知问题。
4. 真实子代理与 Await 至少各覆盖一条有意义的流程，检查原生等待、完成与确认账务；
   优先共用少量场景，不能用纯模拟替代两条运行路径的真实核心验收。
5. 验证 Stop 和 AskHuman 明确结束后的后台完成不会再请求模型；可以共用测试会话，
   不伪造用户同意结束的标记。补验正常启动、窗口重载与关闭开关后的还原。
6. 检查没有改变全局模型偏好、没有隐藏/归档聊天、原 Cursor 仍正常运行，临时接入资源已清理。

**Cursor CLI 禁止实测。** 不为补齐表格启动 CLI 会话、发送模型请求或擅自升级 CLI。
若未来要支持终端 CLI，需要单独授权和适配规格，本功能不得显示它已受保护。

### 5.3 发布门槛与现有证据

macOS Cursor Agents 与普通 IDE 两条路径的核心行为、Await、子代理、正常启动和还原都通过后，
才能交付本实验开关。未匹配路径应显示不可用，不能静默回退成“已保护”。

实现后已在 Cursor 3.24.12 验收普通 IDE / Agent Host（当前 connect 后端）和 Cursor Agents /
legacy：真实 Shell、子代理、Await、Stop / AskHuman 明确结束、主动续聊、自动接入、重载、
Daemon 换新接管和关闭还原均有安装后证据，见实施记录。无需把短暂启动间隙消除作为发布
阻塞项；其它 Cursor 版本仍需匹配内部契约，不能将本次证据扩展到未测试的后端或平台。
