## 1. 背景与目标

待办现在有这些入口：待办窗口、CLI、IM `/todo`、iOS「待办」页、iOS 开发者模式的全局快速添加。但在**收到一个 Agent 请求的当下**，想起一件和这个项目有关的事，得离开眼前的界面：

- **弹窗**：顶栏的「项目待办」按钮只是打开独立的待办窗口（再切到项目、点输入框）；正文里的待办折叠区只能「选中并入回答」或删除，**明确不提供新增**（`todo-whats-next.md` D7 第 11 轮定案）。
- **iOS**：请求页没有任何待办入口；要去「待办」标签、选来源、选项目，或者先打开开发者模式再选目标项目。

**目标**：在**请求本身**上，一步把一句话记成**这个请求所属项目**的待办——弹窗是顶栏浮层，iOS 是请求页「⋯」菜单里的一个入口。

**非目标**：

- 不带 ⚡、不带附件，只填文字（用户定）。
- 不把新待办并入当前回答、不自动选中它：添加不等于作答；要并入回答仍走正文待办区的「选中」。
- 不在浮层 / sheet 里编辑、调序、勾选完成；浮层只提供查看和删除（见 D5），iOS sheet 连列表也不放（D13）。
- 不做推送横幅上的快捷操作（通知扩展不联网）；不改 IM 卡片（`/todo` 已有）。
- 不动开发者模式的全局快速添加，不新增线消息、不改协议号（D15）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 请求的项目 | 请求所属项目：弹窗里是 `popup_init` 给的 `project`（可信会话工作区的 git 根，退而求其次是调用目录，见 `project.rs`），手机上是 `item.summary.project.key`。与待办窗口、历史、待办页用的是同一个 key |
| 浮层 | 弹窗顶栏「项目待办」按钮展开的小面板 |
| 在途请求 | Daemon 的 `RequestRegistry` 里还在等人回答的提问与确认（含被 Daemon 自己持有的卡） |
| 项目 id | 项目 key 的不透明哈希（SHA-256 前 8 字节十六进制），手机与 Mac 各算一份（`TodoProjectId.of(key:)` / `todos_view::project_id`），线上不出现路径（`ios-todos.md` I6） |

## 4. 用户视角

> 2026-11-13：本节描述的顶栏浮层与 iOS 半屏添加页**已被取代**，现行交互见 [`todo-list-actions.md`](todo-list-actions.md) §4。

### 4.1 弹窗

**入口**：顶栏的待办图标（位置不变），悬停提示「项目待办（⌘T）」。点它或按 ⌘T 展开浮层；再点、Esc、点浮层外面、⌘T 都关闭。没有项目的请求里，点它仍是直接打开待办窗口。下图只是示意布局，顶栏图标与真实的不完全一样。

```
                                ┌──────────────────────────────┐
  …  📌 ▤ [☑] ⟲ ⚙               │ 添加到 AskHuman                │
                                │ ┌──────────────────────────┐ │
                                │ │ 添加一条待办…              │ │
                                │ └──────────────────────────┘ │
                                │ ⌘↵ 添加                [添加] │
                                │ ──────────────────────────── │
                                │ 修复 popup 的按键泄漏…     ✕ │
                                │ 补一条 iOS UI 测试        ✕ │
                                │ ──────────────────────────── │
                                │ 打开待办窗口 ↗                │
                                └──────────────────────────────┘
```

**流程**：

1. 打开浮层 → 输入框自动聚焦，列表是这个项目当前的待办（打开时重读一次，之后随 `todos.json` 的变化实时刷新，别处加的 / 删的 / 做掉的也会跟上）。
2. 输入文字，按提交键（⌘Enter，或设置成 Enter 时的 Enter）或点「添加」→ 追加在队尾，列表里新出现一行并高亮，输入框清空、焦点留在输入框，可以接着写下一条。空白文字不能提交。
3. 添加失败（写盘失败等）：输入框下方一行红字写原因，文字保留，浮层不关。
4. 行尾「✕」：第一次点变成「确认删除」，再点才删；点别处取消确认态（与正文待办区一致）。
5. 底部「打开待办窗口」：打开独立待办窗口并预选这个项目，浮层收起。

**各类请求里**：

- **普通提问**：正文里的待办折叠区随之出现（该项目原本没有待办时）或计数 +1；它保持折叠、新条目不会被自动选中。
- **whats-next**：待办本身就是问题选项；添加后新条目立刻作为一个选项出现（沿用既有的实时刷新），已选中的选项保持选中。删除同理。
- **权限 / Stop / 出错确认卡**：同样有浮层。浮层里的 Enter / Esc 绝不会批准或拒绝这张卡；浮层关掉后，Enter / Esc 恢复原来的含义。
- **合并窗口**：浮层属于当前选中的那条请求；切到别的请求时收起，各请求各有各的草稿。
- **多请求同时在等**：每个请求只看自己项目的待办。

### 4.2 iOS

**入口**：请求页右上「⋯」→「添加待办…」。

```
 取消            新待办            添加
 ┌─────────────────────────────────────┐
 │ 📁  AskHuman                         │
 │     Home MacBook Pro                │
 ├─────────────────────────────────────┤
 │ New todo                            │
 │                                     │
 │                                     │
 └─────────────────────────────────────┘
 Home MacBook Pro 暂时连不上。            ← 只在不能发 / 失败时出现
```

- 项目与 Mac 只读显示，不能改；文本框自动聚焦，3–10 行自适应。
- 「添加」在文字为空、超过 4000 字符、Mac 离线、Mac 版本太旧时置灰，原因写在文本框下方；发送中右上角是转圈，且不能下拉关闭（回包前关掉会让失败无处可说）。
- 成功：sheet 收起，请求页顶部浮出「已添加到 AskHuman」约 2 秒；之后「待办」标签页里照常能看到这条（那一页在前台时本来就订阅 Mac 的变化）。
- 请求已经结束（页面显示「这条请求已结束」）时仍可添加，只要 Mac 还认得这个项目。

## 5. 实现要点

### 5.1 弹窗（前端）

- 新组合式函数 `src/views/popup/useTodoPopover.ts`（与 `useUpdateState`、`usePopupFind` 同一模式）：状态（开合、草稿、提交中、错误、刚添加的条目 id）、`add()`（`todosAdd(project, text)` 之后重读列表）、`remove()`（两段式确认在组件里，删后重读）、`handleKeydown(e)`（返回 `true` 表示已消费，接在 `onKeydown` 里 `find.handleFindKeydown` 的旁边，模态规则见 D7）。依赖：`projectPath`、`todos`、`loadTodos`、`submitWithBareEnter`、`popupActive`、一个「是否被用户配置的语音快捷键占用」的判断。
- 新组件 `TodoPopover.vue`（浮层内容）；`PopupNavbar.vue` 里待办按钮保持原位置，加 `@mousedown.prevent`（不抢走原输入框的焦点，才能在关闭时还原）；浮层作为 `.nav-actions-btns` 的子元素渲染，相对 `.nav-actions` 右对齐（顶栏现有的「更新」浮层是相对它自己的按钮定位，待办按钮不在最右，不能照搬），透明背板像 `update-backdrop` 那样放在 `</header>` 之后；样式进 `popup.css`。`.nav-actions` 是 `pointer-events: none`，浮层与背板要显式 `auto`。
- 浮层根元素 `@paste.stop`：核心里有全局的粘贴监听，会把剪贴板里的**图片**收进当前问题的答案，浮层只收文字，图片粘贴不能漏过去（文字粘贴照常）。浮层打开时也要让原生附件预览让位（把浮层状态并进 `nativePreviewBlocked`），否则预览会盖在浮层上。
- `usePopupCore.ts`：`loadTodos()` 的守卫改成「有项目，且有 `request` 或 `confirmRequest`」（D9）；`onKeydown` 里挂 `todoPopover.handleKeydown`（在弹窗取消确认 / 关闭警告这两个模态之外才生效，与查找同一规则）；`renderInit` 里重置浮层状态；`popupActive` 变 false、被合并窗口的「关闭全部」对话框挡住（`scope.blocked`）、或这两个模态出现时收起浮层；新增成员导出给 `PopupNavbar`。**`onKeydown` 里的挂载点在 `find.handleFindKeydown` 之前**（浮层是模态，⌘F / Esc / ⌘G 在浮层打开时要先被它吃掉）。
- `src/lib/shortcut.ts` 的 `shortcutConflict()`：把 ⌘T / Ctrl+T 加进弹窗保留键（设置里录语音快捷键时提示冲突），i18n 加 `shortcut.conflict.todos`。已经把语音快捷键设成 ⌘T 的老用户：⌘T 仍归语音（用户明确配置的优先），浮层只能点按钮打开。
- i18n（`zh.ts` / `en.ts`）：`popup.nav.todos` 带快捷键提示；新增 `popup.todoPopover.*`（标题、占位、提交提示、添加、空列表、打开待办窗口、添加失败）。

### 5.2 Mac（Rust）

- `RequestRegistry::in_flight_projects()`（`daemon/request.rs`）：返回在途提问与确认的非空项目 key，去重。
- `daemon/runtime/ios_todos.rs`：`World` 多一个 `in_flight: Vec<String>`，`gather` 多一个参数，`projects()` / `list()` / `apply()` 三个入口从 `state.registry` 取；`resolve` 在 ranked / stored / synced 之后再查一遍它。只读不写，不影响项目列表的内容与排序。

### 5.3 iOS

- AHCore：`RequestTodoComposer`（`@MainActor @Observable`）：目标（`macId`、项目 id、项目名）、文字、`phase`、`failure`、`unavailable`（复用快速添加的 `QuickTodoUnavailable` / `QuickTodoFailure`，其中 `notFound` 映射成 `refused("unknownProject")`，不用「请另选一个」的说法）、`update(mac:)`、`send()`。发送与「丢回包重发一次」的逻辑与 `QuickTodoComposer` 同源，抽成共享的小函数（若抽取牵动太多，则复制，实现时定）。`AppStore.todoComposer(for:)` 按请求 id 缓存（内存），`closed(id:)` 在请求结束后清掉。
- App：`Views/Request/RequestTodoSheet.swift`；`RequestScreen` 的菜单项与 sheet、成功胶囊（`todo-added-pill`）；菜单项的显示条件放宽到「请求有项目」。
- `ios/Tools/make-catalog.py` 补新文案的中文（「Add todo…」→「添加待办…」；「Added to %@」「New todo」等已有的复用）。
- `MockBackend`：解析在途请求的项目 id（与 Mac 的 D14 对齐），供单测与 UI 测试。

## 6. 边界、风险与已知限制

### 6.1 为什么 Mac 要改（D14）

`World::resolve` 只在 `ranked`（有待办的 key、未隐藏的最近 workspace、**工作中 / 空闲**的 Agent 目录）、`todos.json` 里已有的 key、同步链接里查项目 id。等你回答的 Agent 在 Agent 登记里是 `waiting`，`rank_todo_projects` 明确跳过；它的目录能被查到的唯一途径是 workspace 索引，而索引只在 hook 触发 SessionStart / TurnStart 时登记（没接 hook 的提问方、被用户隐藏的项目都不在）。结果是：弹窗里能加的，手机上同一个项目可能回 `unknownProject`。所以让「在途请求的项目」恒可反查，弹窗与手机才一致。

### 6.2 按键泄漏（最重要的风险）

弹窗的 `onKeydown` 在确认卡里：Enter（或 ⌘Enter）调用 `submitConfirm()`，Esc 调用 `requestConfirmClose()`；普通提问里：Enter 提交答案。浮层的输入框在 `window` 的冒泡监听之下，不隔离就会漏。隔离做在 `handleKeydown` 里（D7），并用集成测试钉住：确认卡 / 普通提问 / whats-next 三种请求里，浮层打开时按 Enter、⌘Enter、Esc 都不触发提交、确认、拒绝或关窗。

### 6.3 已知限制

- **老 Mac**：没有 D14 的 Mac 对「不在待办候选里的在途项目」回 `unknownProject`，手机说「这个项目已不在」。更新那台 Mac 的 AskHuman 即可；不为此加能力位。
- **请求刚结束**：项目已不在在途集合、又不在其他来源里时同样回 `unknownProject`，sheet 保留文字，让用户自己复制走。
- **iCloud 同步的项目**：写到请求所在 Mac 的本地 `todos.json`，由它的同步流程带出去，与待办窗口里添加同一条路。
- **文字长度**：iOS 限 4000 字符（线协议限额）；弹窗不另设上限（与待办窗口的新增框一致）。
- **⌘T 在系统层面的冲突**：弹窗窗口没有自定义原生菜单加速键，Windows / Linux 的 Ctrl+T 在 WebView 里也不是标签页；仍需在真机上按一次确认（§7）。
- **拖文件**：浮层不是文件的投放目标；浮层开着时把文件拖进窗口（落点在浮层上也一样），仍按原规则进当前问题的答案。浮层只收文字（D3），不为此新增拒收提示。
