# 需求：iOS 渠道免费开放（公共推送中继 + 厂商中立的 Broker）

> 状态：2026-11-21 经 AskHuman 多轮问答后获用户批准（P1→P5 全部）。P1（兼容套件与文档）、P2（去 EMQX 绑定）已实现；P3 起要改线上中继，需要用户在腾讯云控制台配合，进度见 `docs/PROGRESS.md`。
> 关联计划：`docs/plans/ios-open-access.md`
> 关联：`ios-channel.md`（D3、D23 已被本文修订）、`ios-external-testflight.md`（首批范围）、`ios-traffic.md`（流量提醒）；用户文档 `docs/wiki/ios-broker.md`、`docs/wiki/ios-setup.md`；兼容套件 `ios/Tools/broker-probe/`。

## 1. 背景与目标

iOS 端要开放给更多用户，初期只提供免费版，靠 TestFlight 或用户自己编译分发。要解决两件事：

1. **不和某一家 broker 绑定。** 作者和 EMQX 没有利益关系，只推荐它会像在给它打广告。
2. **推送中继的成本不能随用户数失控。** 所有推送都经作者那一个部署，用的人多了，成本会涨，而这是个免费产品。

约束（来自用户的回答）：

- 用户以中国大陆为主；成本口径是「每月几块钱可以接受，100 就太高」；增长不确定，希望自然扩大。
- 有已备案的域名，所以中继绑自定义域名没有障碍。
- 措辞中立，不用特意强调「无商业关系」；只把实测兼容的 broker 写成「已实测」；**不只推荐一家**。
- 已排除：方案 A（给 Mac 下发短时效 APNs JWT）；完全自建（要付费 Apple 账号，门槛太高）。

## 3. 总体设计

```
Mac ──MQTT(TLS/WSS)──► 用户自选的 Broker（EMQX / flespi / 自建 / 其它实测兼容的） ──► iPhone
 └──HTTPS──► 公共推送中继（腾讯云 SCF·香港，自定义域名，并发封顶）──► APNs ──► iPhone
```

不变量（均为现状，本需求不改）：

- 消息端到端加密：broker 只见密文与主题名。中继无状态、什么都不存；它只在登记与推送时经手设备 token（登记后以加密句柄的形式存在于 Mac 上）和固定的告警文案键。
- 中继 `register()` 拒绝 `bundleId` 不等于自己的 `APNS_TOPIC`：它不能被当成通用 APNs 代理。所以自己编译、换了 Bundle ID 的人，默认中继会拒绝他们的登记，他们要用自己的中继（向导里的「使用自己的中继」，文档给出自建指南的入口）。
- 手机的中继地址来自**配对二维码**，没有下发通道；所以**老配对继续用旧函数 URL**，旧 URL 要一直保留，直到所有老配对自然迁走。

## 4. 公共中继：成本模型与护栏

### 4.1 价目与合法用户的成本

腾讯云国际站，2025-03 版，2026-11-21 检索。账号是国际站还是国内站、是否已在扣基础套餐，**以用户费用中心的价目为准**；折算按 ¥7 / $ 取整。

| 计费项 | 价格 |
| --- | --- |
| 资源使用量 | $0.0000167 / GBs（实际运行时长 × 配置内存，毫秒计） |
| 调用次数 | $0.002 / 万次 |
| 外网出流量（中国香港） | $0.1504 / GB |
| 基础套餐 | $0.06 / 天（约 $1.86 / 月），含每月 50 万次调用、10 万 GBs、2 GB 出流量；第 4 个月起自动发放并扣费，上月无用量则不扣 |

一次推送约 128 MB × 0.3 s = 0.0375 GBs，资源约 $6.3e-7、调用约 $2e-7，合计约 $8.3e-7（约 ¥0.0000058）。每天 20 次（偏高）× 30 天 = 600 次，**每用户每月约 ¥0.0035**；1,000 / 5,000 / 10,000 个用户约 ¥3.5 / ¥17 / ¥35 每月（不含基础套餐）。基础套餐含的 50 万次大约够 800 个这样的用户。

### 4.2 最坏情形：被人刷

「拒绝类」请求（无效句柄，几毫秒返回）每次约 $2.8e-7。并发超限的请求**不计量**（官方计费说明：「并发超限导致请求错误：未执行、不计量」，预发验证时核对），所以烧钱速度由「并发上限 × 每实例吞吐」决定。按每实例 100 次/秒估算（预发实测后修正）：

| 并发上限 | 全速攻击烧钱速度 | 一天 |
| --- | --- | --- |
| 2（256 MB） | 约 ¥1.4 / 小时 | 约 ¥34 |
| **4（512 MB，起步值）** | **约 ¥2.8 / 小时** | **约 ¥67** |
| 8（1 GB） | 约 ¥5.6 / 小时 | 约 ¥135 |

合法容量：4 个实例每秒能处理约 12 次真推送（约每天 100 万次），按 10 倍峰值估算够几千个用户；监控里并发超限次数持续非零时把配额调高即可。

**没有「到钱就停」的硬封顶**：腾讯云云函数是后付费，做不到。本需求用「封顶速率 + 告警 + 熄火」逼近它，最坏损失 = 速率 × 反应时间。

### 4.3 护栏

1. **最大独占配额**（官方定位就是「费用管控、避免费用失控」）：封顶烧钱**速率**；设为 0 即整个函数关停。
2. **告警**（阈值按预期用量留 5–6 倍余量，上线一周后按实际调整）：调用次数 > 2 万 / 小时；并发超限次数持续 5 分钟非零；费用中心月预算 ¥30（50% 与 100% 各提醒一次）。
3. **熄火**：控制台把最大独占配额设为 0，或 API `PutReservedConcurrencyConfig`（`ReservedConcurrencyMem = 0`）；恢复时设回 512。手动，写成清单并演练一次。

若预发验证出平台有可配的限流（函数 URL 的「限流」），再加一道作为第一道闸：被限流的请求到不了函数，不计费，也不占并发。

### 4.4 没采用的做法

- **API 网关**：SCF 的 API 网关触发器已于 2025-06-30 下线，官方建议用函数 URL。
- **Cloudflare 前置**：大陆访问不稳。
- **WAF**：付费，先不上；真被刷、告警频繁触发时再评估。
- **账户余额清零即停服**：会波及这个账号上的其他产品，风险比收益大。
- **应用内按用户限额**：开户与配额系统是用户明确不要的范围（OA1）。
- **自动熄火**（OA14）。

### 4.5 业界怎么防「被刷」，和这里的差别

ntfy.sh 按访问者 IP 限速（请求令牌桶、匿名每 IP 每天条数、每 IP 订阅数、附件配额，异常请求罚分后交给 fail2ban），主题名就是密码；Bark 对成功请求不限，对错误请求按 IP 计数后封禁，文档写「QPS 超过 200 请自建」。它们的防护都发生在请求**到达服务器之后**，而服务器是固定月费，被刷只是变慢、不多花钱。这里为了「固定成本为零」选了按调用计费的云函数，**请求一到就计费**，函数里再按 IP 限速也省不了调用费，所以必须有平台层的东西封顶（4.3），再加告警和熄火。一致的部分：句柄不可伪造（相当于主题名 / 设备 key），错误请求便宜。

两点局限，如实告知用户：

1. 并发封顶下，攻击者占满并发会把真用户挤掉：被刷期间推送可能发不出（App 前台仍可用）。要避免需要平台限流（若有）或边缘层。
2. 边缘层（腾讯云 EdgeOne：被拦截的请求不计费）免费版目前限量内测、要兑换码，且定位是静态内容加速；个人版约 $4.2 / 月，超出预算，所以不作为默认，被刷、告警频繁触发时再评估。

中继是**尽力而为的免费服务**，不承诺可用性；文案里写明。

## 5. Broker：要求、路径与兼容套件

- 对 broker 的要求、三条路径的事实表（区域、端口、免费额度与缺点、实测结果与日期）、验证与提交新 broker 的办法在 [`docs/wiki/ios-broker.md`](../wiki/ios-broker.md)；这里只记决策：三条并列、不写「推荐」、「已实测」必须有套件运行作依据（OA2–OA4）。
- 兼容套件 `ios/Tools/broker-probe/compat.cjs`（OA5）：检查分 must / should / info 三级；**只有 must 不通过才算「不兼容」**，should 是警告，info 是测量值。账号隔离按**投递层**判断（订阅与发布都被接受，但跨账号的消息永远不会投递，也算隔离）；有第二组凭据时再做跨用户互验。所有测试主题放在 `ah/<user>/t/<运行编号>/`，结束时清除保留消息，密码只走环境变量。离线自测在 `ios/Tools/broker-probe/test/`，CI 的 `broker-probe` 任务跑它。
- `will-clean`（客户端发了 `DISCONNECT` 后 broker 不该再发遗嘱）是 should：EMQX 在 WSS 上会发，但两个 App 在主动断开前都会先自己发一条保留的「离线」，所以最多多一条重复的「离线」，没有影响。

## 6. 产品内改动

### 6.1 流量提示（OA6，已实现）

现状读代码确认：提醒（Mac 设置页与手机收件箱按「每 N GB」提示本月流量快到、已超过几 GB）本来就只数字节、与套餐无关，保持不动。真正和 EMQX 绑定的只有三处，已去掉：写死 1 GiB 的「占免费额度的百分比」（Mac 的 `quotaShare`、手机的 `TrafficStats.quotaShare` 与 Macs 页那一行）、指向 EMQX 控制台的链接（两端各一处）、点名 EMQX 的文案。界面改为只显示已记录的报文流量，并写明真实用量以 Broker 控制台为准。见 [流量统计](ios-traffic.md#与具体服务商解绑)。

### 6.2 默认中继（OA9）

Rust 新增 `effective_relay_url(cfg)`（配置为空 → 内置默认地址），配对二维码里的 `r`、推送、连接串、守护进程、CLI 与健康检查都改用它；设置里有「使用公共中继 / 使用自己的中继」开关（空串 = 公共）。设置里写明：公共中继不保存任何数据，只在登记与推送时经手设备 token，看不到消息内容；免费、尽力而为、不保证可用性。**内置默认地址要等自定义域名生效后才合入。** 老配置里的显式地址不动。

### 6.3 测试连接的隔离自检（OA10）

现有「测试连接」（`commands::ios_test`，设置页与 CLI `channel ios` 共用，内部 `ios/transport.rs::probe`）连上后给自己发一条、收到回声。成功后追加：订阅自己命名空间之外的一个随机主题，向它发布一条 QoS 1 非保留消息，等约 1.5 秒看有没有回声；有回声就警告「这份凭据能读写自己命名空间之外的主题」；被 broker 断开连接也算「已隔离」。警告级，不挡保存与配对。`ios_test` 的返回由单个字符串改为「消息 + 警告列表」的结构（Tauri 命令返回值，**不是 IPC 消息**，不涉及 `PROTOCOL_VERSION`）。不做大消息等重检查（会吃用户的免费流量），那些留给离线套件。

### 6.4 向导与错误提示（OA11）

`src/views/settings/iosBrokers.ts` 是纯数据的服务商目录（名称、主机名后缀、默认端口、要点、文档锚点）；设置卡顶部是服务商下拉与要点块。不新增配置字段，按主机名后缀识别服务商，认不出就是「自建 / 其它」。认证失败 / 超时按服务商给针对性提示（例如 flespi：用户名填 token 编号、密码填完整 token）。

## 7. 风险与未验证项

- **平台行为待预发验证**：Web 函数是否支持最大独占配额及其返回码；自定义域名能否映射到别名；客户端真实 IP 在哪个请求头里；每实例拒绝类请求的吞吐；默认域名「仅供测试」的限制是否波及自定义域名；函数 URL / 自定义域名有没有可配的限流。任何一项不成立就停下来问用户。
- **价目与口径**：国际站 / 国内站、基础套餐是否在扣，要用户核对。
- **flespi 是第三方免费套餐**：条款可被单方面改（自公布起至少 25 天后生效），账号 60 天不活动会被删；大陆有 4% 左右的超时。文档如实写，不当作推荐。
- **自定义域名功能较新**；回滚办法：取消映射，旧函数 URL 一直在。
- **域名要长期持有**：默认地址写进二进制，域名一旦过期，用新域名配对的手机会收不到推送（用旧函数 URL 配对的不受影响）。
- 真实 App 在 EMQX 的 WSS 上断开时是否多发一条遗嘱，**没有实测**；实测的只有套件探针的结果（见 `ios-broker.md`）。
