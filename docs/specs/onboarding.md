## 1. 背景与目标

现状（均已对照代码核实）：

- 发行物只有命令行二进制（npm 包 / Release 压缩包），没有安装器，也没有 postinstall。装完没有任何「下一步」提示：
  无参 `AskHuman` 只报错并打印帮助；只有 README 的 Usage 第 2、3 节说明要去 Settings 配 Agent 与渠道。
- 产品内唯一的引导是弹窗页脚的「配置 IM 渠道」一次性小条（`ui-state.json: im_tip_dismissed`），而且用户得先成功弹出一次问题才看得到。
- 「必要配置」只有一件事：Agent 集成（Cursor / Claude Code / Codex / Grok / Pi / Antigravity，每家 无 / CLI / MCP 中选，
  会改写 `~/.cursor`、`~/.claude`、`~/.codex` 等用户级文件）。远程回答渠道（Telegram / Slack / 钉钉 / 飞书；iOS 为实验功能）是可选项，
  平台侧步骤（建 Bot、开权限、设可用范围）工具无法代劳。
- 新用户会踩、但事先不知道的坑：二进制不在 PATH 上时 CLI 模式的 Agent 整体失效；Hook / MCP 配置 / 登录项写入的是**执行配置的那份二进制的
  绝对路径**，从临时目录或 `npx` 位置运行配置后路径一消失集成就坏；已打开的 Agent 会话必须重启才加载新规则；Codex 的 SessionStart Hook
  未被信任时静默失效；Cursor 的全局规则要求项目在用户主目录下；默认 `menuBarIcon=always` 会在 GUI Host 启动时静默写入登录项。

目标：新用户装完后跑一条约 2 分钟的流程，之后打开 Agent 就能像日常一样使用 AskHuman；老用户可以随时主动重跑，补上缺的 Agent 或渠道、
了解还有哪些开关；已经决定过的项不会被反复提示。

设计原则：

1. 状态尽量从真实配置**派生**，只持久化用户的「决定」，不存步骤进度，所以流程可以随时重跑；
2. 改用户文件之前，先列出路径并让用户确认；
3. 流程要短：必选只有 Agent 一步，其余都可跳过；验证只是可选按钮；
4. 提示要克制：主要引导新用户；每一项（Agent / 远程回答 / 后台）只要已经配置或明确跳过，就不再主动提示。

### 2.2 Agent 步骤

| 编号 | 决策项 | 结论 |
|---|---|---|
| D5 | 应用方式 | 列出探测到的 Agent，每家预选推荐模式（沿用设置页的推荐：Cursor / Claude Code / Antigravity / Pi → CLI，Codex / Grok → MCP），在磁贴下方的折叠清单里列出「将创建或修改的文件」；用户确认一次，向导统一应用，每家仍可改模式或取消勾选。逐家执行，单家失败不影响其他家，失败行显示原因并可重试；成功后回读校验（复用 `agent_mode::current`）并显示每家结果。 |
| D6 | 探测依据 | 满足任一即视为「已安装」：登录 shell 中找得到该 Agent 的 CLI（沿用 `agent_launch` 的探测）、用户级配置目录已存在、（macOS）找得到应用。未探测到的 Agent 折叠在「未检测到的 Agent（N）」里，默认不勾选，仍可手动接入，不阻塞。 |
| D7 | 协作风格 | Agent 页放 2 选 1：对齐 / 自主，默认选中当前值（新用户即「对齐」，即默认与日常用法），各配一句话说明；当前值为「自定义」时多显示一个已选中的「自定义（在设置页编辑）」，用户可改选。先写入协作风格，再应用 Agent 集成，使生成的托管块带上所选风格。 |
| D8 | 能力开关 | 生命周期追踪 / 权限接管 / 停止确认 / AskUserQuestion 接管不进向导，沿用产品默认；完成页列出已启用项并给「去设置页调整」链接。 |
| D9 | 已集成但需处理 | 已集成且最新：显示「已集成 · 模式」，默认保持不动（模式可改）。`needs_update`：显示「有更新」，默认纳入本次应用。Codex Hook 未被信任：显示「待信任」，并在磁贴下方的提示卡片里写「首次启动 Codex 时按提示信任 Hook」。应用后统一提醒「已打开的 Agent 会话需要重启才会加载」。勾选 Cursor 时，同一提示卡片附带现有「项目需在用户主目录下」说明。 |

### 2.3 远程回答与验证

| 编号 | 决策项 | 结论 |
|---|---|---|
| D10 | 渠道页形态 | 向导内嵌精简表单：复用设置页对保存 / 自动识别 / 测试的逻辑（`useChannels` 等组合式函数，抽出共享的配置上下文），只新写展示组件。平台侧步骤只放 3–5 行要点 + 现有 wiki 教程链接，不重写教程。多账号、超时等高级项给「在设置页打开」深链（沿用 `tab#elementId` 定位）。保存即启用该渠道。 |
| D11 | 验证 | 三项都做，但都是「想测就测」的可选按钮，不进主流程，不影响「完成」判定。① **本机自测**（完成页）：向导发一次真实提问到桌面弹窗，验证 CLI → daemon → 弹窗链路；不记入回复历史，不显示设置提示条。② **渠道往返测试**（渠道详情，保存后出现）：只向该渠道投递一条带「收到」按钮的测试提问，等用户在该渠道里点击，验证「发得出去 + 回得回来」；等待 120 秒，超时给该渠道的排查提示。③ **在 Agent 里试一次**（完成页）：向导监听「来自真实 Agent 的第一次提问」，收到即显示来源 Agent；5 分钟无响应给排查清单（重启会话 / CLI 模式需在 PATH / Codex 信任 Hook / Cursor 项目需在主目录下 / MCP 需在 Agent 内启用）。不替用户拉起真实 Agent（会计费，也无法稳定自动化）。 |

### 2.4 后台与启动

| 编号 | 决策项 | 结论 |
|---|---|---|
| D12 | 后台与启动卡 | 完成页一张紧凑卡：开关 A「菜单栏常驻并开机自启」（开 = `menuBarIcon=always`，关 = `active`；`off` 只在设置页提供），默认取当前值；开关 B「保持后台常驻」（`daemonLifecycle=keepalive`），仅当至少有一个远程渠道（已启用的 IM 渠道，或已启用的 iOS 渠道，见 D25），或确认页已选「开启」（D25，此时它固定勾选）时显示，默认取当前值，说明「让手机上的 App / IM 随时能连上这台电脑并发起命令，会常驻少量资源」；「从手机 / IM 创建 Agent 任务」不在这张卡里，而是远程回答步骤后的独立确认页（D25）；它开着时 B 固定为勾选。点「完成」时写入配置，A 开时写登录项，并记 `background_decided`。开关 A 旁的说明提示 macOS 通常会弹出「后台项目已添加」通知。托盘不受支持的环境不显示 A。 |
| D13 | 登录项门控 | 现状：`menuBarIcon` 默认 `always`，GUI Host 启动即静默写登录项（macOS 13+ 通常会弹「后台项目已添加」系统通知），新用户毫无上下文。改为：GUI Host 启动时，仅当模式为 `always` 且（登录项已存在 或 已做过选择）才确保登录项存在；用户在设置里显式切换 `menuBarIcon`（任意模式）或点完成页「完成」都视为已做过选择。已有登录项的用户行为完全不变。影响面核实与必须配套的守卫见 §4.3。设置页「通用 → 菜单栏图标」在 `always` 且登录项尚未写入时，显示一行「开机自启尚未启用」+「启用」按钮。 |
| D25 | 从手机 / IM 创建 Agent 任务（第 9 轮；第 10 轮改为独立确认页；第 11 轮先体检再询问，判定统一） | **背景**：用户在新设备上跑完 setup、没配 IM、手动配了 iOS 渠道，手机「新任务」仍提示「这台 Mac 的 AskHuman 设置里关闭了 Agent 任务」——`agentTasks.enabled` 默认 `false`，向导从未涉及它；iOS 又不算远程渠道，完成页的 B 也不出现；设置页的开关名叫「从 IM 创建…」，iOS 卡片也没写这个前提，用户没有任何线索。用户选定「向导也管」。第 9 轮把它做成完成页「后台与启动」卡里的开关 C，用户验证后反馈「开关放在下面根本看不见，最后直接完成还是没开」，并指出第一次给的几个补丁式方案是在糊弄：根因有三——把一项「能力」当成「设置项」排在一排开关里；问的时机在最后一屏、所有决定都做完之后；开了之后没有任何反馈，能不能用要到手机上才知道。第 10 轮改成独立确认页、点「开启」后再体检。第 11 轮：用户在另一台新设备上点了「开启」，却被带到一个说「没有可以开启的 Agent」的页面——先邀请、后否定，前后矛盾；而那台电脑装着 Cursor Desktop 和 ChatGPT（即 Codex 桌面版），两条路其实都能创建任务。根因有三：向导的体检和手机的「能不能新建任务」是两把尺子（向导只认命令行就绪，手机认 Codex 桌面 App 与 Cursor 路线）；Cursor 的「运行位置」偏好被当成硬开关（偏好终端而终端用不了时，不会改用 Agents 窗口，与 Codex 不对称）；问的顺序仍是先问后查。用户另指出：没配任何远程渠道时也应该有这个页面（开关与渠道配置不在一起，之后配渠道很容易漏掉），并希望少加提醒、把开关放进对应的渠道页。现在的做法：<br>① **「能不能启动」只有一个判定**（后端 `integrations/agent_start.rs`）：Codex = 桌面 App（`/Applications/ChatGPT.app`，即 Codex 桌面版）或终端任一可用；Cursor = Agents 窗口或终端任一可用（`launchPreference` 只决定谁优先，首选用不了、另一条可用就改用另一条，见 `cursor-desktop-task-creation.md` §3）；其余 Agent = CLI 就绪（命令行在 PATH、生命周期追踪、集成已启用）；没有启动路径的（Antigravity）永远不算。手机「新任务」页的 Agent 列表与 `noAgent` 门控、IM `/new`、向导的体检、文字版、设置页的「Agent 就绪状态」矩阵与各处入口都读它：`agent_task_readiness` 因此在每家的就绪详情之外多带 `startable` / `startRoute` / `launch`（additive 字段，不抬协议号），`AskHuman doctor` 每家多一个 `start=desktop \| terminal \| no`。真正创建任务时走的本来就是同一条路线选择（`resolve_launch`），所以「判断说不行、实际能建」的分歧就此消失。<br>② **独立确认页**（页名 `tasks`，属于「远程回答」这一步，步骤条仍高亮第 2 步，`parsePage` / 深链 / `setup-goto-page` 到不了它）：远程回答页点「继续」（只有 iOS 渠道、没有 IM 渠道时是「跳过」，照旧记 `remote` 已跳过）时，若 平台支持（macOS / Windows，与设置页同一判断）∧ 至少有一家 Agent 已集成且有启动路径（Antigravity 不算）∧ 功能当前为关 ∧ 向导里还没回答过 ∧ 用户没有在以前的向导里点过「暂不开启」（④），就先停在这一页，否则直接进完成页；是否满足按**此刻已保存**的配置判断（向导窗口的副本可能比设置窗口旧，见⑨）。**不要求已配置任何远程渠道**：这个开关是全局的，又不在渠道配置里，之后再去配渠道很容易漏掉它，所以趁人在向导里时问。<br>③ **先体检，再询问**：页面一出现就读手机「新任务」页读的同一来源——每家 Agent 的 `startable`（①）与可选项目（`agentTaskWorkspaces(true)`，先合并 Agent 历史里的最近项目，不含隐藏项）；读完之前只显示「正在检查这台电脑」，「开启」不可点。按结果分三种：<br>　· **至少一家能启动**：标题「在手机上直接开新任务？」，一句话说清做什么（按已配置的渠道措辞：iPhone App 点「新任务」/ IM 里发 `/new`（Slack 用 `!new`）/ 两者 / 还没有渠道时「配好之后就能用」），一张体检卡——「现在能启动」（每家一个标签，带路线：终端 / Desktop App / Agents 窗口）、「暂时还不能」（已接入但此刻启不了的 Agent 及原因，只是说明）、「可选项目」（最多列 3 个，其余写「另有 N 个」；没有项目只是中性提示：新设备在用过 Agent 之前没有项目，手机上也会说明，所以**不拦截**）、「后台常驻」（会一并开启并添加登录项）——再加两行好处和一行代价（需要 AskHuman 在后台常驻并添加开机自启项，占用少量内存，随时可在「设置 → 高级」关闭），已启用 IM 机器人渠道时多一行代价「IM 机器人的通道会被长期占用；多台设备共用同一个机器人时会互相抢消息」；底部两个按钮 **[暂不开启] [开启]**。<br>　· **一家都启不了**：标题改为「这台电脑暂时还不能从手机开新任务」，逐家说明缺什么（读 ① 同一判定给出的原因：终端、桌面路线各缺什么，与设置页一致），**完全不给「开启」**；页脚 **[先跳过] [重新检查]**（「先跳过」直接进完成页，不记成「暂不开启」，以后重跑向导还会再看；「重新检查」带 `force` 重新查命令行）。<br>　· **没能检查**（读取失败）：同「能启动」的页面，Agent 与项目行写「没能检查」，仍可「开启」，不当成问题。<br>窗口重新获得焦点时静默重新体检（用户去装了 Agent、打开了 Cursor 回来，不能还显示旧结果），不闪回「正在检查」。**默认仍为关**：只有点「开启」才会打开，不替用户默认打开（它会强制 daemon 保活并安装 daemon 登录项，设置页为此有开启前的确认弹窗）。<br>④ **选择先只记在向导里**，点完成页「完成」时一并写入，与设置页开启同效（后端 `save_settings` 强制 `daemonLifecycle=keepalive` 并同步 daemon 登录项，Dev 实例为 no-op）；只写用户在这一页答过的值，没答过就保持已保存的值。点「开启」后直接进完成页（不再有「已为你开启」的第二屏：体检在询问之前就做完了）。**「暂不开启」被记住**：记入 `ui-state.json` 的 `onboarding.skipped`（域名 `phoneTasks`，经现有 `setup_skip` 命令；`SetupStatus.phoneTasksDeclined` 回传前端），重跑向导不再停在这一页；它不是三个「已决定」域之一（`derive` 不看它），不影响弹窗提示条 / 步骤条 ✓ / 横幅。设置里的开关不受影响，完成页摘要行的链接也始终能回到这一页。<br>⑤ **完成页只报告**：摘要卡里一行「手机 / IM 新建任务：已开启 / 未开启 [开启 → / 更改 →]」（出现条件 = 满足提供条件，或功能已开），链接回到确认页；功能已开而还没有任何远程渠道时写「已开启 · 配好手机 App 或 IM 渠道后即可使用」。通过步骤条直接跳到完成页、没答的人由这一行兜住（显示未开启，且不会被记成「暂不开启」）。B 的联动：功能开着（已保存的值，或确认页刚选了开）时 B 固定勾选且不可改（「……开启期间固定为常驻」），B 的出现条件为「至少一个远程渠道，或已选择开启」。「功能未开、平台支持、但没有任何 Agent 满足提供条件」时，完成页「下次怎么用」卡里仍有一句提示 +「打开设置页」链接（直达「高级」）。<br>⑥ **设置里的入口与就绪矩阵**：开关 `agentTasks.enabled` 在设置里是同一个设置、同一个确认弹窗（开启前确认：强制保活并添加登录项），有两处入口：(a) 每个**已启用**的远程渠道卡片（Telegram / 钉钉 / 飞书 / Slack，以及实验页的 iOS App）展开内容的最底部，一行「从手机 / IM 创建 Agent 任务」开关加一句说明（所有渠道共用这一个开关）；开着时附「管理…」链接（切到「高级」），开着而「高级」页已读出的结果里没有任何 Agent 能启动时多一行警示。它取代第 10 轮只出现在 iOS 卡片顶部的提示条，用户配任何一个渠道时顺手都能开，不会漏；卡片里的开关**不**触发五家 Agent 的探测（那只在「高级」页做，设置页懒加载的约定不变）。(b) 「高级」Tab 的原位置。「高级」页「Agent 就绪状态」矩阵的每一行读同一判定（①）：标签「已就绪」（走 CLI）/「就绪 · Desktop App」/「就绪 · Agents 窗口」/「未就绪」/「暂不支持」；走桌面路线的 Agent，命令行与生命周期两列画「–」（不需要，不是缺项）；两条路都不通的 Agent，行下写明各路缺什么。IM 里 `/new` 被拒的回复沿用同一个开关名（第 9 轮，不变）。<br>⑦ **iOS 渠道算远程渠道**（第 9 轮，不变）：已启用的 iOS 渠道计入确认页措辞、完成页的 B 开关与摘要的出现条件，**不**计入渠道域「已决定」（`any_channel_enabled` 仍只看 IM 渠道：弹窗提示条、步骤条 ✓、远程回答页的「跳过」都不变，D16 / D22 及测试 `channel_counting_excludes_popup_and_ios` 不变）。<br>⑧ **文字版**：同一个问题（先于 B），也是先体检再问（D20）。<br>⑨ **向导读最新配置**（第 9 轮，不变）：向导窗口持有一份配置副本，每次保存都写整份，所以向导开着期间在设置窗口里做的改动（正是链接引导去配的 iOS 卡片）会被向导之后的保存盖掉。离开远程回答页、完成页挂载与点「完成」时重读已保存的配置（`adoptSavedConfig`）；背景开关 A / B 与确认页的选择都是「用户碰过才算选择」，没碰就跟随已保存的值。代价：点「完成」不再顺带保存渠道表单里键入但未保存的值。向导其他保存点（`saveChannel`、`applyAgents`）保持原有行为。 |

### 2.5 状态、提示与重跑

| 编号 | 决策项 | 结论 |
|---|---|---|
| D14 | 「完成」的定义 | 必选 = Agent 域已决定（判定见 D16）：至少一家已集成，或用户明确跳过，或历史里已有来自真实 Agent 的提问。远程回答、后台与启动是可选项，不计入完成；验证不计入。向导主要用来引导新用户。 |
| D15 | 必选可跳过 | 比如还没装任何 Agent、或只用手动集成：点「跳过」或关闭设置页横幅后，所有 Agent 侧主动提示停止；只在用户主动打开向导时再出现。 |
| D16 | 按域独立判定「已决定」 | **不设全局「老用户」标记**：Agent、渠道、后台三个域各看各的证据，互不影响（用户反馈：大部分提示按 Agent 算，只有弹窗里替代旧小条的那个按渠道算）。**Agent 域**（必选；驱动设置页横幅 / 托盘项 / 终端欢迎语）：已决定 = 任一 Agent 已集成（模式 ≠ 无），或在 `skipped` 中，或历史里已有来自真实 Agent 的提问（`agent_kind` 非空，覆盖只做手动集成的用户）。**渠道域**（可选；只驱动弹窗页脚提示条）：已决定 = 任一渠道已启用，或在 `skipped` 中（旧 `im_tip_dismissed = true` 等同于已跳过）；与 Agent 状态、历史、登录项无关。**后台域**（可选；不驱动任何提示，只决定登录项门控）：已决定 = GUI Host 登录项已存在，或 `background_decided`。由此：已集成 Agent 的用户不会再看到任何 Agent 侧提示；弹窗提示条的出现条件与旧 IM 小条完全一致（无渠道且没关闭过），所以从未关闭旧小条的老用户仍会看到一次、点一次即永久消失，不是新增的打扰；先集成、后提问的新用户首次弹窗能看到该提示。在终端里手动试一句 `AskHuman "hi"`（没有 Agent 来源）不会让 Agent 域变成已决定。 |
| D17 | 提示强度 | 按域独立（见下面两张表）。终端欢迎语只在 stdin 与 stderr 都是 TTY 时出现，退出码保持 1，Agent 内的调用不会看到额外输出。托盘项仅在托盘存在时可见。 |
| D18 | 弹窗页脚提示条 | 取代旧 IM 小条及其两个命令。条件：渠道域未决（没有渠道启用且未被跳过），与旧 IM 小条的条件完全一致，不看 Agent 状态与历史。文案按「首个待办项」选择，v1 只有「远程回答」一项：「配置 IM 渠道后，离开电脑也能在手机上收到并回复提问。」+「去配置」；数据驱动（待办项 → 文案 + 目标页），以后新增只加一项。「去配置」打开向导并直达「远程回答」页；点「去配置」或 ✕ 都记为该项已决定（与旧小条一致，避免反复提醒）。旧 `im_tip_dismissed = true` 在读取时等同于「远程回答 = 已跳过」。向导自己发起的测试提问不显示此条。 |
| D19 | 重跑 | 重跑就是**重走同一条流程**，不做体检清单：已配置的项预填，可直接跳过。页 1：探测到的 Agent 全部列出；已集成的显示「已集成 · 模式」并保持勾选；探测到但未集成的默认勾选（这正是重跑要补的）；未探测到的折叠在「未检测到的 Agent（N）」；无待应用改动时主按钮为「下一步」。协作风格预选当前值。页 2：四个渠道各显示当前状态（未配置 / 已配置·已连接 / 已配置·异常，附「编辑」），可直接「继续」。页 3：后台开关取当前值，摘要显示现有配置。首次与重跑的差别只有页头（首次是带应用图标的欢迎页头，重跑是精简页头加「已保留你现有的配置，只会改动你勾选的项」）与预填；重跑不重置任何已持久化的决定。 |

### 3.4 静默环境体检

体检随向导打开在后台运行；只有命中下列条件才在第 1 页顶部出现红卡，无问题时不占任何版面。文字版只在命中时打印。

| 检查 | 命中条件 | 卡片内容 |
|---|---|---|
| PATH | 存在以 CLI 模式集成（已集成或本次勾选）的 Agent，且登录 shell 里的裸 `AskHuman` 解析不到 | 「终端里找不到 AskHuman，CLI 模式的 Agent 将无法调用」+ 可复制的修复命令（把当前二进制链接到 PATH 内的目录；Windows 为加入用户 PATH 的命令） |
| 稳定位置 | 当前二进制位于临时或下载目录（`/tmp`、`$TMPDIR`、`~/Downloads`、`_npx` 缓存等） | 「集成会写入当前路径，移动或清理后集成会失效，请先放到固定位置再运行向导」 |
| 多份 | `doctor install` 的发现（多份 / 被遮蔽 / daemon 在别处 / 被挂起） | 一句话摘要 + 指向 `AskHuman doctor install` |

## 4. 状态模型

### 4.1 派生项与决定

| 域 | 类别 | 驱动的提示 | 「已决定」的条件 |
|---|---|---|---|
| agents | 必选 | 设置页横幅 / 托盘项 / 终端欢迎语 | 任一 Agent 模式 ≠ none；或在 `skipped` 中；或历史里存在 `agent_kind` 非空的记录 |
| remote | 可选 | 弹窗页脚条 | 任一渠道已启用；或在 `skipped` 中；或旧 `im_tip_dismissed = true` |
| background | 可选 | 无（只做登录项门控） | GUI Host 登录项已存在；或 `background_decided` |

- 三个域互相独立：不设全局「老用户」标记，也不需要「首次评估」。每个域的判定每次现算，只有 `skipped` 与 `background_decided` 需要持久化。
- 「完成」= agents 已决定（D14）。Agent 侧提示只看 agents；弹窗页脚条只看 remote，与 Agent 状态、历史、登录项无关。
- Agent 域的历史证据只判断是否存在 `agent_kind` 非空的记录（历史条数有上限，扫描开销可忽略）；终端里手动发起的提问没有 Agent 来源，不算证据。

### 4.2 `ui-state.json`

```json
{
  "onboarding": {
    "skipped": ["remote"],
    "backgroundDecided": false
  }
}
```

- 字段缺失 = 空集 / `false`。
- `skipped` 只会出现 `agents` / `remote` / `phoneTasks`；向导里点「跳过」、关闭设置页横幅、点提示条的「去配置」/ ✕ 都写入对应项，`phoneTasks` 只在向导里点「暂不开启」时写入（D25）。
- 兼容：旧 `im_tip_dismissed = true` 只在读取时等同于 `skipped` 含 `remote`，不改写文件。

### 4.3 登录项门控的影响面核实（读码结论）

用户的前提是「确认这样对我们的功能没有影响」。核实结果：

- **不受影响**：登录项（macOS LaunchAgent / Linux autostart / Windows `HKCU\...\Run`）只服务 GUI Host 的 `menuBarIcon=always` 开机自启（menu-bar-tray D12）。
  提问 / 弹窗 / IM / daemon 保活（daemon 自己的登录项由 `sync_daemon` 管理，`task_launch` / `fork` / `doctor` 读的也是 daemon 登录项）/ 设置、历史、Agents 等窗口
  （按需拉起宿主，D3 / D13）都不依赖 GUI Host 登录项。
- **未写登录项时托盘仍会出现**：`menuBarIcon != off` 时，daemon 启动与配置变更都会兜底拉起宿主（`maybe_spawn_gui_host`，menu-bar-tray D14），
  `always` 的宿主起来后常驻。唯一的差别是「重启系统后、第一次使用 AskHuman 之前」图标不会自动出现。
- **唯一的依赖点（必须配套修改）**：macOS 上 `restart_host()`（宿主在二进制自更新后换新）对 `always` 直接 `exit(0)`，指望 launchd 的 `KeepAlive` 把它拉回来。
  登录项缺失时没人拉回，托盘会消失到下一次 daemon 启动。守卫：仅当 GUI Host 登录项已安装时才走 launchd 路径，否则走已有的「spawn 新进程再退出」路径。
  Windows / Linux 本来就走 spawn 路径，不受影响。
- 已有登录项的用户：`ensure_installed()` 仍按原样刷新（路径漂移时重写），行为完全不变。

## 5. 非目标

- 不做体检 / 审计清单：重跑就是重走流程（用户明确否决）。
- 不做 iOS 渠道的配置引导（v1 只留扩展位；它只作为远程渠道参与手机 / IM 新建任务确认页与完成页的 B 开关，D25）。
- 不改手机端（iPhone App）的文案与「新任务」入口：「Agent 任务已关闭」仍由 App 自己的门控文案提示，需要新的 TestFlight 构建才会跟随。
- 不替用户默认打开「从手机 / IM 创建 Agent 任务」；不在 Mac 上还没有可选工作目录时代为创建目录（手机「新任务」页对 `noWorkspace` 的提示不变）。
- 确认页的体检只提示缺项，从不阻止「继续」或「完成」；也不替用户补项目、不改 Agent 集成。
- 不做 npm postinstall 提示；不做首次启动 GUI Host 自动弹窗。
- 不在向导里暴露能力开关、自定义协作风格正文、多账号等高级项。
- 不提供 `--yes`。
- 不新增 wiki 页；不在向导里重写平台侧教程。
- 不拉起真实 Agent 做测试。
- 不改提问流程的 stdout 契约、退出码、Agent 集成产物格式；不改 `menuBarIcon` 默认值与三态语义（只调整「何时写登录项」）。

## 6. 验收标准

1. 全新安装（无配置、无历史）：`AskHuman setup` 在有图形会话时打开向导窗口并立即返回；3 页走完即可；Agent 页按推荐预选，只改动用户确认的文件；应用后回读校验并逐家显示结果，单家失败不影响其他家。
2. 无图形会话或加 `--text`：走同一流程的文字版；stdin 非 TTY 时报错并退出 1。
3. Agent 域未决（没有 Agent 集成、没点过跳过、历史里也没有来自 Agent 的提问）：设置页横幅、托盘「设置向导…」、终端无参欢迎语出现；关闭横幅或跳过后全部停止；已集成至少一家后也不再出现；在终端里手动 `AskHuman "hi"` 不会让它们消失。终端欢迎语在非 TTY 下不出现。
4. 渠道域未决（不论 Agent 状态）：弹窗页脚条出现；点「去配置」或 ✕ 后不再出现；启用任一渠道后不再出现；「去配置」直达向导「远程回答」页。向导自己发起的测试提问不显示此条。条件与旧 IM 小条完全一致。
5. 已有 Agent 集成的用户（含升级上来的）：Agent 侧提示都不出现；只做手动集成但历史里有 Agent 来源提问的用户同理。弹窗提示条按渠道域判定：旧 `im_tip_dismissed = true` 或已启用渠道的用户不出现；从未关闭旧小条且无渠道的用户仍会看到一次，点一次即永久消失。设置页「通用」卡片与 `AskHuman setup` 始终可用。先集成、后提问的新用户首次弹窗能看到该提示条。
6. 重跑：已集成项显示状态并保持勾选，无待应用改动时主按钮为「下一步」；探测到但未集成的默认勾选；渠道页显示各渠道现状；后台卡取当前值；协作风格预选当前值（含「自定义」）；重跑不重置任何已持久化的决定。
7. 协作风格：选择后先于集成写入，生成的托管块带所选风格；`needs_update` 的 Agent 在本次应用中被同步；Codex Hook 未信任时显示「待信任」。
8. 登录项门控：全新安装启动 GUI Host 后不写登录项；点完成页「完成」且开关 A 开时写入；用户在设置里显式切换 `menuBarIcon` 后按所选模式处理；已有登录项的用户行为不变；macOS 无登录项时宿主换新不会让托盘消失（守卫生效）；设置页在 `always` 且登录项未写入时显示「开机自启尚未启用」+「启用」。
9. 环境红卡：PATH、稳定位置、多份三种条件各自触发正确文案与修复命令；无问题时第 1 页没有任何红卡。
10. 可选验证：本机自测、渠道往返测试、在 Agent 里试一次按 D11 工作，且任意一个失败 / 超时都不阻止「完成」，也不改变「完成」判定；本机自测不记入回复历史。
11. 渠道页：内嵌表单的保存 / 自动识别 / 测试与设置页同源同结果；高级项深链定位正确；保存即启用。
12. Dev 实例：Agent 页只读；不写日常登录项；`ui-state.json` 与 `ASKHUMAN_HOME` 隔离；评估后台域时忽略全局登录项，且不显示「开机自启尚未启用」提示。
13. i18n：向导、提示条、横幅、文字版均有完整中英文案。
14. 既有行为不受影响：提问 stdout 契约、退出码、Agent 集成产物格式、IM 渠道收发、daemon 生命周期与保活语义。
15. README（中 / 英）更新；`docs/overview.md` 复核。
16. 手机 / IM 创建 Agent 任务（D25）：在已集成且有启动路径的 Agent、平台支持、功能当前为关、没点过「暂不开启」时，远程回答页点「继续 / 跳过」先到「在手机上直接开新任务？」确认页（步骤条仍高亮第 2 步），**没配任何远程渠道也一样**（只配了 iOS 渠道的人点「跳过」同样先到这一屏；有 IM 渠道时多一行 IM 机器人通道的代价说明；还没有渠道时一句话写明「配好之后就能用」）；功能已开、没有符合条件的 Agent、平台不支持或以前点过「暂不开启」时直接进完成页。这一屏先体检再询问：读完前只显示「正在检查这台电脑」且「开启」不可点；至少一家 Agent 能启动（含只装了 Codex 桌面版 / Cursor Desktop、没有命令行的电脑）时列出每家的路线标签与可选项目（没有项目只是提示、不拦截）并给 [暂不开启] [开启]；一家都启不了时标题改为「这台电脑暂时还不能从手机开新任务」，逐家写明缺什么，**没有「开启」**，页脚是 [先跳过]（进完成页，不记成「暂不开启」）与 [重新检查]；读取失败只显示「没能检查」，仍可「开启」；窗口重新获得焦点时静默重新体检。点「暂不开启」后记入 `onboarding.skipped`（`phoneTasks`）并进完成页，摘要行显示「未开启 [开启 →]」，之后重跑向导不再停在这一屏（链接仍能回来）；点「开启」直接进完成页，点「完成」后 `agentTasks.enabled=true`、`daemonLifecycle=keepalive`、daemon 登录项就位（Dev 实例除外），B 固定勾选且不可改；没有任何远程渠道时摘要行写「已开启 · 配好手机 App 或 IM 渠道后即可使用」，B 仍显示（已固定）；完成页没有这项的开关，只有摘要行；通过步骤条直接跳到完成页的人由摘要行兜住（未开启，不被记成「暂不开启」）；iOS 渠道不改变渠道域判定（弹窗提示条、步骤条 ✓、远程回答页「跳过」与改前一致）。文字版同序提问（C 先于 B）、同样先体检再问，一家都启不了时只列已接入 Agent 的原因（一家都没接入就只说一句）、不问，开启时登录项失败则保持关闭并说明，摘要列出 iOS 渠道与 Agent 任务，功能未开时末尾有指向渠道卡片 / 「高级」的提示。
17. 配置新鲜度（D25 ⑨）：向导开着期间，在设置窗口里做的改动（iOS 渠道、手动开启 Agent 任务）在离开远程回答页（按此刻已保存的配置决定是否停在确认页）与完成页时可见，点「完成」不会把它们盖回旧值；没碰过的开关 A / B 和确认页的选择跟随已保存的值，碰过的以用户选择为准。
18. 发现路径与统一判定（D25 ①⑥）：设置里的开关名为「从手机 / IM 创建 Agent 任务」，同一个设置有两处入口——每个已启用的远程渠道卡片（Telegram / 钉钉 / 飞书 / Slack / iOS App）展开内容的最底部，以及「高级」Tab；两处走同一个确认弹窗；卡片里的开关开着时附「管理…」链接，开着而没有任何 Agent 能启动时多一行警示，且打开渠道页本身不触发 Agent 探测；平台不支持时卡片里没有这个开关；弹窗的「IM 机器人通道」一条只在有 IM 机器人渠道启用时出现；IM 里 `/new` 在功能关闭时的回复使用同一个名字。「能不能启动」只有一个判定：Codex 桌面 App 或终端任一可用、Cursor Agents 窗口或终端任一可用（偏好只决定谁优先）、其余 Agent 的 CLI 就绪；手机的 Agent 列表、IM `/new`、向导、文字版与「高级」页的矩阵给出同样的结论，矩阵里走桌面路线的 Agent 标「就绪 · Desktop App / Agents 窗口」，CLI 两列画「–」，两条路都不通的 Agent 行下写明各路缺什么。
