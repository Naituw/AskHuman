# Agent 观察中的最新正文与思考

> 状态为已实现，安装与体验验收记录见 §7。2026-11-08 经 AskHuman 定案。
> 适用入口为 Mac Agent 控制台与 iPhone 实时观察，共用后端内容语义。

## 1. 用户目标与已确认决策

打开观察界面，一眼知道 Agent 现在在做什么，同时能稳定阅读它公开的思考。

| 编号 | 决策 | 行为 |
|---|---|---|
| O1 | 沿用现有布局 | 主文字区显示一段最新内容，下方继续展示已有工具调用 |
| O2 | 思考直接可见 | 正文与公开思考按来源顺序选最新一段，思考带小标签，内容默认可读 |
| O3 | 整段更新 | 生成中的内容在后台缓冲，段落定稿后成为可展示候选 |
| O4 | 密集更新合并 | 主文字区最多每 10 秒自动替换一次，期间只保留最新候选 |
| O5 | 阅读时暂停替换 | 展开、选字或上滑阅读时固定当前内容，有更新显示「有新内容」 |
| O6 | 阅读恢复 | 点击「有新内容」主动切到最新，收起回到概览后恢复自动更新 |
| O7 | 稳定预览 | 默认约 4 行的固定高度预览，长内容支持展开 |
| O8 | 时间呈现 | 时间放进次级详情，主文字区以内容为重 |

用户先后否定了密集时间线和额外的「当前动作」主区，认为已有工具调用已经表达动作。
本轮定案为在原主文字区补齐思考，并控制文字替换的节奏。

示意中的中文是本地样本的意译，产品直接展示来源原文。

```text
思考

相机目前显示 4K / 60 FPS。
接下来打开规格面板，确认切换后日志与画面是否一致……

展开                          有新内容

◌ 执行命令  …
✓ 读取文件  …
```

「有新内容」仅在已有更新候选且当前显示被阅读锁固定时出现。已有状态、工具与 TODO 使用各自的更新路径。

## 3. 候选内容与定稿

### 3.1 选择规则

后端按来源顺序提供最近一段已定稿的助手正文或公开思考，附带类型与稳定身份。
新思考可接替旧正文，新正文也可接替旧思考。
工具更新独立进入现有工具区，工具本身不清空主文字区。

同一条来源记录原地增长时，只更新后台缓冲。空内容与纯签名字段跳过。
显示内容保留原文与原语言，思考使用轻量文本样式，正文沿用现有 Markdown 能力。

### 3.2 定稿依据

优先使用来源的明确完成事件或完成字段。Cursor 结合思考时长字段，以及同一主会话顺序中的后续工具调用、
新正文、下一段思考或回合结束，确认前一段的边界。
子 Agent 和并行分支的事件分别归属，避免用其他分支的工具误判主会话思考已经结束。

固定经过若干秒只能用于展示节流。来源缺少完成证据时，继续缓冲，等待可识别的边界。
最新候选为空时，可沿用上一段已定稿内容。来源明确报告仍在思考时，可带轻量状态提示。
记录过的思考与「当前正在思考」分别依据内容和实时状态表达。

### 3.3 预览与展开

概览默认保留约 4 行固定高度。思考优先取最近的完整末段，过长时展示末尾片段，并标明片段属性。
展开后显示该段已取得的有界内容，超出读取或传输预算时保留截断提示。
主文字区的折叠与展开只改变阅读方式，后台仍持续接收更新候选。

## 4. 自动更新与阅读锁

客户端分别保存当前显示内容、最新待显示候选、上次自动替换时刻与阅读锁。
Mac 与 iPhone 使用同一规则，各自维护本地阅读状态。

| 场景 | 主文字区行为 |
|---|---|
| 首次打开或切换会话 | 有定稿内容则立即展示，重置该会话的本地展示状态 |
| 新候选到达且距上次自动替换已满 10 秒 | 概览状态下直接替换为最新候选 |
| 新候选到达且尚未满 10 秒 | 覆盖待显示候选，原截止时刻到达后展示最新一段 |
| 到达截止时刻 | 有新候选且无阅读锁时替换，内容相同则保持 |
| 展开、选字或上滑阅读 | 进入阅读锁，固定当前文字与阅读位置 |
| 阅读锁期间收到新候选 | 保留最新候选，显示一个「有新内容」入口 |
| 点击「有新内容」 | 明确切换至最新候选，仍在展开态时继续固定这一段供阅读 |
| 收起并回到概览 | 恢复自动更新，并立即展示已有最新候选，重新开始节流窗口 |
| 短预览发生选字或滚动 | 同样固定内容，取消选区本身不触发换文；通过「有新内容」恢复概览跟随 |
| 收到相同内容的重复帧 | 保持文字、选区、展开状态与节流截止时刻 |

10 秒窗口从上次实际替换计算，持续收到新候选不会把截止时刻向后推，避免一直等不到展示。
用户主动点击更新或返回概览可即时切换。状态与工具区照常响应各自变化。
窗口重新聚焦、手机回前台时恢复读取与订阅，当前阅读锁仍属于该页面的本地状态。
页面关闭或切换会话后释放阅读状态，跨页面恢复时首先展示最新内容。

## 5. 数据链路与预算

### 5.1 统一候选

活动聚合按来源顺序选出最新定稿文字，候选包含稳定身份、内容修订、`assistant / thinking` 类型、
有界原文、来源事件时间与截断标志。身份来自会话与来源记录，内容修订独立参与比较。
源内容与身份共同决定是否真的有新内容，纯轮询时间或接收时间走动不触发替换。

Mac `AgentDetailFrame` 与 iOS `watch.frame` 消费同一候选。展示节流和阅读锁留在客户端，
后端候选持续反映来源的最新已定稿内容。已有 `text / steps` 为旧客户端提供兼容投影。
新字段采用可缺省的增量格式，依照 overview 中的 IPC 协议号与 iOS 协议兼容规则实施。
缺少 `latestText` 字段表示旧 Mac，可回退旧文字；字段为 `null` 表示新 Mac 尚在缓冲定稿内容，此时保留当前文字。

### 5.2 有界读取

Cursor 数据库在抽样时约 12GB。通过消息目录尾部分块和 bubble 主键查询读取目标会话，
结合有界回看与缓存取得最近定稿内容。兼容旧目录、分块 generation 变化、同数量重建、
消息原地更新和分块暂缺；暂缺读取保留重试机会。
活动与完整会话共用目录和消息解码，缓存失效也需识别新目录 / checkpoint 的变化。

实施中进一步只读核实了 `generation` 的含义。同一会话在 3 秒内从 7639 条消息追加到 7641 条时，
generation 也随普通写入变化。它是写入版本，来源记录身份仍使用会话 ID 与 bubble ID。
尾部每拍重读，新增定稿消息增量消化；目录版本变化引起的较早消息重放最多每 10 秒一次。
目录收缩越过已消化边界或锚点被替换时立即重建缓存。消息目录和 bubble 读取使用同一 SQLite 只读事务。

沿用现有事件唤醒和工作中约 2 秒的兜底读取。只有候选内容、类型或状态确实变化时推送。
思考签名等无展示用途的字段留在源端。iOS 沿用既有 Watch 单帧预算，按最终序列化字节数限制内容，
避免把长思考作为高频增量全文发送。实施时明确截断位置与提示，展开沿用取得的有界内容。

### 5.3 降级

旧 Mac 缺少 `latestText` 字段时，客户端沿用旧版文字字段。支持思考的来源按各自公开记录解析。
读取暂时失败时保留最后成功内容，读取状态单独表达。
回合空闲、等待回答或出错时，生命周期状态及时切换，已显示文字继续作为最近记录供阅读。
单纯长时间无内容变化仍按现有生命周期信号判断会话状态。

### 7.1 2026-11-13：手指落在最新文字上无法滚动页面

用户在 iOS 27 真机上发现，手指先落在「工作中」卡片的最新文字上，页面就没法上下滚动，与请求页的待办行是同一类问题
（[todo-list-actions §6.1](todo-list-actions.md)）。原先在文字上挂 `LongPressGesture(0.15 秒)` 与 `DragGesture(1 pt)`
判断「正在阅读」，`.simultaneousGesture` 在 iOS 27 上仍会让页面的滚动失效；探针只在手指落在这段文字上时卡住，卡片其他区域都能滚。

改为 `Views/Agents/ReadingTouch.swift`：一个只旁观的 UIKit 识别器，挂在文字所在的 `UIScrollView` 上（找不到就挂窗口），
只认起点落在这段文字内的触点，永不识别、不取消、不延迟触点、与其他识别器同时工作；手指停留超过 150 ms 或移动超过 1 pt 就进入阅读锁，
规则与 §4 不变。选字仍由系统的文字选择处理。

`AskHumanAgentPageUITests` 覆盖：手指落在文字上直接滚、先停一下再滚、整张「工作中」卡片各处（含滚到页尾后）扫过都能滚，
以及手指停在文字上时「有新内容」出现、不被 10 秒换文替换。iOS 27.2 的 Duo（en 与 zh-Hans）与 iOS 18.5 的 iPhone 16（en）通过；
换回旧手势后两条滚动测试在 iOS 27.2 上失败（连从文字旁边的页边距起手都滚不动）。
这几条测试里的按钮按名字找：文字区容器的 `watch-text` 标识会盖住里面按钮自己的标识。
