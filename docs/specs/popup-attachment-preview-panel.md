# Popup 附件预览面板

> 状态：基础同窗面板已通过 macOS 安装、自动验证及用户体验验收；系统格式扩展已通过安装、自动实机验证与用户样例验收。
> Windows / Linux 实机 gate 单独保留。
> 实现计划：[popup-attachment-preview-panel.md](../plans/popup-attachment-preview-panel.md)。
> 本文记录 2026-10-05 的需求决策；实际实施与验收证据见关联计划。原型不代替平台实机验收。
> 既有附件契约见 [file-attachments.md](file-attachments.md)，
> macOS Quick Look 的 diff 渲染见 [diff-attachment-preview.md](diff-attachment-preview.md)。

## 1. 目标与范围

在提问弹窗内直接阅读附件，同时保留完整的提问与回答区域。平时保持现有紧凑窗口，用户点击
附件后才展开预览；收起后恢复主区域的尺寸。预览跟随同一个窗口移动、缩放，无需在两个窗口间
协调位置与焦点。

- macOS、Windows、Linux 同时设计和实现。
- 提问附件统一使用新面板，不保留 Quick Look 模式或模式切换设置。
- 支持 Markdown、`.diff` / `.patch`、图片与普通文本；macOS 通过系统框架补齐图片和文档预览，见 §5.4。
  不支持或超限时保留文件信息和原文件操作。
- 首版仅覆盖 Popup 的提问附件。回复附件、历史详情、待办及其他入口继续沿用现有行为。
- 提问附件与回答附件的方向、CLI 参数、提交内容及 stdout 契约沿用现有规格。

最初讨论过附属的独立窗口。经过内部预览与 macOS 原生原型体验，当前方案采用
**同一个窗口中的主区域与预览区域**，按屏幕空间临时扩展窗口。

## 2. 窗口结构与布局

### 2.1 默认与展开

默认只显示原主弹窗，不预留空白预览宽度。主区域保留当前导航栏、Message、问题、预设选项、
按题目需要出现的答案编辑器和页脚；不新增统一的“补充意见”输入区。

右侧展开时，主区域完整留在左边，预览占右边的独立区域。取消、发送、多题导航等回答动作仍在
主区域内，页脚不横跨预览区；预览使用自身区域的完整可用高度。两区域始终按左右顺序排列。

| 状态 | 主区域 | 预览区域 |
|---|---|---|
| 收起 | 占整个原窗口 | 不显示 |
| 正常展开 | 左边保持原宽度 | 右边 |
| 工作区或系统限制扩展 | 左边临时缩窄 | 右边，在同窗内分区 |

### 2.2 固定右侧与空间不足

以主区域所在屏幕的可用工作区为边界，排除菜单栏、Dock / 任务栏等占用：

1. 固定向右展开，不再切换左、上、下布局。
2. 优先保留回答区宽度和默认预览宽度；右侧当前位置不足时，允许整窗向左平移以容纳预览。
3. 整块工作区容不下默认宽度时，先缩小预览到可读宽度，保留回答区原宽度。
4. 只有整块工作区仍容不下回答区与可读预览，或系统限制扩展时，才在同窗内左右分区，
   临时缩窄回答区。尽量使用工作区可用宽度，不把当前位置右边缺空间当成缩窄回答区的理由。

多屏计算使用主区域所属屏幕，处理负坐标、不同 DPI 与可用工作区变化。此规则由 2026-10-05
真实 Tauri 体验后的反馈确认，替代独立原型中的多方向扩展规则。

### 2.3 移动、缩放与恢复

- 拖动标题栏时，两区域作为同一个窗口移动；不在拖动后自动换边或拉回窗口。
- 主区域与预览区域的标题栏均可拖动窗口；右侧文件名、附件计数、图片控件栏和图片周围的
  安全空白、加载 / 不支持状态背景也可拖动。按钮保留点击，正文文字保留选择，图片本身保留
  原文件拖出 / 溢出平移；滚动条、分隔线与 PDF / Office 等原生正文保留各自交互。
- 用户可拖动外缘调整总宽和共享高度，也可拖动分隔线调整分配。
- 正常展开时，外缘宽度变化主要作用于预览；分隔线可显式调整主区域宽度。
- 分隔线拖动实时重分配同窗内的两区宽度，保持外窗尺寸与位置；不等待松手，也不逐帧
  回放过时位置。合并与独立模式最多保留一个执行中的布局请求和最新待更新位置，松手
  落实最终位置后记忆一次有效尺寸；受限 / 最大化分区仍只临时有效。
- 关闭时恢复展开前的位置，包括撤销自动左移；如果展开期间用户移动过窗口，关闭时保持
  用户的新位置。这个标记在本次展开期间保持有效，即使用户后来又拖回原位置。
- 临时缩窄的回答区在关闭时恢复原宽度；不能把临时分区宽度或展开总宽存为下一次偏好。
- 用户正常展开时显式调整主区域尺寸后，关闭使用该有效尺寸；受限分区的分隔线调整仅临时有效。
- 问题选项、答案草稿和当前题目不因展开、切换、收起或窗口移动而重置。
- 展开前先冻结当前主区域尺寸，等待前端绘制，再执行原生几何事务；实际窗口确认完成后
  才解除冻结，避免回答区短暂撑满展开窗口、页脚跳动。
- 尺寸记忆继续遵守既有有效尺寸校验、预热、并发窗口及 rememberSize 规则。
- 预览宽度单独记忆，遵守同一个「记住窗口尺寸」开关。下次展开尽量使用用户上次主动调整的
  宽度；自动受限布局、最大化与 DPI 换算不覆盖保存值。关闭记忆后使用默认预览宽度。

### 2.4 布局参数

| 参数 | 逻辑像素 |
|---|---|
| 默认主区域内容尺寸 | 560 × 620 |
| 默认预览内容宽度 | 700，另加 6 宽分隔线；有记忆值时优先使用 |
| 可读预览空间门槛 | 320 内容宽度 + 6 分隔线 |
| 受限分区主区域保留宽度 | 尽量保持原宽度；不足时至少 240，极窄状态下两区域平分 |

保留现有 420 × 480 原生窗口下限；临时分区不能更改持久化下限。700 默认预览宽度和单独
记忆来自最终安装体验后的反馈，替代此前 560 默认值；空间不足时才临时缩窄。

## 3. 附件激活与切换

| 用户动作 | 结果 |
|---|---|
| 点击未激活附件 | 激活该附件并展开预览 |
| 再次点击当前激活附件 | 取消激活高亮，收起预览 |
| 展开时点击其他附件 | 激活新附件并切换内容，保持预览区展开 |
| 标题栏上一张 / 下一张 | 按附件顺序切换内容并同步列表高亮 |
| 标题栏关闭 | 收起预览并取消当前附件的激活高亮 |
| 双击附件 | 仅执行第一次单击的展开 / 收起 / 切换；忽略第二击，不打开外部应用 |
| 附件列表回车 | 用系统默认应用打开原文件 |

双击规则于 2026-10-07 确认，替代此前的双击打开。第一次单击立即响应，不等待双击判定，
同一连续点击手势的后续 click 不再切换预览。预览标题栏按钮与右键菜单继续提供打开入口。

同一时刻只有一个附件处于激活状态。预览激活与键盘焦点应分别处理：用户继续选择答案或编辑
草稿时，预览保持打开，不因主区域点击而自动关闭，也不抢回编辑器焦点。

切换附件不反复收起、展开或改变窗口总尺寸。首尾导航按钮禁用，不循环。提交、取消或弹窗
销毁时结束当前预览及后台读取；每个 Popup 的预览内容与状态独立。

### 3.1 快捷键与焦点

- 焦点在附件列表时，空格展开 / 收起，方向键按附件顺序切换。
- 焦点在预览标题栏时，左右键切换附件；正文中的方向键用于滚动阅读。
- 答案输入框中的空格与方向键保持编辑作用。输入法组合态优先交给输入法处理。
- Esc 按现有交互优先级关闭查找、结束语音，再收起预览；不取消整次提问。
- 发送、取消及其设置沿用现有行为，预览快捷键不能覆盖这些动作。

## 4. 预览标题栏

标题栏分为左侧文件标题区与右侧固定操作区：

```text
文件名 [查看原文]       2 / 4  ‹  ›  [打开]  ⋯  ×
```

- 文件名在空间不足时截断，提供完整名称；原文切换按钮紧挨文件名右侧。
- 附件计数、上一张 / 下一张、打开、更多、关闭放在右侧，位置不因文件类型或原文按钮的显示
  与隐藏而跳动，允许连续点击同一位置切换附件。
- **查看原文 / 查看预览**使用细边框、明确内边距，与文件标题区分；按钮文案表示点击后的
  动作，不使用“原始 / 渲染”这类难以判断含义的单词。
- Markdown 渲染模式的主按钮为 **浏览器打开**，用默认浏览器打开独立 HTML 阅读快照；原文模式和其他附件仍以 **打开** 打开原文件。主按钮固定占位，详细行为见 [markdown-browser-open.md](markdown-browser-open.md)。
- **⋯**与当前附件的右键菜单共用同一菜单与动作实现，不维护另一套菜单副本。
- Markdown 菜单固定提供浏览器打开和打开原文件，打开方式仍针对原 MD；其他 macOS 菜单沿用打开、打开方式、快速查看、在访达中显示、拷贝文件、拷贝路径；其他平台
  复用各自实际支持的附件菜单能力，不承诺不存在的原生动作。
- 所有按钮具备可访问名称与可见焦点；窄预览区仍须能操作切换和关闭，布局不得裁掉动作。
- 标题栏始终保持一行；宽度不足时截断文件名，不因窄宽度改为两行。

Popup 提问附件的“快速查看”直接展开新面板，不再提供 Quick Look 模式。
该动作是显式查看，不因为目标已经激活而反向收起。

## 5. 内容显示

| 类型 | 默认显示 | 原文切换 |
|---|---|---|
| Markdown | 格式化预览 | 查看原文 / 查看预览 |
| `.diff` / `.patch` | 单栏高亮 diff | 查看原文 / 查看预览 |
| 图片 | 默认居中、等比适应可用区域，支持缩放与拖放 | 不提供 |
| 普通文本 | 保留缩进、空白与换行的文本 | 不提供 |
| macOS 系统文档 / 媒体 | 同窗原生正文，实际能力随系统和预览扩展变化 | 不提供 |
| 其他格式 | 文件信息、打开、在文件管理器中显示 | 不提供 |

### 5.1 Markdown 与 diff

Markdown 预览中的显式 `mermaid` fence 支持图表，沿用正文的 sandbox / 静态 SVG 清洗和
10 图、40,000 字符 / 图、400 条边限制。单图支持复制与查看源码，错误或超限只回退该图。
宽图优先适配到容器，但可见字号不低于 12px；剩余溢出横向滚动。图表随应用有效主题重绘，
切换附件或原文模式后不写入过期渲染结果。正文 HTML 和链接 / 图片 URL 仍由受限后端 renderer
生成，增强层不重新解析原文或放宽 URL。浏览器快照的同等支持见
[Markdown 浏览器打开](markdown-browser-open.md#41-mermaid-图表)。

Markdown 默认展示排版后的结果。diff 沿用既有 unified diff 语义：红绿增删底色、原始前缀、
旧 / 新行号、文件头与变更块；无法解析的内容保留原文。格式与资源边界以
[diff-attachment-preview.md](diff-attachment-preview.md) 为基础，不增加双栏对照或代码语法高亮。

查看原文展示原附件文本，保留格式符号、diff 元数据、缩进、空行与原始前缀，不修改文件。
切回预览恢复格式化显示。正式行为在本次 Popup 内为每个附件独立记住阅读模式和阅读位置，
切换到其他附件或收起后重开时恢复；原文与预览各自保留位置。新 Popup 的 Markdown / diff
首次打开仍默认预览，阅读状态不写入全局设置。早期原型的每次恢复预览 / 顶部行为以此决策替代。

原文与预览属于同一个附件，打开、拷贝、拖出与右键菜单的目标始终是原附件路径。

### 5.2 图片与文本

图片默认为“适应”模式，等比缩放并居中完整显示，不裁切内容；窗口或分隔线改变尺寸时重新
适应。控件保持紧凑，只提供适应、100%、缩小、放大，不添加常驻手势提示栏。

图片拖动根据是否有超出视口的内容区分：

- 默认适应、没有溢出时，直接拖动图片用于 Drag and Drop，拖出原附件文件。
- 放大后内容溢出、出现滚动条时，直接拖动图片用于平移查看；也可用滚动条、滚轮或触控板。
- 没有实际溢出时不切换为平移。放大状态仍可从主区域的附件胶囊拖出原文件。
- 回到适应后恢复直接拖出图片的行为。缩放与平移不修改原附件。

GIF 和动画 WebP 正常播放。图片缩放与查看位置按附件在当前 Popup 内保存。
正式面板已接入缩放 / 拖放分工，项目 `assets/overview.webp` 用于安装后的适应与平移验收。

纯文本使用等宽字体、保留缩进与空行。长行应能横向阅读，正文独立滚动，不挤走标题栏或主
区域的回答按钮。文件读取、编码判定及图片解码失败时，在预览区说明原因并保留打开入口。

格式识别保留 Markdown、diff / patch、已支持图片和有界文本；macOS 富文本、系统文档和媒体优先
识别为原生正文，避免把 RTF 控制文本当作普通正文。
能够可靠解码的普通文本直接展示，包含代码、JSON、日志与无扩展名文件，不仅依赖扩展名白名单。
二进制或无法解码的文件不展示乱码；macOS 可交给系统视图，其他平台保留文件信息与操作。

基础图片格式为 PNG、JPEG、GIF、WebP、BMP、SVG；轻量 ICO、TGA、PNM 解码在三平台可用，
macOS 系统图片扩展见 §5.4。解码不支持时保留文件操作入口。
SVG 使用隔离的图片显示方式。普通文本识别支持 UTF-8 与带 BOM 的 UTF-16，不可靠的编码不展示乱码。
读取有资源上限；超限说明原因并提供文件操作，不用截断内容冒充完整附件。Diff 保持现有
2 MiB / 20,000 行 / 单行 16 KiB 边界。普通文本 / Markdown 为 2 MiB / 20,000 行；
Markdown 另限 50,000 parser events 和 8 MiB HTML；位图 20 MiB / 4,000 万像素，动画最多
500 帧且总 canvas 像素不超过 8,000 万；SVG 2 MiB / 5,000 nodes / 65 层。内容缓存每
Popup 64 MiB，列表缩略图独立预算。具体证据与限制见实现计划 §3.3。

### 5.3 不支持预览

预览内容区居中展示文件名与简短的“不支持预览”说明，下方提供打开和在文件管理器中显示
两个按钮。macOS 的文案为“打开”“在访达中显示”；其他平台使用对应文件管理器的本地化名称。
打开调用原文件的默认应用，显示动作定位原文件。标题栏仍支持切换附件和关闭，不能因不支持
格式而自动打开外部应用。读取失败或超限也保留这两项文件操作。

### 5.4 macOS 系统预览扩展

2026-10-05 发现同窗面板在 ICNS 等格式上缩小了旧 Quick Look 的覆盖范围。本轮在相同布局内
使用公开系统框架补齐；分析、实现及验证记录见
[popup-native-preview-coverage.md](../investigations/popup-native-preview-coverage.md)。

- Image I/O 从有界附件字节解码 ICNS / ICO、TIFF、HEIC、JPEG 2000、PSD、EXR、AVIF、RAW 等
  系统支持的格式，再转成 PNG 交给现有图片组件。格式能力取决于运行系统；PSD 显示合成图，
  RAW 取决于系统和相机型号。旋转方向由系统转换；图标取最大有效表示。
  Image I/O 无法识别的类型交给系统预览扩展尝试；已识别但损坏的图片保留明确失败说明。
- 多图 TIFF / HEIC 等交原始文件给系统预览，并显示已识别的图像数量、提示打开原文件查看全部。
  系统扩展可能仅提供代表图像；不能把单幅 PNG 当作完整多图文件。已有 GIF / WebP 的原字节动画保留。
- PDF 使用 PDFKit 的连续多页阅读，后台创建文档，主线程仅挂载正文视图。保存页码、页面坐标与
  缩放；切换或收起后恢复。加密或 PDFKit 无法加载时交给 Quick Look。
- Office / iWork、RTF、媒体及其他二进制使用 `QLPreviewView`。静态系统文档最多保留两个原生视图，
  在本次 Popup 内保留其滚动 / 选择状态；淘汰后按系统 `displayState` 尽力恢复。媒体不自动播放，
  切换 / 关闭时卸载当前媒体项，恢复位置以系统扩展实际支持为准。
  新请求销毁上一条请求的原生视图缓存与阅读状态。
- 系统视图只占正文，HTML 标题栏仍管理切附件、打开原文件、菜单和关闭。几何按内容点坐标裁剪，
  不覆盖回答区或固定标题栏；取消确认和收尾期间隐藏原生视图。原生焦点下 Esc / 发送 / 取消
  回到现有业务优先级，输入法组合态优先。
- 原生正文命令只接受请求 ID / 附件索引，须先获得有界读取授予的许可，并检查文件大小 / 修改时间、
  活跃请求和更新代次。PDF 异步任务在切换后丢弃结果，旧任务不能重新显示正文。
- 系统文档 / 媒体输入最多 100 MiB；系统图片仍受 20 MiB / 4,000 万像素约束，多图总像素最多
  8,000 万、最多 500 幅，转码 PNG 最多 20 MiB。列表系统图片缩略图最长边 192 px，仍受列表
  2 MiB 读取与 8 MiB 前端缓存预算。原生文档视图按数量限制，系统扩展的内存不计入 64 MiB JSON 缓存。
  未识别的二进制只在 2 MiB 有界文本识别失败后尝试系统预览，不扩大普通文本读取上限。
- 预览格式与 CLI / IM 的 `isImage` 传输分类独立，后者的原有七种扩展名不变。RTFD 目录包仍受
  CLI 只接受普通文件的既有约束；不为本次预览扩大目录附件能力。

## 6. 平台与现有入口边界

三平台的 Popup 提问附件统一使用新面板，不新增预览模式设置。新面板替代该入口的独立 Quick Look
面板；macOS 可以在同窗正文使用系统视图，不保留可切回独立模式。历史、待办、回复附件及其他首版范围之外的入口仍沿用现有行为，
因此本轮不全局删除仍被这些入口使用的 Quick Look 实现。

Linux Wayland / 窗口管理器可能拒绝精确窗口定位。采用同一窗口能保证主区域与预览共同移动，
但不能消除程序扩展窗口、设置位置、恢复锚点的限制。定位或扩展无法可靠完成时应使用原尺寸
内的分区；正式实现须在目标桌面验证，不能用 macOS 原型代替跨平台验收。

## 7. 实现必须保持的边界

- 附件读取与渲染不阻塞主区域作答；加载中、错误或不支持格式仅影响预览区域。
- 快速切换、关闭、提交或销毁后，旧读取结果不能覆盖新附件或重新展开预览。
- 读取目标来自当前 Popup 已提供的附件，不根据 diff 内部路径读取其他文件或应用 patch。
- 内容渲染继续遵守现有转义、清洗、资源上限与隔离规则；原文作为文本展示。
- 深浅色与应用有效主题一致；标题栏、文本和 diff 颜色保持可读。
- 保留既有单题、多题、纵向模式、固定答案编辑器、焦点仲裁、拖入 / 拖出与提交行为。
- 本次规格整理不调整已实现的 stdout、IM 渠道附件发送及其他预览入口。

## 8. 实施阶段需验证的技术参数

产品交互已逐项确认，以下技术参数由实现计划与实机验证收口，不增加未确认的产品功能：

1. **读取性能**：文本判定、Markdown 与图片的具体资源上限和 SVG 隔离验证；diff 不放宽现有上限。
2. **原生布局**：三平台工作区 / DPI / 多屏、Wayland 降级、最小尺寸，以及
   恢复与尺寸记忆的正确性。原型数值与生产尺寸下限需要共同验证。

## 9. 验收矩阵

1. 默认窗口紧凑；点击附件才展开，关闭或再次点击当前附件后恢复主区域尺寸和取消激活。
2. 点击其他附件、连续上一张 / 下一张时内容与高亮同步；按钮坐标稳定，不反复缩放窗口。
3. 固定右侧；当前位置不足时左移，整屏不足时先缩小预览，最后才临时缩窄回答区。
   关闭恢复原位置，手动移动过则保留新位置；受限分区关闭后恢复原主区域宽度。
4. 拖动窗口与分隔线、外缘缩放、关闭后重开、跨屏及工作区变化时主区域与预览保持可用。
5. 发送 / 取消始终留在主区域；单题、多题、纵向题卡与答案草稿的状态不丢失。
6. Markdown / diff 默认预览，带边框的查看原文按钮紧挨标题；原文完整、切回正常。
7. 图片默认适应；没有溢出时拖动可拖出文件，放大溢出后拖动平移，回到适应恢复拖出；动画
   正常播放。纯文本自动识别且保留格式；不支持 / 失败时有信息及打开、文件管理器定位两个按钮。
8. 打开与右键菜单始终针对原附件，更多按钮与右键动作一致；快捷键按最终确认规则验证。
9. Popup 提问附件统一新面板，不新增 Quick Look 模式开关；其他入口不变，展开总尺寸不污染
   下一次主弹窗的尺寸记忆。
10. 快速切换或关闭时旧后台结果失效；三平台实际安装后验证，覆盖主题、输入焦点及读取失败。
11. 在本次 Popup 内恢复各附件的阅读模式、滚动位置与图片缩放状态；新 Popup 不继承这些状态。
