# 多请求统一作答窗口

> 状态：2026-10-07，macOS 正式实现已安装；未读 ripple v2 实机效果已获用户确认。
> 用户要求：Spec → Vue 3 + Tauri 2 demo → 用户确认满意 → 正式实现。不得以浏览器截图替代原生扩窗验收。
> 实施计划见 [popup-request-inbox](../plans/popup-request-inbox.md)，当前实现地图见 [Popup UI 概览](../overview-popup-ui.md)。2026-10-08 已补齐 Windows 11 VM 的合并窗口核心流程与到达动效，见计划 §27；Linux、真实 IM 及 DPI/多屏等外部验收仍按 PROGRESS 的延期安排。
> 关联：[附件预览](popup-attachment-preview-panel.md)、[重复请求收敛](duplicate-ask-coalescing.md)、
> [权限审批](../plans/agent-permission-approval.md)、[结束确认](agent-stop-confirmation.md)。
> §9–14 保留旧原型迭代历史；当前到达提醒以 §4.1 和 [气泡动效规格](popup-arrival-envelope.md) 为准。

## 1. 目标

多个 Agent 同时请求人类回应时，使用一个作答窗口收纳所有本地待答请求，避免窗口堆叠。
只有一条请求时沿用普通弹窗；第二条到达后在左侧出现待答 Sidebar。正文一次只呈现一个请求，
各请求仍独立回答、独立终结，回答结果立即返回对应 Agent，不等待整个队列完成。

一次请求可能包含多道题：Sidebar 的单位是请求，题内导航继续在正文中处理。普通提问、
权限审批和结束确认均收纳，保留各类型的原有表单、提交规则、返回结果和取消语义。

统一范围是同一个 AskHuman 实例；不同 Dev Instance 继续隔离，不跨实例聚合。

## 3. 窗口与导航

```text
┌─────────────────┬──────────────────────────┬─────────────────┐
│ 待答 4          │ 当前请求的来源与工具栏   │ 附件预览（按需）│
│                 │                          │                 │
│ HumanInLoop · 3 │ 问题内容 / 审批详情      │ 当前请求的附件  │
│ ▸ 确认导航方式  │                          │                 │
│   允许运行测试  │ 预设选项 / 回答编辑器    │                 │
│   下一步任务    │                          │                 │
│                 │                          │                 │
│ Website · 1     │                          │                 │
│   选择首页方案  │ 取消当前请求       发送  │                 │
└─────────────────┴──────────────────────────┴─────────────────┘
```

Sidebar 顶部显示待答总数；项目组头显示项目名和该组待答数，完整路径可查看。同名项目以路径
区分，不按 basename 合并；来源缺失的请求归入“未识别项目”，不猜测项目或 Agent 会话。

条目主标题是问题摘要，下面把 Agent 与 session 任务标题合为一行来源路径：
`Agent / 会话图标 + 任务名`。任务名使用次要文字，会话图标与路径关系区分它和问题正文；
不增加“标题”等文字标签、引用线、大块来源区域或第三行元数据。Agent 展示名复用既有本地化口径。
普通提问不显示冗余“提问”标记；权限与 Stop 在摘要前使用短类型标记，草稿标记保留在来源行末。
任务标题长时省略，悬停显示完整文字；只按可信 `(agent_kind, agent_session_id)` 精确取标题，
优先使用 Agent 注册表中已有的标题（包括 Codex App 任务名），缺失时异步复用原生会话标题解析。
会话未追踪也可按可信身份解析；没有可信 session 或标题时隐藏任务标题，不显示“未命名任务”。
普通提问、权限审批和结束确认使用同样的展示。类型用“权限”/
“结束确认”等轻量标记区分；当前条目使用持续选中底色，新条目使用短暂高亮及标题前蓝点，
有未提交内容时显示“草稿”。避免只有“Codex”而无法区分同项目内的并发会话。
会话名不可用时保留 Agent 和请求摘要，不为获取标题阻塞首屏。

摘要来自请求已有标题或正文首个有内容的段落，只供导航，不改变原始题目或结果。类型标记与
草稿状态不能仅靠颜色辨识。条目允许两行摘要，长内容截断并提供完整信息。

答复成功才将条目移出；发送中禁用该请求的重复提交，失败保留表单并就地显示重试入口。
提交任意条目后按当前显示顺序选择其下一条；若当前项目仍有其他条目，优先留在该项目，
没有后继时循环该项目尚存的条目，再进入下一项目；空项目组消失。

## 4. 新请求、切换与终结

### 4.1 新请求

第一条请求显示普通弹窗。第二条请求到达时新增 Sidebar，但正文的选择、滚动、输入焦点和
输入法组合态继续保持。更多请求追加列表，不能自动切换当前提问。
第一条不播放中央气泡，但每轮窗口从隐藏到显示时仍沿用配置的 macOS 原生出现动画
（`general.appearAnimation`，默认 `alert`）；冷启动和复用预热宿主一致，保持其他应用键盘焦点。
已经可见的窗口只非激活前置，不重复原生开窗动画。后续请求在前置和 Sidebar 原生几何提交完成后，以作答区
（含 Sidebar、不含右侧附件预览）中央为起点：柔光瓷面白色底板上的蓝色提问气泡
220ms 出现、上下弹跳两次（1000ms / 616ms）、下落接勾线飞行 750ms，透明问号闭合、底板淡去，落为对应条目的
10px 蓝点；条目随后高亮一次 640ms。每条独立完整播放，允许并发；图标层透过全部鼠标
操作，不改变焦点、选区和输入法组合态。正式参数和边界见 [到达气泡规格](popup-arrival-envelope.md)。
窗口被遮挡时非激活前置；已最小化时也恢复并前置。其他应用保持
键盘焦点，用户点击作答窗口后才转入回答；窗口本已在前台时也不改变原编辑器焦点。
前置仅调整此次层级，不把普通窗口永久设为 always-on-top；保持当前请求、选区与草稿。
开始飞行前只滚动 Sidebar，将新条目放入可见区；飞行中追踪实际蓝点，用户将落点滚出
可见区时结束飞行并保留未读提示。图标在关闭确认框下方；答完换题期间先收纳请求，
换题结束后同时播放仍未查看的新请求。查看或终态取消相应动效，不再重新写回未读状态。
系统减少动态效果时用静态未读高亮和蓝点替代飞行；不缩放整窗。蓝点的查看状态与动效计时独立：
经过再长的时间也不自动清除。主动打开或提交后自动切入该请求，显示正文后才视为查看；
只展开项目组、悬停、看到导航摘要或闪烁结束均不算查看。查看后保留蓝点占位，避免标题左右移动。
正式蓝点直径 10pt，周期 2.8s，使用端点平缓的颜色变化（#2685e8 → #006dff → #2685e8），
始终不透明、不缩放，没有光环、数字或顶部新增提示。系统减少动态效果时保留静态蓝点。
查看后只清除新提示，待答条目不置灰、不改变字重；答复成功才移除。

落位的一次高亮结束后，仍未查看的条目开始循环圆形填色 ripple。源点固定为现有蓝点中心，
初始半径 5px，目标半径是到行最远角距离的 105%；圆形裁切在行的 8px 圆角内，
绘制于文本和蓝点下方，保持现有文字、间距、选中和悬停背景。
用户验收的 v2 参数：扩散 2000ms，曲线 `cubic-bezier(.684, 0, .74, 0)`；从 800ms 开始
线性渐隐 1500ms，与扩散重叠 1200ms（60%），透明休息 1000ms，周期 3300ms，
条目间无额外错峰。填色 `#2685e8`，浅色峰值透明度 18%、深色 25.2%。
柔化是实际行坐标中的宽度，从 0 到 100px 按扩散进度的平方增长，随圆形缩放补偿，
拖动 Sidebar 改变行宽时重新计算覆盖范围并保留当前动画进度。
真正打开该请求后立即停止；条目移出可见列表、文档隐藏或系统减少动态效果时暂停。
透明休息段不提交逐帧绘制；请求移除及 Sidebar 卸载清理动画资源。
减少动态效果使用静态浅蓝行背景和蓝点，不播放持续扩散。

### 4.2 切换与独立状态

用户可先写草稿再切去回答另一条。返回时恢复各题的文字、选项、回复图片/文件、当前题目、
正文滚动，以及该请求附件的激活项、模式、阅读位置和缩放。切换只移交当前请求上下文，
不会把旧请求的草稿、附件、快捷键或异步加载结果套到新请求。

权限审批不预选批准，也不沿用上一请求的决定。已有推荐选项与多题提交规则保留。
发送按钮、题内导航和取消动作只位于正文区域，不横跨 Sidebar 或附件预览。
窗口置顶、主题等窗口级动作属于统一窗口；来源、附件、查找和回答动作属于当前请求。
配置热更新中的主题必须同时应用到原生窗口外观和前端颜色（包括跟随系统），
沿用独立 Helper 的原生主题处理；同步不重建窗口、请求正文或草稿。

### 4.3 外部终态与竞态

非当前请求在其他渠道完成或被撤销：移出条目，更新计数，不动当前正文。
当前请求出现外部终态：立即禁用旧表单发送，短暂显示来源明确的提示，再切到下一条；
全部请求终结时直接关闭。外部终态后的旧草稿不发送、不迁移到下一条；关闭不额外展示恢复页。

每条请求仍沿用 Daemon 首个终态胜出的契约。连续按键、迟到回调、提交与远端回答竞态不能
回答到刚切入的新请求。窗口是否关闭以最新队列为准，不能以陈旧的“最后一条”判断误关
刚到达的新请求。正式实现需验证发送确认、列表更新和窗口关闭之间的并发顺序。

### 4.4 IPC 分段读取与断连诊断

同一连接接收的 JSON 可以跨多次传输到达，包括带截图的大答案。100ms 终态巡检或其他
`select!` 分支完成后，必须保留已经读取的半帧；巡检继续运行，不能因取消一次读取而丢掉
JSON 前缀、误判协议错误并重建宿主。独立 Ask / Confirm 和 Interject 复用读端时遵守同一约束。

共享宿主断连记录 generation、原因及有限的待答请求 ID，区分 EOF、JSON 类别与行列、
IO kind / OS code、写端结束和正常空闲退役。日志不包含答案、图片、token、凭证或可能携带
用户值的原始错误文本。具体修复与回归记录见 `docs/plans/popup-ipc-cancellation.md`。

## 5. 关闭与取消

多条请求时，原生关闭和 ⌘W / Ctrl+W 打开窗口内确认层，不另弹独立系统窗口。
确认层固定当时的当前请求和请求集合，包含三个动作：

- “继续回答”：默认焦点，退出确认层；
- “取消当前请求”：带当前摘要，对该请求执行既有取消语义，之后进入下一条；
- “取消全部 N 个请求”：只处理确认层打开时的那批尚未终结请求。

确认层显示结果摘要，例如：

> 取消 2 个提问、拒绝 1 个权限申请、允许 1 个任务结束。将丢弃 2 份未提交草稿。
> 确认层打开后新到的请求不在此次范围内。

普通 Ask 返回取消状态；Permission 执行其 dismiss action（现为拒绝，已有原因随原语义处理）；
Stop 取消沿用允许结束的语义。Claude 接管的内置提问沿用其取消后要求重新询问的契约。
取消全部不能批量批准权限或把 Stop 的取消解释为继续工作。

快照内已被其他渠道解决的请求跳过，不重复终结。新请求仍进入列表并短暂高亮，确认层内
可提示新到达数量，但不扩大此次取消范围。提交取消失败的条目继续等待并显示错误。
批量取消后仍有新请求则窗口继续存在。

只剩一条时不展示重复的“取消当前 / 取消全部”动作，使用该请求原有取消/关闭确认规则；
Sidebar 是否显示仍按本轮已展开状态处理。Esc 保留关闭查找、语音、附件等已有优先级，
确认层打开时仅关闭确认层，不暗中取消请求。

## 6. 原生几何与附件共存

参考附件预览的工作区计算、冻结主区域、绘制后几何事务和受限尺寸恢复规则，扩展到左右附区。
只有一个请求时不预留 Sidebar 空白。第二条到达时固定向左扩展：

1. 正文原宽度和当前屏幕位置作为基准，尽量向左增加 Sidebar 宽度；
2. 当前左侧不足而屏幕整体可容纳时，整窗向右平移；
3. 有右预览时共同计算左/中/右分配，先缩预览至可读宽度，再缩 Sidebar；
4. 整个工作区仍放不下时才临时缩正文，保持三个区域的方向；极窄分配由原型验证；
5. Sidebar 约 240px、可读下限候选约 180px，数值需原型确认，不能作为未经验证的硬下限。

扩展先冻结正文尺寸，准备侧栏后再执行原生窗口几何；使用实际尺寸对账，避免正文瞬间
撑满扩大的窗口又缩回。扩窗应保留焦点、选区、正文滚动和 composer 位置。
仅冻结正文宽度不足以消除 DOM 与原生窗口分次提交造成的中间帧。macOS 正式实现使用
固定原生画布和窗口裁切（§15）；WebKit 与原生 PDF/Quick Look 位于同一画布。窗口位置
和画布补偿在同一原生事务更新，不逐帧 resize WebKit、不使用截图过渡。其他平台沿用
离散几何提交，Windows/Linux 的实机绘制验收保留为后续 gate。
空间足够且未平移时，正文屏幕坐标不变；必要平移时只允许随整窗移动，不发生额外内部位移。
主动选择的整窗提醒动画短暂缩放画面，结束后必须恢复精确正文尺寸、位置及滚动，不写入尺寸偏好。

正文尺寸、Sidebar 分配和右预览尺寸分开管理。自动受限、最大化、多屏/DPI变化不能污染
正常偏好；下一轮单条窗口恢复有效正文尺寸。用户手动拖动后的新位置应保留。
拖动标题栏时三区同窗移动；窗口外缘、分隔线和请求切换与附件恢复的组合行为在原型中验证。
Sidebar 只由分隔线调整宽度。普通外缘缩放时，预览关闭则正文吸收宽度变化；预览打开
则保持正文和 Sidebar 的宽度，让右预览吸收变化。外缘最小宽度包括当前固定分区及
可读区域下限；受限工作区的临时分配仍按上述缩减顺序。
拖动 Sidebar / 正文分隔线时，窗口外框保持原位与原尺寸，只在这两个区域间分配宽度；
Preview 保持原宽度与屏幕位置。通常 Sidebar 下限 180、上限 600，正文至少保留 420；
已有受限布局允许保留更小的当前尺寸，不能通过内部拖动继续挤压正文。
松开后保存 `channels.popup.sidebarWidth`（默认 240），遵守 rememberSize，与正常正文
尺寸一起在下一轮、重启后恢复。拖动中只更新内存，避免逐帧写配置；保存失败需显示错误。

## 12. WindowServer 私有接口调研

### 候选与推荐

| 接口 | 用途 / 证据 | 对此次提醒的判断 |
|---|---|---|
| `SLSSetWindowTransform` / `CGSSetWindowTransform` | 窗口合成画面的仿射变换；Firefox 源码仍有对应实现 | 推荐先做缩放原型，保持实际 frame 和 DOM 布局不变 |
| `SLSTransactionSetWindowTransform` + create/commit | yabai 的动画路径逐帧提交窗口变换 | 可作为后续同步多个合成属性的事务候选；不是传入 duration 就自动完成动画 |
| `SLSSetWindowWarp` / `CGSSetWindowWarp` | 将窗口局部点映射到屏幕点的网格变形，Chromium 历史实现及较新 GenieWarpMesh 有使用 | 更适合透视、Sheet、Genie；此次轻微均匀缩放无需复杂网格 |
| Metal Sheet / Genie animation + progress | 系统预设的 Sheet / 最小化类型动画对象 | 与待答窗口提醒的形态不匹配，不作为首选 |

推荐方向是用 **WindowServer 合成变换** 替换此次提醒的 frame 动画。窗口边框、交通灯、
内容等作为窗口画面一起变换，实际 NSWindow frame、WebView viewport 和正文滚动保持。
均匀缩放以窗口中心为基准，使用按显示刷新推进的时间曲线；结束及失败恢复捕获的原变换。
这是从源码行为得出的候选判断，仍需当前机器真实画面、阴影、命中区域和恢复验证。

Firefox 的实现说明该接口接收“屏幕像素映射到窗口 buffer”的逆变换，坐标原点为左上；
不可直接照搬普通 View 的正向 scale。窗口隐藏时调用有错位风险，应先完成非激活显示
并确认窗口可见，最后恢复原 transform，不能仅写无位移的 identity 作为恢复。

确认 `SLSMainConnectionID`、`SLSSetWindowTransform`、`SLSGetWindowTransform`、
`SLSGetWindowBounds`、`SLSTransactionCreate`、`SLSTransactionCommit`、
`SLSTransactionSetWindowTransform`、`SLSSetWindowWarp` 等存在。

调研提出的候选：只在隔离 demo 内动态解析必要函数，对自己创建的窗口做短暂缩放，记录

不复制正文、分割线或 PDF，不依赖截图交接。Sidebar / Preview 展开与收起均即时完成，
原生几何 commit 固定为 0ms，不再提供正式宿主内的慢速动画开关。
固定 viewport 只覆盖 pane 过渡；真实用户外缘拖动采用 AppKit autoresizing 和自适应 CSS，
不逐帧异步重设画布。过渡结束保持同一正文原点，移除离屏 reserve 后再恢复自适应布局。
自动布局仍不覆盖尺寸偏好。正式 Dev 入口仅保留 Sidebar 切换和几何只读诊断；
带慢速动画的实验留在独立几何 harness，不进入正常作答窗口。

设置入口为「通用 → 弹窗行为 → 提问窗口模式」（该卡第一项），配置值 `merged` / `independent`。
设置搜索支持合并、独立、窗口模式、Sidebar 及英文模式名称，并跳转到该行。
关闭本地弹窗渠道时该选项仍可见，允许提前选择启用后的模式。
旧配置缺失字段默认合并。修改后新请求走所选模式，已经打开的提问和草稿继续保留；
因此切换时可以暂时同时存在旧合并窗口和新独立窗口。预热只补充当前选中模式的空宿主；
旧模式的空闲实例回收，在途实例答完后按当前配置退出。独立模式沿用旧 Helper / 焦点仲裁。

## 18. 发送成功后的换题

用户最初选择「完成后轻推」，实机使用后要求移除先提示「已发送」并停留的行为。
最终确认：成功后立即开始换题，保留 300ms 接替动画。

| 阶段 | 表现与时序 |
| --- | --- |
| 等待回执 | 发送按钮显示发送中；保留当前问题与回答，阻止重复提交，同时隐藏准备下一条 |
| 正文接替 | 成功回执后不显示「已发送 / 已提交」、完成勾选或确认停留；下一条就绪后直接开始 300ms 接替：旧正文向上 14px 淡出 126ms，曲线 `cubic-bezier(.4, 0, 1, 1)`；新正文从下方 14px 淡入 174ms，曲线 `cubic-bezier(0, 0, .2, 1)` |
| 队列推进 | 当前条目同期收起，高度降到零并淡出 300ms，曲线 `cubic-bezier(.2, 0, .2, 1)`；下一条选中与正文进入同步 |
| 可以继续回答 | 接替结束恢复输入与发送，按既有策略恢复焦点、选区和草稿 |

窗口、来源标题栏和页脚位置保持稳定，只移动正文及已完成的队列条目。下一条沿用
既有同项目优先顺序；未查看状态在真正显示正文时清除。需要附件的下一条应先准备
好正文和原生预览再显示，不能短暂呈现上一个请求的附件或未就绪内容。初始化或原生
同步是实际就绪门槛，不设置额外的成功确认等待。发送开始即隐藏挂载后继表单，ready /
初始化失败信号直接唤醒等待方，避免串行事件队列互等。

失败保留当前问题、选择和输入，就地显示错误并允许重试。取消或其他渠道抢答不使用
成功换题动画。连续到达和终态竞态继续以 Daemon 结果为准，下一条已完成时跳过，不
显示失效表单；动画及计时资源必须可取消并在关窗 / 清空队列时结束。

系统减少动态效果时跳过接替动画，直接换题。最后一条收到成功结果就关闭窗口，不设
成功停留，不增加正式空队列页面。独立窗口行为不变。

正式合并宿主已接入；Sidebar / Preview 的原生几何仍沿用 §17 的即时提交。`Inbox`
按请求 ID 记录本地提交意图，只有 Daemon 确认由 popup 完成的成功终态带内部
`sent` / `submitted` 分类，供前端区分回答、取消和外部终态，不作为用户可见反馈。
迟到成功会清除之前的回执超时错误；同一请求的 Cancel / Ack 只产生一次前端终态。

旧 WindowServer 整窗提醒已由前端气泡飞入替换，生产路径不再注册缩放交互监听。
pane 几何在真实标题栏拖动期间暂缓，松开后按最终工作区对账。
正式即时切换在单次 AppKit 回调内提交绝对尺寸和画布补偿，保留准备后用户移动的增量。
Review 和原生证据见 [原生几何复核](../investigations/popup-native-geometry-review.md)。

原生附件同步期间保留上一条标题栏，下一条以不可见但可测量的布局准备；同步结束才
显示新正文、切换 Sidebar 选中和清除未查看状态。输入阻塞与原生预览准备独立：过渡
中不能作答，但可在揭示前同步下一条原生预览。卸载会结束全部等待；已准备的附件
布局事务仍进行必要的结束清理。

## 19. 内部布局冲突与错误提示

`preview geometry changed` 表示布局等待超时，或准备 / 提交 / 结束阶段的事务已失效，
不能仅凭此返回值断定当前画面有问题。此内部结果不作为用户可见提示，不因该返回值
额外重排窗口或重建表单；继续沿用既有事务结束清理与超时 reconcile。

后端将具体失败阶段写入已有 `daemon.log` 的 `popup_geometry` 事件：等待超时、
准备忙碌、准备超时回收、提交失效及结束失效分别记录固定标签，不包含提问、答案、
附件路径或任意错误文本。队列继续处理后续事件。其他实际操作错误仍按原有入口显示。
成功手动切题和结束本轮清除旧队列错误，避免复用宿主把旧提示带到下一轮；取消失败
保留在关闭确认中，不由后台布局成功清除。

## 20. Markdown 文件链接与页面导航

点击 Message、题干或 Confirm 正文内的本地文件链接时，打开原文件，保留当前作答界面、
所有请求及各自草稿。使用 Markdown 的原始链接路径，不能把 `/Users/...`、Windows 盘符
路径或相对路径当作 Tauri 资源地址。文件引用末尾的 `:行号` / `:行号:列号` 与 `#L行号`
不属于文件名；打开时剥离这些位置标记并解码 URL 路径。相对路径使用当前请求的项目
目录，不能使用共享宿主的进程目录；缺少目录时不猜测。此入口打开原文件，不承诺编辑器
跳转行号。HTTP(S) / mailto 继续由系统默认程序打开，文内片段只在当前正文定位。

所有链接先阻止默认页面导航。不支持、无效或打开失败的链接不能让整个 WebView 跳转，
也不能使合并模式退回无请求 ID 的独立视图。Popup 主文档从初始化阶段就捕获取消普通
及中键链接的默认导航，作为正文处理器之外的兜底；保留 Vue 事件路由及 Mermaid sandbox
子帧。合并与独立模式都遵守此约定，不通过放宽共享宿主请求 ID 校验来掩盖错误跳转。
