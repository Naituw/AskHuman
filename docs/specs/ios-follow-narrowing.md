# 需求：去掉手动「关注」，只给手机创建的任务通知「做完 / 出错」，并遵守「Mac 空闲才推」

> 状态：**已批准并实现；Mac 端（计划 P1–P2）已装机，App 端（P3）已提交**（2026-10-27 起草；同日用户经 AskHuman 批准全部决策 F1–F6）。
> 实施顺序（用户定）：先做 Mac 端并装机，App 去星标之后再单独开工——两步都已完成。自动化覆盖：Rust 网关单测（虚拟时钟）、Swift 单测与真实 daemon 端到端、
> 模拟器 UI 测试（en + zh-Hans）、模拟器上真 App 对真实 EMQX / 中继 / APNs 沙盒的完整场景（含「第一次结果的推送 + 之后铃铛消失」）。
> **没有在用户的真机上验证过**（真机一轮见 `docs/PROGRESS.md`）。
>
> 痛点：`ios-alert-timing` 之后，Agents 页本来就列出所有 Agent 的状态（不用关注也看得到），提问也不再靠「关注」送达。
> 「关注」只剩一个用途：被关注的 Agent 做完 / 出错时给手机推一条通知。这个用途有两个问题：星标的含义说不清；
> 这类推送**立即发**，不看 Mac 在不在用，和刚定下的「你在电脑前不打扰」相悖。
>
> 用户原话（2026-10-26）：「我没有关注过的 Agent 也可以看到当前的状态，这个很好。然后发现有这个功能之后，
> 我们还是有一个关注按钮，这个关注按钮是做什么的？是不是没有什么必要了？」
>
> 目标：手机上不再有手动关注；**只有从手机创建的任务**会在做完 / 出错时通知，并且和提问一样，**Mac 键鼠空闲满 D 才推**。
>
> 关联计划：`docs/plans/ios-follow-narrowing.md`。落地后同步修订 `docs/specs/ios-channel.md`（术语、D18、§6.6、§6.7、局限 4 / 15、验收 8 / 10）、
> `docs/specs/ios-alert-timing.md`（D11、局限 8、后续）、`docs/overview-ios.md`、`docs/wiki/ios-setup.md` 与 `.en.md`。范围**只含 iOS**。

## 现状（供评审对照）

- **关注集**：每台 Mac 上每部手机最多 5 个（`MAX_FOLLOW`，`ios/wire.rs` 与 Swift `Wire.maxFollow` 必须一致）；星标手动加入 / 移出，
  从手机创建的任务启动成功后自动加入；会话结束时静默移出。存在 `~/.askhuman/ios/state.json` 的 `followSet`。
- **三类通知**。手机在前台时发应用内横幅，否则发推送，**都不看 Mac 空闲**：
  - 做完：一轮结束，且 3 秒内没有新活动才算；
  - 出错：lifecycle hook 报告该轮失败，立即；
  - 在等你：被关注的 Agent 有一道没投给手机的提问。自 `ios-alert-timing` 起每道题都挂在手机收件箱，这类推送实际上不再触发
    （只剩边角情形，例如请求创建时还没有配对手机）。
- **App**：详情页的「关注 / 已关注」按钮、列表行的星标、「已关注」过滤、关注名额满的提示条、新任务进度页里「你已关注它」的字样。

## 决策记录

- **F1 去掉手动关注**（用户 2026-10-27 选定：「去掉手动关注星标，只保留『从手机发起的任务做完 / 出错』自动通知」）：
  App 不再有星标按钮、「已关注」过滤和名额提示。从手机创建的任务启动成功后，该会话仍自动进入**通知集**（即现在的关注集）。
- **F2 通知遵守「离开 Mac 才打扰」**（用户选定：「和提问一致：Mac 键鼠空闲满 D（默认 15 分钟）才推，你在电脑前不打扰」）：
  手机没在看时，「做完 / 出错」要等 Mac 键鼠空闲满 `alertAfterSecs` 才推（`0` = 立即）；手机在前台仍是应用内横幅，不推送。
  D 与提问共用同一个设置，不新增配置项。
- **F3 你回到 Mac 前，没推出去的通知作废**（用户批准）：事件发生之后 Mac 上又有了键鼠输入，说明你回来了、多半已经在电脑上看到结果，
  这条通知就不再补推（和提问「看过就不推」同理）。
- **F4 一次性**（用户批准）：从手机创建的任务，**第一次出结果**（做完或出错）并处理完——推出 / 手机正在看 / 你回到 Mac——
  就把该会话移出通知集，之后在 Mac 上接着聊的回合不再通知。理由：星标没了，用户取消不了订阅；一次性让通知集自己清空，
  不会被 5 个名额卡死，也符合「任务做完通知我」的字面意思。Agent 在出结果前又开始工作（新一轮 / 新活动）不算结果，继续等下一次。
- **F5 删除「在等你」推送**（随 F1 一起清理，用户批准）：随 F1，通知只剩做完 / 出错；提问本来就走收件箱 + D 规则的推送。
- **F6 App 里只读地标出「会通知你」**（用户批准）：列表行用小铃铛替换星标，详情页状态区一行说明，都**不可点击**；
  新任务进度页改成「Agent 已经在运行，做完或出错时会通知你（Mac 空闲一阵后）」。

## 术语

| 术语 | 含义 |
|---|---|
| 通知集 | 手机在某台 Mac 上「会被通知结果」的 Agent 集合，即现在的关注集（`follow_set`）。本需求之后，新版 App 只有「从手机创建的任务」会进来。 |
| 结果 | 通知集里某个 Agent 的一轮结束：「做完」或「出错」（事件来源与去抖不变）。 |
| 待通知 | 结果发生时手机不在看、又有可用推送句柄，于是 Mac 记下的一条「等 D 到了再推」的通知，只存在 Daemon 内存里。 |
| D / 手机在看 / Mac 空闲时长 | 同 `docs/specs/ios-alert-timing.md`。 |

## 规则

结果发生时，对通知集里的每部手机各自处理：

| 情形 | 处理 |
|---|---|
| 手机在看（在线 + 前台 + 已 hello） | 发应用内横幅（现状不变）；视为已送达 |
| 手机不在看、有可用推送句柄 | 记一条**待通知** |
| 手机不在看、也没有推送句柄 | 什么都不做、不移出（没有路径可达；会话结束时再静默移出） |

待通知的后续（与提问共用每 250 ms 的到期检查，没有待通知时不读系统时钟）：

| 情形 | 处理 |
|---|---|
| 该 Agent 又开始工作（新一轮 / 新活动） | 作废；仍在通知集，下一次结果重新开始 |
| 会话结束 / 手机被取消配对 | 作废（会话结束时本来就移出通知集） |
| 手机变成「在看」 | 作废；视为已送达（Agents 页就能看到状态） |
| 结果之后 Mac 有过键鼠输入（F3） | 作废；视为已送达 |
| `D = 0`，或空闲时长未知，或空闲满 D | **推一次**；视为已送达 |
| 其他 | 继续等 |

- **视为已送达 = 移出通知集**（F4），并向在线手机发 `follow.state`；之后同一会话的后续回合不再产生通知。
- 同一部手机、同一个 Agent 同一时刻至多一条待通知，新结果覆盖旧的；推送沿用 `collapse-id = fw-{agentKey}`，后一条改写前一条。
- 推送文案、标题、预览沿用现有 `PUSH_FOLLOW_DONE` / `PUSH_FOLLOW_FAILED`，内容在结果发生时定下。
- 「出错」与「做完」**同一规则**：出错事件当场入队，但同样等 D（你在电脑前不打扰）。

## 对 App 的要求

- 去掉：详情页「关注 / 已关注」按钮、列表行星标、Agents 页「已关注」过滤、名额满提示条。
- 新增（只读）：「会通知你」小铃铛（列表行 + 详情页一行说明）。
- 改文案：新任务进度页的「已关注」「因名额满未关注」两句（后者在一次性之后几乎不会出现，保留以备万一）。
- 保留不动：手机在前台时的应用内「做完 / 出错」横幅；点通知打开对应 Agent；`follow.*` 线消息、引擎里的 `setFollow`、`Wire.maxFollow`
  （兼容旧版 Mac / 旧版 App，不做破坏性清理）。

## 兼容

- 线协议、`PROTOCOL_VERSION`、`ios/Fixtures/wire-v1/`、中继、`AppConfig` 都**不变**。
- 旧版 App（仍有星标）连新版 Mac：星标照常能加，但同样一次性、同样遵守 D。
- 新版 App 连旧版 Mac：没有星标；旧 Mac 仍会立即推「做完 / 出错」和「在等你」，直到 Mac 升级。

## 已知局限

1. **只有从手机创建的任务会通知结果**。在 Mac 上自己启动的 Agent 做完，手机不会推（Agents 页仍看得到状态）。
2. **一次性**：任务第一次出结果后，在 Mac 上接着聊的回合不会再推。
3. 待通知只在 Daemon 内存里：Daemon 在推出之前重启，这条通知就丢了。
4. 事件来源（lifecycle hook）的局限不变：Codex 没有出错事件；不经 hook 上报的会话（例如只被 Codex 桌面应用通道发现的）不触发；
   Pi 的出错通知需要更新已安装的扩展。
5. 空闲信号的局限同 `ios-alert-timing`（远程桌面、静静阅读、鼠标抖动器等）；Windows / Linux 读不到空闲，按「未知」处理——立即推。
6. 「在等你」的推送去掉后，手机上只有在 App 里才看得到 Agent 在等什么（提问本身仍按 D 推送）。
