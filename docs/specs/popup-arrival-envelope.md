## 已确认的设计方向

- 新提问到达时沿用非激活前置。保留其他应用键盘焦点，用户点击后才进入作答。
- 以中央提问图标和柔和光晕代替整窗放大。正文不加遮罩。采用「柔光瓷面白底板 + 实心蓝色气泡 + 透明问号」。
- 动画层透过全部鼠标操作，不改变键盘焦点、光标、选区或输入法组合态，不阻塞输入。
- 图标先上下弹跳两次，第一次落下轻微挤压；第二次下落途中沿勾线继续向下，再圆滑转弯飞向新提问对应条目的蓝点。融入蓝点后条目柔和亮起一次。
- 后续继续现有未查看提示；真正打开提问才清除。新到达不自动切换正文。
- 短时间内多条到达时，每条独立完整播放，允许同时进行。先按此方向实现；若实测打扰再由用户决定调整。
- 原型先覆盖侧栏已展开、尚未展开两种初态，先调好单次完整动画，再处理边界。

## 已确认的正式生命周期

- **开发位置**：用户明确要求在当前主工作树接入，不创建 Dev Instance，不改其他 agent 的任务模块。
- **第一条 / 新一轮**：沿用配置的 macOS 原生出现动画，不播放中央图标。之后每条等待原生前置及布局提交再播放；可见窗口不重复开窗动画。
- **冷启动与恢复**：新冷宿主中首条之外的新请求等首次 `popup-inbox-presented` 再播；已呈现或恢复快照不重播。Snapshot 返回 presented，避免订阅时错过首次事件。
- **并发**：每 ID 独立 epoch 与落点，共享 rAF 回调但不排队；取消一条不影响其他条。
- **落点与滚动**：启动时仅改变导航 scrollTop 使新行可见，绝不使用可能滚动作答区的 scrollIntoView。逐帧跟随真实蓝点，落点被滚出可见区则结束飞行、保留未读提示，不再次自动滚动。
- **查看 / 终态**：主动点开、提交、取消、其他渠道回答立即取消相应提醒；落位不能把已查看 / 已结束请求写回未读。
- **关闭框 / 换题**：提醒层在关闭确认框下面、透过鼠标；答完换题期间的新请求等换题结束后同时播放仍未查看的请求。
- **中心与预览**：使用 Sidebar 左边界和当前 `.popup-main` 右边界居中，排除原生附件预览及固定画布离屏 reserve。正文焦点、选区、IME 状态不由提醒修改。
- **隐藏与资源**：隐藏文档结束在播动效并保留未读；尚未开始的请求等文档重新可见再播。清空、卸载取消所有帧和通知计时。沿用非激活前置和最小化恢复，不另改原生 frame。
- **减少动态效果**：跳过浮现及飞行，保留静态未读高亮和蓝点。
- **未读衔接**：飞行中隐藏目标蓝点和 ripple；落位显示蓝点、高亮一次 640ms，随后启动现有持续未读扩散。五次闪烁已移除，提示音继续按原来的 180ms 突发收敛。
- **旧原生提醒**：生产模块不再编译 / 调用 `popup_pulse.rs`；保留文件供旧缩放回归样例使用。
