# iOS 渠道的多设备报文流量统计

2026-11-12 经 AskHuman 确认。首次方案采用各 Mac 累计量乘 2，用户提供第二台 Mac 的用量后，
通过只读 SSH 核实两台使用同一实例、账号与手机。两台本月收发合计约 489.85 MiB，乘 2 得到
0.957 GiB，比用户在 EMQX 看到的 0.77 GiB 高约 24%。用户随后批准本规格的设备端点计量修正。

## 统计归属

每个记录由规范化 Broker 主机名、UTC 月份、设备类型与持久设备 ID 唯一标识。
Mac 使用现有 `macId`，手机使用钥匙串中的 `phoneId`。线字段 `macId` 沿用早期记录的名称，
`deviceKind` 明确其来源为 `mac` 或 `phone`。主机名去除首尾空白和结尾的点并转为小写。
同一实例中的不同 MQTT 用户共享额度。

每台设备记录自己与 Broker 之间的 PUBLISH 负载字节数和消息数。收到的消息在进入应用时计入，
发送的消息在取得 Broker 的 QoS 1 PUBACK 后计入。应用排队和未获确认的发送保留独立语义。
未能确认的发送会使该月记录标为不完整。

实例的已记录报文流量为所有已知设备发送与接收负载字节数之和。
例如 Mac 发送 1 KiB，手机收到 1 KiB，这两段合计 2 KiB。手机离线时，Mac 已获 Broker 确认的
发布贡献 1 KiB。每个订阅端各自收到的消息均贡献自己的接收段。

EMQX 的计费还包含 MQTT 控制报文、TCP/TLS 开销和其他客户端的用量。界面标明报文口径与
记录完整性，并提供控制台入口。

## 合并与历史完整性

合并按每个设备累计字段的最大值进行。副本保存各来源的独立记录，重复转发和乱序保持幂等。
来源更新时间取最大值，记录开始时间取两份都已知时的较早值；存在未知历史的副本保留未知。
发送确认的不确定标记按并集合并。

旧 Mac 累计量缺少实例与确认边界，首次迁移时归入当前配置实例，并显示历史不完整。
本月更换过实例时需要核对历史归属。旧版手机进程退出时丢失的计数无法从现有统计文件还原。

记录包含 `recordedFrom`。已有月份的旧累计保留未知开始时间，后续持续计量保存开始时刻。
新月份按 UTC 月初与已知计量起点推导覆盖范围。全体已知记录覆盖整月且有手机端记录时，
界面可显示免费额度占比；其余情况显示已记录字节数与“历史记录不完整”。
已知旧 Mac 尚未加入设备汇总时，手机端保留覆盖不完整的信息。

## 持久化与同步

Mac 的 `ios/state.json` 保存本机累计量、所属实例、设备记录集合、计量起点与本端同步时间。
每次计数后原子保存，保存失败保留内存值并显示状态，后续计数继续重试。
手机自身计数、实例计量起点和设备记录以同一份 `traffic-ledger.json` 原子保存，`phone-traffic.json` 与
旧 `traffic.json` 提供历史迁移输入。
设备记录独立于配对、历史和草稿。

双方通过 `Hello.trafficUsage` 与 `Caps.trafficUsage` 协商设备端点计量能力，再使用端到端加密的
`traffic.usage` 交换记录。新握手交换完整本月集合，变化期间每个连接最多每分钟更新一次，
单批最多 128 条。接收方接受当前实例与月份、有效设备身份及非负时间戳的记录。
本端的最近同步时间作为副本元数据保存。

同步消息自身按实际收发计入计数。这些计数留待下一次业务流量或新握手发布。
接收方将新来源记录转送给其他配对端，使静止的副本交换能够结束。

早期 `trafficSync` 原型能力与设备端点计量分别协商。旧端继续使用原入口，新增 IPC 状态字段
均有缺省值，保持 IPC 协议号 5。

## 设备变化

- 新增设备导入其本月既有记录，并接收其他来源的记录。
- 删除配对保留已经发生的本月用量，解除的配对结束后续更新。
- 同一设备重新配对后按原身份合并，累计字段取最大值。
- 清空 Mac 数据产生新身份，旧来源的已知用量继续保留。
- 手机重装后可从仍保存设备记录的 Mac 恢复已知汇总。
- 更换 Broker 或月份时，展示对应实例与月份的记录。
- 全部副本同时丢失后，历史需要依赖各来源仍保留的本机计数恢复，并反映覆盖情况。

## 实现地图与验收

Rust 的 `ios/traffic.rs` 实现记录合并，`ios/gateway/traffic.rs` 承载保存、迁移与同步。
`ios/transport.rs` 关联连接内的发送队列、MQTT packet ID 与 PUBACK，重连创建独立计量状态。
Swift 的 `AHProtocol/Traffic.swift`、`AHStore/TrafficLedger.swift` 和
`AHCore/PhoneEngine+Traffic.swift` 对齐协议、手机计数与副本行为。
Mac 设置页与手机 Macs 页显示设备汇总和来源详情。

回归覆盖重复、乱序、多来源、跨实例、跨月、保存失败、重新打开存储、解除配对保留记录、
手机向第二台 Mac 转送、静止后的停止发送、排队与 PUBACK 的计数边界、拒绝发送以及历史完整性。
真实 daemon 与 Swift 引擎通过本地 Broker 验证两台 Mac 和一部手机的记录并集、重连补同步与
解除配对后的保留。
