# 需求：iOS 开发者模式（浮动按钮 + 快速添加待办）

> 状态：2026-11-02 起草；用户已审阅通过，P1–P5 已实现；2026-11-03 经用户同意，按钮与菜单改用系统 `UIMenu`（D18、D19），自绘的菜单与按住状态机已删除；同日，项目选择改成与待办页同一套来源规则（先选 iCloud / 设备，再选项目；iCloud 项目自动换机，D20、D21）。自动化验证见计划的「实现记录」；P6 真机验收：2026-11-03 已出内测包 `0.1.0 (5)`（那一版的项目选择还是按 Mac 分组），**等用户试用反馈**；改后的项目选择**没有出包**（用户看过汇报后选了「先不出：你再看看，需要时再说」）。实现与起草时的出入见 §11。关联计划：`docs/plans/ios-developer-mode.md`。
> 前置资料：`docs/specs/ios-todos.md`（待办写入、项目 id、`todo.op`）、`docs/overview-ios.md`（App 结构与不变量）。
> 范围：仅 iOS App（iPhone，iOS 17+，竖屏单场景）。**不改 Mac 端、不改线协议**（`PROTO`、`PROTOCOL_VERSION` 都不动）。
> 标注「用户定」的决策来自 AskHuman 问答；标注「agent 设计」的是用户委托我设计的部分，请重点审阅，可整条否决。

## 1. 背景与目标

用户原话（2026-11-02，语音转写）：

> iOS 客户端内增加 AskHuman 的开发者模式。在系统设置里面可以打开，打开之后，在 SQ 门的界面增加开发者的快捷入口。比如说第一版可以有一个快速添加 AskHuman 项目待办的功能。

经两轮 AskHuman 问答后的补充（原话）：

- 「可以做一个浮动的按钮，然后随时可以触发一些快捷操作。这个的主要意义是，因为我是开发者，所以我在使用这个 APP 的过程中，我可能随时有一些想法要记录。」
- 「菜单做成那种，我按下就会显示出来的。这样我可以按下，然后移动手指选中对应的条目，就不需要有两次点按了。」
- 浮动按钮要盖在哪些界面上：选「连 sheet / 全屏查看器也盖住（独立透明窗口方案）」。
- 「还是需要能拖动，要不然挡住内容就很难受。你帮我设计一下这个交互怎么做比较好？」

「SQ 门的界面」被判断为语音转写的 “AskHuman”；它原本问的是快捷入口放哪个页面，用户随后把入口改成了**全局浮动按钮**，所以这个词不再影响设计。

**目标**：App 内有一个「开发者模式」开关（默认关）。打开后，全 App 出现一个可拖动的浮动按钮；按下即弹出开发者菜单，手指滑到条目上松开即触发；v1 菜单只有一项「快速添加待办」：不离开当前界面，把一条想法记成某个项目的待办。

**非目标（本期不做）**：

- 菜单里的其他开发者功能（只让结构能扩展）。
- 快速添加里的 ⚡ 自动执行、附件、编辑或查看已有待办（待办页已有）。
- 离线排队（沿用 `ios-todos.md` I13：手机不落盘待办内容、不排队）。
- Mac 端与线协议的任何改动。
- iPad、横屏、多场景。
- 把开关放进 iOS 系统「设置」App（Settings.bundle）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 开发者模式 | App 内的一个开关；关闭时与现在的 App 完全一样，没有任何额外窗口或界面 |
| 浮动按钮 | 开发者模式打开后常驻在所有界面之上的圆形按钮，可拖动 |
| 开发者菜单 | 按下浮动按钮弹出的条目列表，是系统的 `UIMenu`；v1 只有「快速添加待办」 |
| 快速添加页 | 选中菜单条目后弹出的底部 sheet：选项目、写一句话、添加 |
| 来源 | 项目从哪里选：「iCloud」，或某台不在 iCloud 里的 Mac。与待办页标题上的来源菜单是同一套（`docs/specs/ios-todos.md` I17）：多台 Mac 时，开着同步的 Mac 不单独成项，是 iCloud 的成员 |
| 目标项目 | 快速添加把待办写到哪里。两种：**iCloud 项目**（按仓库地址记，经任何一台开着同步且在线的 Mac 写入）；**某台 Mac 上的项目**（Mac id + 项目 id；项目 id 是 Mac 给的不透明哈希，手机看不到路径）。只有一台 Mac 有、没有仓库地址的项目（「仅在 X」）一律是后一种 |

## 3. 决策记录

| 编号 | 决策项 | 结论 | 理由 / 否决后的代价 |
|---|---|---|---|
| D1 | 开关位置（用户定） | App 内：Macs 标签的设置列表里新增「开发者」分区，一个开关，默认关，打开立即生效；存本机 `UserDefaults`，与「发送后自动打开下一条」同一套存法 | 不放 iOS 系统「设置」App：那要加 Settings.bundle，改完要离开 App，回来才生效 |
| D2 | 构建范围 | 所有构建都可用（含 TestFlight），不用 `#if DEBUG` | 用户要在真机的 TestFlight 版里用，Debug 限定就等于用不上 |
| D3 | 入口形态（用户定） | 全局浮动按钮，不是某个页面的工具栏按钮 | 想法随时会来，不挑页面 |
| D4 | 覆盖范围（用户定） | 盖住所有界面，包括 sheet、全屏图片查看器、Safari。用独立的透明窗口实现 | 代价：要自己处理窗口层级、键盘焦点，并从窗口里弹出快速添加页（§5.5） |
| D5 | 菜单手势（用户定） | 按下就显示菜单，手指滑到条目上松开即触发，一次手势完成（2026-11-03 起由系统菜单提供，见 D18） | 见 D6：与拖动需要仲裁 |
| D6 | 拖动与菜单的仲裁（agent 设计；2026-11-03 随 D18 改写） | **按下后立刻开始移动 = 拖动按钮；按住不动 = 系统弹出菜单（按下后约 0.1–0.2 秒，由系统决定）。** 一旦菜单弹出，本次触摸不再能拖动；一旦开始拖动，本次触摸不再弹菜单。轻点（按下后没移动就松手）= 菜单弹出并保持打开，之后可再点条目。详见 §5.2 | 「零延迟弹出」与「直接拖动」在物理上不能同时成立（同一根手指只能干一件事）。菜单的弹出延迟与拖动的识别（移动几个点）谁先到谁赢：模拟器实测（iOS 27.0 与 18.5 一致），按下后立即移动时拖动在 64–108 ms 内开始、菜单不出现，按住不动时菜单在 75–180 ms 内出现。代价同前：熟练后若按下立刻就划向菜单，会变成拖动按钮，要等一拍再划 |
| D7 | 位置与吸附（agent 设计） | 位置 = 左 / 右侧边 + 纵向位置。松手后吸附到最近的侧边、保持纵向位置；默认右侧偏上（40%）；纵向可停在安全区内任意位置（含导航栏、底部标签栏区域）。位置存本机，开发者模式关了再开保持原位 | 贴边最不挡内容；纵向自由让你把它停在不挡东西的地方。不做半隐藏贴边：多一套手势（拉出来）换不来多少空间 |
| D8 | 键盘（agent 设计） | 键盘弹出时，若按钮会落在键盘区域内，临时上移到键盘上沿之上；不改记住的位置，键盘收起回到原位 | 按钮始终可见可按，又不压在键盘按键上 |
| D9 | 空闲外观（agent 设计） | 2.5 秒没有触摸后，按钮降到 50% 不透明；触摸时恢复 | 少遮视线；不会因此变得点不到 |
| D10 | 快速添加页形态 | 在快速添加窗口里弹出的底部 sheet（`.medium` / `.large` 两档，可下拉收起）；顶栏：取消 / 标题「快速待办」/ 添加；中间：项目行 + 多行文本框（自动聚焦） | 与 App 内其他 sheet 同一手感 |
| D11 | 目标项目（用户定；2026-11-03 随 D20、D21 改写） | 第一次用时在快速添加页里选一次（先来源，再项目，见 D20），之后记住，页面上随时可改；不写死任何项目名 | 开发者自己的项目名不该写进代码；没记住目标时，打开快速添加页直接进入项目选择 |
| D12 | 添加成功之后（用户定） | 自动关闭快速添加页，并在屏幕顶部显示「已添加到 <项目名>」约 1.8 秒 | 要的是「记完就走」 |
| D13 | ⚡ 自动执行（用户定） | 快速添加不带 ⚡ 开关，一律不开 | 避免在手机上一不小心就让 Agent 自动开跑 |
| D14 | Mac 离线（沿用 ios-todos） | 不排队：保留已输入文字，「添加」置灰并在输入框下说明原因。目标是**某台 Mac 上的项目**时，不改道到别的 Mac（那个项目别的 Mac 没有）；目标是 **iCloud 项目**时自动换机，见 D21 | 与待办页一致；Mac 上的项目离线时要换目标只能手动改 |
| D15 | 持久化与隐私 | 落盘（`UserDefaults`）：开关、按钮位置、目标项目（Mac id、项目 id、Mac 名、项目名）。不落盘：待办文字（未发送的文字只在内存，本次运行内取消后再打开会恢复，成功后清空） | 与 `ios-todos.md` I13 一致：待办内容不写盘；项目名不含路径 |
| D16 | 协议 | 不新增任何线消息或 `caps`：发送就是一条普通 `todo.op`（`add`，无 `auto`），列表就是 `todo.projects.get`；`PROTO`、`PROTOCOL_VERSION` 不动 | 待办页已经证明这条通路够用 |
| D17 | 提交惯例 | 实现提交用 `feat(ios): …`，并带 `Release-Note: skip` 脚注；文档提交用 `docs(ios): …` | 这是维护者自己用的工具，不应出现在 Mac 版面向用户的发布说明里；先例见 `a3443e3a` |
| D18 | 菜单与按钮用系统组件（用户定，2026-11-03） | 按钮是 `UIButton`，`showsMenuAsPrimaryAction = true`，菜单是系统的 `UIMenu`（v1 一个 `UIAction`）；拖动用按钮上的 `UIPanGestureRecognizer`。不再自绘菜单、菜单行高亮、触觉与命中检测，也没有「按住」状态机。 | 起因：用户看过 Liquid Glass 截图后问「使用系统的 uimenu 不行吗？ 应该默认就有我们需要的交互吧？」。我在 iOS 27.0 与 18.5 的模拟器上做了探针：按住后菜单约 75–180 ms 出现，滑到条目松手即触发，立即移动则是拖动、菜单不出现，菜单能盖在 sheet（键盘不收）与全屏图片查看器之上，点外面收起且不穿透；用户据此选了「改用系统 UIMenu：按钮 = UIButton + 系统菜单 + 拖动手势；删掉自绘菜单和按住状态机；规格、计划、测试一起改」。代价：菜单的位置、样式与滑出菜单松手后的去向由系统决定，与原设计有三处行为差异（§11）；换来系统的玻璃形变、触觉、VoiceOver 与「减少动态效果」处理，少维护一整套自绘菜单、按住状态机和它们的单测 |
| D19 | 外观（用户定，2026-11-03） | 图标保持锤子（`hammer.fill`；用户嫌它丑，看过 9 个候选后选了「保持锤子」）。iOS 26 起按钮与提示条是 Liquid Glass（按钮 `UIButton.Configuration.glass()`，提示条 `UIGlassEffect`）；更早的系统保持毛玻璃材质（按钮薄材质 + 细描边 + 阴影，提示条厚材质）。 | 用户原话：「用：iOS 26+ 玻璃，更早系统保持现在的模糊材质」 |
| D20 | 项目选择：先选来源，再选项目（用户定，2026-11-03） | 与待办页同一套来源规则：第一级是**来源**列表——「iCloud」在前，其后是不在 iCloud 里的 Mac（多台 Mac 时，开着同步的 Mac 并成「iCloud」这一项，同步的项目只出现一次；只配对一台 Mac 时 iCloud 与这台 Mac 各一项）；第二级是该来源的**项目**，分组、折叠、搜索都与待办页一致（`TodoRows.sections` 与 `TodoRows.listed` 是两边共用的纯函数）。离线或太旧的来源、没有 Mac 开着同步的 iCloud 仍列出，置灰并在名字下写原因，点不开。 | 用户问「首次打开的选项目界面，和我在待办里看到的为什么不同？比如我使用 iCloud 待办，askhuman 应该是在 iCloud 里，而不是两台 Mac 各有一个。」，选了「和待办页同一套来源规则」，并补充「你也先选 icloud/设备再悬项目吧」（「悬」即「选」）。起草时把它放进了「后置」（§8 写着「同一个 iCloud 项目会在每台开了同步的 Mac 的分组下各出现一次」），用户看到后觉得不对 |
| D21 | iCloud 项目自动换机（用户定，2026-11-03） | 从「iCloud」下选的项目按**仓库地址**记成 iCloud 项目（只有一台 Mac 有、没有仓库地址的项目仍记成那台 Mac 的）。发送时先走选它时服务 iCloud 的那台 Mac，它不在线或不支持待办就换另一台开着同步且在线的 Mac（顺序与待办页一致：上次服务过 iCloud 的、已知开着同步的、模式未知的），在那台 Mac 的项目列表里按仓库地址找到它自己的项目 id 再写；都不行才报错。已记住的目标不因换机而改。 | 用户选了「自动换机：和待办页一样，优先上次用过的同步 Mac，它离线就换另一台开着同步的 Mac；全都离线才提示发不了。目标按仓库地址记成「iCloud 里的 AskHuman」」。同一个 iCloud 项目在每台开了同步的 Mac 上有各自的 id（id 是路径哈希），所以换机必须按仓库地址重新找 |

## 4. 用户视角

1. **打开**：Macs 标签 → 「开发者」分区 → 打开「开发者模式」。分区脚注说明按钮怎么用。
2. **浮动按钮**：一个 44 pt 的圆形按钮（锤子图标；iOS 26 起是 Liquid Glass，更早是毛玻璃底），默认贴在右侧、屏幕偏上。始终在最上层：标签页、详情页、sheet、全屏查看器、Safari 之上都在。
3. **弹菜单**：手指按住按钮不动，系统很快（约 0.1–0.2 秒）在按钮附近弹出菜单，v1 一行「快速添加待办」。手指不用抬起，滑到那一行（系统给高亮与轻触觉），松手 = 打开快速添加页。轻点按钮：菜单弹出并保持，再点条目触发；点菜单外面收起（这次点按不会传给下面的界面）。菜单的位置、动画与样式都是系统的：iOS 26 上它从按钮的玻璃里长出来，更早的系统是按钮旁的普通菜单；在菜单外松手由系统决定（目前菜单保持打开，点外面收起）。
4. **挪位置**：按下后直接拖，按钮跟手指走，松手吸附到最近的侧边。
5. **快速添加页**：弹出后键盘已起、光标在文本框（文本框默认三行高，写长了最多长到十行）。顶部一行是目标项目：项目名（同名项目带区分后缀），下面一行小字是来源——iCloud 项目写「iCloud」，Mac 上的项目写 Mac 名；点它换项目。写一句话，点「添加」。成功：页面收起，屏幕顶部出现「已添加到 HumanInLoop」。失败：页面不关，文字还在，下面写原因。
6. **选项目**：先选来源（iCloud，或不在 iCloud 里的某台 Mac），再选它下面的项目；项目列表的分组与搜索和待办页一样。**第一次用**没有记住的目标，打开快速添加页就直接是来源列表（只有一个来源时没得选，直接是它的项目列表）。**已有目标时**点项目行，直接打开目标所在来源的项目列表，换同一来源里的另一个项目只要点一下；左上角的返回键回到来源列表，可以换来源。选定后回到文本框。
7. **回到原来的事**：如果你是在回答某个请求、正打着字时触发的，关掉快速添加页后，原来的输入框回到编辑状态，键盘重新起来。
8. **关闭**：把开关关掉，按钮立即消失；位置与目标项目留着，下次打开还在。

## 5. 手势与窗口规则（agent 设计）

### 5.1 常量（集中在 `DeveloperMetrics`）

| 名称 | 值 | 含义 |
|---|---|---|
| 按钮直径 | 44 pt | 与最小点按区一致 |
| 贴边间距 | 6 pt | 吸附后按钮离屏幕边缘的距离 |
| 空闲降透明 | 2.5 s → 50% | 触摸恢复 100% |
| 提示显示时长 | 1.8 s | 「已添加到 …」 |

### 5.2 手势分工

按钮上同时有两个识别器：系统的菜单（手指停在原地，约 0.1–0.2 秒后弹出）和按钮自己的拖动（`UIPanGestureRecognizer`，手指移动几个点就开始）。谁先到谁拿走这次触摸：

| 状态 | 怎么进入 | 手指移动 | 手指抬起 |
|---|---|---|---|
| 待定 | 在按钮上按下 | 先移动 → 拖动；先停够 → 菜单（按住） | 菜单出现之前抬起（轻点）→ 菜单（打开） |
| 菜单（按住） | 系统在手指下弹出菜单 | 系统高亮手指下的条目并给触觉；按钮不再跟手 | 在条目上 → 触发并收起；在菜单外 → 由系统决定（目前：菜单保持打开） |
| 菜单（打开） | 轻点 | — | 点条目 → 触发并收起；点菜单之外 → 收起（这次点按由系统吃掉，不传给下面的界面） |
| 拖动 | 拖动识别器开始 | 按钮跟手（保持抓取时的偏移），夹在安全区内；抬起前不弹菜单 | 吸附到最近侧边，保存位置 |

- 触摸被系统取消（来电、通知、App 失活）：拖动中 → 按钮回到这次手势开始前的位置，不保存；菜单是系统的，由它自己收起。
- 拖动时按钮放大到 1.12 倍（没有玻璃时再加深阴影）。触觉只有系统菜单自带的，App 自己不再发。

### 5.3 位置

- 记住：侧边（左 / 右）+ 纵向位置（占安全区可用高度的比例）。默认右侧、40%。
- 纵向可用范围：安全区上下各留 8 pt。
- 数据损坏或缺失时回到默认。
- 只做竖屏、单场景，不处理旋转与分屏。
- 「减少动态效果」打开时，吸附改为淡入淡出，不做弹簧；菜单的动画由系统按这个设置处理。

### 5.4 菜单

- 由系统摆放与绘制：在按钮附近、完整落在屏幕内。iOS 26 上菜单从按钮的玻璃里展开，打开期间按钮被菜单取代；iOS 18 上是按钮旁的经典菜单，按钮仍可见。不再保证「朝屏幕内侧、与按钮同高」。
- 条目 = 图标（`text.badge.plus`）+ 标题；条目由 `DeveloperMenuItem` 列出，以后加条目只加枚举值。
- 系统菜单的条目不能带 `accessibilityIdentifier`，UI 测试按标题（按钮）找。

### 5.5 窗口与焦点

- **按钮窗口**：独立透明窗口，层级高于主窗口与到达动效窗口。**不成为 key 窗口**——`ArrivalSceneHost` 里记过：`makeKeyAndVisible` 会让正在编辑的输入框失去焦点。除按钮外，所有触摸原样穿透到下面。菜单由系统呈现在所有窗口之上，不属于 App 的任何窗口：没有自己的收起层，点外面收起与「这次点按不传下去」都是系统做的；它盖在 sheet、键盘与全屏图片查看器之上时，键盘不收、主窗口的第一响应者不变（探针与 UI 测试都验证过）。
- **快速添加窗口**：另一个独立窗口，只在打开快速添加页时存在，成为 key 窗口以便弹键盘。打开前先记下主窗口里的第一响应者；关闭后把主窗口恢复为 key，并让原来的第一响应者重新开始编辑。输入框里已有的文字不会丢（作答草稿本来就由 `DraftStore` 保存）。
- 主窗口里已经有 sheet / 全屏查看器 / Safari 时不受影响，它们和这两个窗口互相独立。
- 开关关闭、或 App 被摘掉场景时：两个窗口都拆掉。

## 6. 快速添加待办的规则

### 6.1 添加按钮何时可用

同时满足：文字去掉首尾空白后非空、不超过 4000 字符（与待办页同一个校验）；有目标项目；目标能收：Mac 上的项目要那台 Mac 在线且支持待办（`caps.todos`），iCloud 项目要有一台开着同步（或还不知道它开没开）、在线且支持待办的 Mac。不满足时「添加」置灰，原因写在文本框下面：

| 情况 | 文案（中文；英文见 `Design/DeveloperTexts.swift`） |
|---|---|
| 没有目标项目 | 请先选择项目。 |
| 目标 Mac 离线 | <Mac 名> 暂时连不上。 |
| 目标 Mac 版本太旧（没有待办能力） | 请先更新 <Mac 名> 上的 AskHuman，才能在这里添加待办。 |
| iCloud 项目，没有一台开着同步的 Mac 连得上 | 开启了 iCloud 同步的 Mac 暂时都连不上。 |
| 文字过长 | 内容太长了：<字数> / <上限> 个字符。 |

### 6.2 项目选择

两级，页面都是待办页那套的重绘（`QuickTodoProjectPicker.swift`），数据与规则在 `QuickTodoComposer`（AHCore，有单测）。

**第一级：来源**（标题「来源」）。

- 列表就是待办页标题菜单的那一份（`TodoSources.choices`）：「iCloud」在前，其后是不在 iCloud 里的 Mac。多台 Mac 时开着同步的 Mac 是 iCloud 的成员，不单独成项（iCloud 的副标题写成员名，离线的带「（离线）」）；只配对一台 Mac 时 iCloud 与这台 Mac 各一项。
- 一台 Mac 是否开着同步，由它回的每条 `todo.projects.get` 里的 `mode` 得知；快速添加页也读待办页记下的（`ah.todos.modes`）。在还不知道的那一会儿（有 Mac 被问了、还没答，又没有记录），来源列表显示灰色占位，不显示一份马上就会变的列表。
- 离线或太旧的 Mac，以及没有任何 Mac 开着同步的 iCloud，仍列出，置灰、点不开，名字下写原因（沿用待办页来源菜单的字：「离线」「需要更新」「没有 Mac 开启了 iCloud 同步」）。来源列表里没有「重试」：某个来源没有应答时，点进去在第二级处理。
- 目标所在的来源带对勾。
- 只有一个来源且能打开时没得选，页面直接打开它的项目列表（返回键回到文本页）。

**第二级：项目**（标题是来源名；返回键回到来源列表，标签「来源」）。

- 数据：每台**在线且支持待办**的 Mac 各发一次 `todo.projects.get`，全部一起发。「iCloud」的行取自服务它的那台 Mac（排序同待办页：上次服务过 iCloud 的、已知开着同步的、模式未知的；排在前面的还没答时等它），再加上其他成员 Mac 的「仅本机」项目（没有仓库地址的，别的 Mac 和 iCloud 都不认识；没有待办的归入「没有待办」，有的归入「仅在 X」）；同一个同步项目只出现一次。一台 Mac 自己的来源是它的全部项目，仅云端的项目除外（它们在那台 Mac 上没有目录）。
- 分组、折叠、搜索与待办页相同（`TodoRows.sections`）：有待办 / 与 iCloud 同步 / 最近 / 没有待办（默认折叠，搜索时展开）/ 仅在 X（每台 Mac 一段）；匹配规则：项目名、后缀、仓库地址、Mac 名里每个词都要出现。每行也是待办页的样子（图标、项目名、同名区分后缀、仓库地址或「仅在 iCloud」、待办条数），当前的目标带对勾；没有 Agent 状态点。
- 来源还在加载：灰色占位；某台 Mac 没有应答：说明加「重试」（也可下拉刷新，两者都只重问这个来源）；没有项目：「还没有项目」。这些都是待办页的同一套文字。
- 选定后记住，回到文本框并聚焦。**从「iCloud」下选的项目**，只要它有仓库地址，就记成 iCloud 项目（D21）；没有仓库地址的（只有一台 Mac 有的项目）和 Mac 自己来源下的项目，记成那台 Mac 的。
- 离开第二级时搜索词清空、「没有待办」重新折叠。
- 手机不能新建项目（沿用 `ios-todos.md` I5）；仅云端的项目可以选（Mac 接受给它加待办，只是不能 ⚡，而这里本来就不 ⚡）。

### 6.3 发送

- 点「添加」：页面进入「发送中」（按钮转圈，文本框只读，「取消」置灰，页面不能下拉收起——Mac 的拒绝若在页面走了之后才到，就没处可说），发一条 `todo.op` `add`，不带 `auto`，带新的 `clientMsgId`。
- 发往哪台 Mac、用哪个项目 id：Mac 上的项目就是记下的那台 Mac 与项目 id。iCloud 项目先走选它时服务 iCloud 的那台 Mac（项目 id 照用，同一台 Mac 认它）；那台不在线、不支持待办或已知不再开着同步时，按待办页的顺序（上次服务过 iCloud 的、已知开着同步的、模式未知的）逐台问 `todo.projects.get`，取第一台回 `mode = icloud` 且项目列表里有同一仓库地址的，用**它**给的项目 id 发；一台都找不到就是下表的「没有 Mac 收得下」。已记住的目标不因换机改动。
- 超时重发一次，沿用同一个 `clientMsgId`（幂等，同待办页）。两次都超时后，用户再点「添加」时只要文字和目标项目没变，仍沿用这个 `clientMsgId`：第一次其实已经写进去的话，Mac 按它去重，不会出现两条。（换机的例外见 §8。）
- **成功**（`ok`）：关闭页面，清空文字，顶部显示「已添加到 <项目名>」，VoiceOver 同时播报。
- **失败**：页面保持打开，文字保留，原因写在文本框下面，可以重试或改目标项目：

| 结果 | 文案（中文） | 附加动作 |
|---|---|---|
| 两次都超时 | <Mac 名> 没有响应，请重试。 | 无 |
| Mac 不可达（发送时连不上） | <Mac 名> 暂时连不上。 | 无 |
| iCloud 项目，没有 Mac 收得下（都连不上，或连得上的都还不认识这个项目） | 开启了 iCloud 同步的 Mac 暂时都连不上。 | 无 |
| `notFound` / `unknownProject` | 这个项目已不在 <Mac 名> 上，请另选一个。（iCloud 项目：「已不在 iCloud 上」） | 清掉已记住的目标，自动进入项目选择（这句话红字显示在来源列表或项目列表顶部，看先打开哪一个） |
| `failed` | Mac 没能保存这次修改。（与待办页同一句） | 无 |
| `rejected`（空 / 过长，已被本地校验挡住，理论上到不了） | 沿用待办页对各拒绝原因的说法 | 无 |

- 取消或下拉收起：文字留在内存里，本次运行内再打开会恢复；成功后清空；杀进程后不保留。

## 7. 兼容、隐私与安全

- 没有新的线消息或能力位。没有待办能力的旧 Mac 在来源列表里标明、置灰、不可选。
- 手机落盘：开关、按钮位置、目标项目（Mac id、项目 id、Mac 名与项目名；iCloud 项目再加仓库地址，即项目列表里本来就显示的那一行，不含本地路径）。待办文字不落盘、不进推送。更早版本记下的目标（没有仓库地址）照旧读：按那台 Mac 的项目处理，待办页一旦得知那台 Mac 开着同步，它就归在「iCloud」来源下。
- 发送走现有的端到端加密通路，与待办页一样；幂等日志按 `clientMsgId` 去重。

## 8. 已知局限与风险

- **窗口 + 键盘 + 焦点**的组合在不同 iOS 版本上可能有差异；「关掉快速添加页后原输入框重新编辑」要在模拟器与真机上都验证。
- **拖动与菜单谁先到**由系统决定，没有可调的常量：模拟器上按下后立即移动时拖动在 64–108 ms 内开始、菜单不出现，按住不动时菜单在 75–180 ms 内出现（iOS 27.0 与 18.5 一致）；真机上的手感与玻璃的观感要用户上手确认。
- iOS 26 上菜单打开期间按钮被菜单取代，收起后回到原处；菜单的位置、在菜单外松手的去向都由系统决定，以后系统改了也会跟着变。
- 按钮窗口盖在 App 内的系统弹窗（alert、确认对话框）之上，可能遮住弹窗边缘的按钮；把按钮停到别处即可。
- 目标是某台 Mac 上的项目（含「仅在 X」）且那台 Mac 离线时不会改道：别的 Mac 没有这个项目；需要手动改目标。
- iCloud 项目换机写入时，若第一台其实已经存下了、只是应答丢了，重发又去了另一台，会出现两条：幂等键（`clientMsgId`）只在同一台 Mac 的日志里去重。需要「应答丢失」与「换机」同时发生，且两台 Mac 之间的同步还没把那条传过去；不处理。
- 来源列表要等各 Mac 说过自己是否开着同步才定形（否则开着同步的 Mac 会先作为独立来源出现、随后消失）：待办页还没记下过、又是冷启动时，来源列表会先是几行灰色占位，通常不到半秒。
- 同一个 iCloud 项目在不同 Mac 上 id 不同，记下的 iCloud 目标靠仓库地址跨 Mac 认；新建后还没同步到另一台 Mac 的项目，那台 Mac 的列表里没有，换机时找不到它（按「没有 Mac 收得下」报，等同步完再试）。
- 快速添加页是 `.medium` / `.large` 两档的 sheet，在 `.medium` 档下项目列表一屏只放得下四五行；拖到 `.large` 档或滚动即可，列表本身不会改变 sheet 的档位。
- 快速添加页打开期间，主窗口里正在编辑的输入框会暂时失去键盘；这是「独立 key 窗口」方案的代价（D4）。
- VoiceOver：按钮是系统的菜单按钮，激活后由系统菜单列出条目；浮动按钮的拖动手势本身不要求 VoiceOver 用户会。

## 10. 验收标准

1. Macs 设置里有「开发者」分区与「开发者模式」开关，默认关；关闭时 App 里没有任何额外窗口，现有 UI 测试不受影响。
2. 打开开关后，按钮立即出现在所有界面之上，包括新建任务 sheet、待办编辑 sheet、Safari 与图片查看器；关闭立即消失。
3. 按住按钮不动，系统菜单在手指下弹出；手指滑到条目上松开，触发快速添加页；在菜单外松手不触发任何条目。
4. 轻点按钮，菜单保持打开；再点条目触发，点外面收起（且那次点按不触发下面的控件）。
5. 按下后立即拖动，按钮跟手；松手吸附到最近侧边；重启 App 位置不变；拖动过程中不会弹菜单。
6. 键盘弹出且按钮会被盖住时，按钮显示在键盘之上；键盘收起后回到原位，记住的位置没被改动。
7. 没有目标项目时，打开快速添加页直接是来源列表（iCloud 在前，其后是不在 iCloud 里的 Mac），点进来源是它的项目列表（分组、折叠、搜索与待办页一致）；多台 Mac 都开着同步时它们并成一个「iCloud」，同一个同步项目只出现一次，各 Mac 自己的项目在「仅在 X」下；选定后记住，下次打开直接显示目标并聚焦文本框；已有目标时点项目行直接是目标所在来源的项目列表，返回键到来源列表。
7a. 从「iCloud」下选的项目是 iCloud 项目，页面上来源一行写「iCloud」；服务它的那台 Mac 不在线时，换另一台开着同步的 Mac 写入，写得进去且 Mac 上的待办里多了这一条；都连不上时「添加」置灰，原因写明。
8. 添加成功：页面关闭，顶部出现「已添加到 <项目名>」，Mac 上的待办里多了这一条（不带 ⚡）。
9. 文字为空：「添加」置灰（空文字不需要解释，不写原因）；Mac 离线 / 版本太旧 / 无目标项目 / 文字过长：「添加」置灰且有原因；发送失败：文字保留，原因明确，可重试。
10. 在回答请求、正在输入时触发并关闭快速添加页，原输入框恢复编辑，已输入的文字与光标不丢。
11. 全部新增文案有英文与简体中文；没有 Rust 改动，`PROTOCOL_VERSION` 与 `PROTO` 不变。

## 11. 用户审阅反馈与实现注记

### 用户审阅反馈（原话）

- 「认可，按这个做（真机后手感不对再调常量）」——对 §3 中标注「agent 设计」的各项（D6–D9、§5）整体认可；0.12 s / 10 pt 等常量等真机上手感不对再调（这两个常量随 D18 一起删除，见本节末尾）。
- 「通过：提交文档，开始实现 P1–P5（P6 真机前再问我）」——真机一轮（计划的 P6）开始前必须先问用户。
- 「给我个 liquid glass 的截图，另外这个锤子图标有点丑」，看过截图与 9 个图标候选后选「1  保持锤子」（2026-11-03，D19）。
- 「使用系统的 uimenu 不行吗？ 应该默认就有我们需要的交互吧？」；看过探针结果后选「改用系统 UIMenu：按钮 = UIButton + 系统菜单 + 拖动手势；删掉自绘菜单和按住状态机；规格、计划、测试一起改」与「用：iOS 26+ 玻璃，更早系统保持现在的模糊材质」（2026-11-03，D18、D19）。
- 看过 `0.1.0 (5)` 之后的提问：「首次打开的选项目界面，和我在待办里看到的为什么不同？比如我使用 iCloud 待办，askhuman 应该是在 iCloud 里，而不是两台 Mac 各有一个。」；回答项目选择选「和待办页同一套来源规则」并补充「你也先选 icloud/设备再悬项目吧」，Mac 离线选「自动换机」，包体选「不动」（见下），出包选「先不出：我验证完汇报，你再决定」（2026-11-03，D20、D21）；看过汇报后又选了：出包「先不出：你再看看，需要时再说」，半屏 sheet 里项目列表偏挤「保持现状：需要时手动上拉，真机上看了再定」（§8 最后一条，没有改档位）。

### 实现与起草时的出入（正文已按实际改过）

- 版面与文案：§4 第 5 点、§6.1、§6.2、§6.3 的版面与句子以实现为准；离线 / 太旧的原因写在项目选择的组脚注里，不在组头。
- 新增两条规则：发送中的页面不能取消、不能下拉收起；两次超时后再点「添加」，只要文字和目标没变就沿用同一个 `clientMsgId`（§6.3）。
- 对既有界面的一处改动：D4 让键盘从另一个窗口盖到全屏图片查看器上，这在实现中暴露了 `ImageGalleryViewer` 原有的一个布局死循环（分页的竖直方向用 `containerRelativeFrame` 时，容器尺寸被键盘反复改动，分页永远排不稳，App 主线程被占满）。每页的尺寸现在取自外层的 `GeometryReader`（整张 sheet），查看器里图片的位置因此比以前高约 11 pt，其余不变；这个卡死只在开发者模式的键盘盖上来时复现过。原因与约束写在 `docs/overview-ios.md` 的不变量里。

### 改用系统 UIMenu 之后与原设计的出入（D18）

自绘版（已提交过一次，之后删除）与系统菜单相比，拖动、吸附、键盘避让、空闲降透明、盖住 sheet / 键盘 / 全屏查看器、轻点保持打开、点外面收起且不穿透都没变，行为上有三处不同：

1. 菜单弹出的延迟由系统定（实测 75–180 ms），不再是 0.12 s 的常量：`DeveloperPressTuning` 没有了，真机手感不对时没有常量可调。
2. 菜单的位置与样式由系统定：不再保证朝屏幕内侧、与按钮同高；iOS 26 上菜单从按钮里长出来，期间按钮被取代。
3. 滑出菜单、在菜单外松手：原设计是取消并收起，现在由系统决定，实测菜单保持打开（点外面收起）。

另外：菜单行的无障碍标识 `dev-menu-quickTodo` 没有了，UI 测试按标题找；自绘版给 VoiceOver 的自定义动作也不再需要，系统菜单自己支持 VoiceOver。

### 改成与待办页同一套来源规则之后与原设计的出入（D20、D21）

- 起草时项目选择是「每台 Mac 一组」，并在 §8 记过「同一个 iCloud 项目在每台开了同步的 Mac 下各出现一次」「离线不自动换机」；这两条（以及 §9 的「自动改道」）都被 D20、D21 推翻，正文已改。
- 用户只说了「先选来源，再选项目」。两处细节是实现时定的、没有单独问过：**已有目标时点项目行直接打开目标所在来源的项目列表**（返回键到来源列表），不是每次都从来源列表开始；**只有一个来源时跳过来源列表**。都在 `QuickTodoView.openThePicker`，想要「总是从来源列表开始」改那一处即可。
- 目标的存法加了 `icloudRepo`（可选字段，旧版记下的目标没有它，照旧读）。「iCloud 里的项目」靠它跨 Mac 认；换机逻辑与它的测试在 `QuickTodoComposer`。
- 项目列表的数据取法与待办页共用 `TodoRows.listed`（iCloud：服务它的 Mac 的行 + 其他成员 Mac 的「仅本机」项目）与 `TodoRows.sections`，两边不会各说各的；`TodosStore` 与快速添加页各自问 Mac（快速添加页不依赖待办页是否开着）。
- 包体（`0.1.0 (5)` 约 13 MB）：App 本体 12.9 MB，其中可执行文件 6.3 MB、Markdown 渲染页 3.7 MB（Mermaid 3.6 MB）、图标 1.7 MB、通知扩展 1.0 MB；用户选「不动」，没做任何瘦身。
