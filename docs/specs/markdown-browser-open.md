# Markdown 附件的浏览器打开

> 状态：已实现并完成 macOS 安装与本地验证；Windows / Linux 实机沿用既有外部 gate。
> 实现与验证记录见 [markdown-browser-open.md](../plans/markdown-browser-open.md)。
> 基础面板行为见 [popup-attachment-preview-panel.md](popup-attachment-preview-panel.md)。

## 1. 目标与范围

用户主要希望阅读 Markdown 的渲染结果，并希望用浏览器进行放大、查找和阅读。
旧 Quick Look 把 Markdown 转为临时 HTML，面板的打开动作因此打开渲染结果；现有 Popup
面板把打开动作绑定原附件路径，Markdown 会进入其默认应用。本设计让主操作与当前阅读模式一致，
同时保留明确的原文件入口。

范围为 Popup 提问附件中既有 Markdown 类型（`.md`、`.markdown`、`.mdown`、`.mkd`、`.mdwn`，
大小写不敏感）。其他附件与历史、待办、回复附件等入口保持现有打开行为。

## 2. 主按钮跟随阅读模式

| 当前阅读模式 | 主按钮文案 | 点击结果 |
|---|---|---|
| 渲染预览 | 浏览器打开 | 系统默认浏览器打开渲染后的 HTML |
| 原文 | 打开 | 系统默认应用打开原 MD 文件 |

用户点击「查看原文」进入原文模式时，主按钮切换为「打开」；点击「查看预览」回到渲染模式时，
恢复「浏览器打开」。判断依据是实际阅读模式，不是原文切换按钮的文字。

标题示意：

```text
渲染预览：文件名 [查看原文]   2 / 4  ‹  ›  [浏览器打开]  ⋯  ×
原文模式：文件名 [查看预览]   2 / 4  ‹  ›  [打开      ]  ⋯  ×
```

主按钮区域保留固定占位，文案变化和切换附件不使附件计数、导航、更多或关闭的位置跳动。
沿用本次 Popup 的每附件阅读模式记忆：切到其他附件或收起重开后，主按钮与恢复的模式一致。
新提问首次阅读 Markdown 仍默认渲染预览。

## 3. 其他打开入口

以下决策由用户分别确认，不把主按钮的新行为自动扩展到所有入口：

- 单击附件：沿用当前同窗预览的激活 / 收起行为。
- 双击 Markdown 附件：按第一次单击执行预览切换，不打开外部应用；沿用面板规格的最新双击规则。
- 在附件列表按回车：始终打开原 MD 文件，保留现有行为。
- 更多菜单与附件右键菜单：同一菜单提供明确的「浏览器打开」和「打开原文件」。两项行为固定，
  不随当前阅读模式改变。「打开方式…」仍针对原 MD 文件。
- 拷贝文件、拷贝路径、拖出与在文件管理器中显示：始终针对原 MD 文件。
- 其他文件的主按钮：继续为「打开」，使用原文件默认应用。

菜单中的「浏览器打开」表示渲染结果；原文件动作不打开生成的 HTML。浏览器入口不改变当前
Popup 的阅读模式、位置、附件激活或回答草稿。

## 4. 浏览器结果

使用系统默认浏览器，不硬编码 Safari，也不新增浏览器选择设置。即使 `.html` 的文件默认应用
被设为编辑器，仍应按浏览器入口的含义进入默认浏览器。

每次点击使用当前原文件生成本地 HTML 阅读快照，复用现有 Markdown 渲染能力与资源边界，
不修改源文件、不要求用户手动导出，不新增实时文件监视。原文件变化后重新点击生成新的结果；
浏览器刷新当前 HTML 不代表重新读取 Markdown。

渲染结果有完整的 HTML 文档和阅读样式，支持浏览器原生搜索、缩放及打印。标题保持可识别的
附件名称，同名附件之间不覆盖。临时 HTML 使用已有预览临时目录及清理机制。

生成和打开失败时给出明确反馈，并保留打开原文件入口；不把失败的浏览器操作静默转换为打开
原文件。已有不支持、读取失败和超限状态继续提供原文件操作。

实现复用请求内附件索引授权、有界后台读取与现有渲染策略，避免直接接受前端传来的任意路径。
浏览器 HTML 是独立输出，不能直接开放应用 WebView 或扩大其权限。

## 5. 验收要求

- 默认 Markdown 主按钮为「浏览器打开」，实际进入默认浏览器并展示渲染结果。
- 切为原文后主按钮为「打开」，实际打开原 MD；切回预览恢复浏览器入口。
- 切换附件、收起重开及重新提问时，模式记忆与按钮行为符合 §2。
- 双击只执行一次预览切换，不打开原 MD 或浏览器；列表回车仍打开原 MD，菜单两种动作始终明确、固定。
- 修改原文件后重新点击使用新内容；原文件字节、路径及复制 / 拖出目标保持不变。
- 主按钮文案变化不使其他操作跳动；已有窗口拖拽区域不抢走按钮点击。
- 文件名含空格 / Unicode、同名附件、读取 / 转换 / 打开失败和超限行为可验证。
- 默认浏览器与 HTML 文件关联应用不同的场景仍进入浏览器。
- 三平台实现遵循相同语义；平台实机证据分别记录，不以 macOS 验收代替 Windows / Linux。
