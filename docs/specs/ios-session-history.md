## 1. 背景与目标

收到 Agent 的追问时，最常见的需求是「我上次是怎么答的」。手机上现在做不到：

- 「历史」标签只有**这部手机见过**的请求；在 Mac 弹窗 / IM 里答掉的题，手机只知道「已在 X 回答」，**没有答案内容**（`HistoryEntry.answers` 只含这部手机发出的）；
- 它也不按会话分组，请求页上看不到「这个会话之前聊过什么」。

Mac 端的 `history.jsonl` 已经按请求保存了完整的问答（任何渠道作答的真实答案、Agent 会话 id），缺的只是一条「按会话读取」的通路。

**目标**：在作答页与确认页（含已结束页）上，下拉即加载**这个 Agent 会话更早的问答**，显示在当前提问的上方，继续上滑就能读；「⋯」菜单里有一个等价入口。

**定位：Power User 功能**（用户语）。不做任何提示、不加任何设置项、不改变页面默认外观；不用这个功能的人什么都察觉不到。

**非目标**（§11 有后置理由）：

- 手机本地「历史」标签不改（仍是本机的、按条平铺）；
- 「历史」标签的详情页、Agents 详情页不提供这个下拉；
- 不显示 Agent 的原始对话（transcript），只有 AskHuman 的问答；
- 权限审批不在线程里（Mac 历史本来就没记它们）；
- 不搜索、不跨会话；
- 不落盘、不离线（需要 Mac 在线）；手机不能删除 Mac 上的历史；
- MCP 兜底分区（Mac 历史窗口里「近似」的分组）与无会话信息的请求，本期没有入口（S6）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 会话键 `agentKey` | `{kind}:{sessionId}`，与 `AgentView.key` 是同一个字符串（Mac 的 `ios_agents::agent_key`）；手机本来就能在 Agents 列表里看到它 |
| 往来（exchange） | Mac 历史里的一条记录：一次提问加它的回答。记录的 id 就是请求 id，每个请求至多一条 |
| 线程（thread） | 请求页上方、当前提问之前的往来时间线，旧的在上、新的在下 |
| 锚点 | 线程只含「早于当前请求创建时刻」的往来：当前请求自己的那条（答完的请求在 Mac 历史里也有）和更晚的往来都不在里面 |
| 游标 | `(beforeMs, beforeId)`：只要排序键 `(timestampMs, id)` 小于它的往来；首次的 `beforeMs` 是当前请求的 `createdAt`，之后是线程里最旧一条 |

## 3. 决策记录

| 编号 | 决策项 | 结论 | 理由 / 否决后的代价 |
|---|---|---|---|
| S1 | 数据来源（用户定） | 读 Mac 的完整历史（`history.jsonl`），手机不另存 | 别处作答的真实答案只有 Mac 有；手机本地历史不完整，也没有会话归属。代价：需要 Mac 在线，Mac 与手机都要更新（`caps.sessionHistory`）；老 Mac 上没有入口 |
| S2 | 「更多」菜单（用户定） | 「此会话的历史」与下拉是同一个入口的两种手势、读同一份线程：加载最近一页并**滚到最新一条往来**（已加载过则只滚动）；不做单独的全屏页。与下拉的区别（2026-11-12）：下拉加载后停在原处、新消息出现在松手时留出的空地里（S12、S19），菜单则直接滚到最新一条 | 同一套线程、一份实现。菜单不是在页面顶部拉出来的，没有「那一行」可看，所以加载时用悬浮的小胶囊（也做 shimmer，S19）。代价：不能搜索、不能一次看全（§11） |
| S3 | 支持的页面（用户定） | 作答页、确认页，含它们的已结束态；不含「历史」标签详情页与 Agents 详情页 | 收到消息是主场景；其余后置 |
| S4 | 可发现性（用户定） | **不做任何提示**：没有一次性小提示，没有常驻提示行。只有下拉手势与「更多」菜单项。（S18 的下拉头只在手指正拉着页面的时候出现，是对这个动作的反馈，不是提示；没拉的时候页面上什么也没有） | 页面保持原样；VoiceOver 与不知道手势的人走菜单项 |
| S5 | 会话键放在请求里 | `RequestView` 新增可选 `agentKey`（§5.1）；不放进 `RequestSummary`（收件箱行用不到） | 手机缓存的请求带着键，Mac 忘了这条请求（已结束、重启后）也能查；沿用 `AgentView.key` 的既有格式，手机本来就看得到，没有新增信息 |
| S6 ⚠（用户 2026-11-11 确认） | 范围：只认真实 Agent 会话 | 本期只对「Mac 知道真实会话 id」的请求提供，即现在能显示会话标题的那一批。MCP 实例兜底分区与无会话信息的请求没有入口（线程区、菜单项、下拉都不出现） | **与上一轮方案相比是收窄**（上一轮写的是「MCP 兜底会话标『近似』」），用户已同意。原因：iOS 请求现在只携带真实会话（`SessionRef`），兜底分区要把 MCP 实例 id 与项目穿过 4 处投递点并新增一种键；而它本来就是「近似」的，会把不同对话混在一起。代价：只有 MCP 兜底的调用方（拿不到真实会话 id 的）用不了这个功能 |
| S7 | 锚点与分页 | 手机用 §2 的游标向更早翻页：每页默认 8 条、最多 20 条；Mac 按字节预算少给也行，`more` 说明后面还有没有 | 用时间加 id 的游标而不是偏移量：新往来加在「新」的一端，偏移会错位；排序键 `(timestampMs, id)` 降序，同毫秒也不重复、不遗漏 |
| S8 | 只含已完成的往来 | 只取 `action = Send` 的记录（与 `show-last` 同一口径）；用户主动取消的不列。离开 / 静音模式的自动回复（`channel` 为 `away` / `mute`）要列出，弱化显示 | 「我答过什么」是核心；自动回复能解释「Agent 为什么自己往下走了」。列出取消的往来可以后置（§11） |
| S9 | 往来的内容 | 只带提问与**已选 / 已写的答案**，不带没选的选项；附件、图片、批注只给个数；不带任何路径（**图片部分已被 [历史里的图](ios-history-pictures.md) 取代**：Agent 带的图与回答里的图改为缩略图 + 点开看大图，其余仍只给个数） | Mac 历史里的 `selectedOptions` 是文本，没选的选项既对不上号也不是这里要看的；体积小，一页几乎总能装进一条消息；不暴露路径（沿用 ios-todos I6 的姿态） |
| S10 ⚠（用户 2026-11-11 确认） | 展开方式 | 点卡片**就地展开 / 收起**（原生 Markdown 渲染全文），不跳详情页 | **与上一轮「点开进只读详情（复用历史详情页）」不同**，用户已同意。原因：`HistoryDetailScreen` 吃的是手机本地的 `HistoryEntry`（带 `AskView` 与选项下标），与 Mac 的往来对不上；就地展开不新增页面、不新增 WebView，也更符合「往上滑着读」 |
| S11 | 渲染 | 旧卡片用原生 `MarkdownView`（块渲染、有缓存）；**不新增 WebView**，当前提问的消息仍是这一页唯一的 WebView | 一页一个 WebView 的既有约束 |
| S12 | 视口不跳 | 历史到达的那一刻，当前提问在屏幕上的位置**不动**：松手时它已为 S19 的那一行下移了一行，此后不再动；新往来出现在那一行的位置上，继续往上翻才看到更早的。菜单入口则滚到最新一条往来 | 用户原话「刷新之后继续往上滑」，以及 2026-11-12 的「加载完了之后，底下的消息不跳动，顶上直接出现新的消息」。实现上复用锚点补偿（§7.3，第一版的原型已验证） |
| S13 ⚠（用户 2026-11-11 确认） | 已结束页与 3 秒倒计时 | 在已结束页上加载历史（下拉或菜单）等于点了「停留」：取消该页的倒计时 | 上一轮的默认，用户已确认。它**增加了一个打断源**：`ios-answer-flow.md` E12 列的打断源不含这一项，「手指碰屏幕不算停留」的决定不变——这里是明确的加载动作，不是碰屏。落地时同步改 E12。否则翻到一半会被自动带走 |
| S14 | 不落盘 | 线程只在页面存活期间的内存里；切到别的请求再回来要重新加载 | 与 ios-todos I13 同一立场；Mac 读取很快 |
| S15 | Mac 离线 / 无回应 | 线程区顶端出一行「连不上 Mac」加「重试」；不回退到手机本地历史 | 两处来源不同，混用会让人以为这就是完整的 |
| S16 | 能力协商与协议号 | `Caps.sessionHistory`（缺省不发，沿用 `annotations` 的写法，夹具里既有能力集的形状不变）；新消息 `history.session.get` / `history.session`；`PROTO`（线协议）与 `PROTOCOL_VERSION`（IPC）都不动 | 加可选字段与新消息类型，旧对端靠能力位与 `unknown_type` 兜底；规则见 `docs/overview.md`「IPC 协议号」与 `docs/overview-ios.md`「不变量」 |
| S17 | 无设置项 | 不加 Mac 设置，也不加手机设置 | Power User 功能 |
| S18 ⚠（用户 2026-11-12 确认） | 下拉的反馈：自绘，不用系统控件 | **不用系统的下拉刷新控件，没有转圈。** 手指拉着页面越过顶部时，露出的空地里（直接画在页面背景上，没有色块、不用蓝色）出现一枚历史图标（`clock.arrow.circlepath`）和一行字「下拉查看此会话的历史」，图标随拉的距离逆时针转（像「倒带」）；拉过阈值，字变成「松手查看此会话的历史」、颜色变深、图标转满一圈、**轻震一下**。**松手时已过阈值才加载**，没过什么也不发生。只在手指**按着拉**的时候出现：回弹、惯性冲出去的越界、程序滚动都不出现，页面静止时没有任何痕迹（S4）。再到线程顶端拉更早一页时，字是「下拉加载更早的记录」「松手加载更早的记录」。**横向上，头与松手后换上它的那一行站在同一条区域里：页面内容所在的安全区，不是整个滚动视图**——两栏并排时就是右栏的中线（2026-11-12 补：iOS 26 起并排的侧栏是浮在详情上的一块玻璃，详情栏的滚动视图铺满整个窗口，侧栏的宽度是它的左安全区；横跨整个滚动视图的头会居中在整个窗口、左端还被侧栏盖住，松手换成加载行时字横向跳半个侧栏宽。iOS 18.5 上滚动视图本身就是右栏，看不出来）。没有入口、已读到会话开头、或已有一次加载在途时没有下拉头，页面只有普通回弹。数字沿用初值、没有改（模拟器上没有触觉，也调不了手感；真机一轮由用户来看，不满意改常量、不动结构）：拉出约 12 pt 以内不出现，之后随距离淡入，约 36 pt 时完全可见；越过顶部约 72 pt 算过阈值（空地更高时取空地高度加 8 pt，字体放大后也拉得过）；轻震用 `.light`，每次从下往上越过阈值震一次，阈值上下有 4 pt 的滞回 | 用户原话：「你下拉直接用标准控件，让人以为是刷新消息」。系统控件的转圈在读者看来是「刷新消息」，而这里是把更早的历史翻出来。「安静款」（图标加一行字，不带色块）与「过阈值轻震、松手才加载」是用户在两套方案里选的。自绘也去掉了系统控件的毛病：要把页面拉过约 170 pt 才触发（模拟器上量的越界，iPad 约 230 pt），键盘弹起时上方的空间不够一次拉到。代价：自己跟踪手势与回弹，要多一个原型关卡（计划 R1） |
| S19 ⚠（用户 2026-11-12 确认） | 加载中与加载完 | **松手（已过阈值）后，页面回弹到刚好留出一行空地（约 64 pt）就停住**，这一行是页面顶部的内容：历史图标加「正在加载历史…」，**文字做 shimmer**（一道高光从左到右扫过文字，循环；灰字、高光取主文字色，浅色 / 深色自动适配，不用蓝色）。页面**不锁住**：照常能滚，这一行随内容一起滚走。**历史到达时，请求在屏幕上的位置不动（S12）**：这一行换成历史，空地里露出最新一条往来的下沿与「当前提问」分隔线，继续往上翻读更早的。失败：这一行变成「连不上 Mac」加「重试」（S15），**高度不变**，点「重试」后同一行回到 shimmer。读到头：这一行写「没有更早的记录了」，高度不变。加载中这一行至少停 0.6 秒（答案已经在手也不一闪而过）；手指还按着页面、或页面还在滑动时历史到了，等停下再换（至多 10 秒），不在手底下换内容。「减弱动态效果」下不做 shimmer、不转图标（字用固定的灰），其余不变；VoiceOver 看不到下拉头（走菜单项），加载开始时读出「正在加载历史」。「⋯」菜单入口加载时仍用悬浮小胶囊，里面的字也做 shimmer | 用户原话：「加载过程中，那个文字变成就是 Shimmer 的那种文字的效果……加载的过程中，顶部这个文字都是留在那的，但我可以往下滚动。然后加载完了之后，就是底下的消息不跳动，然后顶上直接出现新的消息就行」，并否决了「文字钉在屏幕顶部、页面回到原位」的做法（「如果上滑，那个文字应该跟着滑上去」）。配色是用户交给我定的：蓝色在 iOS 里意味着「可点」，这一行不能点，所以用灰字加主文字色的高光，与页面里其他安静的小字一致（对比图 `docs/assets/ios-session-history/pull-shimmer.jpg`）。代价：请求比拉之前低一行；要自己实现「持住一行空地—换成历史—请求不动」（计划 R1） |

## 4. 用户视角

**入口**（两个，等价）：

- 在作答页或确认页，页面停在顶部时**下拉**；
- 「⋯」菜单 →「此会话的历史」。

**下拉**（S18、S19；示意图见 `docs/assets/ios-session-history/pull-storyboard.jpg`，三格依次是下面的 1、2、3；实现后在模拟器上拍的真实截图序列见同目录的 `pull-real-storyboard.jpg`）：

1. **拉**：页面停在顶部，手指按着往下拉。拉出一小段后，露出的空地里淡入一枚历史图标加一行字「下拉查看此会话的历史」，图标随距离逆时针转；拉过阈值，字变成「松手查看此会话的历史」、颜色变深、图标转满一圈，轻震一下。没拉到阈值就松手：页面照常弹回，什么也不发生。
2. **松手后**（已过阈值）：页面回弹到刚好留出一行空地就停住，这一行写「正在加载历史…」，文字上有一道高光从左扫到右、循环。这一行是页面内容：页面照常能滚，它随内容一起滚走。
3. **到达**：这一行被换成历史，**当前提问在屏幕上的位置不动**，空地里露出最新一条往来的下沿与「当前提问」分隔线；继续往上翻，看到更早的往来。再到顶再拉是同样的一轮，字是「下拉加载更早的记录」「松手加载更早的记录」，历史加在上面、正在读的卡片不动。没有更早的了，这一行写「没有更早的记录了」（Mac 只保留最近 N 条，所以不说「第一条」），此后不再出现下拉头，也不再请求。

当前提问本身不足一屏时（多数请求如此），线程出现后它所在的区域会补到至少一屏高（下方留白，与没有线程时短页「请求在上、下面空着」的样子一致），所以当前提问同样留在原处，页面也不会停在内容之外（§7.2）。

**菜单**：与下拉读同一份线程，但加载完会**滚到最新一条往来**，已加载过则只滚动。页面不一定在顶部，没有「那一行」可看，加载时用悬浮的小胶囊「正在加载历史…」（文字同样 shimmer）。没有更早的记录时，滚到顶并显示「没有更早的记录了」。

**线程的样子**（示意；当前提问在最下面）：

```
┌ 导航栏：‹ 会话标题              ‹ ›  ⋯
│
│  没有更早的记录了                      ← 顶端那一行（S19）：加载中写「正在加载历史…」，失败写「连不上 Mac」加「重试」，到头写这句
│
│  ┈┈ 昨天 21:40 · Mac 弹窗 ┈┈
│  Agent：我准备把缓存层改成……（最多约 4 行，渐隐）
│  1 缓存要不要改？
│    ✓ 方案 B；先别动 schema
│
│  ┈┈ 今天 09:12 · 离开模式 · 自动回复 ┈┈   ← 整张弱化
│  ……
│
│  ━━━━━━ 当前提问 ━━━━━━
│  [头部] [消息] [问题卡……]               ← 原来的页面，一点不变
│
└ 底栏：已答 0/2                 [发送]
```

**卡片（收起）**：头部一行「相对时间 · 渠道名」；Agent 的消息（原生 Markdown，最多约 4 行，超出渐隐，没有消息时省略）；每题两行：题干（1 行，截断）与「✓ 已选项；写的文字」（至多 2 行），没答的题写「未作答」；多题时最多显示前 2 题，其余写「还有 N 题」。
**卡片（展开）**：点一下展开，全文消息与全部题（题干全文、已选项、文字回答），附件 / 图片 / 批注只写个数（「附件 2 个」）；再点收起。文字可选中复制。展开状态只在内存。（2026-11-12 起图片改为缩略图与查看器，见 [历史里的图](ios-history-pictures.md)。）

**渠道名**：`popup` Mac 弹窗、`dingding` 钉钉、`feishu` 飞书、`telegram` Telegram、`slack` Slack、`ios` iPhone、`away` 离开模式、`mute` 静音模式（后两者是自动回复）；不认识的 id 原样显示。

**回到当前提问**：向上滚得离当前提问超过一屏时，出现一枚悬浮胶囊「回到当前提问」，点一下滚回去。（这是最先可砍的一项：成本高了就不做，不影响其余；用户 2026-11-11 选择保留。）

**没有入口的情形**：请求没有 `agentKey`（S6）、这台 Mac 太旧（没有 `caps.sessionHistory`）、页面还只有摘要拼出的占位视图（完整视图到了才出现，§8）：没有菜单项，下拉也没有下拉头（只有普通回弹），页面与现在完全一样。

**错误**：Mac 离线、超时：顶端那一行变成「连不上 Mac」加「重试」（S15、S19），高度不变，不影响作答。

## 5. 线协议（`ios/wire.rs` 与 Swift `AHProtocol` 共用 `ios/Fixtures/wire-v1/messages.json`）

全部是加字段 / 新消息类型，JSON 键 camelCase，可选字段缺省不发。

### 5.1 请求上的会话键

`RequestView` 新增可选 `agentKey`：提问的 Agent 会话的键（`{kind}:{sessionId}`，与 `AgentView.key` 逐字相同）。Mac 不知道真实会话（没有 `SessionRef`）时不发。作答页与确认页的请求都带它。

### 5.2 能力位

`hello.ack` / `pair.accept` 的 `caps` 增加 `sessionHistory`（缺省 false、为 false 时不发）。

### 5.3 消息

| 方向 | 类型 | 主要字段 |
|---|---|---|
| 手机 → Mac | `history.session.get` | `reqId`（手机生成，应答原样带回）、`agentKey`、`beforeMs`、`beforeId?`、`limit`（Mac 夹到 `1…SESSION_HISTORY_PAGE_MAX`） |
| Mac → 手机 | `history.session` | `reqId`、`agentKey`、`items: [Exchange]`（新的在前）、`more`（最后一条之前还有没有） |

`beforeMs` / `beforeId` 是 §2 的游标：只要 `(timestampMs, id)` 小于 `(beforeMs, beforeId)` 的往来；没有 `beforeId` 时是 `timestampMs < beforeMs`。`items` 可以比 `limit` 少而 `more` 仍为真（页字节预算用完）。键不合法、会话没有记录、Mac 的历史关着（`general.historyLimit = 0`）时，都是空 `items` 加 `more = false`，不是错误。

**Exchange**：

| 字段 | 含义 |
|---|---|
| `id` | 往来 id（即请求 id） |
| `at` | 记录的时刻（`timestampMs`，回答被记录的那一刻） |
| `channel` | 作答渠道 id（原样，见 §4 的渠道名） |
| `markdown` | 消息与题干是否按 Markdown |
| `message` | Agent 的消息，裁剪到 `HISTORY_MESSAGE_MAX_CHARS` |
| `attachments?` | 消息带的附件个数（只有个数，没有名字和路径） |
| `qs` | 每题一项：`text`（题干，裁剪到 `HISTORY_QUESTION_MAX_CHARS`）、`selected`（已选项文本，每个裁剪到 `HISTORY_OPTION_MAX_CHARS`）、`input?`（写的文字，裁剪到 `HISTORY_INPUT_MAX_CHARS`）、`images?` / `files?`（回复带的图片 / 文件个数） |
| `notes?` | 批注个数 |

第 i 题的答案取 `answers[i]`（自动回复只有一条答案，落在第 0 题）。文字被裁剪时以 `…` 结尾。

**限额**（`ios/wire.rs` 与 Swift `Wire` 必须一致）：`SESSION_HISTORY_PAGE = 8`（手机默认）、`SESSION_HISTORY_PAGE_MAX = 20`、`SESSION_HISTORY_BYTES = 262144`（一页 JSON 的预算）、`HISTORY_MESSAGE_MAX_CHARS = 4000`、`HISTORY_QUESTION_MAX_CHARS = 1000`、`HISTORY_OPTION_MAX_CHARS = 500`、`HISTORY_INPUT_MAX_CHARS = 2000`。整条消息不能超过 `MAX_ENVELOPE_BYTES`（`send` 对超限消息是静默丢弃，必须在构造时避免）。

超预算时的收缩与 `todo.list` 同一套（`shrink`）：先少给最旧的往来（`more` 保持为真，手机下次从新的游标继续）；只剩一条还超，就把它的各段文字减半，直到装下。

## 6. Mac 端行为

### 6.1 请求带键

`IosChannel::start`（`channels/ios.rs`）在写 `session_title` 的同一处写 `agent_key`；确认请求在 `channels/confirm.rs` 写 `session_title` 的同一处写。取值来自 `SessionRef`，格式化函数与 `ios_agents::agent_key` 是**同一个**（挪到两边都能用的地方），保证与 `AgentView.key` 逐字相同。没有 `SessionRef`（无 Agent，或没有真实会话 id）就不写。

### 6.2 读取

`Host` trait（`ios/gateway/mod.rs`）新增 `async fn session_history(&self, agent_key, before, limit) -> wire::SessionHistory`，默认实现返回空页（所以只实现自己要的宿主不受影响，与 `todo_list` 同）。Daemon 的实现在新文件 `daemon/runtime/ios_history.rs`：

1. `ios_agents::split_key` 解析会话键，失败返回空页；
2. 调 `history.rs` 的新函数 `sends_for_session_before(agent_kind, session_id, before, n)`：口径与 `recent_sends_for_session` 相同（`action == Send`，`agent_kind` 与 `agent_session_id` **精确相等**，即 `reply-history.md` F1 的「真实 session」；不碰 MCP 分区），但按 `(timestampMs, id)` 降序，取游标之前的 `n + 1` 条，多出的那一条只用来得出 `more`；
3. 投影成 `Exchange`（裁剪文本、只留个数）；
4. 整个读取在 `spawn_blocking` 里做（要读整份 `history.jsonl`，上限默认 200 条）。

读取是只读的，不进幂等日志，不订阅，不广播。

### 6.3 网关

`ios/gateway/history.rs`（新）的 `on_session_history_get`，与 `on_todo_list_get` 同样用 `spawn_then`：把 `limit` 夹到范围内，调 Host，按 §5.3 收缩后发回，应答回显 `reqId`。老手机不会发这条消息。

### 6.4 能力位

Daemon 的 Host `caps()` 返回 `session_history: true`。

## 7. 手机端行为

### 7.1 入口条件

`item.view?.agentKey != nil` 且这台 Mac 的 `caps.sessionHistory == true`（`macs[macId]?.caps?.sessionHistory`）。不满足时请求页与现在完全一致：没有菜单项，也没有下拉头（只有普通回弹）。`RequestScreen.hasMore` 把这个条件算进去（只有这一项时菜单也要出现）。

### 7.2 模型与通路

- `SessionThread`（`AHCore`，`@MainActor @Observable`，由请求页持有：`RequestScreen` 里的 `RequestHistoryHolder` 按请求留一份 `RequestHistory`，它包着线程与滚动协调者；**不进 `AppStore` 的缓存**：页面随请求切换重建时一并丢掉，不落盘，即 S14）：状态 `idle / loading / failed / ready`、`reachedStart`；`items`（旧到新）；`loadMore(beforeInsert:)`（首次与翻页共用一个入口，页面到手、显示之前先调一次 `beforeInsert`，让界面记下滚动位置）；同一时刻只有一个在途请求（重复触发忽略）；游标由线程里最旧一条决定，首次用当前请求的 `createdAt`；`intent` 计数每次用户要求历史加一（下拉、菜单、重试），`RequestScrollPosition` 据此放弃还没还原的阅读位置。
- `Backend` 新增 `sessionHistory(macId:agentKey:beforeMs:beforeId:limit:)`（`AHCore/Backend.swift`）。`PhoneEngine+SessionHistory.swift` 用与 `PhoneEngine+Todos.swift` 相同的「信箱 + 超时」（键为 `reqId`，超时 10 秒，沿用 `todoReadTimeout`）；离线、能力位缺失分别抛 `macOffline`、`rejected("unsupported")`。
- `AHMock` 有对应的 `MockBackend+SessionHistory.swift` 与一个带多页历史的场景；`AHCoreTests` 有 `TestMac+SessionHistory.swift`（与 `TestMac+Todos.swift` 同款）。

### 7.3 页面集成与滚动

- `AnswerScreen` 与 `ConfirmScreen` 现在是 `ScrollView { VStack { … }.background(RequestReadingAnchor(name: "request-top")).background(RequestScrollPosition(…)) }`。改成：滚动内容外层再包一层 `VStack`：`[线程区][当前请求区]`，**原来的 VStack 连同 `request-top` 锚点与 `RequestScrollPosition` 整个留在「当前请求区」**，所以阅读位置的保存与还原、「下一题」、问题卡的锚点都不受影响。线程区为空时高度为 0。
- 新文件 `Views/Request/SessionThreadView.swift`：卡片、顶端的状态行（加载中 / 「连不上 Mac」加「重试」/ 「没有更早的记录了」，三种同一个最小高度，S19）、「回到当前提问」胶囊。
- 「⋯」菜单（`RequestScreen.moreMenu`）加一项「此会话的历史」（`clock.arrow.circlepath`，标识 `request-menu-session-history`）：线程未加载就加载并滚到最新一条往来；加载过就只滚动；失败显示 S15 的错误行并滚到顶。
- **滚动做法**（P1 原型的结论，依据与踩到的坑见 `docs/plans/ios-session-history.md` 的「P1 结论」）：
  - **下拉**（第一版用 `UIRefreshControl`，**2026-11-12 起按 S18、S19 改为自绘**；原型与踩到的坑见计划里的「R1 结论」）：`ThreadScrollHook` 仍挂在滚动内容的背景上，沿 `superview` 找到页面的 `UIScrollView`，只在入口条件满足、且还没读到会话开头、也没有加载在途时才有下拉头；**不再装 `UIRefreshControl`**（转圈、触发距离、回弹都由系统定，与 S18 冲突）。手势用滚动视图自己的 `panGestureRecognizer`（多加一个 target，看开始 / 变化 / 结束）与 `contentOffset` 的 KVO 跟踪：只有手指按着（`isTracking`）并把页面拉过顶部时才有下拉头；越界量、是否过阈值、要不要轻震、松手时是否触发，由一个纯值类型的状态机算（不依赖 UIKit，可单元测试）。下拉头是滚动内容顶端上方的一个 UIKit 子视图，随内容一起动，不比内容晚一帧。**松手时已过阈值，空地是页面内容里真实的一行**（`SessionStateRow`，约 64 pt，加载中带 `ShimmerText`），**不是 `contentInset`**：SwiftUI 持有滚动视图的内边距，外部写进去的值约 10 ms 内就被改回去（R1 用 KVO 探针量到，试过的写法结果都一样）。这一行在松手那次布局里进入内容，锚点补偿同时把 `contentOffset` 加上它的高度，请求在屏幕上不动，UIKit 的下拉头在同一次布局里藏掉（补偿之后它比这一行高出一整行）；写偏移用 `setContentOffset(_, animated: false)`，它也停住 UIKit 自己的回弹，页面的回弹由下一个运行循环里的 `setContentOffset(静止位置, animated: true)` 接着做（越界的程序化偏移会一直停到下一次触摸，所以回弹得自己起）。系统的 `.refreshable` 仍然不用：线程晚于首帧出现时，条件修饰符会改变 `ScrollView` 的结构身份，页面被重建。SwiftUI 会按内容高度把 `alwaysBounceVertical` 改回 `false`（内容不足一屏的页面——多数请求——因此拉不动），继续用 KVO 在被改掉的那一刻放回去。
  - **前插不动**：一页到手 → 等页面停住（手指抬起后至多 1.5 秒，回弹的弹簧尾巴很长；手指一直按着最多等 10 秒）→ 记下 `request-top` 锚点在视口里的位置 → 把顶端那一行加载中换成线程（它至少已经停了 0.6 秒）；此后每一次布局（附着视图的 `layoutSubviews`、`contentSize` 与锚点各级祖先层 `position` / `bounds` 的 KVO）都把 `contentOffset` 调回到锚点原来的位置，与新内容是同一次布局，所以没有任何一帧是错位的。**补偿的窗口从插入的那次布局到来起算 0.5 秒（后续那几遍布局，比如卡片再量一次），不从「要求插入」起算**：主线程被抢占（内存紧张的设备、在换页的机器）时，那次布局可以晚一秒以上，从要求插入起算的 0.5 秒早已过去，请求就会在那一帧被推到线程的下面去（探针量到过：插入后的下一帧在一秒多之后，请求从 23 pt 变成 1238 pt）。所以布局到来之前窗口最多留 4 秒，期间请求在内容里没有被推动过就什么也不做（页面这段时间怎么动是它自己的事，不去碰）；布局一到，请求回到要求插入时它在视口里的位置，并再补偿 0.5 秒。状态行的最小高度等于持住的空地，所以失败与读到头时「换成状态行」不改变高度、不需要补偿。线程区用普通 `VStack`，不用 `LazyVStack`（估算高度会让前插后的位置漂）。
  - **短页要留余地**：当前提问不足一屏时，它下面没有内容可滚，要调回的偏移就超出内容末端；UIKit 不会夹住程序设置的越界偏移，页面停在越界处还是被夹回，取决于时序（两次运行不一样），停在越界处时第一次触摸会跳一下。所以线程出现（含「没有更早的记录了」与错误行）后，当前提问的区域用 `ZStack` 里一块 `containerRelativeFrame(.vertical)` 的透明垫子补到至少一屏高（`requestRoom`）；没有线程时垫子高度为 0，结构不变，页面不会因此重建。「滚到最新一条」与「回到当前提问」的目标位置也因此总在有效范围内。
  - **与阅读位置**：`RequestScrollPosition` 多一个 `intent` 令牌（变了就放弃还没还原的位置，菜单入口不是手指拖动，不然会与「滚到最新一条」打架），兜底分支在视口停在请求之上时保存「`request-top` 加 0」，所以重进页面回到请求顶部，而不是被还原到页面中间。
  - **菜单入口**：`RequestHistory.reveal()` 用同一套前插补偿加载，然后等页面把线程真正布局出来（`waitForThreadLayout`：至少 120 毫秒；有往来时还要等最新一张卡片的锚点出现、且 `contentSize` 已静止 0.1 秒，至多 2 秒），结束补偿窗口，再滚到最新一张卡片（没有记录就滚到顶）；已加载过就只滚动。**不能只等固定的一小段**：主线程被抢占（机器换页、别的进程占满 CPU）时，线程的布局会晚于固定的等待到来，补偿窗口已过、最新卡片的锚点还没出现，「滚到最新」的守卫会直接返回，页面就停在线程顶端（实测在负载很高的机器上约十分之一的概率出现）。

### 7.4 与已结束页的接缝

在已结束页上加载历史（下拉、菜单或「重试」）时，调 `AppStore.stayOnEnded(_:)`（经 `RequestHistory` 的 `engaged` 回调），等同于点了「停留」：取消该页的倒计时（S13）。落地时 `stayOnEnded` 也管「条还没显示、倒计时还没开始」的那段（`pendingEndedCountdownId`），所以在条出现之前就开始读历史也不会被带走。其余打断规则（E12）不变。

### 7.5 其它

- 本地化：英文为源语言，补 zh-Hans，沿用 `Localizable.xcstrings` 的生成脚本。
- 无障碍：每张卡片是一个合并的读屏元素（时间、渠道、消息、各题与答案）；VoiceOver 用户用菜单项（下拉对他们不可用）。
- 大屏：线程在请求页内部，`ColumnsOrStack` 不受影响。
- 深色、最大字号、iPhone SE 宽度下卡片不截断、不挤成几个字宽。

## 8. 兼容

| 组合 | 表现 |
|---|---|
| 新手机 + 旧 Mac | 旧 Mac 不发 `caps.sessionHistory`，也不发 `agentKey`：没有入口，什么都不变 |
| 旧手机 + 新 Mac | 旧手机忽略 `agentKey` 与能力位，不会发新消息：什么都不变 |
| 新 + 新 | 带 `agentKey` 的请求有入口 |

`RequestView` 在每次（重新）投递时重建（恢复快照里只存各手机的投递状态，不存视图），所以 Mac 升级后仍在途的请求也会带上 `agentKey`。`content_hash` 是对整份序列化视图算的（`ios/gateway/requests.rs`），加了字段后新哈希不同于手机缓存的旧视图；手机按既有规则（`PhoneEngine+Requests.swift`：摘要哈希与缓存视图不同就 `request.get`）重拉一次，无害。收件箱摘要里没有 `agentKey`，所以请求页在只有摘要拼出的占位视图时没有入口，完整视图到了才出现。`PROTO`、`PROTOCOL_VERSION` 都不动。

## 9. 隐私与安全

- 已配对的手机本来就是 Mac 的遥控端，能收到所有提问；这里新增的是**能回看 Mac 上保留的旧问答**（包括配对之前的）。传输仍是端到端加密（同 `todo.*`），不进推送、不进通知。
- 手机不写盘（S14），也不会拿到任何路径：往来里没有项目路径、附件路径、图片路径，只有个数（S9）。
- 会话键是手机给的任意字符串：Mac 只做 `split_key` 解析与精确相等匹配，不拼路径、不进 shell。
- 读取是只读的、有上限的（一页 ≤ 20 条，≤ 256 KB），不会被用来拖垮 Mac。

## 10. 已知局限

- **深度受 Mac 历史保留数限制**：默认全局 200 条（`general.historyLimit`，不是每会话），很忙的 Mac 上，较老会话的记录可能已被挤掉；Mac 上删掉的历史（历史窗口、清空）手机也看不到。
- `at` 是回答被记录的时刻，不是提问的时刻；锚点按当前请求的创建时刻切：同一会话里并行提问时，晚于它创建、早于它被看到才答完的往来不会出现在线程里（罕见，接受）。
- `channel` 为 `ios` 时不知道是哪部手机答的。
- 附件、批注只给个数，不能在手机上看；图片自 2026-11-12 起可看，见 [历史里的图](ios-history-pictures.md)。
- 只列「发送」的往来，不列用户主动取消的（S8）。

## 12. 验收标准

1. 有 `agentKey`、Mac 有 `sessionHistory` 能力时，作答页与确认页（含已结束页）在顶部下拉出现下拉头（S18），没有系统转圈；松手后留出一行空地写着「正在加载历史…」（S19）；加载后，当前提问的上方出现最近至多 8 条往来（新的在下），**历史到达前后，当前提问在屏幕上的位置不变**（松手时它下移一行空地，之后不再动）；继续往上翻看到旧往来。
2. 再到顶再下拉加载更早一页，不重复、不遗漏（同毫秒的往来也是）；没有更早的了，顶端那一行写「没有更早的记录了」，之后不再出现下拉头，也不再发请求。
3. 「⋯」→「此会话的历史」：未加载时加载并滚到最新一条往来，已加载时只滚动，没有记录时滚到顶并显示「没有更早的记录了」。
4. 没有入口的情形（无 `agentKey`、老 Mac、只有占位视图时）：没有菜单项、没有下拉头、页面与现在一致。
5. 当前请求自己的往来与比它更晚的往来不出现在线程里；只出现这个会话的往来（`agent_kind` 与 `agent_session_id` 精确相等），不混入别的会话。
6. 卡片收起 / 展开如 §4；离开 / 静音模式的自动回复弱化显示；多题、未作答、很长的文字、没有消息只有题干，都显示正常；不新增 WebView。
7. Mac 离线或超时：顶端那一行变成「连不上 Mac」加「重试」（与空地等高），作答不受影响；点「重试」后同一行回到 shimmer，成功后线程照常。
8. 在已结束页上加载历史取消 3 秒倒计时（等同「停留」）；不加载时倒计时行为不变。
9. 阅读位置还原、「下一题」、键盘的交互式收起、发送、草稿保存，在加载了线程与未加载时行为一致。
10. 深色、最大字号、iPhone SE 宽度、中英文、iPad 都正常；VoiceOver 能通过菜单项使用。
11. 老手机连新 Mac、新手机连老 Mac 都没有任何变化；`PROTO`、`PROTOCOL_VERSION` 不变；新增的线协议夹具两边往返测试通过，既有夹具原样保留。
12. **下拉头（S18）**：只在手指按着往下拉的时候出现；拉过阈值，字与图标变化并轻震；没过阈值松手什么也不发生（不发请求、不留空地）；回弹、惯性冲出去的越界、程序滚动都不出现；页面静止时没有任何痕迹；页面上没有 `UIRefreshControl`、没有转圈。已读到会话开头、已有加载在途、没有入口时不出现。
13. **空地（S19）**：松手后页面停在「留出一行」的位置，文字有 shimmer，页面照常能滚、这一行随内容滚走；历史到达的每一帧，当前提问相对屏幕的位置不变（误差 ≤ 1 pt）；到达时手指还按着或页面还在滑动，等停下再换；失败与读到头的行和空地等高。
14. 键盘弹起、短页、长页、iPad 上下拉都能触发（阈值是我们自己的，不再受系统控件触发距离的限制）。
14a. **两栏并排时下拉头居中在右栏**（S18 的横向规则）：下拉头的中线与松手后加载行的中线是同一条（±2 pt），在 iOS 26 及更新的并排窗口里也是（UI 测试 `testWithTwoColumnsThePullHeaderIsCenteredWhereTheLoadingLineIs` 读探针里下拉头的横向区域与加载行比；手机与窄浮层跳过）。
15. 「减弱动态效果」下没有 shimmer 与图标转动；VoiceOver 看不到下拉头、加载开始时读出「正在加载历史」，菜单入口照旧。

## 13. 测试

- **Rust（`history.rs`）**：游标分页（同毫秒、跨页边界、`more`）、只取 `Send`、自动回复列出、精确会话匹配（别的会话与 MCP 分区的记录不混入）、空历史。
- **Rust（网关 / Host）**：`limit` 夹取、非法键、超预算收缩（先少给旧的，再减半文字）、`reqId` 回显、能力位只在 Host 声明时才发；`RequestView.agent_key` 在有 / 无 `SessionRef` 时的取值，并与 `AgentView.key` 逐字相同；投影的裁剪与个数。
- **线协议**：夹具往返（有 `agentKey` 与无 `agentKey` 两种请求、新旧能力集）。
- **Swift 包**：`SessionThread`（首页、前插顺序、耗尽、失败后重试、重复触发只发一次、游标推进）、`PhoneEngine`（应答路由、超时、离线、不支持）、已结束页上加载取消倒计时；下拉的状态机（纯值类型，不依赖 UIKit）：死区与淡入、过阈值与回落、每次从下往上越过阈值各震一次、松手时已过阈值才触发、手指没按着的越界不算、没有入口 / 到头 / 加载在途时不工作。
- **UI 测试（Mock 场景）**：下拉与菜单两个入口；松手后请求下移一行空地、历史到达前后请求的位置不变（量锚点距离）；没拉到阈值松手不加载、不留空地；空地里有「正在加载历史…」；收起 / 展开、已结束页与倒计时、没有入口时页面不变、中英文、最大字号、深色；键盘弹起时的下拉（iPad 上也要能触发）；减弱动态效果。
- 滚动原型的结论写进计划：第一版（P1）与 2026-11-12 的重新设计（R1）各一个关卡。
