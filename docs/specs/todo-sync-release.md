# 需求：iCloud 待办同步的正式版分发

> 2026-11-06，经 AskHuman 逐项确认；同步语义沿用 [todo-sync](todo-sync.md)。
> 本文补充从自用安装走向公开分发的交付与验收要求，实施见 [计划](../plans/todo-sync-release.md)。

## 已确认的范围

1. 按面向所有用户的正式发布要求准备，不先做朋友专属功能版本。
2. 以 npm 为主要安装入口。helper 随 `@humaninloop/darwin-arm64`、
   `@humaninloop/darwin-x64` 一起交付，首次启用同步时才安装并注册后台项。
   不引入新的 DMG / PKG；已有 GitHub 直接下载、自更新也要携带组件。
   为兼容已发布的「只复制可执行文件」更新器，用户随后确认把已签名公证的 helper zip
   嵌入 Mac 可执行文件；不使用必须另行复制的旁置资源。
3. AskHuman 本体继续支持 macOS 11；同步仅支持 macOS 14+，旧系统说明原因。
4. 设置入口仍在「实验」，须先开启实验功能，同步默认关闭。
5. 用户接受现有后台传播延迟，不以「活跃时 5 秒内」作为发布门槛。
   后台依赖推送与轮询；打开窗口、手动同步与 whats-next 读取刷新沿用既有策略。
   whats-next 超时使用本机数据并在后台补拉，不能承诺每次都立即看到另一台的最新改动。
6. 朋友可在候选包完成后用独立 iCloud 账号验收首次使用，已记录项目待办。
   稳定版 macOS 与双机恢复场景仍须记录真实结果，不以模拟器或单元测试代替。
7. 用户要求直接在当前主工作树开发，不创建新的 worktree。
8. 2026-11-07 用户明确要求不做断网相关与睡眠测试，其他工作继续完成。
   本轮不执行网络切换、断网编辑 / 恢复、睡眠 / 唤醒操作；保留这些场景未验证的记录。

## 安装与升级

- 未开启同步时只携带资源，不解包、不安装、不注册登录项、不访问 iCloud。
- 首次启用时从本地安装资源安装 helper，验证 Developer ID、固定 Team ID / bundle ID、
  Production 容器权限与公证状态；失败保留本机待办，说明原因，提供重试。
- helper 仍作为独立 `.app` 放在用户的 Applications 目录，沿用已验证的启动形态。
  替换采用暂存、验证、备份、切换和失败回滚；并发安装串行化。
- 需要系统批准时明确引导至登录项，批准后可以重试；不误报首次同步成功。
- 已开启同步的用户升级 AskHuman 后，组件应能升级；旧进程不得把较新的组件降级。
  没有新组件资源的源码构建继续兼容已安装的自用 helper，不伪造已完成组件更新。
- npm 包与直接下载资产使用相同的已签名、公证、staple 的 helper 资源；
  组件版本、RPC 协议号与容器环境可核对。旧直接更新器复制新程序即携带完整资源。
- 安装、升级、停止同步都不清除 `todos.json`、同步旁路状态或 iCloud 数据。

## 发布验收

1. 自动化覆盖无组件、错误签名 / 环境、版本不兼容、并发、安装失败回滚与防降级。
2. 两种 Mac 架构的 npm pack 均包含 helper；Linux / Windows 包不包含；
   npm 安装、直接下载和两条更新路径都有资源传播与失败保护的验证。
3. 公证后的资源在携带 quarantine 的真实下载路径可安装、启动和使用 Production。
4. 独立账号从空状态创建私有数据区与订阅，不需要开发者账号、Xcode 或 Dashboard。
5. 稳定版 macOS 14+ 上验证首次安装、系统批准、双机传播、组件升级、停用与重新启用；
   至少一次 24 小时运行。按上述用户决定，本轮不要求执行断网与睡眠场景，保留未验证边界。
6. 健康联网且清醒时后台最终追平；空闲时保留既有「轮询周期 + 2 分钟」目标，
   主动刷新有界等待，离线保留本机读写。记录实际传播分布，不宣传秒级保证。
7. 中英文用户说明写明项目匹配规则、附件与自动执行标记不同步、历史清空的全局影响、
   账号切换保护、系统要求、启用 / 停用 / 排障与真实延迟。

公开发布须以上证据齐备。实现代码、候选包、公证成功与正式发布分别记录，不能互相代替。
