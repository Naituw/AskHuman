# Popup 提问与附件的分区查找

> 状态：已实现、安装并通过 macOS 交互验收；其他平台实机验收待补。
> 日期：2026-10-09。
> 基础行为：[popup-find.md](popup-find.md)、[popup-attachment-preview-panel.md](popup-attachment-preview-panel.md)。

## 1. 问题与目标

附件改为窗口内预览后，⌘F / Ctrl+F 仍固定打开提问侧查找，不能搜索当前附件正文。
用户正在阅读右侧文件时，快捷键的目标与阅读目标不一致。

本设计让查找按用户操作的区域选择目标，并明确显示搜索范围。同一时刻只有一个查找会话
和一条搜索条；计数和上下条导航仅属于所选范围。

本文覆盖旧规格 F5 的标题栏内叠放位置，以及固定交给提问侧的快捷键路由。
其他提问查找语义继续沿用。

## 2. 已逐项确认的决策

| 编号 | 决策 | 结论 |
|---|---|---|
| S1 | 默认范围 | 按最近操作的区域路由，可手动切换「提问 / 当前附件」 |
| S2 | 附件范围 | 只搜当前附件，不跨所有附件，也不跨请求 |
| S3 | 首版能力 | Markdown、文本/代码、diff，以及有可提取文字的 macOS PDF |
| S4 | 搜索条位置 | 在目标区域标题栏下临时展开一行，同一时刻只显示一条 |
| S5 | 点击入口 | 仅附件标题栏增加放大镜；提问继续通过快捷键进入 |
| S6 | 关键词 | 切换范围、附件或阅读模式保留同一关键词与 Aa 状态 |
| S7 | 切附件 | 重新计数，定位新附件的首个命中 |
| S8 | 切阅读模式 | 重新计数与高亮，保持该模式的阅读位置，不自动跳转 |
| S9 | 多请求 | 每条提问独立保留搜索状态；返回时恢复，不自动滚动 |
| S10 | 结束 | 关闭搜索清空关键词、索引和高亮；提交/取消释放该请求状态 |
| S11 | 收起预览 | 若当前搜索目标为附件，结束搜索，不隐式切为提问搜索 |

下文的路由、交互、能力说明及实现边界已随最终评审一起确认。

## 3. 快捷键路由

### 3.1 范围判定顺序

1. 焦点在搜索条内：⌘F / Ctrl+F 重新聚焦并全选关键词，保持当前范围。
2. 本次按键来自 PDF / Quick Look 原生正文：选择附件区。
3. 使用本请求最近主动操作的内容区域，包括最近由用户移动的焦点。
   旧答案输入框仍持有 DOM 焦点时，不能覆盖用户后来在附件内的阅读/滚动操作。
4. 尚无操作记录时，以有效内容焦点兜底；仍无法判定，或附件已收起则默认提问区。

「主动操作」包括点击、键盘聚焦、文字选择和用户滚动；鼠标经过、程序聚焦、程序滚动、
高亮重画、原生布局更新和单独按下修饰键不改变记录。搜索条及其范围选择器不参与最近操作区域的推导。
在附件列表显式打开/切换预览，视为用户开始阅读附件；答案编辑器的编辑或聚焦属于提问区。

原生 PDF / Quick Look 的输入来源也属于附件区，不能只依赖 `document.activeElement`。
如果搜索已打开，用户点击另一区域不会立即迁移搜索条或重搜；再次按 ⌘F 才按该区域
切换，或由用户在范围选择器中明确切换。

### 3.2 场景表

| 场景 | ⌘F / Ctrl+F 的结果 |
|---|---|
| 无附件预览 | 搜索提问 |
| 打开附件后阅读正文 | 搜索当前附件 |
| 在附件正文选字 | 搜索当前附件，可用本区域选区预填 |
| 附件展开，但正在写答案 | 搜索提问；答案草稿继续排除 |
| PDF 原生正文拥有键盘焦点 | 搜索该 PDF，输入焦点转到 HTML 搜索条 |
| 在搜索输入中再按快捷键 | 保持范围，聚焦并全选现有关键词 |
| 在图片或 Office 原生预览中按快捷键 | 显示附件范围及能力说明，不改搜提问 |

只在新开查找会话且目标区域存在有效正文选区时预填，沿用最多 200 字符的限制。
会话已经打开时保留关键词。答案草稿、其他区域选区和上个附件的残留选区不用于预填。

## 4. 搜索条与布局

附件正常状态：

```text
文件名 [查看原文]       2/4  ‹ ›  [查找图标] [打开] ⋯ ×
──────────────────────────────────────────────────────
附件正文
```

附件查找状态：

```text
文件名 [查看原文]       2/4  ‹ ›  [查找图标] [打开] ⋯ ×
[当前附件 ▾] [关键词…………] 3/12  ↑ ↓  Aa  ×
──────────────────────────────────────────────────────
附件正文，高亮命中并定位当前项
```

搜索提问时，同一搜索条位于提问导航栏下；右侧附件标题栏和正文保持正常。
左侧原有导航动作无需渐隐。范围菜单包含「提问」「当前附件」，当前附件项只在预览展开时可选。
附件名称保留在原标题栏，范围选择器无需重复长文件名；可访问名称包含完整文件名。

- 搜索条只在打开时占用高度，不遮盖正文，也不扩展原生窗口或改变持久尺寸偏好。
- 默认采用约 36 逻辑像素的一行布局，最终尺寸由既有字体和控件实测确定。
- 目标区域宽度较小时，先缩输入框；无法容纳时仅搜索条内部换为两行。原附件标题栏仍为一行。
  上下条、Aa、关闭和范围选择不得被裁掉，提问区临时缩窄时同样可操作。
- 搜索条不是窗口拖拽区；标题栏的安全空白继续可拖拽。
- HTML 搜索条展开/收起后重新测量原生正文矩形，PDF/Quick Look 只占剩余正文区域。
  不把原生正文盖在搜索输入上，不重建 PDF 文档，不改变缩放或主动跳页。
- 附件放大镜拥有「查找当前附件内容（⌘F / Ctrl+F）」的本地化提示与可访问名称。
  点击始终打开或聚焦附件搜索，不反向关闭；包括加载中及不支持格式的附件。

## 5. 匹配、导航和阅读状态

提问范围沿用原先的 Message、题干、选项、附件名、Confirm 详情/选项和跨题导航。
当前附件范围按当前阅读模式搜索正文，排除工具栏、提示文案和自动生成的行号。

- 连续子串匹配，默认忽略大小写，Aa 可切换；不新增正则、整词、替换或多关键词语法。
- 全部命中使用柔和高亮，当前命中更醒目；浅色/深色均可读。
- 上下条和首尾循环沿用既有行为，计数只属于当前范围。
- Enter / Shift+Enter 在搜索条内用于下一条/上一条；⌘G / Ctrl+G 及 Shift 反向仅在搜索打开时有效。
  正常输入法组合态不触发搜索导航或业务提交。
- ⌘G 始终导航当前搜索范围，不因鼠标点击另一内容区而隐式换目标。
- Esc 先结束搜索、清空关键词和高亮，再按后续独立按键处理语音及预览；同一次按键不取消提问。
  模态确认层按现有阻塞规则独占输入，背景搜索不接收其按键。
- 带主修饰键的既有发送/取消快捷键继续有效；搜索输入内的普通 Enter 不会触发裸 Enter 提交。
- 关闭后恢复打开前的有效控件/原生正文焦点；不强制聚焦答案框，不把搜索前滚动位置倒回去。

| 用户动作/事件 | 查询与高亮 | 阅读位置 |
|---|---|---|
| 输入关键词或切 Aa | 重算当前范围 | 定位当前命中；Aa 尽量保持同一命中 |
| 切换「提问 / 当前附件」 | 保留关键词和 Aa，清旧范围高亮，重新计数 | 定位新范围首个命中 |
| 切换到另一附件 | 保留关键词和 Aa，旧任务失效 | 有结果时定位首个；无结果时保留该附件既有阅读位置 |
| Markdown/diff 切原文/预览 | 按新模式重算，只重画高亮 | 恢复该模式原先位置；下次导航再跳命中 |
| 重渲染、窗口缩放或被动恢复 | 保持有效逻辑命中，只重画 | 不主动滚动或切题 |
| 切换请求，再返回 | 恢复该请求的查询、范围和有效命中 | 保留阅读位置，不自动跳转、不抢输入焦点 |
| 关闭搜索 | 清查询、索引、高亮；Aa 回到默认 | 保留当前位置 |
| 收起预览，当前搜索为附件 | 结束该搜索会话 | 原阅读状态按既有规格保存 |
| 收起预览，当前搜索为提问 | 保留提问搜索 | 提问阅读位置不变 |

新附件加载中可先编辑关键词，显示「加载中」；加载完成后按切附件动作定位首个命中。
失效任务不能在之后改变新的查询、范围、附件、计数或滚动位置。

## 6. 附件能力与状态文案

| 类型/模式 | 搜索数据与定位 |
|---|---|
| Markdown 预览 | 当前排版正文的可见文字，定位到对应显示文本；不搜索隐藏语法、链接 URL 或 HTML 属性 |
| Markdown 原文 | 原始文本，包含 Markdown 标记 |
| 普通文本/代码/日志 | 全部已读取文本，保留行与字符偏移 |
| diff 预览 | 完整解析模型中的文件头、变更块头、增删/上下文文字；不靠可见 DOM 计算全集 |
| diff 原文 | 原 diff/patch 文本，包含元数据与前缀 |
| macOS PDFKit PDF | 搜索可提取文字，使用 PDFSelection 高亮并跨页定位 |
| 图片/媒体/Office/其他系统预览 | 显示该预览暂不支持内容查找，保留打开原文件入口 |
| Windows/Linux PDF | 本轮沿用现有预览能力边界，显示明确说明和原文件入口 |

搜索当前显示的完整模式数据；diff 预览不把折叠或不显示的原文元数据混进计数。
跨格式的排版空白、PDF 阅读顺序或跨页连续文本，依各显示引擎的实际文字结构处理，
不承诺 OCR、跨页拼接或语义搜索。混合文字/扫描页面的 PDF 只搜索可提取文字。

| 状态 | 搜索条反馈 |
|---|---|
| 空查询 | 显示范围与输入提示，计数留空 |
| 支持搜索、确认没有命中 | `0/0`，轻量无结果状态 |
| 附件读取/文档准备中 | 「加载中」，不显示最终 0/0 |
| PDF 正在搜索 | 「搜索中」，最终计数完成后可循环导航 |
| PDF 未检测到可提取文字 | 「未检测到可搜索文字」及「打开原文件」 |
| 系统预览/图片等不支持 | 「此预览暂不支持内容查找」及「打开原文件」 |
| 读取失败、资源超限或搜索失败 | 明确原因及「打开原文件」；不冒充零结果 |

不支持时保留已有关键词供下一附件使用，导航/Aa 不可用；不自动外开原文件，
不自动转换范围。PDF 仅在确认缺少可搜索文字后给出对应说明，普通查询无命中不等于扫描件。
OCR 和 Office 内容解析不纳入首版。

## 7. 实现方案

复用现有查找控件、匹配与高亮工具，引入一个请求级查找控制器，避免左右区各维护一套
独立的键盘处理和开放状态。

```text
DOM 区域操作 / 原生附件操作
             ↓
请求级 FindController（范围、查询、Aa、当前命中、生命周期）
             ↓
提问 adapter / Markdown・文本 adapter / 虚拟 diff adapter / PDFKit adapter
             ↓
同一 FindBar：在当前目标区域标题栏下挂载
```

- 控制器保存 `scope`、`lastInteractionRegion`、`query`、`caseSensitive`、`currentMatch`、
  `status` 和取消代次；每条请求独立，不写入设置或全局持久状态。
- 现有 `usePopupFind` 的提问索引、跨题 reveal 和被动重画继续由提问 adapter 承担。
  `FindBar` 复用请求级状态和动作，`PopupNavbar` 不再拥有唯一固定入口。
- 文本类 adapter 使用现有有界读取结果；搜索原文或排版文字与高亮的偏移模型保持一致。
  查询只作为字符串处理，高亮不经 HTML 拼接，不重新读取 diff 内部路径。
- diff 全集从解析模型扫描，保存行号/字符偏移。跳转先设置虚拟列表 scrollTop，再等待目标行
  挂载并高亮；水平长行也要露出当前命中。屏幕外命中计入全集，用户滚动只更新可见高亮。
- PDFKit adapter 调用可取消的异步查找，保留原生 PDFSelection，不把 PDF 全文搬进前端。
  搜索完成前显示进行中，完成后才使用最终计数与循环导航。一个查询仅允许一次初始自动定位，
  后续命中通知只更新结果，不能反复抢滚动。
- 原生事件桥补齐 ⌘F、⌘G、⌘⇧G 及准确修饰键和来源范围；既有 Esc/发送/取消保持路由。
  在原生视图接到查找时先移交 WebView 的原生 first responder，再聚焦 HTML 输入。
  附件点击/滚动/焦点来源须通过公开 AppKit 事件与视图归属识别，不窥探系统预览的私有正文。
- 命令与异步回执显式绑定 request ID、附件索引、加载/查询代次、阅读模式。关闭、切请求、
  切附件、改查询或终态都取消旧工作，丢弃迟到事件。恢复请求时只重建有效高亮，不执行旧导航。
- PDF 的每次查询使用独立搜索文档与 delegate，复用展示文档加载时的有界数据快照；
  将搜索命中的页内字符范围映射回展示文档。取消后的旧通知不能被标记为新查询结果，
  原文件后续变化也不会让搜索内容偏离当前显示内容。
- 搜索不放宽现有文件、文本、图片或缓存预算。文本类扫描是否需要任务分片/去抖由边界样本
  验证确定，保持主区输入响应；导航不额外去抖。

Office 使用的 QLPreviewView 在本机公开 SDK 中没有与 PDFKit 对等的全文命中/定位接口。
基于公开 API 检查，本方案不承诺通过系统预览扩展实现统一 Office 搜索，也不访问私有子视图。
后续若需要 Office 窗口内全文查找，另行确定内容解析和定位方案。

技术依据：Apple 的 [PDF 异步搜索](https://developer.apple.com/documentation/pdfkit/pdfdocument/beginfindstring(_:withoptions:))
提供开始、命中和结束通知；[PDF 选择与高亮](https://developer.apple.com/documentation/pdfkit/document-interactions)
提供多命中高亮、当前选择与滚动定位；[Quick Look UI](https://developer.apple.com/documentation/QuickLookUI)
负责系统格式预览。上述 API 能力已对照本机 Xcode SDK；原生回归脚本已验证取消竞态与焦点交接。

## 8. 实施顺序与验收

实现按依赖顺序推进，最终交付覆盖已确认的完整首版范围：

1. 提问查找适配现有行为，请求级状态与区域路由，目标区域搜索条和附件放大镜。
2. Markdown、文本、原文模式与虚拟 diff 的完整索引/高亮/定位。
3. macOS 原生输入桥、PDF 异步搜索与能力/错误状态。
4. 安装正式代码并通过新安装的 AskHuman 验收；平台证据分别记录。

关键验收场景：

- 同一个窗口中交替阅读附件、编辑答案、搜索提问；范围显示和实际目标一致，草稿/选区不丢。
- 只打开一条搜索条，切范围清除另一范围高亮，计数不混合两个范围。
- Markdown 的渲染/原文各搜当前模式；切模式、重渲染、缩放不把视口拉回旧命中。
- 长 diff 的首屏外、最后一行、长行命中均可定位；全集计数与挂载行数无关。
- PDF 多页大小写、上下条、原生焦点 ⌘F/⌘⇧G、搜索中改查询、切附件和关闭均正确。
- 扫描/混合 PDF、加密 PDF 回退到 Quick Look、Office、图片、加载失败和超限均有准确反馈。
- 快速切附件时关键词保留，只有当前附件的有效结果能定位；切请求再返回恢复且不自动滚动。
- 收起附件结束附件搜索；提问搜索不受收起影响。搜索输入 Enter 不误发送，Esc 不取消提问。
- 最窄有效区域、两行搜索条、深浅主题、中文输入法、键盘导航、可访问名称和计数播报可用。
- 原生 PDF 正文避让搜索条；展开/收起、分隔线和外缘缩放保持当前页面位置与缩放。
- 文本类查找在 macOS/Windows/Linux 使用相同语义，PDF 本轮能力按平台明确区分。

## 9. 实现与验证记录（2026-10-09）

- `usePopupFind.ts` 管理每请求的范围、关键词、区域交互记录和生命周期；
  `FindBar.vue` 在目标区域标题栏下挂载，跨区域重新挂载时保持输入引用和焦点。
- `useAttachmentFind.ts` 适配 Markdown/文本 DOM、完整 diff 模型和原生结果；
  `attachmentFind.ts` 共享 diff 行模型与匹配偏移，虚拟行通过安全文本片段绘制高亮。
- `popup_preview_find` 命令和 macOS Rust/Swift 桥绑定请求、附件和查询代次，验证原生许可；
  PDF 每次查询单独取消，输入去抖 100ms。原生匹配上限为 50,000，超限明确提示；
