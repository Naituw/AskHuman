## 1. 背景与目标

现状有四个缺口：

- **iOS 选不了待办**：弹窗里可以勾选项目待办并入回答，手机上不行；手机唯一能碰到待办的地方是 What's next 里预先塞进去的那几条，而且列表常被截断（Mac 端为了弹窗与 IM 卡片把待办选项限制在 10 个名额内）。
- **没法告诉 Agent「这个会话别再用 AskHuman 了」**：想停用只能在对话里另说；Agent 再调用时也没有即时的提示。
- **没有「我走了」的开关**：人离开电脑时，Agent 的每一次提问都会挂在那里等，卡住整轮工作；人又不想为此停用 AskHuman，因为真卡住时仍希望被找到。
- **没有快捷回复**：「继续」「按你的判断来」这类高频回复每次都要手打。

目标：四块能力，共用一套 Daemon 内的「模式引擎」，弹窗、Mac 各承载面与 iPhone 都是它的入口：

1. **iOS 待办（P1）**：手机上像弹窗一样选项目待办；What's next 看到完整队列。
2. **离开模式 / 本会话不再使用 AskHuman（P2）**：Agent 的提问与 whats-next 被自动回复，真卡住或做完才带 `--escalate "理由"` 来找人；会话可以单独停用。
3. **快捷回复（P3）**：可编辑的预设一键回复。
4. **CLI / IM 命令（P4，可选）**。

**非目标**：

- 不按时长或到点自动结束离开（用户定：只能手动结束）；不做「锁屏 / 合盖自动进入离开」。
- 不拦截 Stop 确认、权限审批、出错卡（它们由 Hook 触发，Agent 控制不了，见 D5）。
- 手机上不编辑快捷回复、不删除待办。
- 引导语不写细则：不教 Agent「有推荐就用推荐」，也不列「破坏性操作不要做」之类（D16）。
- 本期不做 Live Activity（锁屏 / 灵动岛）、「离开超过 N 小时提醒推送」、Windows / Linux 的桌面胶囊（§9）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 离开模式（away） | 人不在，Agent 的普通提问与 whats-next 被 Daemon 直接自动回复，不弹窗、不推送 |
| 不再使用（mute） | 用户在某个会话里关掉 AskHuman：该会话的提问与 whats-next 即时回提示、Stop 确认静音。只有会话级 |
| 范围 | 一次设置作用的对象：「所有 Agent」（全局）或「仅此会话」 |
| 升级提问 | 带 `--escalate "理由"`（CLI 参数；MCP 为 `escalate: "理由"`）的提问或 whats-next，或被防呆放行的第 4 次提问；离开模式下照常送达 |
| 自动回复 | Daemon 在建请求之前直接回给 Agent 的一段文字（`[status]` 开头）；不弹窗、不推送，但进历史 |
| 引导语 | 自动回复里的文字，三段，见 §4.1 |
| 会话键 | `sid:{agent_session_id}`，拿不到时退到 `mcp:{mcp_instance_id}`（`daemon/ask_dedup.rs::session_key`，与重复提问收敛同一个） |
| 预设 | 快捷回复里可编辑的一整句文字 |
| 指令 | 「离开模式」「不再使用 AskHuman」两条固定的特殊回复，不可编辑 |
| 待发标签 | 弹窗 / 手机里选了指令后，输入区上方出现的一条；按发送才生效，× 可撤销 |

## 5. 实现要点

### 5.1 模式引擎（Daemon，Rust）

- **状态**：`AwayState { global: Option<{since, note}>, sessions: 会话键 → {Away{since, note} | Mute{since} | Normal}, 计数 }`，Daemon 独占写入、原子落盘到 `~/.askhuman/state/`（与 `failure-cards.json` 同类：Daemon 自持，换新保留）。纯函数 `verdict(任务, 状态) -> Deliver | AutoReply{种类, 文本} | Escalated` 单独成模块，便于单测。
- **插入点**：`daemon/runtime/mod.rs::handle_submit` 里，在刷新 Agent 会话活动（`state.agents.upsert_working / touch_activity`）之后、重复提问收敛（`registry.try_attach` / 重放缓存）之前。自动回复走与重放同一条输出路径：`ServerMsg::Accepted` + `ServerMsg::Final { stdout, exit_code }`（退出码 0，不是错误）；同时写历史（D13）与计数，不触发 `ask-received`、不进重放缓存（N4）。会话键沿用 `ask_dedup::session_key`，拿不到会话键时只看全局（N5）。
- **输出格式**：自动回复复用取消 / 重放已有的状态载体（`cli/output.rs` 的 `[status]` 区块；JSON 输出模式下写入 `status` 字段，同 `ask_dedup::mark_replayed`），另加一个可选字段标明是自动回复的种类，让 Claude 内置提问钩子能把它认出来；MCP 路径原样透传文本区块（`mcp/ask.rs`），Agent 看到的就是引导语。
- **Stop 确认**：不进引擎拦截（D5）。「不再使用」时的静音放在 Stop hook 现有的抑制通路里：`agents/stop.rs::confirmation_suppression_reason`（已用于 Codex 委派运行的静默，命中时写 `log_guard_audit` 并按「没接入 AskHuman」放行），新增一个「会话已静音」的原因。注意 `TaskRequest::popup_kind()` 会把 `!record_history` 的内部卡片（出错卡等）也归为 `Stop`，所以识别 Stop 确认要用 `task.stop_confirmation`，不能用 `popup_kind()`，否则会误把出错卡静音。权限审批走 `ClientMsg::SubmitConfirm`（`ConfirmTask`），不进引擎。
- **Hook 怎么读模式**：Stop hook 与 Claude 内置提问钩子是各自独立的短命进程；它们只读状态文件（原子替换写入，读到的永远是完整版本），不走 IPC，Daemon 没起来也读得到；写入仍只有 Daemon（D38）。
- **`--escalate "理由"`**：`cli/args.rs` 解析，经新增可选 `TaskRequest.escalationReason` 送到 Daemon；旧 `escalate: bool` 只供兼容提示。MCP 的 `ask` / `whats_next` 对外提供字符串、兼容解码旧布尔值。理由由 Daemon 在判定后、去重前加入共享正文，所有渠道与历史一致；已有升级标记与提示条保留。详细规则见[离开模式修订 §7](away-completion-guidance.md#7-输入兼容展示与兜底)。
- **防呆**：每个会话键一个「连续未升级的被拦次数 + 首次时间」，10 分钟窗口；第 4 次放行并前置「系统兜底放行」，注明 Agent 未提供理由；任何一次真实回答或窗口过期都清零。
- **Claude 内置提问接管**（`ask_question.rs`，PreToolUse 钩子）：它提交的是一个普通的 `TaskRequest`（带会话 id、`record_history: true`），所以离开模式下由引擎拦截，钩子收到带自动回复标记的 JSON 后，`decide()` 返回 `deny`，把引导语放进 `permissionDecisionReason`（Claude 会看到它）；「不再使用」时钩子在 `run_inner` 开头读状态文件，命中就什么都不写、让 Claude 用它原生的选择器（与该钩子「任何让人无法作答的失败都不输出」的既有做法一致）。
- **插话**：解除「不再使用」时调用 `InterjectQueue::append(会话, 文本, [], None)`；Grok 不通知（D15）。
- **配置**：`general` 下新增 `quickReplies`（缺省 = 出厂默认）与 `away`（`capsule`、`welcomeBack`、`pushAfterSecs`，默认 `true`、`true`、`60`）；出厂预设与引导语文本放 `prompts.rs` / i18n。

### 5.2 弹窗（Vue）

- 页脚新增「快捷回复」按钮与菜单组件、待发条、升级提示条。⌘K / Ctrl+K 加进 `src/lib/shortcut.ts::shortcutConflict()` 的弹窗保留键（设置里录语音快捷键时提示冲突，同 ⌘T 的做法）；菜单打开期间对键盘是模态的（除 ⌘W 外其余弹窗快捷键暂停，Esc 只关菜单，做法同 `todo-quick-add.md` D7）；待办浮层打开时 ⌘K 不响应，反之亦然。按钮与菜单只出现在提问弹窗（普通提问与 What's next），不出现在 Stop 确认卡、权限审批与出错卡（N10）。
- 预设：前端把未作答的题填成预设文字，走与普通回答同一条提交路径，输出格式不变。指令：提交载荷新增可选的 `directive { kind, scope, note }`，Daemon 在记录回答后应用并追加引导语（N3）。
- `popup_init` 带上预设列表与升级标记；文案进 i18n（zh / en）。原型即 `src/prototype/popup-reply-menu.html`。

### 5.3 Mac GUI Host

- **桌面胶囊**（仅 macOS）：GUI Host 里新增一个窗口类型，非激活面板、层级高于普通窗口、加入所有桌面、不抢焦点；位置存 `state/`（不是配置）；点击 / 悬停展开成卡。「欢迎回来」由空闲采样触发（`crate::idle::secs_since_last_input`，空闲满 5 分钟后的第一次操作，N7），同一张卡换标题与按钮。

- **控制台**：全局提示条、侧栏小图标、详情页「AskHuman ⌄」下拉（Agent 快照里增加每会话的可选 `mode`）。
- **设置**：「通用」页两张卡（`SettingsView.vue`）。原型：`mac-away.html`、`mac-away-board.html`、`console-away.html`、`settings-away.html`。

### 5.4 iOS

- 不与「在请求里直接添加待办」（`todo-quick-add.md`，请求页 ⋯ 菜单的「添加待办…」）冲突：那是新增，本需求是选择。

## 6. 边界、风险与已知限制

- **忘记关离开**：靠强可见（手机青绿色条、Mac 胶囊、托盘月亮）与「欢迎回来」；不做时长自动结束（D10）。
- **Agent 不认识 `--escalate`**（旧规则、MCP 客户端丢参数）：靠引导语自带说明与 D9 防呆放行。
- **Agent 在离开期间自作主张**：引导语只说「自己判断」，不写细则，是用户的明确选择（D16）；每条自动回复都进历史，回来后可复核（D13）。
- **自动回复与重复提问收敛**：自动回复不进重放缓存（N4），否则被拦的提问会在恢复正常后被「重放」成一个不存在的人给的答案。
- **多 Mac**：离开状态是每台 Mac 自己的；手机一次下发到多台在线 Mac，离线的不补开（D34）。Mac 互通（弹窗网，`docs/specs/mac-mesh.md`）落地后是否跨 Mac 共享离开状态另议，本期各 Mac 独立。
- **没有会话键的调用**：只受全局模式管（N5）。
- **Windows / Linux**：没有空闲检测，所以没有「欢迎回来」；桌面胶囊先不做，靠托盘变色、弹窗提示与控制台横幅（D37）。
- **iOS 26 以前**：没有液态玻璃，常驻条与 What's next 页的按钮降级为材质与描边按钮，位置不变（D31）。
- **老 Mac**：没有 `away` 能力位时，手机隐藏相关入口或提示需要更新；`todoIds` 对老 Mac 是被忽略的多余字段，选了的待办会被悄悄丢掉，所以手机在没有对应能力位（暂名 `answer_todos`，与 `caps.todos` 一起判断）的 Mac 上不显示「待办」卡。
- **手机选中的待办在提交前已被 Mac 删除或完成**：网关以 `invalid`（`todo gone`）拒收整条回答，手机重新取一次列表后再发（与未知选项下标同一处理）；这是实现默认，不是用户定的。
