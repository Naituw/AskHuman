# 需求：消息附注——在消息正文里选字写附注，随回答一起发给 Agent

> 状态：**设计已于 2026-11-07 与用户逐项对齐（四轮 AskHuman 问答，选项与原话见 §10），计划已于同日获用户批准（审批轮的回答与据此的改动见 §11 反馈意见）**；§3.7 列了用户没有单独确认过的默认做法，不同意可整条否决。
> 关联计划：`docs/plans/message-annotations.md`。
> 前置资料：`docs/specs/ios-web-markdown.md`（手机上 Message 的网页渲染；U2「题干保持原生」在直接提问这一形态下被本需求改写）、`docs/specs/ios-answer-flow.md`（回答页底栏 G10–G13 的渐进降级）、`docs/specs/special-replies.md`（回答里的可选字段 `directive` / `todoIds`、快捷回复菜单、`quick_reply` 的判定）、`docs/specs/strict-choice-and-structured-output.md`（输出契约 D6 / D7）、`docs/specs/todo-whats-next.md`（What's next 的固定问题）、`docs/specs/popup-request-inbox.md`（共享作答窗口）、`docs/specs/duplicate-ask-coalescing.md`（重复提问重放）。

## 1. 背景与目标

Agent 的消息（Message）常常是一大段分析、方案或完成报告。读的时候，对其中某一句有疑问，现在只能先记在脑子里，读完再到回答框里重新写一遍「第二点里说的……」：慢，而且 Agent 看不出指的是哪一句。

目标：在弹窗和 iOS 上，选中 Message 里的文字就能就地写一条附注；提交回答时，附注连同被选中的原文一起交给 Agent。

**非目标**：

- 不做附注之间的讨论、也不做 Agent 逐条回复附注；附注不是回答，不计入「已回答」（D4）。
- 多题提问、以及题目与 Message 并存时，题干不可附注，用户直接在回答里写（D2）；选项文字、附件、代码块的复制按钮、Mermaid 图里的文字也不可附注。
- 确认卡（权限 / Stop / 出错）、`--select-only`、IM 渠道不做（D3）。
- 不新增 CLI / MCP 参数；CLI help 与 MCP 描述只多一句（D9）。
- 手机上非 Markdown 消息与原生降级渲染不做附注（N9）；不在 Mac 与手机之间同步附注草稿。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 附注（annotation） | 用户在正文里选中的一段原文 + 自己写的一段话。英文界面叫 Annotation，输出区块叫 `[user_annotations]` |
| 原文（quote） | 被选中的那段文字，随附注一起交给 Agent |
| 可附注的文字 | Message 的文字；没有 Message 且恰好一个问题时，该问题的题干（D2） |
| 直接提问 | 没有 Message、只有一个问题的提问（带不带预选项都算）。命令行里 `AskHuman "长文" -o A -o B` 就是这种：归一化时第一个参数被提升为唯一的问题、Message 清空（`cli/args.rs`） |
| 高亮 | 正文里已有附注的文字：紫色下划线底色 + 编号小圆点 |
| 附注清单 | 页脚（弹窗）或底栏（手机）的「附注 N」打开的列表 |
| 附注根 | 引擎在其中取选区、做高亮的那块文字：弹窗里是 Message 正文或直接提问的题干，手机里是上方的 Message 网页 |

## 3. 决策记录

「第 N 轮」指第 N 轮 AskHuman 问答，原话与选项见 §10；「第 2 轮默认 #k」指第 2 轮 Q6 里用户批准的十条默认中的第 k 条（原文见 §10）。

### 3.1 范围与语义

| 编号 | 决策项 | 结论 | 理由 / 否决后的代价 |
|---|---|---|---|
| D1 | 功能 | 弹窗和 iOS 上，选中 Message 正文的文字 → 直接写附注 → 提交回答时，附注（带被选原文）随回答发给 Agent | 用户提出（原话见 §10）。读正文时的疑问当场写下，不用读完再凭记忆重述 |
| D2 | 可附注的文字 | ① Message 的文字；② 没有 Message 且恰好一个问题（带不带预选项都算）时，这个问题的题干。多题提问、或题目与 Message 并存时，题干不可附注，用户直接在回答里写 | 用户定（第 1 轮 Q1 提出「Message 和题干都应该可以」；第 3 轮 Q1 澄清「只在大段文字里要加……多题直接在回复里写……唯一可能对题干加附注的是 Agent 没发 Message、只给一个提问和一些预选项」；第 4 轮 Q1「可以，就这样」） |
| D3 | 不支持的地方 | IM 渠道；权限 / Stop / 出错确认卡（它们返回的是「选了哪个动作」，没有回答正文这条通路）；`--select-only` 严格选择（本来就禁止自由文本） | 第 1 轮开场事实 #4 列出，用户没有异议；第 2 轮默认 #10 再次确认；第 4 轮 Q1 的范围里重申 |
| D4 | 附注不是回答 | 不占「已回答 N/M」；只写了附注、其余什么都没填也能提交，**不加任何提示**，不改变其余答案的含义，由 Agent 自行判断 | 用户定（第 1 轮 Q3「能提交，但不加提示，让 Agent 自己判断」）；第 3 轮列为共同默认，用户未反对 |
| D5 | What's next | 在 What's next 里选了「结束本轮」又写了附注：不批准结束，只把附注交给 Agent，由它回应后再次 `--whats-next` | 用户定（第 2 轮 Q4）。沿用「结束＋文字＝继续」：有话说就是还没完；误结束的代价比多问一轮大 |
| D6 | 取消、草稿与提交途径 | 弹窗点取消 = 丢弃附注；iOS 附注随草稿保存，离开页面再回来还在；任何提交方式（发送、快捷回复、挑待办……）都带上当时已写的附注 | 第 3 轮列为两端共同默认，用户未反对 |

### 3.2 Agent 看到的输出

| 编号 | 决策项 | 结论 | 理由 / 否决后的代价 |
|---|---|---|---|
| D7 | 区块 | 新增 `[user_annotations]`（标记恒英文、不本地化，同 strict-choice 的 D6）：每条 = 一行 `> 原文` + 附注正文，条与条之间空一行；文本区块里原文超过 300 字时中间截成「…」。位置：单题放在其余区块之后；多题放在最后一题之后，用 `---` 隔开、不带 `# Qn`；只有附注时只输出这个区块（不是「未作答」，也不是「取消」）。示例见 §4.1 | 用户定（第 1 轮 Q2 选独立区块；第 2 轮 Q5 选引用块格式）；位置与「只有附注」的写法是第 2 轮示意里写明的，用户选了该格式 |

| D9 | 说明保持简洁 | `--agent-help` 的结果区块清单里只多一行，MCP 工具描述只多一句；不新增参数，不展开讲用法 | 用户定（第 1 轮 Q2：「这个附注应该不是特别常用，所以你不要把那个 CLI help 或者是 MCP 的 description 写得特别复杂，保持简洁」；第 2 轮回应为各只加一行） |

### 3.6 协议与引擎（按仓库既有规则做出，不是用户逐项确认的）

| 编号 | 决策项 | 结论 | 理由 |
|---|---|---|---|
| E1 | 可选字段，不抬协议号 | 新增 `UserAnnotation { quote, note }`。`ChannelResult.annotations`、IPC `ClientMsg::Answer.annotations`、弹窗提交 `PopupSubmission.annotations`、`HistoryEntry.annotations`、手机 `AnswerSubmit.annotations`、手机本地历史条目的 `annotations` 都是「缺省为空、为空不序列化」的可选字段；`AskRequest.annotatable` 与手机 `AskView.annotatable` 缺省为 false、为 false 不序列化。`PROTOCOL_VERSION` 与 iOS `PROTO` 都不动 | `docs/overview.md`「IPC 协议号」：带 `#[serde(default)]` 的可选字段不 +1；老端缺字段按空 / false 读，同一个协议号内保持互通 |
| E2 | 能力位与请求级开关 | `Caps.annotations`（D24）说明这台 Mac 收附注；`annotatable`（请求级）说明这条提问可以带附注：= Agent 自己的提问（CLI、MCP、Claude 内置提问接管；与快捷回复菜单同一个判定 `away::is_agent_ask`）且不是严格选择。手机两者都满足才出现入口，弹窗只看 `annotatable` | 出错卡 / 复查卡、Codex 原生问题与开发中继不是 Agent 自己的提问，它们的回答不会交给 Agent 读（N2） |
| E3 | 汇聚点清洗 | `Coordinator::try_submit`（所有渠道的回答在这里决出胜负、存下结果）一处清洗所有来源的附注：取消、或请求不可附注时整体丢弃；去掉空原文 / 空附注；最多 20 条；附注 ≤ 2000 字；原文换行与连续空白压成一个空格并 ≤ 2000 字（中间截断）。文本区块里的 300 字缩短在渲染时做 | 弹窗、手机、将来的渠道都只经过这一处；任何来源的越界载荷在这里被收口，渲染、历史、`--show-last` 看到的都是清洗后的同一份 |
| E4 | 引擎 | 选区 → 偏移 → 高亮 → 重新定位的逻辑只写一份纯 TypeScript 模块（`src/lib/annotations.ts`）：弹窗直接用，手机网页打成一份脚本（`annotations.js`）随 App 分发。DOM 是唯一事实来源：附注根下「未被跳过的文本节点依次拼接」就是文字坐标系 | 两端行为一致，一份代码一套测试 |

### 3.7 我加的默认（用户没有单独确认过）

| 编号 | 默认做法 | 理由 |
|---|---|---|
| N1 | What's next 的固定问句不挪、不可附注（iOS 不把它搬进 Message 区，弹窗保持原样）；它的 Message（完成报告）照常可以 | 固定问句不是 Agent 写的话，没有可批注的内容；What's next 屏幕是另一套版面 |
| N2 | 出错卡 / 复查卡、Codex 原生问题与开发中继不开放附注（`annotatable` 为 false） | 它们的回答由 Daemon 自己的逻辑或原生接口消费，附注会被悄悄丢掉；用户只说过确认卡不做，这几类是我按同一道理补的 |
| N3 | 附注按在正文里的位置编号并输出（最靠前 = 1），新增 / 删除后重排；找不到位置的排在最后 | Agent 读输出的顺序和读正文的顺序一致 |
| N4 | 原文取所见文字：渲染后的正文，不含 Markdown 符号；换行与连续空白压成一个空格；「查看源码」下选的是源码文字 | 引文要一行一条；想精确引源码就切到源码视图 |
| N5 | 键盘（弹窗）：清单里 ↑↓ 移动、Enter 定位到原文（同点击）、E 编辑、Delete / Backspace 删除、Esc 关闭；清单与浮层对弹窗其余快捷键模态（做法同快捷回复菜单）；不新增全局快捷键 | 避免和已有快捷键冲突；Enter 与点击一致，编辑另有专用键 |
| N6 | JSON 不带 `question_index` | 题干只在「单题且无 Message」时可附注，指向永远唯一；第 2 轮示意里的这个字段不再需要 |
| N7 | 选区必须完全落在附注根里才出现入口；空白选区、跨出正文的选区不出现；选区中间夹着复制按钮或 Mermaid 图时，它们的文字不算原文 | 避免引到不属于正文的文字 |
| N8 | 未发送的附注算「有内容」：共享窗口里的未答标记、手机的草稿标记亮起；但不计入「已回答」，也不影响发送按钮对回答的要求（D4） | D15 的延伸 |
| N9 | iOS 的非 Markdown 消息、原生降级渲染（网页没起来或超时）不提供附注入口（菜单项与圆钮不出现）；草稿里已有的附注仍保留，仍能在清单里看到并随回答发出 | 没有网页引擎就没有选区；已写的话不能丢 |
| N10 | Claude 内置提问（AskUserQuestion）的接管：它是 Agent 自己的提问，单题时可附注。接管把答案转成 Claude 的 `answers` 字典，附注并进该题答案文字（后接 `[user_annotations]` 区块）；只有附注时放进 `deny` 的理由里 | 不能让附注在这条路径上无声消失 |
| N11 | 控制台对话记录（`agents/transcript_full.rs`）认识 `[user_annotations]`：附注行不再被并进 `[user_input]`，作为回答文字的第三段（选项、输入之后）原样显示（引用块 + 附注），不做独立卡片（§9）；多题时跟在最后一题的回答之后 | 否则附注行会被误当成用户输入；做成独立卡片是后置项 |
| N12 | 重复提问收敛重放的是第一次渲染好的输出，附注已在里面，不另做处理 | 无需处理 |
| N13 | Daemon 对附注内容原样转交、不解释；Agent 读到的和 `[user_input]` 一样是不可信的人类输入 | 与现有输入同等对待 |

## 4. 用户视角

### 4.1 Agent 看到的文字

单题，选了选项、写了回复、加了三条附注：

```
[selected_options]
方案 2：改用 grid 统一

[user_input]
先按这个做，细节看附注

[user_annotations]
> 需要同时调整三处表单
是哪三处？把文件名列一下，我想先看影响面。

> Chrome 与 Firefox 下表现一致
具体是哪两个版本？

> 回归测试也已补充
补在哪个文件里？覆盖 Safari 15 了吗？
```

只写了附注（什么都没选、没写）——只有这个区块，没有「未作答」「取消」之类的状态：

```
[user_annotations]
> 需要同时调整三处表单
是哪三处？把文件名列一下，我想先看影响面。
```

三题（Message 上有附注）：区块在最后一题之后，用 `---` 隔开，不带 `# Qn`：

```
# Q1
[selected_options]
独立会话表

---

# Q2
[status]
用户未回答此问题

---

[user_annotations]
> 线上还有约 1.2 万条旧会话
这些里面还在活跃的有多少？
```

`--output json`（只列有变化的部分；没有附注时没有这个键）：

```json
{
  "action": "answer",
  "channel": "popup",
  "answers": [ { "question_index": 0, "selected_options": ["方案 2：改用 grid 统一"], "selected_indices": [1] } ],
  "user_annotations": [
    { "quote": "需要同时调整三处表单", "note": "是哪三处？把文件名列一下，我想先看影响面。" }

}
```

What's next（只有文本输出，没有 JSON）：「派活」「建议」都是原输出（含 `[files]`）之后追加区块；选了「结束本轮」或什么都没选、又写了附注，**不批准结束**——输出里不再有「结束本轮」那行 `[selected_options]`，只有 `[files]`（如有）和附注区块（D5）；取消从不带附注。

[user_annotations]  The user's notes on passages of your message: a quoted passage (> …) followed by the note

## 5. 实现要点

细节与文件清单见计划，这里只写会影响判断的几条。

### 5.1 Daemon 与 CLI（Rust）

- 附注只在一处汇聚清洗（`Coordinator::try_submit`，E3），之后分头去：渲染（文本区块 / JSON / What's next）、历史条目（`HistoryEntry.annotations`）、`--show-last`、重复提问重放（重放的是渲染好的文本，不用管）。
- 渲染的位置规则见 D7 与 §4.1：`render_result` / `render_whats_next` 在已渲染的回答上追加区块，只有附注时替换掉「未作答 / 取消 / 确认继续」状态，做法仿 `append_status`（`cli/output.rs`）；JSON 在顶层加字段；取消不带附注。
- 所有读取回答的地方都要认识新区块：`cli/help.rs`（`result_field_lines` 与 `agent_help_markers_match_output`）、`mcp/ask.rs`（描述一句；`[files]` 区块以空行结束，新区块不会被当成路径）、`agents/transcript_full.rs`（N11）、Claude 内置提问接管 `ask_question.rs`（N10）、`show_last.rs`。
- `ChannelResult` 与 `ClientMsg::Answer` 的构造点分散在 daemon、iOS 网关、待办、渠道会话、`cli/output.rs` 与开发中继等十余处，加字段后按编译器的提示逐个补 `annotations: Vec::new()`（现有的 `directive` 先例同理）。

### 5.2 弹窗（Vue）

- 引擎（E4）：附注根下取「未被跳过的文本节点依次拼接」为坐标系，块与块之间（段落、列表项、表格单元格、`<br>`）补一个虚拟换行；**跳过的是静态清单** `script, style, textarea, input, button, svg, iframe, .mermaid-block`，不沿用「页内查找」那套随 Mermaid 状态变化的动态跳过（`[data-find-skip]` / `[data-find-atomic]`）：Mermaid 图渲染完成、切换「显示源码」时 DOM 会变，坐标系必须不跟着变，所以整个 `.mermaid-block`（源码与图）从头到尾都不计入。选区 → `{start, end, quote}`，`quote` 取自这套坐标系的文字，空白压成一个空格、去首尾空白；高亮用 `<mark data-annotation-id>` 包裹，编号小圆点用 CSS 伪元素（`::after`，内容取自 mark 上的编号属性）画，不引入文本节点，所以不改变坐标系；先清掉再重绘，幂等；重绘后按 `{start, end, quote}` 校验，对不上就在文中就近找原文，再找不到标「找不到原文位置」（D16）。
- 与「页内查找」共存：查找的 `<mark data-popup-find>` 与附注的 `<mark data-annotation>` 互不清除；Markdown 重新渲染（深浅色、Mermaid 异步完成）会换掉 DOM，所以每次 `markdown-content-updated` 之后重新应用高亮。
- 状态在组合式函数 `useAnnotations` 里（每个请求一份，收件箱里每个请求一个 `usePopupCore` 实例，自然隔离），键盘模态的做法同 `useQuickReply` / `useTodoPopover`；提交时随 `PopupSubmission.annotations` 交给 Daemon。

### 5.3 iOS

- 上方的 Message 网页（`WebMarkdownView`）新增附注能力：页面里引擎取选区，去抖后用 `selection` 消息通知原生；`WKWebView` 子类在 `buildMenu(with:)` 里按最新选区状态插入「添加附注」或「编辑附注」；点高亮用 `noteTap` 消息通知原生。`render.js` 每次重绘都会替换 `#content`，所以每次重绘后重新应用高亮。
- 附注存在 `AnswerComposer` 里并随草稿保存（`DraftAnnotation` 带偏移，用于重新高亮；线上只发 `{quote, note}`）。
- 直接提问：`MessageCard` 显示题干，`QuestionCard` 不再显示题干；`ReadingTracker` 等「网页排版完成」的逻辑照旧。

## 6. 边界、风险与已知限制

- **Agent 不认识 `[user_annotations]`**：靠区块自解释（引用块 + 附注）与 help 里的一行；不教用法是用户的明确选择（D9）。
- **选区跨块**：允许（跨段落、列表项）；原文把块间换行压成一个空格（N4）。
- **同一句话出现多次**：用偏移定位并校验原文；对不上才按原文就近查找，仍找不到就不高亮、清单里标出（D16）。
- **iOS 的系统菜单加项**依赖 `buildMenu(with:)` 对 `WKWebView` 生效：开工前先在模拟器上验证（iOS 18.5、26.2、27.0、27.1；iOS 17 不验，D17），若某一版本不行，停下来问用户，不悄悄换成别的入口。
- **iOS 窄屏**：宽度是估算，实测不达标就回来商量（D21）。
- **直接提问多起一个网页进程**：约 36 MB、页面就绪 0.1–0.2 秒、首屏一次淡入；用户已明确接受（D19）。
- **大消息**：引擎遍历文本节点是线性的，只在渲染完成后应用一次，消息在几十 KB 内没有压力。
- **老 Mac / 老手机**：缺 `Caps.annotations` 的 Mac 不出现入口（D24）；老手机不认识 `annotatable` 与 `annotations`，只是没有这个功能。
- **Windows / Linux**：同一份 Vue 代码，修饰键差异沿用既有 `primaryModifierPressed`；需要在这两个平台各点一遍选字与清单。
