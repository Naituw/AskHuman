# 需求：iOS 作答页的选项手感与「下一题 / 发送」逻辑

> 状态：已实现（2026-10-28；Swift 包与模拟器 UI 测试通过；真机验收待用户，见 `docs/PROGRESS.md`）；
> 底栏外观（§3.4，2026-10-29）已实现，模拟器测试通过，真机待看；
> 输入栏（Agent 页的插话栏、待办页的添加栏，§3.4 G11，同日）已实现，同上
> 关联计划：`docs/plans/ios-answer-flow.md`
> 关联既有：`docs/specs/multi-question-vertical.md`（Mac 弹窗纵向多题，V1 / V2 / N1–N4）、
> `docs/specs/ios-channel.md` §6.3（作答）、`docs/overview-ios.md`（「多题表单的发送要等看过最后一题」）

## 1. 背景

用户在真机上用过作答页后提了两点（2026-10-28）：

1. **选项的手感比较怪**：选中是「渐变」出来的，显得软。要重新设计优化。
2. **「下一题 / 完成」的逻辑与弹窗不太一样**：例如看过一些题但没回答，往回滑了，再点「下一题」会把这些看过没答的题**跳过**。要重新设计优化。
3. **底栏不像原生的 Liquid Glass**（2026-10-29，一条独立的待办）：提问页底部是一整条带材质与分隔线的色带，「Liquid Glass 应该是没有那个背后的蒙层的」，要重新设计得更像原生界面。
4. **Agent 页的插话栏、待办页的添加栏也改成同样的浮动玻璃栏**（2026-10-29，上一条做完、报告后，用户从「下一步」选项里选的：「Agent 页的插话栏、待办页的底栏也改成同样的浮动玻璃栏」）。

## 2. 现状与根因

### 2.1 选项行（`OptionRow`）

`Button` + `.buttonStyle(.plain)` + 选中态用 `Image(systemName:)` 换符号、背景在 12% 强调色与灰底之间切换。
`.plain` 在按下时把整行变淡、松手再淡回，状态切换发生在这段淡入淡出里；SF Symbol 换名在有事务动画时是交叉淡入。
合起来的观感就是「选中是渐变出来的」。

### 2.2 下一题

`AnswerComposer.nextUnread` = 第一个「没读过」的题，「读过」= 题卡底部进过屏幕**或**已作答。所以：
看过 Q2、Q3 没回答 → 滑回 Q1 → 点「下一题」→ 直接去 Q4（Q2、Q3 已「读过」）。它依赖**历史**，
而用户期待的是**位置**：从我现在在的地方往下一题走。

Mac 弹窗（`usePopupCore.ts`）的做法：`goNext` = 当前题指针 +1，滚到刚好完整可见（已完整可见就不滚），
落点题整题闪一下；当前题完全在屏外（如长 Message 把 Q1 顶出屏幕）时，先把它露出来而不是越过它；
「发送」在最后一题被看到后出现（V1 / V2），此后「下一个」仍可用，直到指针到末题。

### 2.3 底栏（`SendBar`）

`safeAreaInset(edge: .bottom)` 里放一条 `.background(.bar)` + 顶部 `Divider()` 的色带，里面是左侧计数文字、右侧 `borderedProminent` 的实心按钮；「下一题」与「发送」是两个不同的 `Button`，靠 `if` 换。在 iOS 26 上，这条色带是一块带材质与分隔线的横带，把内容在它背后截成一条硬边，与系统自己的浮动玻璃栏不一致。

### 2.4 输入栏（`InterjectBar`、`TodoAddBar`）

Agent 页的插话栏与待办页的添加栏也是 `safeAreaInset(edge: .bottom)` 里一块 `.background(.bar)` 的色带（没有分隔线）。里面一排：左边一个图标按钮（插话栏是回形针的附件菜单；待办栏是「自动执行」的闪电圆圈，只在项目支持时有）、中间分组背景色的圆角矩形输入框（`axis: .vertical`，1–5 行）、右边 `arrow.up.circle.fill` 的图标按钮；排上方是附件列表与上传进度（只有插话栏），下方是字数提示（接近上限时）。「不能插话 / 不能添加」时整条是一行灰字。在 iOS 26 上也是一块带材质的横带，与提问页旧底栏同一个毛病。

## 3. 决策

### 3.1 选项行手感

| 编号 | 决策项 | 结论 |
|---|---|---|
| O1 | 总原则 | 选中是**一帧完成**的：按下立刻有反馈，抬手状态立刻翻转，没有交叉淡入、没有整行变淡 |
| O2 | 按钮样式 | 自定义 `ButtonStyle`，不用 `.plain`；按下时底色立即加深、整行轻微下压（缩放 0.985，约 0.08 秒），不改透明度 |
| O3 | 选中态 | 选中行：强调色 2 pt 描边 + 约 14% 强调色底 + 实心指示器（单选实心圆点、多选实心勾选框）；未选行：中性灰底、无描边（选中才有描边，一眼分得出；不再靠颜色渐变区分） |
| O4 | 指示器 | 自绘（圆 / 圆角方框），不再换 SF Symbol 名，避免交叉淡入；选中时内部标记以短弹簧（响应 0.22 秒）弹出（「减少动态效果」下无弹跳） |
| O5 | 触感 | 每次点按一次 `selection` 触感（用点按计数触发，单选换项时不会响两下） |
| O6 | 其它 | 最小高度 44 pt；Dynamic Type 下指示器随字号缩放；无障碍沿用 `.isSelected` 特征与标识 `option-<q>-<i>`；推荐徽标不变，仍**不预选** |

### 3.2 下一题 / 发送

| 编号 | 决策项 | 结论 |
|---|---|---|
| F1 | 「下一题」按**位置**走 | 目标 = 底部还没进入屏幕的**第一张题卡**（= 弹窗的「当前题 + 1」）。与「读过 / 答过」无关，所以不会越过任何一题。Message 很长、Q1 还在屏外时，目标就是 Q1 |
| F2 | 滚动方式 | 目标题放得下一屏：滚到刚好整题可见（贴底，留 16 pt 呼吸位）；放不下：先滚到题顶，再点一次滚到题底，之后才去下一题 |
| F3 | 落点提示 | 落点题卡整张闪一下（强调色淡底约 12%，0.8 秒淡出；「减少动态效果」下不闪），对应弹窗 `flashCard` |
| F4 | 键盘 | 点「下一题」时如果键盘开着，先收起键盘（等其动画结束）再滚动，避免带着键盘的视口算位置 |
| F5 | 「发送」何时出现 | 不变（V1 / V2）：最后一题的底部进过屏幕、或最后一题有答案（含草稿恢复），才出现；一旦出现不再收回（滚回去也不收回）。「读过」只用来管这一道闸，不再用来导航 |
| F6 | 出现「发送」之后 | 主按钮是「发送」。若屏幕下方还有没走到的题，左边多一个次要的「下一题」图标按钮（⌄），行为同 F1，对应弹窗里「发送」出现后「下一个」仍可用；已经在末尾则不显示 |
| F7 | 「仅选择」未选全 | 「发送」不可点（不变）；提示文字「每题都要选一个选项」变成可点：滚到第一道没选的题并闪一下（弹窗没有对应物，但「⌘↵ 找下一个未答题」是同一意图） |
| F8 | 单题 | 不变：只有「发送」，没有「下一题」 |
| F9 | 换页 | 每条请求独立页面、各有自己的状态（`ios-channel.md` 2026-10-27 一节）；不变 |
| F10 | 非目标 | 「上一题」按钮（手机上往回滑最自然；弹窗有是因为键盘流）；当前题高亮 / 选项角标（键盘专用）；自动聚焦输入框（会弹键盘） |
| F11 | 辅助字号下的底栏 | 系统字号进入辅助档（Accessibility sizes）时，计数文字与按钮上下排列：按钮占满整行宽，文字不再被挤成一两个字一行；普通字号仍是左文字右按钮 |

### 3.3 对应关系（弹窗 → 手机）

| 弹窗 | 手机 |
|---|---|
| 当前题指针（滚动同步 / 键盘） | 由屏幕位置推出，没有显式状态 |
| 下一个 = 指针 + 1，滚到完整可见，闪一下 | F1–F3 |
| 当前题完全在屏外先露出它 | F1 的第一题情形 |
| 发送在最后一题被看到后出现 | F5 |
| 发送出现后下一个仍可用 | F6 |
| ⌘↵ 智能前进（下一个未答题 / 未看题 / 提交） | 手机无键盘流；F7 覆盖「找未答题」 |

### 3.4 底栏外观（Liquid Glass，2026-10-29）

用户只给了一句话（「没有背后的蒙层」「更像原生界面」），具体设计由我定，没有再向他提问，可否决：

| 编号 | 决策项 | 结论 |
|---|---|---|
| G1 | 范围 | 提问页（`SendBar`）与确认页（提交栏）。Agent 页的插话栏与待办页的添加栏起初不动（没被提到）；这一节的头一版做完后，用户从「下一步」选项里选了它们，见 G11 |
| G2 | iOS 26 起：浮动，栏自己没有底 | 栏里只有控件，没有材质、没有分隔线；内容一直滚到栏的后面。可读性靠系统的**柔和滚动边缘效果**（`scrollEdgeEffectStyle(.soft, for: .bottom)` + `safeAreaBar`；导航栏下面也是这种边缘效果），而不是自己画一层。`.soft` 要显式写：自动样式在有的系统版本上是带硬边的色带 |
| G3 | 不是控件的文字放进玻璃小块 | 「Answered n/m」（连同上传进度）放进行内的一块玻璃（计数块，胶囊，与按钮同高，见 G10）；提示（可点的「每题都要选」、「已结束 / Mac 离线 / 等待 Mac 确认」）是行上方单独的一小条玻璃（圆角小的矩形，折成两行也是矩形而不是胶囊），确认页的状态行同款。小块不可点，除了会跳去未答题的那条提示。放进玻璃，是因为直接放在渐隐上，滚过来的内容会和它叠在一起读不清（三种都在模拟器上试过：「关掉边缘效果 + 纯文字」文字与滚过的选项行叠在一起；「关掉边缘效果 + 小块」小块四周漏出内容；「渐隐 + 纯文字」在辅助字号下仍会叠字；「渐隐 + 小块」读得最清，就选了它） |
| G4 | 按钮 | 主按钮 `glassProminent`（着色玻璃），次要的「下一题」图标按钮 `glass`；一栏里的玻璃放进同一个 `GlassEffectContainer`（提问页间距 8、确认页 4，都小于版面里各块的间距，所以不会融成一块） |
| G5 | 「下一题 → 发送」是**同一个按钮** | 只换文字与标识（`next-button` ↔ `send-button`）、文字交叉淡入淡出。原来是 `if` 换两个按钮，经典样式下无所谓，玻璃样式下换身份的那几帧会闪出一个空胶囊（逐帧看录屏发现的） |
| G6 | 辅助字号 | F11 不变：提示、计数块各占满一行，按钮在下面占满整行；这时不求同高（上下排的块本来就不并排） |
| G7 | iOS 17–25 | 经典栏不变：`.bar` 材质 + 顶部分隔线 + `borderedProminent` / `bordered`，只是「下一题 / 发送」也成了同一个按钮；`safeAreaInset` 照旧 |
| G8 | 实现 | `Views/Common/BottomBar.swift`：`.actionBar { }`（固定到底部，`#available(iOS 26)` 分叉）、`classicBarBacking()`、`barStatusChip(compact:fillsHeight:)`、`barChipButtonLabel()` + `barChipButtonGlass()`（可点的提示小块：玻璃包在按钮外面、内边距留在标签里；玻璃放进标签里时 iOS 26.2 上点它没有反应）、`barPrimaryButton()` / `barSecondaryButton()`、`GlassGroup`；输入栏另用 `barFieldBox(focus:)`、`barRoundButton()` + `barRoundGlyph()`、`BarSendButton`、`barPanel()`，经典样式没有分隔线的栏用 `classicBarBacking(hairline: false)`（G11）；`BottomBar.floats` 供 `SendBar` 判断上传进度画在哪（浮动栏画在计数块里，经典栏仍是栏上方的一条线）、提示放在哪（浮动栏是行上方的小条，经典栏仍在计数下面一行） |
| G9 | 非目标 | 用系统 toolbar 的 `.bottomBar`（栏里是可变宽、最多两行的状态块加主按钮，更像自定义的浮动栏，所以用 `safeAreaBar`）；`glassEffectID` 的形变转场；把渐隐也去掉（试过，见 G3） |
| G10 | 一行里的块同高（2026-10-29，用户看过第一版后反馈：「你左边那块和右边高度不一样，有点难看呀」） | 计数块与右边的按钮一样高，不管有没有提示、在不在上传：行用 `fixedSize(horizontal: false, vertical: true)` 排成最高那块的高度，计数块与按钮的标签都 `maxHeight: .infinity` 吃满（只在浮动栏、非辅助字号下；`maxHeight: .infinity` 要配 `fixedSize`，行高才由最高的那块自己定）。第一版把提示放在计数块里，提示一折行块就两三行高，右边的按钮要么比它矮、要么跟着变高（试过让两边一起长：提示折成两行，块连计数三行高，按钮跟着长，栏变得很厚），所以提示挪到了行上方（G3），行的高度不随提示变。只有「下一题」图标按钮出现时行里多一个圆形玻璃，它同样与行等高 |
| G11 | 输入栏（Agent 页的插话栏、待办页的添加栏，2026-10-29，用户从「下一步」选项里选的；设计由我定，没有再问他，可否决） | 与 G2 同一套机制：`.actionBar`，iOS 26 起栏自己没有底板、内容滚到它后面并柔和渐隐；iOS 17–25 仍是原来的 `.bar` 材质色带（输入栏本来就没有分隔线，所以也不加）。栏里的控件都是玻璃，**一排里的块同高**（G10 的教训，`BottomBar.rowHeight` = 44 pt）：输入框是玻璃胶囊（一行时是胶囊，折行后变成圆角矩形、向上长高，按钮留在底部）；附件（回形针菜单）、自动执行（闪电，开着是橙色实心，关着是灰色空心）是 44 pt 的玻璃圆钮；发送是着色的玻璃圆钮（`arrow.up`，发送中转圈，不可用时是系统的灰）。附件列表与上传进度合成一块玻璃面板放在这一排上方；字数提示（右对齐）与「不能插话 / 不能添加」的说明（居中）是 G3 的小条。一栏里的玻璃放进一个 `GlassGroup(spacing: 4)`，各块之间 8 pt，不会融在一起；水平边距 16 pt（经典栏 12 pt）。**整个输入框都是点按区域**：点框里任何地方（上下左右的空白）都让输入框获得焦点——`TextField` 自己只有那一行字能点，框（至少 44 pt）比它高，空白处点了没反应（模拟器上量过），所以框自己接一个点按手势去设焦点；输入框被禁用（正在发送）时不设。经典栏（iOS 17–25）一点没改：图标按钮、分组背景色的输入框、没有分隔线。**没改的**：操作结果的提示胶囊（`interject-notice`、`todo-notice`，`thinMaterial` 的胶囊，离屏幕底 90 pt）仍是原样——没被提到，位置在新栏上方留有空隙，要不要也换成玻璃可以再定 |

### 3.5 页内编辑时的光标可见性（2026-10-31）

用户反馈回答框和创建任务框换行后被键盘遮住；确认只修复输入时光标持续可见，始终留在原页面，不增加展开编辑入口。

- 输入、自动折行、换行、粘贴、选区改变、键盘及候选栏高度变化后，按真实插入点与当前可见区域修正滚动；同时避开键盘和底部操作栏，光标下方保留约 12 pt。
- 只移动露出当前行所需的距离，不按整张题卡或全文末尾定位。回答框仍为 1–10 行、任务框仍为 4–12 行；到上限后框内滚动，与外层页面配合。
- 用户手动滚动查看上文时不持续抢回位置；下一次输入或移动光标再跟随。不重建输入控件，不改写中文输入法的 marked text，不替换选区。
- 共用 `Views/Common/CaretTextView.swift` 的原生多行输入与可见性处理。Debug + mock + `-AHInputCaretDiagnostics YES` 才暴露实测光标／视口，供原生 UI 测试断言；正式使用不展示诊断。

2026-10-31 用户补充：聚焦空白／短回答后，光标虽然可见，下方的「添加附件」仍可能在屏外；确认采用自动露出作答区的方案，空间不足时优先光标。

- 回答页每题分别关联输入框与实际附件菜单的几何位置；聚焦、输入、选区、键盘／候选栏及作答区布局变化后，由同一套可见性处理计算最小滚动距离。
- 空间足够时完整露出短回答框和附件入口；完整输入框放不下时，尽量同时露出当前光标与附件入口。两者也放不下时只保证当前光标可见，不把编辑位置移到全文末尾。
- 可见范围同时避开键盘与发送栏，目标下方约留 12 pt。已有附件按真实布局计入距离；达到附件上限、菜单不显示时，沿用光标目标。
- 手动滚动暂停布局／键盘变化引起的自动跟随，继续输入、移动选区或重新聚焦后恢复；各题的几何目标独立。创建任务框沿用现有光标跟随。

## 4. 验收标准

1. 三题表单：不作答，依次滑到底（看过全部）再滑回顶部，点「下一题」（若可见）或每次点都去紧邻的下一题，不跳题。
2. 点「下一题」后目标题整题可见并闪一下；放不下一屏的题先到题顶、再点到题底。
3. 最后一题底部进屏前主按钮是「下一题」，之后是「发送」；滑回去后「发送」仍在，且下方还有题时出现次要的「下一题」。
4. 「仅选择」且没选全：提示可点，点后滚到第一道没选的题。
5. 选项：点按瞬间状态翻转（无淡入），按下有下压 / 加深，单选换项只有一次触感；深色模式、最大 Dynamic Type 下正常；VoiceOver 报 selected。
6. Swift 包测试覆盖导航算法（位置、长卡片两步、未布局回退）、闸门、草稿；UI 测试覆盖「滑回去再点下一题不跳题」与选项行为。
7. 底栏（iOS 26 起）：栏背后没有色带与分隔线，内容在栏下可见并柔和渐隐；计数在行内的玻璃块里、与按钮同高（有无提示、上传中都一样），提示是行上方的一小条玻璃；「下一题」变「发送」时胶囊不换、不闪出空胶囊；键盘弹起时栏在键盘上方；深色、最大字号、离线（「发送」不可点）、发送中（转圈）、确认页都正常；iOS 17–25 仍是经典栏。
8. 输入栏（iOS 26 起，Agent 页的插话栏与待办页的添加栏，G11）：栏背后没有色带，内容在栏下可见并柔和渐隐；一行时输入框与两侧的圆钮同高，折行后输入框向上长、圆钮留在底部；点输入框里任何地方（含上下左右的空白）都弹出键盘；有附件 / 上传进度时是一块玻璃面板，字数提示、「不能插话 / 不能添加」是小条；键盘弹起时栏在键盘上方；深色、最大字号都正常；iOS 17–25 仍是经典栏、一点没变。
