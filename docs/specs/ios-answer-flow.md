## 1. 背景

用户在真机上用过作答页后提了两点（2026-10-28）：

1. **选项的手感比较怪**：选中是「渐变」出来的，显得软。要重新设计优化。
2. **「下一题 / 完成」的逻辑与弹窗不太一样**：例如看过一些题但没回答，往回滑了，再点「下一题」会把这些看过没答的题**跳过**。要重新设计优化。
3. **底栏不像原生的 Liquid Glass**（2026-10-29，一条独立的待办）：提问页底部是一整条带材质与分隔线的色带，「Liquid Glass 应该是没有那个背后的蒙层的」，要重新设计得更像原生界面。
4. **Agent 页的插话栏、待办页的添加栏也改成同样的浮动玻璃栏**（2026-10-29，上一条做完、报告后，用户从「下一步」选项里选的：「Agent 页的插话栏、待办页的底栏也改成同样的浮动玻璃栏」）。
5. **输入完点「下一题」，落下来的还是当前这一题**（2026-11-04，用户用了一阵之后）：「有的时候我在一个问题里输入完毕之后，我点下一步，跳到的还是当前的问题。帮我仔细分析一下，看一下这个交互怎么优化，可以用起来更顺手。」
6. **小屏上，多题表单的底栏把按钮撑高**（2026-11-06）：「iPhone 做小屏的时候，如果有多个问题，那在回答的界面，底部的空间不够，会把按钮撑高。」
7. **快捷回复按钮与其他按钮的高度、大小不一样**（2026-11-06，看过上一条的截图后）：「你看一下你图 2 里面，那个快捷回复的按钮和其他按钮的高度都不一样，大小不一样。」

## 2. 现状与根因

### 2.1 选项行（`OptionRow`）

`Button` + `.buttonStyle(.plain)` + 选中态用 `Image(systemName:)` 换符号、背景在 12% 强调色与灰底之间切换。
`.plain` 在按下时把整行变淡、松手再淡回，状态切换发生在这段淡入淡出里；SF Symbol 换名在有事务动画时是交叉淡入。
合起来的观感就是「选中是渐变出来的」。

### 2.2 下一题

`AnswerComposer.nextUnread` = 第一个「没读过」的题，「读过」= 题卡底部进过屏幕**或**已作答。所以：
看过 Q2、Q3 没回答 → 滑回 Q1 → 点「下一题」→ 直接去 Q4（Q2、Q3 已「读过」）。它依赖**历史**，
而用户期待的是**位置**：从我现在在的地方往下一题走。

Mac 弹窗（`usePopupCore.ts`）的做法：`goNext` = 当前题指针 +1，滚到刚好完整可见（已完整可见就不滚），
落点题整题闪一下；当前题完全在屏外（如长 Message 把 Q1 顶出屏幕）时，先把它露出来而不是越过它；
「发送」在最后一题被看到后出现（V1 / V2），此后「下一个」仍可用，直到指针到末题。

### 2.3 底栏（`SendBar`）

`safeAreaInset(edge: .bottom)` 里放一条 `.background(.bar)` + 顶部 `Divider()` 的色带，里面是左侧计数文字、右侧 `borderedProminent` 的实心按钮；「下一题」与「发送」是两个不同的 `Button`，靠 `if` 换。在 iOS 26 上，这条色带是一块带材质与分隔线的横带，把内容在它背后截成一条硬边，与系统自己的浮动玻璃栏不一致。

### 2.4 输入栏（`InterjectBar`、`TodoAddBar`）

Agent 页的插话栏与待办页的添加栏也是 `safeAreaInset(edge: .bottom)` 里一块 `.background(.bar)` 的色带（没有分隔线）。里面一排：左边一个图标按钮（插话栏是回形针的附件菜单；待办栏是「自动执行」的闪电圆圈，只在项目支持时有）、中间分组背景色的圆角矩形输入框（`axis: .vertical`，1–5 行）、右边 `arrow.up.circle.fill` 的图标按钮；排上方是附件列表与上传进度（只有插话栏），下方是字数提示（接近上限时）。「不能插话 / 不能添加」时整条是一行灰字。在 iOS 26 上也是一块带材质的横带，与提问页旧底栏同一个毛病。

### 2.5 输入完点「下一题」回到当前题（2026-11-04）

模拟器上稳定复现（三题表单：在 Q1 的输入框打两行，键盘开着，点「下一题」→ 页面停在 Q1，Q2 没有出来）。根因有三处，都在 `AnswerScreen.next` 一带：

1. **键盘是在 SwiftUI 的更新过程里收起的**：旧实现把 `focused` 置空，由 `CaretTextView.updateUIView` 去 `resignFirstResponder`。键盘在更新中途退出，SwiftUI 的布局停在「键盘还在」的几何上（底栏与滚动区的底卡在键盘顶，下面一条空白），直到别的事让它再排一次版（实测单步值：底栏的底 359 pt 对最终的 653 pt）；而旧实现固定等 0.32 秒再量位置，量到的就是这个没排完的布局。
2. **键盘开着时，位置推不出人在哪**：底栏贴着键盘上沿，正在输入的那张卡的底边比栏顶线还低 2 pt 左右（卡内边距 16 pt，光标可见处理只留 12 pt，§3.5），F1 的「底部还没进入屏幕的第一张卡」选中的就是这张当前卡。
3. **视口顶用错了坐标**：用了导航栏的 `safeAreaInsets.top`（116 pt），而 `answer-scroll` 坐标空间的原点本身就在导航栏下沿，顶边偏了一个导航栏的高度（影响长卡片「先题顶、再题底」的判断）。

另外，键盘动画约 0.44 秒、布局其实几帧（约 70 ms）就排完，固定等 0.32 秒再滚 0.4 秒，点按到落位要 0.7 秒以上，也偏慢。

## 3. 决策

### 3.1 选项行手感

| 编号 | 决策项 | 结论 |
|---|---|---|
| O1 | 总原则 | 选中是**一帧完成**的：按下立刻有反馈，抬手状态立刻翻转，没有交叉淡入、没有整行变淡 |
| O2 | 按钮样式 | 自定义 `ButtonStyle`，不用 `.plain`；按下时底色立即加深、整行轻微下压（缩放 0.985，约 0.08 秒），不改透明度 |
| O3 | 选中态 | 选中行：强调色 2 pt 描边 + 约 14% 强调色底 + 实心指示器（单选实心圆点、多选实心勾选框）；未选行：中性灰底、无描边（选中才有描边，一眼分得出；不再靠颜色渐变区分） |
| O4 | 指示器 | 自绘（圆 / 圆角方框），不再换 SF Symbol 名，避免交叉淡入；选中时内部标记以短弹簧（响应 0.22 秒）弹出（「减少动态效果」下无弹跳） |
| O5 | 触感 | 每次点按一次 `selection` 触感（用点按计数触发，单选换项时不会响两下） |
| O6 | 其它 | 最小高度 44 pt；Dynamic Type 下指示器随字号缩放；无障碍沿用 `.isSelected` 特征与标识 `option-<q>-<i>`；推荐徽标不变，仍**不预选** |

### 3.2 下一题 / 发送

| 编号 | 决策项 | 结论 |
|---|---|---|
| F1 | 「下一题」按**位置**走 | 目标 = 底部还没进入屏幕的**第一张题卡**（= 弹窗的「当前题 + 1」）。与「读过 / 答过」无关，所以不会越过任何一题。Message 很长、Q1 还在屏外时，目标就是 Q1 |
| F2 | 滚动方式 | 目标题放得下一屏：滚到刚好整题可见（贴底，留 16 pt 呼吸位）；放不下：先滚到题顶，再点一次滚到题底，之后才去下一题 |
| F3 | 落点提示 | 落点题卡整张闪一下（强调色淡底约 12%，0.8 秒淡出；「减少动态效果」下不闪），对应弹窗 `flashCard` |
| F4 | 键盘（2026-11-04 改写） | 点「下一题」时键盘开着：由按钮的动作直接收键盘（`resignFirstResponder`，不经过 SwiftUI 的更新过程，见 §2.5），然后**等布局排完**（底栏落回底部、卡位置连续两次不变，实测约 70 ms）就开始算、开始滚，不等键盘动画走完（约 0.44 秒），也不再固定等 0.32 秒：滚动与键盘下去并行，点按到落位约 0.4 秒。收不到「键盘将收起」通知（外接键盘，屏上没有键盘）时不等。一次「下一题」落位前再点一次不会再启动一次 |
| F5 | 「发送」何时出现 | 不变（V1 / V2）：最后一题的底部进过屏幕、或最后一题有答案（含草稿恢复），才出现；一旦出现不再收回（滚回去也不收回）。「读过」只用来管这一道闸，不再用来导航 |
| F6 | 出现「发送」之后 | 主按钮是「发送」。若屏幕下方还有没走到的题，左边多一个次要的「下一题」图标按钮（⌄），行为同 F1，对应弹窗里「发送」出现后「下一个」仍可用；已经在末尾则不显示 |
| F7 | 「仅选择」未选全 | 「发送」不可点（不变）；提示文字「每题都要选一个选项」变成可点：滚到第一道没选的题并闪一下（弹窗没有对应物，但「⌘↵ 找下一个未答题」是同一意图） |
| F8 | 单题 | 不变：只有「发送」，没有「下一题」 |
| F9 | 换页 | 每条请求独立页面、各有自己的状态（`ios-channel.md` 2026-10-27 一节）；不变 |
| F10 | 非目标 | 「上一题」按钮（手机上往回滑最自然；弹窗有是因为键盘流）；当前题高亮 / 选项角标（键盘专用）；自动聚焦输入框（会**新**弹出键盘；键盘本来就开着时的接力见 F13） |
| F11 | 辅助字号下的底栏 | 系统字号进入辅助档（Accessibility sizes）时，计数文字与按钮上下排列：按钮占满整行宽，文字不再被挤成一两个字一行；普通字号仍是左文字右按钮 |
| F12 | 正在输入时，从输入的那一题往后（2026-11-04） | 键盘在哪一题，那一题就是「当前题」（对应弹窗 H4：在某题输入即切为当前题）：目标 = 它 + 1，不再按屏幕位置推。目标整题已在屏内就不滚，只闪一下（弹窗 `goNext` 同）；整题放不下屏仍是先题顶、再题底（F2）；目标的底在屏内、顶被切掉，就从题顶露出。键盘没开时规则不变（F1） |
| F13 | 键盘接力（2026-11-04） | 键盘开着、下一题是**纯文本题**（没有选项，且表单不是「仅选择」）时不收键盘：输入焦点直接移到那一题的输入框，键盘既不收也不重现；页面按光标可见性（§3.5）滑过去（约 0.3 秒；「减少动态效果」下直接到位），那一题闪一下。**实现上由 UIKit 直接交接**（`InlineTextView.takeTheKeyboard()`，从按钮的动作里调用），不走 SwiftUI 的 `updateUIView`：在更新过程里让旧输入框 resign、新输入框 become，resign 引起的嵌套布局会把新输入框的 become 撤销，键盘留在屏幕上却没有任何输入框拿着它（实测：键盘还在、打字没有去处、页面也没有跟过去）。下一题有选项（光标没有用处）则收键盘并滚过去（F4 + F12）。这是 F10「自动聚焦输入框」的一个例外，用户明确同意：只在键盘本来就开着时发生，不会新弹键盘 |

### 3.3 对应关系（弹窗 → 手机）

| 弹窗 | 手机 |
|---|---|
| 当前题指针（滚动同步 / 键盘） | 由屏幕位置推出，没有显式状态；键盘在哪一题，就从那一题往后（F12） |
| 在某题输入即切为当前题（H4） | F12；下一题是纯文本题时光标跟过去（F13） |
| 下一个 = 指针 + 1，滚到完整可见，闪一下 | F1–F3 |
| 当前题完全在屏外先露出它 | F1 的第一题情形 |
| 发送在最后一题被看到后出现 | F5 |
| 发送出现后下一个仍可用 | F6 |
| ⌘↵ 智能前进（下一个未答题 / 未看题 / 提交） | 手机无键盘流；F7 覆盖「找未答题」 |

### 3.4 底栏外观（Liquid Glass，2026-10-29）

用户只给了一句话（「没有背后的蒙层」「更像原生界面」），具体设计由我定，没有再向他提问，可否决：

| 编号 | 决策项 | 结论 |
|---|---|---|
| G1 | 范围 | 提问页（`SendBar`）与确认页（提交栏）。Agent 页的插话栏与待办页的添加栏起初不动（没被提到）；这一节的头一版做完后，用户从「下一步」选项里选了它们，见 G11 |
| G2 | iOS 26 起：浮动，栏自己没有底 | 栏里只有控件，没有材质、没有分隔线；内容一直滚到栏的后面。可读性靠系统的**柔和滚动边缘效果**（`scrollEdgeEffectStyle(.soft, for: .bottom)` + `safeAreaBar`；导航栏下面也是这种边缘效果），而不是自己画一层。`.soft` 要显式写：自动样式在有的系统版本上是带硬边的色带 |
| G3 | 不是控件的文字放进玻璃小块 | 「Answered n/m」（连同上传进度）放进行内的一块玻璃（计数块，胶囊，与按钮同高，见 G10）；提示（可点的「每题都要选」、「已结束 / Mac 离线 / 等待 Mac 确认」）是行上方单独的一小条玻璃（圆角小的矩形，折成两行也是矩形而不是胶囊），确认页的状态行同款。小块不可点，除了会跳去未答题的那条提示。放进玻璃，是因为直接放在渐隐上，滚过来的内容会和它叠在一起读不清（三种都在模拟器上试过：「关掉边缘效果 + 纯文字」文字与滚过的选项行叠在一起；「关掉边缘效果 + 小块」小块四周漏出内容；「渐隐 + 纯文字」在辅助字号下仍会叠字；「渐隐 + 小块」读得最清，就选了它） |
| G4 | 按钮 | 主按钮 `glassProminent`（着色玻璃），次要的「下一题」图标按钮 `glass`；一栏里的玻璃放进同一个 `GlassEffectContainer`（提问页间距 8、确认页 4，都小于版面里各块的间距，所以不会融成一块） |
| G5 | 「下一题 → 发送」是**同一个按钮** | 只换文字与标识（`next-button` ↔ `send-button`）、文字交叉淡入淡出。原来是 `if` 换两个按钮，经典样式下无所谓，玻璃样式下换身份的那几帧会闪出一个空胶囊（逐帧看录屏发现的） |
| G6 | 辅助字号 | F11 不变：提示、计数块各占满一行，按钮在下面占满整行；这时不求同高（上下排的块本来就不并排） |
| G7 | iOS 17–25 | 经典栏不变：`.bar` 材质 + 顶部分隔线 + `borderedProminent` / `bordered`，只是「下一题 / 发送」也成了同一个按钮；`safeAreaInset` 照旧（2026-11-08 起计数与按钮的排法有一处例外：放不下就把计数挪到按钮行上方，见 G14） |

确认页还在倒数「x 后过期」。人是从正文读起的，那张卡排在最前面，却没有任何「整页作废」的信号，一滚动连它也看不见了。

### 3.8 已结束页的「下一条 / 关闭」按钮与 3 秒倒计时（2026-11-12 修订）

用户反馈：「当一个消息在其他端完成或被取消，ios 端顶部的横幅加一个按钮，可以继续跳转下一条或关闭消息」。
我问了按钮的形式、「下一条」的目标、在哪个工作树做，他选了「一个按钮，随状态切换」「同提交后自动前进的目标规则」「主工作树」，并追加：「按你说的，随状态切换。不过加一个倒计时，就是当我在这个页面，这个横条显示出来的时候，5 秒倒计时，自动按这个按钮的操作。然后再加一个停留按钮，就是可以让我在 5 秒钟之内可以停在这个页面。」
随后我问了倒计时与设置的关系、哪些情况要打断它：他选了「受『提交后自动前进』开关管（开关文案改成同时覆盖两种情形，并加一行说明）」，打断只勾了「页面上开着弹层或键盘」；
当时 App 退到后台、VoiceOver / 切换控制开着、手指碰屏幕算停留这三项他没勾，所以没做；2026-11-11 又明确横幅可见后才开始、开始后切后台不打断，见 E10、E12。2026-11-12 用户将固定时长改为 3 秒。只在这一页开着时数、倒数中再来的请求不重新计时、「停留」只管这一条，是我按默认定的，他没有否决。

这条**推翻**了 §3.7 与 `ios-request-switching.md` §2 里「请求结束后不自动跳走」的原则：倒计时数完会自己换页或回列表。留下的保护是：能一键停下（「停留」）、关掉开关的人完全不被带走、开着弹层或键盘的人不被带走。

| E9 | 一个按钮，随状态切换 | 条的右边一枚白色胶囊：还有别的待答请求时写「下一条消息」，没有时写「关闭」。点「下一条」去 `AppStore.endedAction(for:)` 给出的那条，规则与提交后自动前进相同（`nextPending(after:)`：最早未读，否则最新；只要还有别的待答就一直是「下一条」）；点「关闭」回列表，与返回键相同（两栏布局清空选中）。右上角的 ‹ › 不变，仍按列表顺序走相邻项。按钮随状态实时变：条出来时没有别的请求、之后来了一条，「关闭」就变「下一条」，倒计时不重来；数完时按**那一刻**的状态执行（原先要去的那条若已结束，就换成现在的下一条，没有了就关闭） |
| E10 | 3 秒倒计时与「停留」 | 横幅在当前详情页实际显示、App 在前台且没有键盘或弹层遮挡时开始数 3 秒，数完自动按主按钮；后台收到结束事实时只等待显示，不提前消耗秒数。倒计时一旦开始，切后台不打断、不重置（2026-11-11 用户确认）。主按钮上写「3 秒后下一条 / 3 秒后关闭」（逐秒减），白色胶囊从左往右渐渐染上条的颜色；开着「减弱动态效果」时只有数字、不做渐变。时长固定 3 秒，不可调。条上主按钮左边多一枚「停留」：点一下，倒计时取消，「停留」消失，主按钮回到「下一条消息 / 关闭」，页面留着，想走时再点按钮；「停留」只对这一条请求有效。点主按钮立刻执行，不等倒计时 |

## 4. 验收标准

1. 三题表单：不作答，依次滑到底（看过全部）再滑回顶部，点「下一题」（若可见）或每次点都去紧邻的下一题，不跳题。
2. 点「下一题」后目标题整题可见并闪一下；放不下一屏的题先到题顶、再点到题底。
3. 最后一题底部进屏前主按钮是「下一题」，之后是「发送」；滑回去后「发送」仍在，且下方还有题时出现次要的「下一题」。
4. 「仅选择」且没选全：提示可点，点后滚到第一道没选的题。
5. 选项：点按瞬间状态翻转（无淡入），按下有下压 / 加深，单选换项只有一次触感；深色模式、最大 Dynamic Type 下正常；VoiceOver 报 selected。
6. Swift 包测试覆盖导航算法（位置、长卡片两步、未布局回退）、闸门、草稿；UI 测试覆盖「滑回去再点下一题不跳题」与选项行为。
7. 底栏（iOS 26 起）：栏背后没有色带与分隔线，内容在栏下可见并柔和渐隐；计数在行内的玻璃块里、与按钮同高（有无提示、上传中都一样），提示是行上方的一小条玻璃；「下一题」变「发送」时胶囊不换、不闪出空胶囊；键盘弹起时栏在键盘上方；深色、最大字号、离线（「发送」不可点）、发送中（转圈）、确认页都正常；iOS 17–25 仍是经典栏。
8. 输入栏（iOS 26 起，Agent 页的插话栏与待办页的添加栏，G11）：栏背后没有色带，内容在栏下可见并柔和渐隐；一行时输入框与两侧的圆钮同高，折行后输入框向上长、圆钮留在底部；点输入框里任何地方（含上下左右的空白）都弹出键盘；有附件 / 上传进度时是一块玻璃面板，字数提示、「不能插话 / 不能添加」是小条；键盘弹起时栏在键盘上方；深色、最大字号都正常；iOS 17–25 仍是经典栏、一点没变。
9. 输入后点「下一题」（F4、F12）：在有选项的 Q1 输入（一行、七行，同一次运行里反复几轮）后点「下一题」，落到 Q2、整题在两条栏之间，键盘收起，底栏落回屏幕底部（下面没有空白）；不再停在 Q1。
10. 键盘接力（F13）：在 Q2 输入后点「下一题」，键盘全程不收，光标在纯文本的 Q3，接着打的字进 Q3 而不是 Q2；Q3 在键盘上方可见，「发送」出现。
11. 三题连着走：在 Q1 输入 → 下一题（Q2，键盘收）→ 在 Q2 输入 → 下一题（接力到 Q3）→ 在 Q3 输入，三题都有答案。
12. Swift 包测试覆盖输入时的下一题（`QuestionNavigator.next(after:in:)`：从输入的那题往后、整题可见只指不滚、长卡两步、顶被切掉从题顶露出、末题与未量到回退）与 `isTextOnly`；UI 测试覆盖 9–11。
13. 已结束的请求页（§3.7）：页面开着时请求在别处结束（别处回答、Agent 取消、超时、其它），导航栏下面出现带色的状态条，写「无需回复」与原因，滚动页面时条不动；消息、各题（确认页：详情、选项、输入框）明显变灰，页头不变；选项、备注框、确认页的选项与输入框点不动、打不进；确认页的过期倒计时消失；底栏「该请求已结束。」、发送 / 提交钮灰着。自己发出的回答不出现这套（页面是回执）。深色、最大字号、iOS 17–25 都正常。
14. `AskHumanEndedUITests`（中英文）覆盖 13：提问与确认页在页面开着时结束、条在滚动后位置不变、四种结束方式各有各的原因句、自己发出的回答不被当成结束。
15. 窄屏底栏（G12）：375 pt 宽的屏上，三题表单在「下一题」、「发送 + 下一题 + 菜单」、「发送并离开」三个状态里，主按钮都不比初始时高（不被撑高），计数块不折行、不被压成空条、不与按钮重叠——放得下时是「Answered 0/3」在左、按钮在右，其次是「0/3」，再放不下是计数块在按钮上方单独一行；宽屏上外观与改前一样；辅助字号、深色、中英文都正常。`AskHumanBarUITests`（五档字号，中英文）覆盖：375 pt 的模拟器上用字号档位模拟更窄的栏。
16. 图标按钮（G13）：浮动栏上，快捷回复与「下一题」图标都是圆（宽 = 高），与「发送」同高、两个图标按钮大小一样（默认字号 50 pt，XL / XXL / XXXL / 辅助字号随行高变大）；多题表单在输入框里打字再点「发送」不卡，回执出现、请求离开收件箱。`AskHumanBarUITests` 逐态量了圆的宽高；`testAnsweringAMultiQuestionRequestSendsItAndLeavesTheInbox` 覆盖不卡。
17. 附注圆钮（G14）：请求里没有附注时按钮行与改前完全一样；写了附注后，圆钮出现在快捷回复与「下一题」之间，与「发送」同高、与另外两个圆一样大，角标显示条数（1 到 20 条）；375 pt 宽的屏上三个状态（「下一题」、「发送 + 下一题 + 菜单」、「发送并离开」）与五档字号下主按钮不被撑高、计数块不折行、不被压成空条、不与按钮重叠（G12 的判据）；中英文、深色、iOS 26 浮动栏与 iOS 18 经典栏都正常。`AskHumanBarUITests` 的带附注用例覆盖。
18. 已结束页的按钮与倒计时（§3.8）：开着「自动打开下一个请求」时，页面开着的请求在别处结束、横幅实际显示后，条上出现「停留」与「3 秒后下一条」（没有别的待答请求时是「3 秒后关闭」）；3 秒后自动换到下一条（或回到列表）；点主按钮立刻执行；点「停留」后倒计时与「停留」消失、页面不动、主按钮留着；页面上开着弹层或键盘时不倒计时；开关关着时条上只有主按钮；375 pt 宽与各档字号下按钮不被截断、句子不被挤成几个字宽、条不占去屏幕的五分之一以上（按钮并排放不下就排到句子下面）；中英文、深色都正常。
19. `EndedCountdownTests`（Swift 包）覆盖按钮的目标与随状态的变化、倒计时的开始与走完、「停留」、开关、打断（离开页面、别的请求、别的标签页、结束时页面已被盖住）；`AskHumanEndedUITests`（中英文）覆盖 18 里看得见的部分，包括弹层打断、写回答时请求结束（键盘开着：不开始倒计时，写的字还在页面上），以及三档大字号下条的尺寸与按钮位置（`testTheStripHoldsAtLargeTextSizes`）。前后台补充：后台取消后返回才开始完整倒计时（`testACancellationInTheBackgroundWaitsUntilItsStripIsSeen`），已开始后进入后台仍按原截止时刻前进（`testBackgroundingAfterSeeingTheCountdownDoesNotRestartIt`）；这两条通过激活系统设置让 App 真正进入后台并检查其状态，再返回验证；Duo runtime 的 XCTest Home 键可能不生效，不能把按过 Home 当作已后台化。
