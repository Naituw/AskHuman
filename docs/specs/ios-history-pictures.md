# 需求：iOS 历史里的图（会话历史卡片与「历史」标签详情页）

> 状态：**2026-11-12 起草并经用户评审通过**（AskHuman 两轮：先问范围，再给图稿与三问，用户全选了推荐项），实现与验证记录见 `docs/plans/ios-history-pictures.md`。用户原话：「历史记录里的图怎么都看不见？」
> 关联：[会话历史规格](ios-session-history.md)（S9 当时只给个数、§11 把「在手机上看往来的附件与图片」后置，本文把其中的**图片**做出来，其余附件仍后置）；附件传输见 [`ios-channel.md`](ios-channel.md) §6.5 与 `docs/overview-ios.md`；图稿 `docs/assets/ios-history-pictures/cards-mock.jpg`。
> 平台：Mac 端沿用现有 Daemon；手机端 iPhone（iPad 随既有大屏布局），iOS 17+，中 / 英双语。

## 1. 背景与目标

手机上有两处「历史」，图片在两处都看不见：

- **会话历史卡片**（请求页下拉或「⋯ → 此会话的历史」）：S9 只给个数，展开后才有一行「附件 N 个」，折叠时连个数都没有；
- **「历史」标签的详情页**：附件只留文件名（页面上写着「Only the file names are kept on this phone」），回答里的图只写个数。

用户这台 Mac 的真实历史（`history.jsonl`，200 条往来）里：Agent 随消息 `-f` 传的**图片附件 74 张**（PNG 为主，中位数约 344 KB，最大约 1.1 MB），其中 18 张的原文件已被系统清掉（多放在 `/tmp`）；用户在回答里贴的图 1 张；Markdown 正文引用的图 0 张。所以「看不见的图」基本就是 Agent 当时附带的截图。

**目标**：在这两处看得见这些图：缩略图直接可见，点开看大图。

**非目标**：

- 非图片附件（仍只给个数）、批注（仍只给个数）；
- Markdown 正文里的 `![](…)` 图（App 里任何地方都不联网取图、显示成「图片说明」胶囊，`ios-web-markdown.md` W5，这次不动）；
- 让 Mac 在记录历史时**留图片副本**（HP12：用户选择先不做）；
- 手机落盘历史；预取原图。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 图（picture） | 一条往来里的一张图片：Agent 随消息带的图片附件（`FileAttachment.is_image`），或回答里贴的图（`answers[q].images` 的一项） |
| 图引用 | 线上的 `AssetRef`（`assetId`、`name`、`size`、`mime`、`isImage`、可选 `thumb`、`tooLarge`、新增的 `gone`）；与请求附件同一个形状，所以手机的缩略图格、查看器、下载、拖出全部复用 |
| 槽（slot） | 图在往来里的位置：`m{i}`（消息文件第 i 个）或 `q{q}.{i}`（第 q 题回复图的第 i 张） |

| HP7 | 图的 id 与取图 | `assetId` 是**确定的**：`base32_lower(sha256("askhuman.history.picture\0" + 往来 id + "\0" + 槽)[..16])`（与别的 `assetId` 同一个 26 位格式）。Mac **不登记注册表**：`asset.get` 找不到待答请求的附件时，经 `Host::history_picture` 在历史里按 id 解析（读最近的历史，逐张算 id 比对；命中后文件必须仍在、是普通文件），结果在网关里缓存（≤ 256 条）避免一次下载的几个窗口重复扫描 | 重启 / 换新 Daemon 之后手机里已经显示的缩略图仍能点开；手机的缓存文件以 `assetId` 为名，重新加载历史后同一张图命中缓存。代价：第一次取原图要扫一遍历史（最多 200 条，毫秒级） |

| HP9 | 「历史」标签详情页 | 进页时，Mac 在线且 `caps.historyPictures` 时发 `history.exchange.get`（请求 id）；到了就把「消息文件」里的图换成缩略图网格、回答里的图换成缩略图排；非图片文件仍是只有文件名的行；读不到（离线、老 Mac、Mac 已没有这条）就是现在的样子，不报错、不阻塞页面；每次进页重读，不落盘 | 详情页的请求 id 就是 Mac 往来的 id。手机本地历史不存图（「Only the file names are kept」），图只能向 Mac 要 |

## 4. 用户视角

**会话历史卡片（收起）**：头部、消息之后，有图时多一排缩略图（HP3）；题与答案不变。点缩略图 → 全屏查看器（本往来的所有图，消息图在前、各题回复图依次在后，左右滑动，标题写文件名与「N / M」）；点其它处展开 / 收起。已不在 Mac 上的格子（HP8）是占位，点一下弹出说明。

**会话历史卡片（展开）**：消息的图排成网格；每题的答案下面是该题回复图；最后一行「附件 N 个」（没显示成图的文件数，为 0 时不写）。

**「历史」标签详情页**：消息卡里，图片附件变成缩略图网格（点开同一个查看器），非图片文件仍是文件名行；回答卡里，该题回复图排在答案下面。页面一进来就按现在的样子显示，图到了再换进去（不跳动：只在图所在的位置出现缩略图格）。

**没有图的往来、没有能力的老 Mac**：与现在完全一样。

## 5. 线协议（`ios/wire.rs` 与 Swift `AHProtocol` 共用 `ios/Fixtures/wire-v1/messages.json`）

全部是加字段 / 新消息类型，JSON 键 camelCase，可选字段缺省不发。

| 位置 | 新增 | 含义 |
|---|---|---|
| `Caps` | `historyPictures`（缺省 false，false 时不发） | Mac 认识 `pictures` 与 `history.exchange.get` |
| `AssetRef` | `gone`（缺省 false，false 时不发） | 文件已不在 Mac 上 |
| `history.session.get` | `pictures`（缺省 false，false 时不发） | 手机想要图引用与缩略图；老手机不发，所以不会白收 |
| `SessionExchange` | `pictures?: [AssetRef]` | 消息的图片附件，按记录顺序，最多 12 条；`attachments` 仍是消息文件的**总数**（含这些图），手机用「总数 − 图数」得到没显示的 |
| `SessionQuestion` | `pictures?: [AssetRef]` | 该题回复图，最多 12 条；`images` 仍是回复图的总数 |
| 手机 → Mac `history.exchange.get` | `reqId`、`id`（往来 id，即请求 id） | 取一条往来（带图），给「历史」标签详情页用 |
| Mac → 手机 `history.exchange` | `reqId`、`id`、`item?: SessionExchange` | 没有这条往来、历史关着时没有 `item`，不是错误 |

引用里的 `size` 是投影时磁盘上的字节数（`gone` 时为 0），`mime` 由文件名推出，`isImage` 恒为真，`tooLarge` 在大于 10 MB 时为真（没有缩略图，沿用现有的「太大」标记）。常量（Rust 与 Swift 必须一致）：`HISTORY_PICTURES_MAX = 12`、`HISTORY_THUMB_MAX_BYTES = 6144`。

`history.exchange` 与 `history.session` 一样要装进一条消息：超限时先去掉缩略图，再减半文字（`shrink`）。

## 6. Mac 端行为

- **投影**（`ios/history_view.rs`）：在原来的纯投影之外，按「文件探测」给往来加图引用。探测是一个接口：返回文件大小与缩略图，或「文件不在」；生产实现读磁盘（`metadata`、`image` 解码、缩略图缓存），测试用脚本。槽、顺序与上限如 §2、§5；回复图只有路径，名字取文件名。
- **页预算**（`wire::SessionHistory::shrink`）：第一步去掉最旧的有缩略图的往来的缩略图，没有可去的再走原来的丢旧往来 / 减半文字。
- **取图**（`ios/gateway/assets.rs`）：`on_asset_get` 先找待答请求的附件；找不到再查网关里的历史图缓存；再找不到、且是合法的 id 形状，就经 `Host::history_picture(assetId)` 异步解析，命中后照常分块发送，未命中回 `notFound`。分块、校验、10 MB 上限、窗口规则都不变。
- **单条往来**（`ios/gateway/history.rs`）：`on_history_exchange_get` 交给 `Host::history_exchange`，装进 `history.exchange` 发回；默认实现回没有 `item`。
- **Daemon 的实现**（`daemon/runtime/ios_history.rs`）：`session_history` 在 `pictures` 为真时加图；`history_exchange` 按 id 找一条记录；`history_picture` 读最近的历史逐张算 id。都在 `spawn_blocking` 里。历史关着（`general.historyLimit = 0`）时一律回空。
- **能力位**：Daemon 的 Host `caps()` 返回 `history_pictures: true`。

## 7. 手机端行为

- **协议与引擎**：`AHProtocol` 的同名类型；`Backend.sessionExchange(macId:id:)`（`PhoneEngine+SessionHistory.swift` 与 `sessionHistory` 同一套「信箱 + 超时」，离线 / 能力位缺失分别抛 `macOffline` / `rejected("unsupported")`）；`sessionHistory` 在 Mac 有 `historyPictures` 时自动带 `pictures`。下载仍是 `download(macId:asset:)`，一行不改。
- **会话历史卡片**（`SessionThreadView.swift`）：折叠排、展开网格、占位格、回复图、查看器，复用 `ImageThumbnail`、`ImageGalleryViewer`；卡片是一个合并的读屏元素，缩略图加一个读屏动作「查看图片」。
- **「历史」标签详情页**（`HistoryDetailScreen.swift`）：进页读一次 `sessionExchange`，用本地状态保存，页面离开就丢。
- **Mock**：`sessionHistory` 场景带有图的往来（0、1、2、5、7 张，含已不在的、含回复图）；`download` 返回生成的图。

## 8. 兼容

| 组合 | 表现 |
|---|---|
| 新手机 + 旧 Mac | 没有 `caps.historyPictures`：不带 `pictures`，不发 `history.exchange.get`；卡片与详情页和现在一样 |
| 旧手机 + 新 Mac | 旧手机不发 `pictures`，Mac 不带图引用；`AssetRef` 多出的 `gone` 只会出现在带 `pictures` 的往来里 |
| 新 + 新 | 有图的往来露缩略图 |

## 9. 隐私与安全

- 手机仍拿不到路径：线上是确定的 `assetId`、文件名、大小。Mac 只能按历史里**记过的**路径取文件，id 是哈希，不可猜；与手机本来就能读 Mac 上保留的旧问答（S1、§9）同一信任水平，传输仍是端到端加密、不进推送。
- 原图只进手机的系统缓存目录，可被系统清理；历史本身不落盘（S14 不变）。
- 读取有上限：单张 ≤ 10 MB、每个往来 ≤ 12 张引用、整页 ≤ 256 KiB；缩略图只在小图（≤ 10 MB）上解码，且有缓存。

## 10. 已知局限

- 被系统清掉的原文件（`/tmp` 等）看不到，只有占位（HP8、HP12）。较老的往来更常碰到。
- Markdown 正文里的图、非图片附件、批注仍是文字 / 个数。
- 缩略图是 6 KiB 以内的小图，格子较大时偏软；点开看到的是原图。
- 「历史」标签详情页只对 Mac 还留着的记录有图（默认保留 200 条）。

## 12. 验收标准

1. 有能力的 Mac 上，带图的往来在会话历史卡片折叠时露一排缩略图（最多 4 格，多于 4 张第 4 格写「+N」）；点缩略图打开查看器，点其它处展开 / 收起。
2. 展开后消息的图成网格，每题回复图在答案下面，末尾只写没显示成图的附件数；已不在 Mac 上的是占位格，点一下有说明，不进查看器。
3. 查看器里是该往来所有可看的图（消息图在前，回复图在后），原图点开才下载；下载失败有错误页，不影响卡片。
4. 一页里图很多时，页仍装得进预算：先去旧往来的缩略图（占位仍可点开），再少给旧往来。
5. 「历史」标签详情页：Mac 在线且有能力时，消息图与回复图换成缩略图并可打开；读不到时与现在一样，不报错。
6. 老 Mac / 老手机组合没有任何变化；`PROTO`、`PROTOCOL_VERSION` 不变；新增夹具两边往返通过，既有夹具原样保留。
7. 深色、最大字号、iPhone SE 宽度、中英文、iPad 正常；VoiceOver 能通过读屏动作打开查看器；点缩略图不会同时展开卡片。
8. Daemon 重启后，手机里已显示的缩略图仍能点开下载（HP7）。

## 13. 测试

- **Rust**：槽与 id（确定、不同槽不同 id、格式合法）；投影（顺序、12 条上限、回复图取文件名、文件不在 → `gone`、太大 → 无缩略图、非图片只计数、序列化里没有路径）；缩略图阶梯与 6 KiB 上限（真实小图）；缩略图缓存命中；`shrink` 先去缩略图再丢旧往来；网关：`pictures` 才带图、`history.exchange.get` 找得到 / 找不到、`asset.get` 对历史图分块与校验、重启后仍可解析（换新网关实例）、未知 id 回 `notFound`；能力位只在 Host 声明时发。
