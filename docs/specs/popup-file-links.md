# 正文本地文件链接：右侧预览与右键菜单

> 状态：设计已于 2026-11-21 评审通过并已实施（§11）；Windows / Linux 实机验证是外部 gate，记录在 `docs/PROGRESS.md`。
> 本文只写相对既有规格的增量。未提及的行为——面板几何、内容类型与资源上限、查找、macOS 系统预览、
> 读取代次与取消——全部沿用 [popup-attachment-preview-panel.md](popup-attachment-preview-panel.md)
> （下称“面板规格”），历史窗口沿用其 §10。
> 现有链接行为见 [popup-request-inbox.md](popup-request-inbox.md) §20，附件契约见
> [file-attachments.md](file-attachments.md)。

## 1. 目标与范围

Message 与题干的 Markdown 里经常有指向本地文件的链接（`[报告](docs/report.md:82)`）。今天单击它会把文件交给
系统默认程序，用户要离开作答界面去看；同一个文件作为附件时，却能在右侧面板里直接读。本设计让
**本地文件链接的行为与附件一致**：单击在右侧面板预览，右键弹出附件同一套菜单，文件打开期间链接显示选中态。

范围（用户 2026-11-21 逐项确认）：

- Popup（合并与独立模式）与历史详情窗口里的 Message、题干。
- 正文里的本地图片 `![](路径)`。
- 面板里预览的 Markdown 文件中的本地文件链接：在面板内继续打开，并可返回。
- 附件胶囊的 ⌘ / Ctrl+单击，与链接同一规则（D2）。

不在范围：

- Confirm（权限 / Stop）卡片、更新说明里的链接，Agent 控制台与转录面板：保持系统打开。
- 行号 / 列号 / `#L行` 定位：与现状一致，只剥离、预览从头显示（D6）；以后要加，本设计不用动。
- 正文里的裸路径与行内代码路径：不是链接，保持不变。
- 目录预览、从链接拖出文件、新增设置项，以及 IPC 协议与恢复存储的任何变化（§4.5）。

## 2. 术语

- **本地文件链接**：Markdown 链接 `[文字](目标)`，目标经 `lib/markdownLinks.ts` 的 `resolveMarkdownLink` 解析为本地
  路径——绝对路径、盘符路径、UNC、`file:` URL，或以请求项目目录（面板内则是当前预览文件所在目录）为基准的相对路径。
  `http(s)`、`mailto`、`#片段` 与其他协议不是。
- **链接文件**：本地文件链接所指的文件，路径已剥离 `:行:列`、`?`、`#` 并解码。
- **所有者与索引**：面板规格 §10.5 的预览所有者 ID（Popup 为请求 ID，历史为 `history:<条目 ID>`）加索引。所有触碰
  文件的预览命令都按它们取文件，路径从不由前端给出——§4 说明本设计对这一点的唯一例外。

## 3. 交互

### 3.1 决策

| D5 | 同期覆盖：历史详情、正文本地图片、面板内 Markdown 里的本地链接（含返回） | 用户 |

### 3.2 点击、修饰键与菜单

| 用户动作 | 结果 |
|---|---|
| 单击未选中的本地文件链接 | 链接文件在右侧面板打开（面板收起则展开），链接进入选中态 |
| 单击已选中的链接 | 收起面板并取消选中态（D7，与附件一致） |
| 面板已展开时单击另一个链接或附件胶囊 | 切换内容并保持展开，选中态跟随 |
| ⌘+单击（macOS）/ Ctrl+单击（Windows、Linux） | 系统默认程序打开原文件；面板与选中态不变（D2） |
| 双击 | 只执行第一击；第二击忽略（D11）。此前双击会连开两次系统程序 |
| 右键 | 弹出附件同一菜单，针对链接文件；不改变面板。macOS 为原生 NSMenu，Windows / Linux 为 Tauri 菜单 |
| 聚焦链接按 Enter | 与单击相同（浏览器对链接的原生行为） |
| 目录、非常规文件的链接 | 单击交给系统打开（Finder 等）；右键不弹自定义菜单（D9） |
| 网页、mailto、`#片段` 链接 | 不变 |

macOS 上 Ctrl+单击就是右键，所以“直接打开”的修饰键在 macOS 取 ⌘；判定复用 `lib/platform.ts` 的
`primaryModifierPressed`，只认当前平台宣告的那一个修饰键，其他组合键按普通单击处理。

附带收益：以前单击指向脚本、`.command` 的链接会由系统直接运行；现在单击只是预览，运行需要明确的 ⌘ / Ctrl+单击或菜单。

### 3.3 选中态

- **判定**：链接的解析路径（渲染期写入的 `data-local-file`）已登记到某个索引，且该索引正是面板当前显示的索引；或者
  其路径与当前显示文件的路径字面相等（覆盖“附件又被链接”的常见情形）。
- **样式**：与 `.attachment.selected` 同源——`--accent` 2px 环；行内链接折行时每一段都画（`box-decoration-break: clone`），
  另加很浅的底色；本地图片用 2px `--accent` 描边；同时设 `aria-current="true"`。具体数值以实机截图为准。
- **清除**：面板收起、切换到其他文件、请求切换、历史换条目时清除。
- **重绘**：主题 / 语言切换、Mermaid 水合会整体替换正文 DOM，选中态在每次替换后重新套用，不依赖节点身份。
- **多处引用（D8）**：行号后缀被剥离后，`a.rs:10` 与 `a.rs:20` 解析为同一路径，本来就是同一个文件；选中态表达的是“这个文件
  正在右边打开”，所以全部点亮。只点亮被点的那一处需要节点身份，重绘后易丢失，不采用。
- **已知限制**：CLI 按真实路径（`canonicalize`）记录附件，链接则保留作者写的路径。两者因符号链接而不同（macOS 的 `/tmp`
  指向 `/private/tmp`）时，只点附件胶囊不会点亮对应链接；点过该链接后（登记时按真实路径去重，索引相同）两处同步。

### 3.4 面板里的链接文件

```text
附件：        文件名 [查看原文]               2 / 4  ‹  ›  [查找] [浏览器打开]  ⋯  ×
链接文件：    文件名 [查看原文]                            [查找] [浏览器打开]  ⋯  ×
面板内跳转后： ‹ 返回  文件名 [查看原文]                    [查找] [浏览器打开]  ⋯  ×
```

- 标题栏右侧是靠右对齐的固定操作区，隐藏「n / m」与 ‹ › 不会让查找、打开、⋯、× 的位置跳动。
- 文件名悬停显示完整路径；原文 / 预览切换、查找、主按钮（Markdown 为“浏览器打开”，其他为“打开”）、⋯ 菜单、Esc、×
  与附件完全一致。⋯ 与右键共用同一菜单实现。
- 阅读状态（原文 / 预览、滚动位置、图片缩放）按文件保留到请求结束；历史窗口保留到切换条目。
- 点附件胶囊：回到附件导航，「n / m」恢复，返回栈清空。附件列表本身不增减、不重排。
- 菜单“快速查看”是显式查看，不因目标已选中而收起（面板规格 §4）。

### 3.5 正文本地图片

- 单击 `![](路径)`：在面板打开，复用面板的适应 / 缩放 / 平移；⌘ / Ctrl+单击：系统看图软件；右键：同一菜单。
  选中态与链接相同；悬停提示改为完整路径。这样链接进面板、图片却跳到看图软件的不一致不会出现。
- 图片加载失败时的占位按钮（“… · 打开原图”）保持系统打开：用户明确要原文件，而面板对同一张图只会遇到同样的失败。
- 聚焦的图片上 Enter 与单击相同（D14，此前是系统打开）。

### 3.6 附件胶囊的 ⌘ / Ctrl+单击

Popup 与历史详情的附件胶囊：⌘ / Ctrl+单击直接用系统默认程序打开原文件，等同在胶囊上按 Enter；不切换预览、不改变选中。
待办窗口等其他入口的附件不变。这一条修订面板规格 §3 与 §10.2 的“打开原文件”入口清单。

### 3.7 面板内 Markdown 里的本地文件链接

- **适用**：面板预览的是 Markdown 文件，其中的链接指向本地文件（相对路径、绝对路径、`file:` URL）。
- **基准**：相对路径以**当前预览文件所在目录**为基准（不是请求的项目目录——文件里的相对链接按文件所在位置读）。
- **动作**：单击在面板内打开目标，替换当前内容；⌘ / Ctrl+单击系统打开；右键同一菜单；目录、非常规文件同 D9。
  `http(s)` / `mailto` 仍交给系统，`#片段` 在面板内定位，其他协议丢弃，目标里的片段与行号只剥离（D6）。
- **返回**：发生面板内跳转后，标题栏文件名左侧出现 ‹ 返回，回到上一个文件，恢复它的滚动位置与原文 / 预览模式。
  Esc 与 × 仍关闭整个面板，不是后退一步。
- **返回栈（D12）**：只记录面板内跳转。从正文链接、附件胶囊、菜单“快速查看”打开是新起点，清空返回栈；链接自己指向
  当前文件时无变化。栈深有上限（50，丢最早的）。
- 不提供前进、也不新增快捷键，避免与输入框编辑键和既有 Esc / 方向键规则冲突。

### 3.8 失败与降级

- 链接文件读取失败 / 超限 / 不支持：显示面板既有的状态页与打开、在文件管理器中显示（面板规格 §5.3）；返回栈仍可用。
- 登记命令失败或超过上限（D13）：该次点击降级为旧行为，交给系统打开，并在控制台记录错误。这是预先定好的降级，
  不改变其他点击的行为。
- 快速连续点击：以最后一次为准，先返回的登记结果若已过期则丢弃。

## 4. 数据与授权

### 4.1 为什么不能直接复用附件命令

所有预览命令只接受 (所有者 ID, 索引)；路径由 `attachment_owner::files()` 取——Popup 为请求的 `message.files`，历史为
`history::attachment_files`。macOS 原生菜单与非 macOS 菜单在动作触发时会再核对一次（macOS 还核对路径相等）。正文链接指向的
文件不在这份列表里，没有索引可用。

### 4.2 链接文件登记表

- **共用索引空间**：链接文件追加在所有者的附件之后，索引 = 附件数 + 登记顺序，永不复用。读取、系统预览、查找、浏览器快照、
  定位、菜单（macOS 原生与 Tauri）、读取取消等所有按 (所有者, 索引) 工作的命令不改一行即可处理链接文件；唯一的扩展点是
  `attachment_owner::files()` 在附件之后追加该所有者的登记项。
- **新命令** `popup_preview_link(request_id, path)`（仅 Popup / 历史窗口），返回 `{ kind: "file", index, file }`
  （`file` 与附件同形：`path`、`name`、`size`、`isImage`）或 `{ kind: "other" }`（目录、设备、管道等，前端按 D9 处理）。
  命令在阻塞线程里做文件系统访问。
- **校验**：窗口与所有者相符，且请求已在屏幕上（同 `files(.., true)`）；路径非空、不超过 4096 字节、无 NUL、是本平台的
  绝对路径；先词法规整（`.`、`..`），再尝试 `canonicalize`——与 CLI `-f`（`cli/file_attachment.rs`）一致，使同一个文件得到
  同一个路径；存在但不是常规文件 → `other`；不存在 → 照常登记（D10），`size` 记 0。
- **去重**：与所有者的附件、已登记项按规整后的真实路径比较，命中返回已有索引。“既是附件又被链接”的文件只有一个索引，
  所以点链接会点亮对应附件胶囊，缓存与阅读状态也共用。
- **上限**：每个所有者 64 个，超出返回错误（前端按 D13 降级）。
- **生命周期**：随所有者结束清除——Inbox 请求终结（`Inbox::finish`）；历史窗口与读取代次一样同一时刻只有一个当前所有者，
  换条目登记时丢弃上一个历史所有者的登记，窗口销毁（`attachment_owner::forget_history`）时清空；独立 Popup 随进程结束。
  登记表只存在于托管窗口的进程里，不落盘、不跨进程。
- **索引的唯一权威是后端**：每次打开都经命令登记（幂等，已登记的路径原样返回索引），前端从不自己推算或沿用旧索引。
  前端另存“作者路径 → 索引”与“索引 → 文件”两张镜像表，只用于两件事：选中态，以及“点击当前正在显示的链接”时不等
  命令往返、立即收起。所有者变化时镜像清空；网页视图单独重载而后端表仍在时，镜像按命令返回的索引重建（允许稀疏）。

### 4.3 对既有不变量的修订

面板规格 §7“读取目标来自当前 Popup 已提供的附件”追加“以及用户点击正文或面板里的本地文件链接而登记的文件”；§10.5“路径始终由
后端提供，不接受前端路径”的唯一例外是 `popup_preview_link`，且只有它接受路径。

这一例外不放宽实际能力，先例都在：

- `open_path` 今天就按前端给的任意路径交给系统打开，链接单击就是它。
- `local_image_prepare` 接受前端给的路径并做有界图片读取。
- Agent 本来就能用 `-f` 附任意文件，并让用户在面板里读。

链接文件的读取不比这些更宽：只读、遵守面板既有的资源上限（文本 2 MiB、图片像素、原生预览 100 MiB 等）、结果只显示给用户、
必须由用户点击或右键触发。

没有要求“路径必须出现在请求正文里”：那需要在 Rust 里再复刻一份 Markdown 链接解析（前端 markdown-it、面板 pulldown-cmark，
再加一份就是三套互不同步的解析器），得到的只是形式上的来源，并没有实质收紧——Agent 可以直接把这个文件当附件发来。

### 4.4 面板内链接需要的渲染器改动

面板里的 Markdown 由 `attachment_markdown::render_popup` 渲染。现状：凡是目标不是 `http(s)` / `mailto` / `#` 的链接，目标都被
改成空串（`href=""`），作者写的路径就此丢失，所以面板里的本地链接今天是死的。

变更：popup 渲染时，对“本地文件形目标”——无协议的相对 / 绝对路径、盘符路径、`file:`——生成
`<a href="" data-local-link="<转义后的作者目标>">`（保留 `title`），仍不输出任何带 URL 语义的属性。`javascript:`、`data:`、
`tauri:`、`ftp:` 等其他协议、`//host`、含控制字符或超过 4096 字节的目标照旧丢弃。`data-local-link` 是惰性数据，只被面板的
点击 / 右键处理器读取，解析仍在前端（`resolveMarkdownLink`，基准为当前预览文件所在目录）。

- 图片目标的策略不变（仍丢弃）；浏览器快照（`render(.., false)`）不变。
- 单元测试 `popup_escapes_html_and_rejects_active_and_local_urls` 的断言从“HTML 不含本地路径”收紧为“HTML 不含带 URL 语义的
  本地路径属性”，并补充：各协议被丢弃、属性注入被转义、超长被丢弃。

### 4.5 不触及

- IPC 协议与 `PROTOCOL_VERSION`：新命令是托管窗口进程内的 Tauri 命令，不经 daemon，不改 `ClientMsg` / `ServerMsg`。
- 恢复存储与 `SCHEMA_VERSION`：登记表不落盘；宿主重启后恢复的请求没有链接登记，等于重新开始。
- CLI、daemon、渠道、iOS、历史文件格式。

### 4.6 放弃的方案

- **前端直接请求读取任意路径的通用命令**：绕开所有者 + 索引模型，菜单、原生预览许可、读取代次、查找都要另写一套。
- **把链接文件合成附件胶囊**：改变附件列表语义与计数，与 D4 相悖。
- **后端解析正文校验来源**：见 §4.3。

## 5. 实现结构

后端：

- 新增 `app/linked_files.rs`：托管状态（所有者 → 登记项）、`register`、`forget`、单元测试；在 `app/mod.rs` 与其他预览状态一起 `manage`。
- `app/attachment_owner.rs`：`files()` 追加登记项；`forget_history` 一并清除历史所有者的登记。
- `commands.rs`：`popup_preview_link`，登记到 `app/invoke.rs`；`app/popup_inbox.rs` 的 `Inbox::finish` 清除所有者登记。

## 7. 验收矩阵

1. 正文里相对路径、绝对路径、`file:` URL、带 `:行:列` 与 `#L行`、含中文与空格的链接：单击在面板打开，链接高亮；预览从头显示。
2. 再次单击已选中的链接收起面板并取消高亮；单击另一个链接或附件胶囊切换，高亮与「n / m」同步；窗口不反复缩放。
3. ⌘ / Ctrl+单击链接、附件胶囊、正文图片：系统打开，面板与高亮不变；双击不产生第二次切换。
4. 右键链接 / 图片：菜单项齐全，动作作用于链接文件；“快速查看”展开面板且不因已选中而收起；⋯ 与右键一致。
5. 目录链接交给系统；不存在的文件展开面板并显示“无法读取”与打开 / 定位；非常规文件交给系统。
6. 附件与链接指向同一文件：只有一个索引，两处同时高亮；点链接点亮胶囊。
7. 历史详情同上；换条目 / 删除 / 清空时面板收起、高亮清除、旧读取结果不出现在新条目上。
8. 面板内 Markdown：相对 / 绝对链接单击在面板内打开；返回恢复上一个文件的滚动位置与原文 / 预览模式；从正文或胶囊再打开清空返回栈；
   Esc 关闭整个面板。
9. 多请求的合并 Popup：各请求的链接、登记、选中态与返回栈互相独立；请求结束后登记清除。
10. 主题 / 语言切换与 Mermaid 水合后选中态保持；窄面板、深浅色、查找、macOS 系统预览（PDF）对链接文件同样可用。
11. 网页、mailto、`#片段`、Confirm 卡片、Agent 控制台的链接行为不变；登记失败与超过上限时降级为系统打开。
