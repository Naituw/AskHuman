# 日常沟通与开发验收隔离

> 状态：两阶段接口与实现已接入，验证记录见 [实施计划](../plans/dev-verification-routing.md)。
> 用户体验与范围于 2026-10-30 确认。既有安装在明确迁移前保留旧自动路由。
> 关联讨论：[GitHub issue #23](https://github.com/Naituw/AskHuman/issues/23)。
> 实现地图：[开发验收](../overview-development.md)；每树数据与渠道模型见
> [Dev Instance](dev-instance-parallel.md)，操作见 [工作树准备流程](../agent-worktree-setup.md)。

开发 AskHuman 时，日常需求讨论始终使用正式版；验收刚修改的代码时，由 Agent 明确发起一次
Dev 验收，回答返回原来的 Agent。验收不会切换日常会话的实例归属，结束后也无需切回。

本方案覆盖 macOS、Linux、Windows，以及现有 CLI／MCP Agent 接入。各客户端的独立测试会话
按实际隔离能力适配，不把某个平台或客户端验证通过等同于全部支持。

## 1 用户体验

### 日常开发流程

以修改弹窗按钮布局为例：

1. Agent 通过普通 AskHuman 讨论按钮位置，使用正式版和用户平常的渠道。
2. Agent 在已启用 Dev Instance 的工作树修改代码，安装到本树独立的程序和数据目录。
3. Agent 主动调用 Dev 验收入口，运行本树刚安装的代码。测试卡片显示
   「开发验收 · 按钮布局 · 工作树名称」。
4. 用户回答「右边再留一点空白」，答案和附件返回原来的开发 Agent。
5. Agent 继续修改、安装、验收。其间普通讨论、权限确认和 Stop 继续使用正式版。
6. 验收通过后，再按项目流程合并、发布或安装正式版。Dev 验收不顺带升级正式版。

用户不需要为每次验收切换模式或选择实例。Agent 按项目开发规范区分普通讨论与开发验收。

### 两种测试

| 测试 | 适用范围 | 日常会话 |
| --- | --- | --- |
| 一次 Dev 验收 | 弹窗、Markdown、附件、问答流程及局部渠道行为 | 保持正式版，接收测试答案 |
| 独立 Dev 测试会话 | MCP、生命周期、权限、Stop、恢复及原生会话操作 | 保持正式版，负责安排和解释测试 |

一次 Dev 验收只创建测试请求，不授予 Dev 对当前日常 Agent 会话的控制能力。
测试 Watch、插话、权限、Stop 等行为时，目标必须是独立测试会话。

## 2 已确认决策

| 编号 | 决策 |
| --- | --- |
| V1 | 迁移后的普通 CLI、MCP 和受管 Agent 日常入口固定正式版，不按 cwd 自动进入 Dev |
| V2 | 保留每工作树独立程序、home、daemon 和测试渠道的 Dev Instance 模型 |
| V3 | Agent 安装后主动使用明确的 Dev 入口验收，无需用户逐次决定是否进入 Dev |
| V4 | 一次 Dev 验收的回答返回发起它的 Agent，不改变后续普通请求的目标 |
| V5 | 完整 Agent 集成使用独立 Dev 测试会话，不临时切换当前日常会话 |
| V6 | 普通 MCP 连接固定正式目标；Dev 工具显式委托测试，不改变 server 自身的 home |
| V7 | 本机验收由 Dev 弹窗渲染；可通过正式版渠道转送远程验收消息 |
| V8 | 渠道转送不复制生产密钥，不作为 Dev 渠道实现已经通过测试的证明 |
| V9 | 不提供日常模式与会话策略的组合矩阵；旧自动行为通过明确迁移保留兼容路径 |
| V10 | 选中的 Dev 缺失、不可执行、构建不匹配或不兼容时明确失败，不回退正式版 |

本需求调整 Dev Instance 规格 D5、D8 的日常入口。它们描述的旧行为保留在兼容模式；
新行为通过实际目标解析与受管集成迁移生效。

## 3 调用入口

| 入口 | 目标和语义 |
| --- | --- |
| `AskHuman …` | 正常安装入口使用正式版；cwd 标记不改变目标 |
| MCP `ask`、`whats_next`、`show_last` 和待办工具 | 当前普通连接固定的正式实例 |
| `AskHuman dev ask …` | 明确使用选定工作树的 Dev，复用现有问答入参和回答格式 |
| MCP `dev_ask` | 发起一次 Dev 验收，返回人类回答、附件和实际构建信息 |
| 开发测试页的「启动测试会话」 | 使用选定 Dev 的独立 Agent 配置启动完整测试 |

CLI 的 `dev ask` 从调用 cwd 查找已启用的工作树，也允许显式指定工作树。MCP `dev_ask`
必须携带明确的工作树路径，由 Agent 从当前开发任务取得；共享 MCP server 的 cwd 不能充当
工作树授权或目标依据。入口校验规范化后的路径、enabled 状态及对应程序身份。

`dev_ask` 支持测试说明、问题、选项和附件，复用问答结果语义。结果附带验收 ID、Dev 身份及
实际构建；这些元数据不能混入人类回答正文。重取结果按验收 ID 定位同一次测试，不能静默
重发问题或把其他构建的旧答案当成本次验收。普通 `show_last` 不跨实例混查。

Pi 等 CLI Agent 通过 `dev ask` 获得同样的问答验收能力。使用 MCP 的 Agent 通过专门工具发起，
无需修改正在使用的 MCP 注册或重启日常会话。首次增加工具时仍需按客户端要求刷新工具目录。

## 4 目标解析与进程继承

### 完整实例目标

解析结果必须同时包含实例类型与身份、工作树、规范化数据目录、稳定的程序安装入口、
通信端点、构建身份及选择原因。程序路径与数据目录不能分别决定，避免开发程序使用正式数据。

目标在读取实例业务配置、访问密钥或启动 daemon／GUI 之前确定。入口的显式目标参数先于
cwd 路由解析。内部进程继承已解析目标，不再次根据 cwd、设置变化或 marker 变化选择实例。

| 情况 | 处理 |
| --- | --- |
| 普通安装入口，无显式隔离上下文 | 正式实例 |
| 明确 Dev 验收 | 选定工作树对应的 Dev 程序和 home |
| 直接运行工作树的 Dev 程序 | 识别其所属 Dev；无法建立一致目标则失败，不使用正式 home |
| 显式 `ASKHUMAN_HOME` 的高级隔离调用 | 保留隔离用途；不能据此宣称它是正式版或某工作树 Dev |
| 显式正式／Dev 目标与外部 home 冲突 | 报告冲突和来源，要求调用方明确处理，不静默覆盖 |
| 内部继承目标与新入参冲突 | 失败，不改道 |

受管日常入口携带明确的正式目标。外部继承的隔离环境与其冲突时报告错误，不能把权限或 Stop
发送到其他实例。内部上下文必须限制在对应的子进程链路，不泄漏给无关启动器。

目标解析是共享模块，CLI、MCP 测试发起端、daemon、Popup 和更新 worker 使用同一契约。
Linux 必须保留稳定安装入口与运行中映像的区分；Windows、macOS 也不能仅依赖 PATH 首个同名程序。
旧 Dev 程序须先验证入口能力，不能让它重新按 cwd 路由，也不能产生重启循环。

### MCP 和会话归属

普通 MCP server 的进程内工具与其 CLI 子进程全部固定同一正式目标。启动后启用／禁用 Dev、
改变 cwd 对应的 marker 或修改开发偏好，都不改变现有连接和在途请求。

`dev_ask` 是明确的测试委托：启动目标 Dev 的问答执行链路，收取答案；不修改 MCP 进程环境，
不让待办、历史或其他普通工具随之跳转。不能通过在多线程 server 中临时设置全局环境实现。

正式版拥有日常原生会话的可信绑定。Dev 验收记录只关联一次测试及其回传通道，不直接沿用
日常 session token、MCP 实例登记或可执行会话控制操作的凭据。恢复、取消与回传按测试关联标识
处理；原生会话控制能力属于独立测试会话，必须另行建立可信绑定。

## 5 安装与构建验证

已启用工作树的普通安装继续只更新本树 Dev，不因日常调用默认正式版而改为安装正式版。
显式全局安装的逃生口保留。安装完成后输出正确的 Dev 验收入口和构建信息。

成功安装记录程序指纹、源码版本、相关未提交构建输入的快照及构建时间。commit 号或路径本身
不足以证明正在运行刚修改的代码；构建期间输入变化时，不签发「与当前源码一致」的验收凭据。

每次验收校验安装记录、实际程序和实际提供服务的 Dev daemon。源码已有未构建变化、程序被替换、
daemon 仍运行旧构建、程序不可执行或能力不兼容时，明确提示重建、重连或升级。
不能把「成功连上一个 daemon」当作版本校验通过。

开发卡片始终展示工作树和构建时间；详细诊断提供程序、home、endpoint、构建指纹和选择来源，
不显示密钥。构建记录与诊断使用平台一致的语义。

## 6 本机与远程验收

### 本机窗口

由目标 Dev 的 Popup 渲染，窗口标题和卡片均有开发验收标识。视觉标识应在 Dev 支持框架中稳定提供，
不能只靠 Agent 在正文里自称正在测试。正式版的开发测试页负责发起和查看状态，不能替 Dev
渲染被测弹窗。

全局 GUI Host 维持现有唯一窗口模型。访问 Dev 状态或配置时使用明确实例上下文和对应 endpoint，
不能临时切换 GUI Host 的进程级 home。

### 借用日常渠道转送

用户可在开发测试页配置验收投递方式：本机弹窗，或通过正式版的日常远程渠道转送。
Agent 不必逐次让用户选择。正式版凭自己的配置维护渠道连接，Dev 只取得本次验收的投递能力，
不读取、复制或导出生产凭据。

转送记录使用 Dev 身份和验收 ID 组合定位，保留构建标识。正式版将用户回答和附件回传给对应
Dev 请求，再由测试入口交给发起 Agent。复用既有回答、附件、取消及首个终态生效的语义。

转送授权限定在该 Dev、该验收请求及其有效期，不能变成任意历史查询、待办写入或会话控制入口。
正式版仅保存投递和恢复所需的有界状态；测试问答历史归 Dev，不进入正式实例普通历史、
`show_last`、待办和自动执行队列。回答附件按原有权限规则处理。

取消、超时、Dev 退出或发起 Agent 断开时终止对应转送，迟到回答不能落到下一次测试。
不搬迁正在等待回答的请求。正式版连接失败时报告投递失败，不能将普通正式问答伪装成验收成功。

### 测试渠道实现

验证飞书、钉钉、Telegram、Slack 或 iOS 渠道本身时，使用 Dev 自己的专用测试 bot 或独立配对，
沿用现有工作树预设与凭据隔离原则。渠道转送只证明投递链路工作，不证明开发版渠道实现通过。

手机收到测试消息也不等同于验收 Mac 弹窗外观；外观验收需本机实际窗口或其截图。

## 7 独立 Agent 测试会话

启动前检查 Agent 的隔离配置能力和平台支持，生成仅供测试使用的启动配置。测试会话内的 CLI、
MCP、生命周期、权限、Stop、恢复及原生控制操作都绑定同一 Dev；工作目录改变也不能重新选目标。

配置使用客户端正式支持的独立 profile、配置目录、项目配置或专用启动参数。不能假设所有 Agent
都支持重定向 `HOME`，也不能临时改写用户级规则、MCP 或 Hook 再尝试恢复。
不支持可靠隔离的客户端组合明确显示能力限制，保留普通 Dev 问答验收。

独立测试会话创建的子任务与 Fork 默认继承测试环境和目标。无法保证继承时拒绝该测试操作，
不能悄悄创建正式会话。日常会话创建任务或 Fork 继续属于正式环境，不因目的目录已 enable 而进入 Dev。

测试会话、窗口和相关确认显示 Dev 标识。关闭会话只清理本次启动拥有的配置与进程，
保留工作树数据和明确保存的测试记录，不中断正式会话或其他 Dev。

| Agent | 基础验收入口 | 完整会话适配要求 |
| --- | --- | --- |
| Claude Code | CLI／MCP | 独立配置及全套 Hook、可信会话绑定 |
| Codex | CLI／MCP | 区分 App／CLI 的配置作用域，包含协议与 Hook 信任配置 |
| Cursor | CLI／MCP | 分别确认 IDE／CLI 和 MCP server 的配置作用域 |
| Grok | CLI／MCP | 独立 skill／MCP／Hook 及可信绑定 |
| Pi | CLI | 独立扩展和启动环境；不提供 MCP 选项 |
| Antigravity | 当前支持平台的 CLI／MCP | 可靠隔离与原生身份能力不足时限制完整会话测试；Windows 沿用现有限制 |

此表定义适配范围，不代表已经实测支持。正式开放前必须公布各平台和客户端的实际能力状态。

## 8 设置与迁移

设置增加「开发测试」页，展示工作树、构建、就绪状态、验收投递方式和独立测试会话入口。
不增加「普通模式 × Agent 策略 × 工作树覆盖」的日常选择矩阵。
目标解析所需的注册和迁移状态使用用户私有、无密钥的数据，先于实例业务配置读取。

已有安装的旧自动路由继续有效，直到用户明确完成迁移。迁移说明普通调用将留在正式版，
Dev 安装之后须走显式验收；不把旧 enabled marker 自动解释为同意新流程。

迁移按受管产物逐项检查并记录结果：

1. 升级正式版的开发支持入口，验证所需能力，避免新入口委托给不理解目标语义的旧程序。
2. 更新受管 Agent 规则、MCP、生命周期、权限、Stop、恢复及 Pi 扩展；Codex 同步更新受管信任配置。
3. 检查旧注册指向 Dev、冲突 home、旧程序和仍在运行的旧 MCP server。
4. 验证普通调用和显式 Dev 验收分别进入正确目标，再标记迁移完成。

自定义配置只报告冲突，不认领或覆盖。保留修改前的受管配置和迁移状态，失败时能报告部分完成
情况并重试／回退，不能以单一「已启用」状态掩盖不一致。

全套集成变更不等同于当前客户端立即生效；需按客户端提示重启或新建测试会话，保留在途请求。
Dev 不允许借测试配置操作改写日常集成；修改正式集成须通过明确的正式入口。

回退恢复旧受管流程与路由行为，不删除 Dev home、程序或历史。只改变新调用和新连接，
不将等待中的测试、日常请求或会话搬迁到另一实例。

## 9 实施阶段与验收

### 第一阶段 核心开发验收

实现完整目标解析、CLI／MCP 显式 Dev 入口、本机 Dev 弹窗标识、构建验证，以及日常入口固定和迁移。
同步更新项目的安装后验收规范与工作树文档；现行指令只能在新入口实际可用时切换。

首阶段开放条件：

- 普通 CLI、MCP 各工具及受管配套 Hook 在 enabled 工作树内仍固定正式版。
- 同一日常 Agent 连续执行普通讨论、Dev 验收和普通讨论，分别进入正式、Dev、正式，答案返回正确。
- 两棵工作树并行安装、验收、取消和换新，彼此及正式实例互不覆盖、互不 drain。
- MCP 启动后启用／禁用 Dev 或修改 marker，进程内工具与普通 ask 子进程仍保持原目标。
- 缺失、不可执行、旧版、不匹配构建、冲突 home、直接 Dev 程序及旧新程序组合均有明确结果，且无回退或循环。
- 子角色和更新 worker 继承目标；源码与构建、daemon 身份不一致时不能给出通过结论。
- Dev 验收不注册当前日常会话的控制能力；取消和重取结果不串请求、构建或附件。
- 旧用户迁移、部分失败、客户端未重启、自定义配置冲突和回退均可诊断。

### 第二阶段 远程投递与独立测试会话

远程转送和各客户端独立会话可以分别交付，能力未就绪时不展示为可用。

远程转送验收覆盖回答、附件、重复／迟到回答、断线、重启、取消、过期和并发 Dev；
证明生产凭据没有进入 Dev，普通历史、待办和会话控制没有取得测试权限。

独立会话按客户端和平台验证全套 Hook／MCP、跨 cwd、子任务／Fork、关闭与清理。
问答成功与权限、Stop、恢复、Watch／插话的正确归属分别验收。

三平台需验证 Unix socket／Windows named pipe、macOS launchd、Linux 稳定安装入口与图形运行、
Windows worker 和终端启动链路。自动化覆盖解析和跨进程不变量；原生图形、真实渠道和各 Agent
测试会话仍需相应平台实测，未完成项保留能力限制。

## 10 文档生效边界

新安装直接使用显式流程；既有安装通过开发测试页检查并明确迁移后生效。未迁移时仍遵循原有 cwd
自动路由，不由升级或 enabled marker 代替用户同意。`AGENTS.md` 与工作树文档使用显式 Dev 验收入口，
普通讨论始终按安装当前生效的路由执行。

模块与数据位置见 [实现地图](../overview-development.md)，平台实测和未验证的原生场景见
[实施计划](../plans/dev-verification-routing.md)。实现能力与原生平台验收分别记录。
