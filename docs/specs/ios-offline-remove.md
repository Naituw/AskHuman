# iOS：Mac 离线时暂时移除请求

> 状态：已实现（2026-11-21，第 3 版：按「不要搞重」收窄了入口；用户确认「够轻」与名字「暂时移除」）。
> 本文只写相对既有规格的增量；连接状态的划分沿用 [ios-answer-flow.md](ios-answer-flow.md) §3.6，
> 离线与提交的总体约定见 [ios-channel.md](ios-channel.md) §6.10、§12 第 10 条。
> 实现地图见 [overview-ios.md](../overview-ios.md)。

## 1. 问题与目标

用户反馈（2026-11-21）：「mac 离线的时候，收到的提问草稿不能发送也不能取消。」

读代码确认：目标 Mac 够不到时，请求页的「发送」置灰，「⋯」里的「取消请求」（确认类是「Dismiss」）也置灰
（`RequestScreen.moreMenu` 里的 `!store.isOnline`），收件箱的行没有任何动作。这条请求会以缓存的样子一直留在手机上，
**唯一的出口是解除这台 Mac 的配对**，它会把这台 Mac 的全部请求、草稿与待发项一起清掉。这是 `ios-channel.md` §12
第 10 条「不做离线排队」的后果；那一节的标题就是「我自行决定的项（请审阅，可否决）」。

我先提过「离线排队 + 撤回 + 离线取消」，用户的回答是：

> 不能简单处理吗？就是离线的时候取消，就是暂时忽略。然后如果连回来了，还有这个问题，它再加载出来。

只放在「⋯」菜单里被指出不容易发现（「用户关不掉，他会很懊恼。怎么让他能更明显的知道怎么关？」）；
我接着做的版本（顶部橙色提示卡、列表提示卡上的批量按钮、常驻的「已隐藏 N 条 · 显示」）又被否决：

> 不要搞得这么重，一会网络抖动，各种黄条就闪出来了。
>
> 暂时隐藏感觉也不太好，好像是藏在我手机上什么地方了，实际上我手机上已经没有了，除非再次连线才会出来。

本设计取这几句话的交集：Mac 够不到时，用户能把一条暂时处理不了的请求**从手机上移走**，出口就在发送键旁边那句
「Mac 已离线」后面；Mac 回来后它如果还在等，就自动重新出现。**不排队，不替 Agent 做任何决定，也不新增任何会闪的东西。**

## 2. 决策

| # | 决策 | 来源 |
|---|---|---|
| D1 | 离线时的「取消」就是**暂时移除**：只在本机生效，不向 Mac、也不向 Agent 发送任何消息；Agent 照常等待 | 用户 |
| D2 | 连回来后，仍在等待的请求**自动重新出现**；已经结束的不再出现。没有手动恢复入口、没有「已移除」列表 | 用户 |
| D3 | 「发送」不变：离线仍不可发、不排队 | 用户（2026-11-21 确认） |
| D4 | **轻**：不新增任何横条、提示卡、按钮行，页面内容不位移。入口只有三个：请求页底栏上**已有的**离线提示条尾部的动作、「⋯」菜单里原来灰掉的取消换成的可点项、收件箱行左滑（§3.1） | 用户 |
| D5 | 叫「**暂时移除**」（英文 Remove for now）：「移除」是应用里本来就用于「从这部手机上拿走」的词（移除附件、从这部手机移除密钥）。不叫「隐藏」（用户：像藏在手机里什么地方）；不叫「忽略」（中文里它已经是确认类 Dismiss 的译名，而 Dismiss 会让 Agent 收到默认回复） | 用户确认（2026-11-21） |
| D6 | 可用条件只有一个：目标 Mac **离线**（`RequestConnection.macOffline`）。「连接中断，重试中」「连接中」「Mac 更新中」会自己恢复，「连接被拒绝」要去 Mac 上改设置，这几种都不提供 | 自行决定 |
| D7 | 提示条上的动作与「⋯」里的项先弹一个确认，说清后果；行左滑一滑就走，不再确认（滑动本身已是两步） | 自行决定 |
| D8 | 草稿保留：内容与附件原样在手机本地，只是不显示；请求回来时草稿徽标与内容都在 | 自行决定 |
| D9 | 状态存在手机本地，App 重启后仍然移除，直到 Mac 回来 | 自行决定 |
| D10 | Mac 回来时仍待处理的请求带未读蓝点重新出现（对列表它是新的），不弹通知、不播到达动画 | 自行决定 |
| D11 | 处于「发送中 / 未送达」的请求也可以移除。只影响可见性：那条提交保持原来的处理。Mac 回来的快照里它先照原样（「发送中」或「未送达」，不带蓝点）重新出现，补发被接受后随请求一起结束 | 自行决定 |
| D12 | 从请求页移除后回到列表，不自动前进：下一条多半也是这台离线 Mac 的，前进过去只会再看到同一句话 | 自行决定 |
| D13 | 不写历史，不加设置项，不加任何横幅或临时提示；不改 Mac 端、线协议与 IPC | 自行决定 |

**为什么不会闪（D4）**：新的动作和已有的离线提示条同生同灭，没有新增元素；Mac 在线与离线之间抖动时，变化的只是那条提示条
（它今天就会这样）和它尾部多出的两个字，页面内容不动。左滑与菜单项不占画面。

## 3. 行为

连接状态是 `RequestConnection`（`AHCore/RequestConnection.swift`，与发送栏共用的那一份事实）。
下面的入口都只在它是 `macOffline`、且请求没有结束（`finished`）时出现。

### 3.1 入口

| 位置 | 形态 |
|---|---|
| 提问页底栏 | 已有的「Mac 已离线，草稿已保留。」后面加「**暂时移除 ›**」（强调色、半粗），整条提示是一个按钮（与「去选择」那类带箭头的提示条同一做法） |
| 确认页底栏、只有摘要的加载页 | 同上：它们各自的离线提示（「Mac 已离线，回来后再试。」「Mac 已离线，请求回来后再加载。」）后面加同一个动作 |
| 请求页「⋯」菜单 | 把灰掉的「取消请求」/「Dismiss」换成可点的「暂时移除」。菜单出现与否的规则不变（有取消 / Dismiss / 会话历史时才有），所以不能 Dismiss 的权限确认与只有摘要的加载页只靠提示条上的动作。不为了多一个入口让菜单按钮随连接状态忽有忽无（D4 的初衷：网络一抖，画面不跟着闪） |
| 收件箱的行 | 向左滑出「暂时移除」，只对这台 Mac 离线的行；一滑就走 |

提示条上的动作与菜单项弹同一个确认（与「取消这个请求？」同一种 `confirmationDialog`）：

> **暂时移除这个请求？**
> Mac 离线，无法通知 Agent，它会继续等。Mac 重新连上后，如果请求还在等你，它会再出现在这里。草稿会保留。
> [暂时移除]　[保留]

在线时一切不变：「⋯」里仍是「取消请求」/「Dismiss」，需确认，Agent 会被告知。

### 3.2 移除之后

- 这条请求从收件箱、列表计数、App 图标角标、请求页的上一条 / 下一条里消失；
- 从请求页移除：页面收起，回到列表（D12）；不出回执页；
- **没有任何消息发给 Mac**：这不是取消，Agent 不会被告知，仍在等待；
- 草稿保留（D8）；
- 列表空了且没有别的可达的 Mac 时，显示已有的空状态「连不上你的 Mac · Mac 一连上，请求就会显示在这里」
  （`listReadiness == .unreachable`），不加新文案；还有在线的 Mac 时按原来的规则。

### 3.3 Mac 回来

该 Mac 重新连上、收到收件箱快照时（每次连上都有一份）：

- 快照里**仍有**的被移除请求：取消移除，回到原来的位置（按 Agent 提问时间排序），仍待处理的带未读蓝点（D10；发送中 / 未送达的见 D11）；
- 快照里**没有**的：说明离线期间已结束，沿用现有「离线期间结束」的收尾（进历史，结果「已结束」），不特殊处理。

### 3.4 边界

- **重启**：仍然移除（D9）。
- **多台 Mac**：每条请求独立；一台回来只恢复它自己的。
- **点开推送**：对应请求被移除时沿用现有「手机上没有这条请求」页——Mac 离线时写「连不上你的 Mac，连上后会自动出现」，与本设计一致。
- **已提交的请求**（D11）：移除后发件箱里的提交不动。Mac 回来、快照到达时它先以原来的样子（「发送中」或「未送达」）回到列表，
  不带蓝点；随后补发被接受，请求正常结束并进历史。
- **一直不回来**：一直移除，直到 Mac 回来或解除配对；这正是「暂时」的含义，没有超时。
- **iPad 双栏**：列表的选中项就是 `inboxPath.last`，移除当前选中的请求会清空它，详情栏回到「选择一个请求」占位
  （按这一机制推得；没有单独在 iPad 模拟器上跑）。

## 4. 实现结构

只列触点。内部叫 `removedForNow`（「暂时移除」的字面），与 `LocalStore` 里真正删除缓存的 `remove`、引擎里「停放」的提交（parked submissions）都不是一回事。

- `AHStore/Models.swift`：`CachedRequest` 增加 `removedForNow: Bool`，默认 `false`；`init(from:)` 用 `decodeIfPresent`，旧缓存文件照常读出，标志随请求落盘（D9）。
- `AHCore/PhoneEngine`：
  - `snapshot()` 的 `inbox`、各 Mac 的待处理计数都不含被移除的请求；另在 `EngineState` 加 `removedForNowIds: Set<String>`（请求 key，默认空），
    供 `AppStore` 判断「请求其实还在」；
  - `removeRequestForNow(macId:requestId:)`（经 `RemoteBackend` 协议）：只在该 Mac 此刻是 `.macOffline`、请求存在且尚未移除时置标志、落盘、`publish()`；
    其余情况什么也不做（在线时没有「移除」，要走真正的取消）。**不发任何消息，不动发件箱，不动草稿**；
  - `onInboxSnapshot`：对仍在快照里的被移除请求清掉标志、只有 `.pending` 才置 `unread`、落盘；不在快照里的走原来的「离线期间结束」收尾，不改；
  - `removeMac` 清掉这台 Mac 的全部请求时，被移除的也一并清掉（沿用）。
- `AHCore/Backend.swift`：`RemoteBackend` 加 `removeRequestForNow`；`AHMock/MockBackend` 同步实现，并在 mock 的 Mac 回到 `.online` 时把它们放回（按时间排序、带未读点）。
- `AHCore/AppStore`：
  - `canRemoveForNow(_:)`（请求没结束、仍在列表里、`state.requestConnection == .macOffline`）、`removeForNow(_:)`（收起它的页，不自动前进，再交给后端）；
  - `removalPrompt: String?`：底栏动作与菜单项只置它，确认弹窗由 `RequestScreen` 持有。它在 Mac 回来（不再可移除）、页面关闭、页面换了请求时清掉；
  - **`apply(_:)` 里「离开收件箱就丢弃 Composer / 草稿」把 `removedForNowIds` 并入「仍存在」，`closed(id:)` 对它们也保留 Composer 与草稿**；
    `retained`（刚结束的请求留给页面显示十分钟）里被移除的条目清掉。否则移除会把草稿删掉。
- `Views`：
  - `Request/RequestConnectionNotice`：提示可带一个动作（文字，`NoticeActionWords`）；`notice(offlineText:updatingText:removable:)` 只在 `macOffline` 且可移除时给出；
  - 三处渲染它的地方（提问页 `hintView`、确认页 `bar`、加载页 `status`）把动作画在文字后面，整条做成按钮（`hint-remove`）；
  - `RequestScreen`：确认弹窗、`moreMenu` 里取代灰掉的取消 / Dismiss 的「暂时移除」（`request-menu-remove`）；`hasMore` 不变；
  - `Inbox/InboxScreen`：行的 `.swipeActions`（`swipe-remove-<requestId>`，一滑就走，不用红色：它不是删除）。
- 本地化（`ios/Tools/make-catalog.py` 生成目录）：`Remove for now`「暂时移除」、`Remove this request for now?`「暂时移除这个请求？」
  及确认说明；「保留」已有。

## 5. 放弃的方案

- **离线排队（发送与取消都存在手机上，Mac 回来补发）**：用户问「Mac 如果一直不回来，排队怎么办？」，随后要求「简单处理」。
  它牵出带附件的答案（要先上传）、答案过期、排队多久、一直不回来如何清理等一串问题，收益只有「离线时能先写好答案」，已有的草稿保留已经覆盖了大半。
- **离线取消＝移走并排队一条取消**：会在 Mac 回来时替用户取消 Agent 的请求，而用户要的只是暂时不看它。
- **只放进「⋯」菜单**（第 1 版）：用户指出菜单里容易发现不了。
- **请求页顶部橙色提示卡、收件箱提示卡上的批量按钮、常驻的「已隐藏 N 条 · 显示」与手动恢复**（第 2 版）：用户否决，太重，
  网络一抖提示就闪，卡片还会把页面内容顶来顶去；用户的心智是「手机上已经没有了，除非再次连线才会出来」，所以也不要恢复入口。
- **叫「暂时忽略」**：与中文里已有的「忽略」（Dismiss）重名且后果相反。**叫「暂时隐藏」**：用户说像藏在手机里什么地方。
- **「连接中断重试」「连接被拒绝」也给移除**：前者自己会恢复，一移除又弹回来；后者要去 Mac 上改设置。需要时再放宽 D6。

## 6. 验收矩阵

1. Mac 离线：提问页底栏的提示条尾部有「暂时移除 ›」；点后弹确认；确认后页面收起回到列表，请求从列表、计数、角标、上一条 / 下一条里消失。选「保留」什么都不变。
2. 确认页与只有摘要的加载页的离线提示条同样带这个动作。
3. Mac 离线：「⋯」里是可点的「暂时移除」，不再是灰的「取消请求」/「Dismiss」，走同一个确认。
4. Mac 离线：行向左滑出「暂时移除」，只移除那一条，没有确认。
5. Mac 在线、「连接中」「Mac 更新中」「连接中断」：没有任何移除入口；在线时「⋯」里仍是「取消请求」/「Dismiss」，行为不变。
6. 只有一台 Mac 且全部移除后：列表显示已有的「连不上你的 Mac」空状态。
7. 移除后再回来：草稿内容与附件原样在。
8. 移除后重启 App（Mac 仍离线）：仍移除；Mac 回来后出现。
9. Mac 回来：仍在等的请求重新出现且带未读蓝点；已结束的不出现，并以「已结束」进历史。
10. 移除的请求处于「发送中 / 未送达」：Mac 回来后提交照常送达，请求结束，不再出现。
11. 点开被移除请求的推送：显示「连不上你的 Mac…」占位页；Mac 回来后进入正常页。
12. 解除配对仍清掉该 Mac 被移除的请求、草稿与待发项（沿用）。
13. 没有任何消息发给 Mac（引擎测试里断言发送计数不变）；没有新增横幅、提示卡或临时提示。

自动测试（第 11 条的推送页面、第 13 条的「没有消息发给 Mac」都在里面）：

- `AHStoreTests`：`CachedRequest` 的新字段与旧缓存文件解码；
- `AHCoreTests/RequestRemovedForNowTests`（引擎，真实回环 broker 与测试 Mac）：在线时不移除、移除后各列表与计数不含它且不发任何消息、
  回来时在原位置带未读点且不报到达、期间结束时进历史、草稿保留、重启后仍移除、待发的提交照常送达并结束请求、解除配对一并清掉、重复或未知请求无效果；
- `AHAppTests/RemoveForNowTests`（`AppStore` 与 mock）：可用条件的状态矩阵、移除后的列表与页面（回到列表、不是别的请求的邻居）、草稿与 Composer 保留
  （含 `closed(id:)`）、一台 Mac 只带回自己的请求、全部移除后的空状态、确认问题随 Mac 与页面清掉、被移除请求的推送页面是「连不上你的 Mac」。
  去掉 `apply`/`closed(id:)` 里的保护，对应用例会变红；
- 模拟器 UI 测试 `AskHumanRemoveForNowUITests`（mock，`-AHLink macOffline`）：提示条动作与确认（含「保留」）、确认页的提示条、菜单项取代灰掉的取消、
  左滑，以及 Mac 可达、连接中、Broker 不通时都没有入口。iOS 26.2 英文与中文、iOS 18.5（经典栏、操作表带「保留」）都跑过，截图目测过。
