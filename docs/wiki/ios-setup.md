# iOS App 渠道配置（实验功能）

简体中文 | [English](./ios-setup.en.md)

AskHuman 的 iOS App 是和飞书、Slack 并列的一个通信渠道：Agent 在 Mac 上提问，你在 iPhone 上回答；还能在手机上看 Agent 的状态、实时观察、给它发消息、创建新任务。**多台 Mac 可以和同一部手机配对**（比如家里一台、公司一台），所有问题混排在同一个收件箱。

> 这是**实验功能**，需要自备三样东西：一个 MQTT broker（EMQX Serverless 的免费额度即可）、一个推送中继（腾讯云云函数，免费额度即可）、一个 Apple 开发者账号（生成推送密钥、安装 App）。下面逐步说明。

## 它怎么工作（以及谁能看到什么）

```
Agent ─► Mac 上的 AskHuman ──MQTT（TLS）──► EMQX ──► iPhone 上的 AskHuman
                 └── 推送中继（云函数）──► APNs ──► iPhone 通知
```

- **端到端加密**：每次配对都会生成一对只有这台 Mac 和这部手机知道的密钥。EMQX 和推送中继只能看到密文和「谁在线」这类元数据，看不到问题和答案。
- **你的 APNs 密钥只在云函数里**：Mac 不保存任何 Apple 密钥；中继是无状态的，只按固定白名单把加密后的预览转给 Apple。
- **推送内容也是加密的**：锁屏上看到的问题摘要由手机上的通知扩展解密后显示；解密失败时只会显示一句通用提示。
- **多台 Mac 共用一份 broker 凭据**：第一台 Mac 配好后，其它 Mac 在设置里粘贴「连接串」即可。

## 一、准备 EMQX（broker）

1. 在 [EMQX Cloud](https://cloud.emqx.com/)（国内站）或 [国际站](https://cloud-intl.emqx.com/) 创建一个 **Serverless** 部署（每月免费 100 万连接分钟、1 GB 流量）。
2. 在部署的「概览」里记下**连接地址**和端口：TLS `8883`，WSS `8084`。
3. **认证**：添加一个用户名 / 密码。用户名只用**字母和数字**（它同时是这条线路的话题命名空间 `ah/<用户名>/`）。
4. **授权（ACL）**（控制台「访问控制 → 客户端授权」）。这个页面默认是**黑名单模式：没被明确拒绝的请求一律放行**，所以下面第 1 条兜底**必须有**，否则任何账号都能读写别人的话题：
   1. 切到「全部用户」标签，添加：话题 `#`，动作「发布 & 订阅」，**不允许**（兜底）。
   2. 切到「用户名」标签，添加：用户名填上一步建的用户名，话题 `ah/<用户名>/#`，动作「发布 & 订阅」，**允许**。EMQX 先看这个账号自己的规则，再看「全部用户」规则，所以只有自己的话题放行。
   
   配好后可以用 `ios/Tools/broker-probe/acl-check.cjs` 验证隔离（需要一个账号的用户名和密码，在 `ios/Tools/broker-probe` 里先 `npm install`；密码通过环境变量 `AH_PROBE_PASSWORD` 传入，见脚本开头的说明）。
5. **消费上限保持 0**。免费额度用完后服务会暂停，但不会自动扣费；AskHuman 会在你接近额度时提示（见下文「流量与费用」）。

> 给朋友用：为每个人另建一个用户名 / 密码，并各加一条自己的 `ah/<用户名>/#` 允许规则（第 2 条）；「全部用户」的兜底拒绝不要动。这样互相看不到对方的话题。

## 二、准备 Apple 开发者资源

1. 在 Apple Developer → Identifiers 注册两个 App ID：主 App `com.naituw.humaninloop.ios`（勾选 **Push Notifications**）和通知扩展 `com.naituw.humaninloop.ios.notification`（不需要任何能力）。使用自己的团队时，把 `ios/project.yml` 里的 Team 与 Bundle ID 一并改成自己的，并让中继的 `APNS_TOPIC` 与主 App 的 Bundle ID 一致。
2. Keys → 新建一个启用 **Apple Push Notifications service (APNs)** 的密钥。点 APNs 一行的 Configure，环境选 **Sandbox & Production**（开发构建走沙盒、TestFlight / 正式版走生产，一把密钥通用；此时限制只能选 Team Scoped）——这两项**保存后 Apple 不允许修改**。注册后下载 `.p8` 文件（**只能下载一次**），记下 **Key ID** 和你的 **Team ID**。

## 三、部署推送中继

1. 在仓库里运行 `relay/scripts/build-zip.sh`，得到 `relay/dist/askhuman-relay.zip`。
2. 腾讯云控制台 → 云函数 → 新建 **Web 函数**：运行环境 Node.js 20，地域「中国香港」（无需备案、能直连 APNs），内存 128 MB，超时 15 秒，上传 zip。
3. 在函数配置里填环境变量：

   | 变量 | 内容 |
   |---|---|
   | `APNS_KEY_P8` | `.p8` 文件的全部内容（直接粘贴，换行可以写成字面的 `\n`） |
   | `APNS_KEY_ID` | 密钥的 Key ID |
   | `APNS_TEAM_ID` | 你的 Team ID |
   | `APNS_TOPIC` | `com.naituw.humaninloop.ios`（主 App 的 Bundle ID） |
   | `RELAY_HANDLE_KEY` | 32 字节随机数的 base64（例如 `openssl rand -base64 32`） |
   | `REVOKED_RIDS` | （可选）要手动作废的句柄编号，逗号分隔 |

4. 创建**函数 URL**（公网访问，授权类型「开放」）。访问 `<函数URL>/v1/health`，应返回 `{"ok":true,"v":1,"apns":true}`。

> `.p8` 和 `RELAY_HANDLE_KEY` 只放在云函数的环境变量里，不要放进仓库、聊天记录或截图。

## 四、在 Mac 上启用

1. 打开 AskHuman 设置 → **通用** → 最底部打开「实验性功能」，设置里会出现「实验」Tab（也可以用 `AskHuman config set experimental.enabled true`）。
2. **实验** → **iOS App 渠道**，打开开关并填写：
   - Broker 主机、TLS 端口（8883）、WSS 端口（8084）、用户名、密码；
   - 推送中继地址（函数 URL）；
   - 本机显示名（手机上显示的 Mac 名字，留空用电脑名）。
3. 点 **测试连接**：先连 broker 并发一条回环消息，成功会显示走的是 `tls` 还是 `wss`，以及往返耗时；再向中继要健康信息，显示它的响应耗时、是否已配置 APNs 密钥（没填中继地址时会提醒手机收不到推送）。
4. 命令行等价写法：

   ```bash
   AskHuman channel set ios --enable --host <主机> --username <用户名> \
     --relay-url <函数URL> --password-stdin        # 密码从 stdin 读
   AskHuman channel test ios
   ```

5. **第二台 Mac**：在第一台点 **复制连接串**（包含 broker 密码，只在自己的设备之间传递），在第二台的「沿用另一台 Mac 的设置」里粘贴并点「导入」。命令行是 `AskHuman channel ios export` 与 `AskHuman channel ios import -`。

> iOS 渠道不会强制守护进程常驻：Agent 在工作时它本来就在线；它停了，手机上这台 Mac 会显示离线。想让手机随时能看到这台 Mac，把「守护进程生命周期」设为保活（设置 → 高级；开启「从 IM 创建 Agent 任务」时会自动设为保活）。

## 五、安装 App 并配对

1. 用 Xcode 打开 `ios/AskHuman.xcodeproj`（先 `cd ios && xcodegen generate`），选你的设备，Run；或者通过 TestFlight 安装。首次启动允许通知。
2. Mac 上：设置 → 实验 → iOS App 渠道 → **配对新手机**（命令行：`AskHuman channel ios pair`），出现二维码和配对码，**5 分钟内有效，只能用一次**。
3. 手机上：App 的「Mac」页 → **添加 Mac** → **扫描二维码**（扫码不方便时选「粘贴配对码」）。
4. 手机和 Mac 上会各显示一个 **6 位确认码**，核对两边一致后在 Mac 上点 **允许**。配对完成，手机立刻收到 Mac 当前的请求。
5. 想撤销：Mac 设置里点这部手机的 **撤销**（`AskHuman channel ios revoke <名称>`）；手机端在 Mac 详情里点「解除与这台 Mac 的配对」，或在「Mac」页底部「忘记所有配对」。重装 App 后，手机会提示是否沿用钥匙串里遗留的配对。

## 六、日常使用

- **收件箱**：所有 Mac 的问题混排，按项目分组，可按 Mac 筛选。点开后可以单选 / 多选、写补充说明、附图片和文件；多题合并请求是纵向一页，推荐选项有星标（不会自动选中）。需要你确认的操作（权限、Stop）有专门的确认页。
- **跨渠道抢答**：同一个问题在 Mac 弹窗、飞书、手机上同时出现，谁先答谁生效，其它地方会收到「已被处理」。
- **Agents 页**：列出各 Mac 上的 Agent 会话。**关注**（每台 Mac 最多 5 个）后，Agent 完成 / 等你 / 出错时会推送；点进详情可以**实时观察**（只在 App 前台时，最多同时 2 路）、**插话**（排队中 → 已被 Agent 读取，撤回前可编辑）。
- **新任务**：Agents 页的「新任务」按钮，选 Mac、项目、Agent 类型、权限（行动前先询问 / 自动执行，必须明确选一个）、可选 TODO，经 Face ID 确认后由 Mac 在终端启动。需要 Mac 上开启「从 IM 创建 Agent 任务」且满足它的前提。
- **历史**：已回答的请求和附件保存在手机本地。

## 流量与费用

- EMQX 国内站免费额度：每月 100 万连接分钟、1 GB 流量（入站加出站）；典型使用（每天 100 个请求、每天实时观察 1 小时）每月远低于 300 MB。
- Mac 设置页和手机的「Mac」页都显示本月流量（本机统计，一条消息按发布 + 投递各算一次）。**达到免费额度的 80% 时会黄色提示**，估计用完时变红。消费上限为 0 时，用完后 broker 会拒绝连接，App 会提示「Broker 拒绝了连接，可能是本月的免费额度用完了」。
- 腾讯云云函数的调用量很小（每月约 1 千到 2 万次）；部署前在费用中心核对一下你账号的计费规则，避免意外的固定月费。

## 排查

| 现象 | 处理 |
|---|---|
| 设置页显示「Broker 未连接」 | 点「测试连接」看具体原因；公司网络封了 8883 时会自动改走 WSS 8084；认证失败多半是密码或 ACL 不对 |
| 手机收不到推送，但 App 打开时能收到 | 检查系统通知权限；Mac 设置里手机条目下是否有「推送已失效」；用 `<函数URL>/v1/health` 确认 `apns:true` |
| 推送能到但只显示通用文案 | 通知扩展没能解密：确认两边是同一次配对；重装 App 后需要重新配对或选择沿用旧配对 |
| 「手机时间与 Mac 相差过大」 | 消息有 ±15 分钟的重放窗口；校准手机的日期与时间 |
| 想让手机上完全不再看到某台 Mac | 在手机的 Mac 详情里解除配对，同时在 Mac 上撤销该手机 |
| 手机上这台 Mac 显示离线 | Mac 上的守护进程没在运行（没有 Agent 活动时它会空闲退出）；让 Agent 提问一次，或把守护进程生命周期设为保活 |
| 流量警告 | 减少实时观察 / 附件，或到 EMQX 控制台核对用量；本机统计只含这台设备的消息 |

## 限制

- 实验功能：设置里的入口与命令默认隐藏，细节可能调整。
- 实时观察只在 App 前台工作，退到后台即停止。
- Codex 桌面 App 的会话暂不支持从手机插话；Codex 没有「出错」状态，因此不会有「出错」推送。
- 回撤插话只取回文字，不取回已选的附件。
