# iOS App 渠道配置（实验功能）

简体中文 | [English](./ios-setup.en.md)

AskHuman 的 iOS App 是和飞书、Slack 并列的一个通信渠道：Agent 在 Mac 上提问，你在 iPhone 上回答；还能在手机上看 Agent 的状态、实时观察、给它发消息、创建新任务。**多台 Mac 可以和同一部手机配对**（比如家里一台、公司一台），所有问题混排在同一个收件箱。

> 这是**实验功能**，需要自备三样东西：一个 MQTT broker（EMQX Serverless 的免费额度即可）、一个推送中继（腾讯云云函数，免费额度即可）、一个 Apple 开发者账号（生成推送密钥、安装 App）。下面逐步说明。

## 它怎么工作（以及谁能看到什么）

```
Agent ─► Mac 上的 AskHuman ──MQTT（TLS）──► EMQX ──► iPhone 上的 AskHuman
                 └── 推送中继（云函数）──► APNs ──► iPhone 通知
```

- **端到端加密**：每次配对都会生成一对只有这台 Mac 和这部手机知道的密钥。EMQX 和推送中继只能看到密文和「谁在线」这类元数据，看不到问题和答案。
- **你的 APNs 密钥只在云函数里**：Mac 不保存任何 Apple 密钥；中继是无状态的，只按固定白名单把加密后的预览转给 Apple。
- **推送内容也是加密的**：锁屏上看到的问题摘要由手机上的通知扩展解密后显示；解密失败时只会显示一句通用提示。
- **多台 Mac 共用一份 broker 凭据**：第一台 Mac 配好后，其它 Mac 在设置里粘贴「连接串」即可。

## 一、准备 EMQX（broker）

1. 在 [EMQX Cloud](https://cloud.emqx.com/)（国内站）或 [国际站](https://cloud-intl.emqx.com/) 创建一个 **Serverless** 部署（每月免费 100 万连接分钟、1 GB 流量）。
2. 在部署的「概览」里记下**连接地址**和端口：TLS `8883`，WSS `8084`。
3. **认证**：添加一个用户名 / 密码。用户名只用**字母和数字**（它同时是这条线路的话题命名空间 `ah/<用户名>/`）。
4. **授权（ACL）**（控制台「访问控制 → 客户端授权」）。这个页面默认是**黑名单模式：没被明确拒绝的请求一律放行**，所以下面第 1 条兜底**必须有**，否则任何账号都能读写别人的话题：
   1. 切到「全部用户」标签，添加：话题 `#`，动作「发布 & 订阅」，**不允许**（兜底）。
   2. 切到「用户名」标签，添加：用户名填上一步建的用户名，话题 `ah/<用户名>/#`，动作「发布 & 订阅」，**允许**。EMQX 先看这个账号自己的规则，再看「全部用户」规则，所以只有自己的话题放行。
   
   配好后可以用 `ios/Tools/broker-probe/acl-check.cjs` 验证隔离（需要一个账号的用户名和密码，在 `ios/Tools/broker-probe` 里先 `npm install`；密码通过环境变量 `AH_PROBE_PASSWORD` 传入，见脚本开头的说明）。
5. **消费上限保持 0**。免费额度用完后服务会暂停，但不会自动扣费；AskHuman 会在你接近额度时提示（见下文「流量与费用」）。

> 给朋友用：为每个人另建一个用户名 / 密码，并各加一条自己的 `ah/<用户名>/#` 允许规则（第 2 条）；「全部用户」的兜底拒绝不要动。这样互相看不到对方的话题。

## 二、准备 Apple 开发者资源

1. 在 Apple Developer → Identifiers 注册两个 App ID：主 App `com.naituw.humaninloop.ios`（勾选 **Push Notifications**）和通知扩展 `com.naituw.humaninloop.ios.notification`（不需要任何能力）。使用自己的团队时，把 `ios/project.yml` 里的 Team 与 Bundle ID 一并改成自己的，并让中继的 `APNS_TOPIC` 与主 App 的 Bundle ID 一致。
2. Keys → 新建一个启用 **Apple Push Notifications service (APNs)** 的密钥，选择自己的 App 所在团队及匹配的推送环境：开发构建用 Sandbox，TestFlight / 正式版用 Production。Apple 新建密钥支持按团队或指定 App 授权，并按环境区分；已有同时支持两个环境的旧密钥仍可继续使用。当前中继实例配置一把密钥，需要同时使用两种环境时分别部署对应环境的中继。注册后下载 `.p8` 文件（**只能下载一次**），记下 **Key ID** 和你的 **Team ID**。以 [Apple 当前的推送认证说明](https://developer.apple.com/documentation/UserNotifications/establishing-a-token-based-connection-to-apns)为准。

## 三、部署推送中继

1. 在仓库里运行 `relay/scripts/build-zip.sh`，得到 `relay/dist/askhuman-relay.zip`。
2. 腾讯云控制台 → 云函数 → 新建 **Web 函数**：运行环境 Node.js 20，地域「中国香港」（无需备案、能直连 APNs），内存 128 MB，超时 15 秒，上传 zip。
3. 在函数配置里填环境变量：

   | 变量 | 内容 |
   |---|---|
   | `APNS_KEY_P8` | `.p8` 文件的全部内容（直接粘贴，换行可以写成字面的 `\n`） |
   | `APNS_KEY_ID` | 密钥的 Key ID |
   | `APNS_TEAM_ID` | 你的 Team ID |
   | `APNS_TOPIC` | `com.naituw.humaninloop.ios`（主 App 的 Bundle ID） |
   | `RELAY_HANDLE_KEY` | 32 字节随机数的 base64（例如 `openssl rand -base64 32`） |
   | `REVOKED_RIDS` | （可选）要手动作废的句柄编号，逗号分隔 |

4. 创建**函数 URL**（公网访问，授权类型「开放」）。访问 `<函数URL>/v1/health`，应返回 `{"ok":true,"v":1,"apns":true}`。

> `.p8` 和 `RELAY_HANDLE_KEY` 只放在云函数的环境变量里，不要放进仓库、聊天记录或截图。

## 四、在 Mac 上启用

1. 打开 AskHuman 设置 → **通用** → 最底部打开「实验性功能」，设置里会出现「实验」Tab（也可以用 `AskHuman config set experimental.enabled true`）。
2. **实验** → **iOS App 渠道**，打开开关并填写：
   - Broker 主机、TLS 端口（8883）、WSS 端口（8084）、用户名、密码；
   - 推送中继地址（函数 URL）；
   - 本机显示名（手机上显示的 Mac 名字，留空用电脑名）。
3. 点 **测试连接**：先连 broker 并发一条回环消息，成功会显示走的是 `tls` 还是 `wss`，以及往返耗时；再向中继要健康信息，显示它的响应耗时、是否已配置 APNs 密钥（没填中继地址时会提醒手机收不到推送）。
4. 命令行等价写法：

   ```bash
   AskHuman channel set ios --enable --host <主机> --username <用户名> \
     --relay-url <函数URL> --password-stdin        # 密码从 stdin 读
   AskHuman channel test ios
   ```

5. **第二台 Mac**：在第一台点 **复制连接串**（包含 broker 密码，只在自己的设备之间传递），在第二台的「沿用另一台 Mac 的设置」里粘贴并点「导入」。命令行是 `AskHuman channel ios export` 与 `AskHuman channel ios import -`。

> iOS 渠道不会强制守护进程常驻：Agent 在工作时它本来就在线；它停了，手机上这台 Mac 会显示离线。想让手机随时能看到这台 Mac，把「守护进程生命周期」设为保活（设置 → 高级；开启「从手机 / IM 创建 Agent 任务」时会自动设为保活）。

## 五、安装 App 并配对

1. 用 Xcode 打开 `ios/AskHuman.xcodeproj`（先 `cd ios && xcodegen generate`），选你的设备，Run；或者通过 TestFlight 安装。首次启动允许通知。
2. Mac 上：设置 → 实验 → iOS App 渠道 → **配对新手机**（命令行：`AskHuman channel ios pair`），出现二维码和配对码，**5 分钟内有效，只能用一次**。
3. 手机上：App 的「Mac」页 → **添加 Mac** → **扫描二维码**（扫码不方便时选「粘贴配对码」）。
4. 手机和 Mac 上会各显示一个 **6 位确认码**，核对两边一致后在 Mac 上点 **允许**。配对完成，手机立刻收到 Mac 当前的请求。
5. 想撤销：Mac 设置里点这部手机的 **撤销**（`AskHuman channel ios revoke <名称>`）；手机端在 Mac 详情里点「解除与这台 Mac 的配对」，或在「Mac」页底部「忘记所有配对」。重装 App 后，手机会提示是否沿用钥匙串里遗留的配对。

## 六、日常使用

- **收件箱**：所有 Mac 的问题混排，按项目分组，可按 Mac 筛选。点开后可以单选 / 多选、写补充说明、附图片和文件；多题合并请求是纵向一页，底部按钮先是「下一题」，看到最后一题后才变成「发送」（和 Mac 弹窗一致，不会没看完就误发），推荐选项有星标（不会自动选中）；答完一条会自动推到下一条，并提示还剩几条。需要你确认的操作（权限、Stop）有专门的确认页。
- **快速切换消息**：详情右上角的左右箭头可直接查看上一条／下一条，更多菜单仍在最右。切回来保留草稿、附件和阅读位置，切换时收起键盘。列表筛选范围会沿用，新消息追加到本次浏览末尾；上传或发送可以在后台完成，不会把你从另一条消息拉走。发送后的自动前进仍按原来的全部收件箱规则。
- **通知什么时候来**：每个提问都会出现在手机的收件箱里，不需要任何「激活」或「接管」操作，打开 App 随时能看到、能回答。系统通知则只在你离开 Mac 一阵之后才发：Mac 的键盘和鼠标空闲满设定的时间（默认 15 分钟）、而你又没在手机上看过这道题，才推送一次，之后不会重复提醒；你还在用 Mac 时不会推送。想更快收到通知，到 Mac 设置 → 实验 → iOS App 渠道 → **推送时机** 改成 5 分钟、甚至「立即」（问题一出现就推送）；同一块里的「Mac 已空闲 N 分钟」可以看检测有没有在工作。
- **跨渠道抢答**：同一个问题在 Mac 弹窗、飞书、手机上同时出现，谁先答谁生效，其它地方会收到「已被处理」。
- **Agents 页**：显示所有 Mac 上的会话状态与上轮结果。失败和未完成的结果用红色／橙色标出并写明原因，要处理时看收件箱里的出错卡；用户中断显示「已中断」，不发结果提醒。手机创建的任务，以及从手机发消息或在出错卡上「要求继续」真正启动的新一轮，会登记首次完成／出错／未完成通知（每台 Mac 最多同时 5 个），仍等 Mac 空闲后才推，你先回到电脑前就作废。会通知的会话显示只读的小铃铛；电脑上的其它回合不会自动订阅。详情支持实时观察（仅前台，最多 2 路）。
- **继续原会话**：空闲的 Codex Desktop、Cursor Desktop 和存活且更新了扩展的 Pi，可以在详情直接发消息，保留未发送的输入草稿；Cursor Desktop 的聊天即使 Mac 已把它标成「已结束」（一小时没动静就会），只要它还在 Cursor 里也能发，不过得先在 Cursor 窗口里把它打开，否则会提示不可用；失败后从已有进度继续，在收件箱的出错卡上点「要求继续」。其它会话会说明不可用原因。工作中的既有插话仍可排队并在读取前编辑／撤回；原生发送被接受后不可撤回。提示结果不明时，先检查原聊天，再决定是否新发。此功能需要新版 App 与 Mac 端。
- **新任务**：Agents 页的「新任务」按钮，选 Mac、项目、Agent 类型、权限（行动前先询问 / 自动执行，必须明确选一个）、可选 TODO，经 Face ID 确认后由 Mac 启动（Codex 可走桌面 App 或终端，其余 Agent 走终端）。需要 Mac 上开启「从手机 / IM 创建 Agent 任务」且满足它的前提；没开时手机上会提示「这台 Mac 的 AskHuman 设置里关闭了 Agent 任务」。开启入口有三处：设置 → 实验 → iOS App 渠道卡片底部的「在 App 里新建 Agent 任务」（点「开启…」）、设置 → 高级，以及 `AskHuman setup` 向导完成页上的同名开关（已接入 Agent 且配好 iOS 或 IM 渠道时才出现）。
- **任务附件**：新任务可添加拍照、相册图片／视频和文件，手机新增最多 5 个、每个不超过 10 MB。仍需填写任务文字或选待办；待办自带附件会一并发送。上传失败时任务不会启动，草稿保留供重试；旧 Mac 需更新 AskHuman。
- **App 内新请求**：收到提问、权限或 Stop 确认时，蓝色问号气泡弹跳两次，飞入收件箱；底栏不可见时，收入顶部短暂的收件提示。每条独立播放，提醒层不接收点击，也不会切页面或收起键盘；去收件箱查看即可。开启系统「减少动态效果」时只显示静态提示。
- **Codex Fast**：新任务中选具体的支持模型后可开启 Fast，桌面 App 和 CLI 都支持。每次新建默认关闭，关闭使用标准速度；Fast 更快但消耗更多额度，速度选择不记忆。Mac 上的 AskHuman 和 Codex 也须支持此功能。
- **待办页**：底部的「待办」标签，管理 Mac 上的待办——浏览项目、新增、编辑（点按）、完成（向右滑）、删除（向左滑，点「删除」即删）、拖拽排序（右上「编辑」）、开关 ⚡ 自动执行、看「历史」里做过的并恢复。标题处的菜单选「看谁的待办」：某一台 Mac（只列那台 Mac 上有目录的项目），或 **iCloud**（你开了 iCloud 待办同步时：列出同一个 Apple ID 下所有同步的项目，包括这台电脑上没有目录的；由一台**开着同步且在线**的 Mac 代为读写，那台掉线会自动换另一台）。待办只存在 Mac 上，手机不保存内容——所以要看 / 改待办，对应的 Mac 得在线（离线时页面会提示，输入条禁用，不排队）；手机不能新建项目（项目是 Mac 上的目录，在「最近项目 / 没有待办」里点进去就能给它加第一条待办）。在 Mac 上改了待办，手机上几秒内跟上；手机上的改动先写到那台 Mac，开着 iCloud 待办同步的话再由它带到你其他 Mac（iCloud 本身的传播延迟照旧，通常几十秒）。Mac 上的 AskHuman 版本太旧、还不认识待办时，菜单里它显示「需要更新」，更新那台 Mac 上的 AskHuman 即可。
- **在请求页直接加待办**：请求页右上角「⋯」里有「添加待办…」（请求带项目时才有）。半屏里只填一句话，项目和 Mac 已经定好（就是这条请求的），点「添加」后顶部浮出「已添加到 项目名」。待办写到这条请求所在的那台 Mac；那台 Mac 离线或版本太旧时，半屏里会说明原因、「添加」置灰，写好的文字不会丢。
- **回答时选待办**：请求页最后一题下面有一张折叠的「待办」卡（请求带项目、该项目有待办、且不是仅选择的题时才有）；点开像选项一样勾选，发送时选中的待办并进最后一题的回答（「另外看一下这个待办任务：…」）并从队列里出队，只选待办也能发。What's next 里取的是**完整队列**：默认显示前 5 条，点「显示全部 N 条待办」展开，不再被截成前 10 个。对应的 Mac 也要是新版；旧 Mac 上没有这张卡，What's next 仍是原来的选项。
- **离开模式**：Agents 页右上角的月亮按钮（再点一次就是结束）打开半屏开启页，选生效的 Mac、写备注；开着时，每个标签页的标签栏上方都有一条青绿色（与 iOS「睡眠」专注模式同色）的「离开模式开启中」条，点「结束」一键关闭。开启后 Agent 的提问与 What's next 由 Mac 自动回复「我不在，请按你的最佳判断继续」，不再打扰你；Agent 在原目标完成或剩余工作确实无法继续时带 `--escalate "理由"`（MCP：`escalate: "理由"`）联系你，理由显示在正文最前面；无有效理由的连续第 4 次请求保留系统兜底，并明确注明没有 Agent 理由，手机上的提问页顶部会有一张说明卡，可就地结束离开模式。Agent 详情页头的「此会话的 AskHuman」一行可以只对这个会话设成「离开模式」或「不再使用」。
- **快捷回复**：提问页底栏「发送」左边的按钮打开菜单。下半部分是预设（在 Mac 设置 → 通用 → 快捷回复里编辑，手机上只读镜像），点一下就发出，还没回答的题都回复这一句；上半部分是「离开模式」「不再使用 AskHuman」两条指令，选了先停在底栏上方，随这次回答发送才生效。What's next 与仅选择的题没有预设。
- **给消息加附注**：读正文时有疑问，可以直接在 Agent 的消息里选一段文字，点系统菜单里的「添加附注」写下来；这段文字会被标上颜色，点它可以改或删。发送回答时，附注连同你选的原文一起发给 Agent，所以只写附注、不选选项也不填文字也能发。有附注后，底栏上多出一个紫色的「附注」圆钮（带条数），点开是清单，可以改、删、跳到原文；一次回答最多 20 条。Mac 要是新版，消息按 Markdown 渲染时才能选字添加；确认页和仅选择的题没有这个功能。Agent 只发了一个问题、没有单独写消息时，这个问题会放进消息区，同样可以选字。附注没发出去之前保存在手机的草稿里。
- **历史**：已回答的请求和附件保存在手机本地。

## 流量与费用

- EMQX 国内站免费额度：每月 100 万连接分钟、1 GB 流量（入站加出站）；典型使用（每天 100 个请求、每天实时观察 1 小时）每月远低于 300 MB。
- Mac 设置页和手机的「Mac」页都显示本月流量（本机统计，一条消息按发布 + 投递各算一次）。**达到免费额度的 80% 时会黄色提示**，估计用完时变红。消费上限为 0 时，用完后 broker 会拒绝连接，App 会提示「Broker 拒绝了连接，可能是本月的免费额度用完了」。
- 腾讯云云函数的调用量很小（每月约 1 千到 2 万次）；部署前在费用中心核对一下你账号的计费规则，避免意外的固定月费。

## 排查

| 现象 | 处理 |
|---|---|
| 设置页显示「Broker 未连接」 | 点「测试连接」看具体原因；公司网络封了 8883 时会自动改走 WSS 8084；认证失败多半是密码或 ACL 不对 |
| 手机收不到推送，但 App 打开时能收到 | 检查系统通知权限；Mac 设置里手机条目下是否有「推送已失效」；用 `<函数URL>/v1/health` 确认 `apns:true` |
| 提问发出去很久了，手机一直没有通知 | 通知要等 Mac 键盘 / 鼠标空闲满「推送时机」设定的时间才发（默认 15 分钟），你还在操作 Mac 时不推；看 Mac 设置里「Mac 已空闲 N 分钟」是否在增长（一直是 0 说明有程序在不停产生输入），或把推送时机改成「立即」。打开 App 总能看到所有待答提问 |
| 推送能到但只显示通用文案 | 通知扩展没能解密：确认两边是同一次配对；重装 App 后需要重新配对或选择沿用旧配对 |
| 「手机时间与 Mac 相差过大」 | 消息有 ±15 分钟的重放窗口；校准手机的日期与时间 |
| 想让手机上完全不再看到某台 Mac | 在手机的 Mac 详情里解除配对，同时在 Mac 上撤销该手机 |
| 手机上这台 Mac 显示离线 | Mac 上的守护进程没在运行（没有 Agent 活动时它会空闲退出）；让 Agent 提问一次，或把守护进程生命周期设为保活 |
| 流量警告 | 减少实时观察 / 附件，或到 EMQX 控制台核对用量；本机统计只含这台设备的消息 |

## 限制

- 实验功能：设置里的入口与命令默认隐藏，细节可能调整。
- 实时观察只在 App 前台工作，退到后台即停止。
- Codex Desktop 会话可以在运行中补充消息、空闲时继续对话，支持图片和文件，沿用原聊天设置。Mac 上的 Desktop 必须保持连接；发送成功表示 App 已接受，不表示模型已阅读，消息不可撤回。提示结果不明时先检查原聊天，再选择「我已检查原聊天」；此提示和恢复动作需要新版手机 App。Codex 没有「出错」状态，因此不会有「出错」推送。
- 回撤插话只取回文字，不取回已选的附件。
