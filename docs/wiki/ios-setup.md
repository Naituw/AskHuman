# iOS App 渠道配置

简体中文 | [English](./ios-setup.en.md)

Agent 在 Mac 上提问，你在 iPhone 上回答。多台 Mac 可以和同一部手机配对，问题混排在同一个收件箱。配好之后怎么用，见 [iOS App 使用说明](./ios-usage.md)。

**需要准备**：

- 一台装了 AskHuman 的 Mac，和一部 iOS 17 或更高版本的 iPhone；
- 一个自备的 MQTT broker：托管服务的免费额度或自建都可以，见 [Broker 的要求、选择与验证](./ios-broker.md)；
- 不需要 Apple 开发者账号：推送默认走公共推送中继。

在 AskHuman 设置 → **通信渠道** → **iOS App** 点「开始设置」，卡片按三步带你完成：连接 Broker、安装 iPhone App、配对手机。也可以点「让 Agent 帮我配置」，把复制的文字发给你的 Agent。下面是同样的步骤。

## 1. 连接 Broker

1. 按 [Broker 文档](./ios-broker.md)选一条路径（EMQX Cloud Serverless、flespi 或自建 Mosquitto）配好。配好后你手里要有：
   - **主机**，TLS 端口（默认 `8883`）和 WSS 端口（默认 `8084`；各服务不同，flespi 是 `443`）；
   - **用户名和密码**：用户名只用字母和数字，它同时是话题命名空间 `ah/<用户名>/`；
   - **访问控制**：这个账号只能读写 `ah/<用户名>/#`。多人共用一个 broker 时必须配，各服务的写法见 Broker 文档。
2. 在卡片第 1 步选 Broker 服务商，填上面这些，点 **测试连接**。它会连上 broker 发一条回环消息（显示走的是 TLS 还是 WSS，以及往返耗时），向推送中继要健康信息，并检查这个账号能不能读写自己话题之外的主题。能的话会给出警告（不挡保存与配对），请到 broker 的访问规则里把账号限制在 `ah/<用户名>/#`。

命令行的等价写法：

```bash
AskHuman channel set ios --enable --host <主机> --username <用户名> \
  --password-stdin                              # 密码从 stdin 读
AskHuman channel test ios
```

「更多设置」里还有推送中继（默认「使用公共中继」）和本机显示名（手机上显示的 Mac 名字，留空用电脑名），一般不用改。

## 2. 安装 iPhone App

在 iPhone 上安装 [TestFlight](https://apps.apple.com/app/testflight/id899247664)，再打开卡片第 2 步的二维码或链接指向的[加入页面](https://naituw.github.io/AskHuman/)：加入测试，安装 AskHuman，首次启动时允许通知。

## 3. 配对手机

1. Mac：卡片第 3 步点 **配对新手机**（命令行：`AskHuman channel ios pair`）。出现二维码和配对码，**5 分钟内有效、只能用一次**。
2. 手机：AskHuman 的「Mac」页 → **添加 Mac** → **扫描二维码**（扫码不方便时选「粘贴配对码」）。
3. 手机和 Mac 各显示一个 **6 位确认码**，核对一致后在 Mac 上点 **允许**。配对完成，手机立刻收到这台 Mac 当前的请求。

要撤销：在 Mac 设置里点这部手机的 **撤销**（`AskHuman channel ios revoke <名称>`）；手机上在 Mac 详情里点「解除与这台 Mac 的配对」，或在「Mac」页底部点「忘记所有配对」。重装 App 后，手机会提示是否沿用钥匙串里遗留的配对。

## 4. 发一条测试问题

设置完成后卡片显示「已就绪」。点 **发一条测试问题**，在手机上回答；这是不调用模型的收答测试，测试问题会立即推送。想测通知，先在手机上关闭 AskHuman 再发一次。

其它问题默认要等 Mac 空闲 15 分钟才推送，卡片上的 **推送时机** 可以改成 5 分钟，或「立即」。手机收件箱不受这个等待限制，问题一出现就能看到。

## 多台 Mac

第二台 Mac 不用重新配 broker。在已配好的那台，展开卡片里的「连接设置」点 **复制连接串**（含 broker 密码，只在自己的设备之间传递）；在第二台的第 1 步选一个服务商，点「从另一台 Mac 导入…」，粘贴并点「导入」，再照第 3 步把这部手机配对到它。命令行：`AskHuman channel ios export` 与 `AskHuman channel ios import -`。

## 让手机随时看到这台 Mac

iOS 渠道不会强制后台服务常驻：Agent 在工作时它本来就在线，它停了，手机上这台 Mac 会显示离线。想让手机随时能看到这台 Mac，开启卡片里的「保持这台 Mac 随时可连」（等同于设置 → 高级里把「守护进程生命周期」设为保活；打开「允许从手机 / IM 创建 Agent 任务」时会固定为常驻）。

## 它怎么工作（以及谁能看到什么）

```
Agent ─► Mac 上的 AskHuman ──MQTT（TLS）──► 你的 broker ──► iPhone 上的 AskHuman
                 └── 推送中继（云函数）──► APNs ──► iPhone 通知
```

- **端到端加密**：每次配对都会生成一对只有这台 Mac 和这部手机知道的密钥。broker 和推送中继只看得到密文和「谁在线」这类元数据，看不到问题和答案。锁屏上的问题摘要同样是加密的，由手机上的通知扩展解密，解密失败时只显示一句通用提示。
- **公共推送中继只转发推送，不保存任何数据**：它看到登记推送时的设备 token 与 App 的 Bundle ID、推送时的加密信封与句柄，以及请求的网络地址（只在内存里用来限制滥用，不写日志；腾讯云平台自己的访问日志另算）。Apple 的推送密钥只在中继的云函数里，Mac 不保存任何 Apple 密钥。详见[隐私政策](https://naituw.github.io/AskHuman/privacy-zh/)。

## 排查

| 现象 | 处理 |
|---|---|
| 设置页显示「Broker 未连接」 | 点「测试连接」看具体原因。公司网络封了 8883 时会自动改走 WSS 8084；认证失败多半是密码或访问控制不对 |
| App 打开时能收到提问，但没有推送 | 检查系统通知权限；看 Mac 设置里这部手机下是否有「推送已失效」；打开 `https://askhuman-relay.maipo.me/v1/health`，应该返回 `"apns":true` |
| 提问发出去很久了，手机一直没有通知 | 通知要等 Mac 键盘和鼠标空闲满「推送时机」（默认 15 分钟）才发，你还在用 Mac 时不推。看卡片里的「Mac 已空闲 N 分钟」是否在增长（一直是 0 说明有程序在不停产生输入），或把推送时机改成「立即」。打开 App 总能看到所有待答提问 |
| 推送能到，但只显示通用文案 | 通知扩展没能解密：确认两边是同一次配对；重装 App 后需要重新配对，或选择沿用旧配对 |
| 「手机时间与 Mac 相差过大」 | 消息有 ±15 分钟的重放窗口，校准手机的日期与时间 |
| 手机上这台 Mac 显示离线 | Mac 上的后台服务没在运行（没有 Agent 活动时它会空闲退出）。让 Agent 提问一次，或开启卡片里的「保持这台 Mac 随时可连」 |
| 想让手机上不再出现某台 Mac | 在手机的 Mac 详情里解除配对，同时在 Mac 上撤销该手机 |
