# iOS App 使用说明

简体中文 | [English](./ios-usage.en.md)

配置见 [iOS App 渠道配置](./ios-setup.md)。本文说明配好之后手机上的功能。有些功能需要 Mac 和手机上的 AskHuman 都是较新的版本，旧的一端上没有对应入口，其余照常。

## 回答问题

- **收件箱**：所有 Mac 的问题混排，按项目分组，可按 Mac 筛选。点开一条，可以选选项、写补充说明、附图片和文件。多题请求是纵向的一页，底部按钮先是「下一题」，看到最后一题才变成「发送」（和 Mac 弹窗一致，不会没看完就误发）；推荐选项带星标，不会自动选中。答完一条会自动进入下一条，并提示还剩几条。
- **确认页**：权限和 Stop 这类需要你决定的操作，有专门的确认页。
- **切换请求**：详情页右上角的左右箭头切换上一条 / 下一条，草稿、附件和阅读位置都会保留；上传和发送可以在后台完成。
- **跨渠道抢答**：同一个问题在 Mac 弹窗、飞书、手机上同时出现，谁先答谁生效，其它地方会收到「已被处理」。
- **快捷回复**：「发送」左边的按钮打开菜单。下半部分是预设（在 Mac 设置 → 通用 → 快捷回复里编辑，手机上只读），点一下就发出，还没回答的题都回复这一句。上半部分是「离开模式」「不再使用 AskHuman」两条指令，选了先停在底栏上方，随这次回答发送才生效。What's next 和只能选择的题没有预设。
- **附注**：在 Agent 的消息里选一段文字，点系统菜单里的「添加附注」写下想法。发送时附注连同所选原文一起发给 Agent，只写附注也能发。底栏的「附注」按钮（带条数）列出所有附注，可以编辑、删除、跳到原文；一次回答最多 20 条，没发出去的附注留在手机的草稿里。需要新版 Mac 和按 Markdown 渲染的消息，确认页和只能选择的题没有这个功能。
- **会话历史**：请求来自某个 Agent 的真实会话时，在请求页顶部下拉（或点「⋯」→「此会话的历史」），请求上方会列出这个会话之前的问答（一次 8 条，到顶再下拉加载更早的）。内容读自 Mac 的回复历史，和 Mac 上的历史窗口是同一份，只保留设置里的条数（默认 200）；手机不保存。Mac 离线时显示「连不上 Mac」，点「重试」。没有会话信息的请求（比如拿不到会话 id 的 MCP 调用）没有这个入口。
- **本地记录**：已回答的请求和附件保存在手机本地。

## 通知

- 每个问题一出现就进手机的收件箱，不需要「激活」或「接管」，打开 App 随时能看到、能回答。
- 系统通知只在你离开 Mac 一阵之后才发：Mac 的键盘和鼠标空闲满设定的时间（默认 15 分钟），而你又没在手机上看过这个问题，才推送一次，之后不重复提醒；你还在用 Mac 时不推送。想更快收到，把设置 → 通信渠道 → iOS App 卡片里的 **推送时机** 改成 5 分钟，甚至「立即」（问题一出现就推送）；同一块里的「Mac 已空闲 N 分钟」可以看检测有没有在工作。

## Mac 离线时

Mac 够不到时，请求页的「发送」是灰的（不排队，草稿保留），也不能取消，因为通知不到 Agent。可以点底栏「Mac 已离线」后面的「暂时移除 ›」，或「⋯」菜单里的「暂时移除」，或在收件箱里把那一行向左滑：请求只是从这部手机的列表上拿走，**不会通知 Mac 和 Agent，Agent 照常等**，草稿保留。Mac 重新连上后，请求如果还在等你，会带着未读点自动回到列表；已经结束的不再出现。连接中、重试中、更新中这类会自己恢复的状态没有这个动作。Mac 在线时取消请求是「⋯」→「取消请求」。

## Agents

- **状态**：Agents 页显示各 Mac 上会话的状态和上一轮结果。失败和未完成的结果标红 / 橙并写明原因，要处理时用收件箱里的出错卡；你中断的显示「已中断」，不发结果提醒。
- **实时观察**：在会话详情里，只在 App 前台工作（最多 2 路），退到后台即停止。
- **完成通知**：手机创建的任务，以及从手机发消息或在出错卡上点「要求继续」启动的新一轮，会登记一次完成 / 出错 / 未完成通知（每台 Mac 最多同时 5 个）。规则同「通知」一节：等 Mac 空闲后才推，你先回到电脑前就作废。会通知的会话有只读的小铃铛；电脑上的其它回合不会自动订阅。
- **继续原会话**：空闲的 Codex Desktop、Cursor Desktop 会话，以及存活且已更新扩展的 Pi 会话，可以在详情页直接发消息，未发送的草稿会保留；其它会话会说明不可用的原因。Cursor Desktop 的聊天即使 Mac 上已标成「已结束」（一小时没动静就会）也能发，但要先在 Cursor 窗口里打开它。失败后从已有进度继续，在收件箱的出错卡上点「要求继续」。对工作中的会话发的消息会排队，Agent 读取前可以编辑或撤回；原生发送被接受后不能撤回，结果不明时先检查原聊天再决定要不要重发。需要新版 App 与 Mac。
- **新任务**：Agents 页的「新任务」按钮：选 Mac、项目、Agent 类型、权限（行动前先询问 / 自动执行，必须明确选一个）和可选的待办，经 Face ID 确认后由 Mac 启动。Codex 可走桌面 App 或终端，Cursor 可走终端或 Agents 窗口（实验），其余 Agent 走终端；只装了桌面版、没有命令行也能启动。可以附拍照、相册图片 / 视频和文件（手机新增最多 5 个，每个不超过 10 MB；仍需填写任务文字或选一个待办，待办自带的附件会一并发送）；上传失败时任务不会启动，草稿保留。选了支持的 Codex 模型后可开 **Fast**（更快，更耗额度；默认关闭，每次新建都要重选）。
  需要在这台 Mac 上打开「允许从手机 / IM 创建 Agent 任务」（打开后后台服务会常驻并开机自启）：设置 → 通信渠道里 iOS App 卡片和各 IM 渠道卡片、设置 → 高级，或 `AskHuman setup` 向导里都有这个开关。没打开时手机上会提示「这台 Mac 的 AskHuman 设置里关闭了 Agent 任务」。
- **离开模式**：Agents 页右上角的月亮按钮（再点一次结束）打开开启页，选生效的 Mac、写备注。开着时每个标签页上方都有一条「离开模式开启中」，点「结束」一键关闭。开启后，Agent 的提问和 What's next 由 Mac 自动回复「我不在，请按你的最佳判断继续」，不再打扰你；Agent 在原目标完成或剩余工作确实无法继续时，带 `--escalate "理由"`（MCP：`escalate: "理由"`）联系你，理由显示在正文最前面。无有效理由的连续第 4 次请求由系统兜底放行并注明没有 Agent 理由，这时提问页顶部有一张说明卡，可以就地结束离开模式。Agent 详情页头的「此会话的 AskHuman」一行可以只对这个会话设成「离开模式」或「不再使用」。

## 待办

- **待办页**：底部的「待办」标签管理 Mac 上的待办：浏览项目、新增、编辑（点按）、完成（右滑）、删除（左滑后点「删除」）、拖拽排序（右上「编辑」）、开关 ⚡ 自动执行，并在「历史」里查看做过的、恢复它们。标题处的菜单选看谁的待办：某一台 Mac（只列那台 Mac 上有目录的项目），或 **iCloud**（开了 iCloud 待办同步时，列出同一个 Apple ID 下所有同步的项目，包括这台电脑上没有目录的；由一台开着同步且在线的 Mac 代为读写，它掉线会自动换另一台）。
- **待办只存在 Mac 上**，手机不保存内容，所以要看 / 改待办，对应的 Mac 得在线（离线时页面会提示、输入条禁用，不排队）。手机不能新建项目（项目是 Mac 上的目录，在「最近的项目」或「没有待办」里点进去就能加第一条待办）。Mac 上的改动几秒内同步到手机；手机上的改动先写到那台 Mac，开着 iCloud 待办同步时再由它同步到你其他 Mac。Mac 上的 AskHuman 太旧、不认识待办时，菜单里显示「需要更新」。
- **在请求页整理待办**：提问页的「待办」卡，以及 What's next 与 Stop 确认页里的待办行，可以就地完成（右滑）、删除（左滑后点「删除」）和添加（清单末尾的「＋ 添加待办」），长按一行也能「完成 / 复制 / 删除」；完成后几秒内可以点「撤销」。改动写到这条请求所在的那台 Mac，它离线或版本太旧时，行上的操作会停用并说明原因，不排队。确认类页面和只能选择的题没有这张清单。
- **回答时选待办**：提问页最后一题下面有一张折叠的「待办」卡（请求带项目、该项目有待办、且不是只能选择的题时才有）。点开像选项一样勾选；发送时选中的待办并进最后一题的回答，并从队列里出队，只选待办也能发。What's next 里是完整队列：默认显示前 5 条，点「显示全部 N 条待办」展开。需要新版 Mac；旧 Mac 上没有这张卡。

## 流量与费用

- **用量**：手机在后台时不产生同步流量。重度使用（七八个 Agent 并行、每天进前台约 70 次）实测同步约 0.4 GB/月，前提是 Mac 与手机都是较新的版本（本机统计：一条消息按发布加投递各计一次）。**附件是大头**：手机打开大图时才从 Mac 下载，一张约 2 MB 的截图打开一次按这个口径约计 7 MB，所以整月用量主要看你打开了多少张大图。
- **提醒**：Mac 设置页和手机的「Mac」页都显示本月流量。快到每个 GB 时（默认从 0.8 GB 起）提醒一次：手机收件箱顶部的提示可以点 ✕ 关掉，用量走到下一个 GB 才会再出现；「Mac」页的「流量提醒」可以改成每 2 / 5 / 10 GB，或关闭。提醒只数流量，不读你 broker 的任何信息，也不判断额度是否用完，所以充值或改套餐后不用处理；每月（UTC 月初）从头计。
- **额度**：broker 有没有免费额度、多大、用完会怎样，取决于你选的服务，见 [Broker 文档](./ios-broker.md)。想知道 broker 那边的真实用量，到它的控制台看，本机统计只含这台设备的消息。额度用完后 broker 若拒绝连接，App 会提示「Broker 拒绝了连接，可能是本月的免费额度用完了」。想省流量，少开实时观察和大附件。
- 使用公共中继不产生你的费用。

## 限制

- 实时观察只在 App 前台工作，退到后台即停止。
- Codex Desktop 会话：运行中可以补充消息，空闲时可以继续对话，支持图片和文件，沿用原聊天的设置；Mac 上的 Desktop 必须保持连接。发送成功表示 App 已接受，不表示模型已阅读，也不能撤回。结果不明时先检查原聊天，再选「我已检查原聊天」（此提示需要新版手机 App）。Codex 没有「出错」状态，所以没有「出错」推送。
- 撤回插话只取回文字，不取回已选的附件。
