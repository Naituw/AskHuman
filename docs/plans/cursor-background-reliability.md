# Cursor 后台完成续跑控制可靠性复审

2026-10-15 用户拒绝当前 CLI 入口接管和 JS 运行时补丁的可靠性，要求自行研究：先核对 Desktop 旧版兼容，再研究 CLI 的合适替代方案；没有可靠方案就移除功能，不继续扩展脆弱补丁。用户外出，不等待常规答复。

## 工作边界

- 当前主分支 `fe2385c` 已包含 Desktop 实验；CLI 实验未合并，保留在 `codex/cursor-cli-followup` 供历史查询，不再作为待发布方案。
- 在现有 popup-only Dev Instance / `codex/cursor-background-reliability` 研究与验证，生产集成、其他任务和用户 Cursor 会话不被测试打断。
- Desktop 先做官方发行包的静态契约比较；缺少关键契约可确认不兼容，存在符号只能说明候选兼容，不能冒充实机验收。
- 优先官方配置、Hook、公开协议；不以更多内部字段、版本特判或替换原命令来伪装可靠的长期能力。
- 保留原需求：后台工作与结果继续、当前 Await 和主动输入正常，只控制完成通知启动模型。冻结/杀进程、禁止后台任务、仅压住回复文本不满足该语义。
- 所有实际模型测试仍仅 Grok 4.7；优先无模型调查。

## 顺序

1. 对比 Desktop 当前与多个旧构建的 provider、服务、分发/ACK/Await/inbox 契约及桥接前提。
2. 查官方配置、Hook 与 CLI/ACP 调度代码，验证是否存在无需注入的控制面。
3. 按证据决定保留边界或撤回。撤回前先用旧安装恢复现有保护，再删除 UI、运行时、启动及状态接入，避免留下已注入代码。
4. 运行适当回归与安装脚本；整合到主分支，保持常规 AskHuman 集成和其他功能。
5. 清理过时进度/待办，记录证据与最终决定，完成后通过 AskHuman 交接。
