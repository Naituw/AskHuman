# 历史、待办草稿与 Interject 的显示图片 URL

2026-10-10。用户在 Base64 审计后确认继续优化三处纯显示图片读取，沿用已验收的
`askhuman-image` 协议。历史原生拖出的图标经确认采用 Popup 的系统图标 / 应用 PNG 兜底。

## 范围与行为

| 入口 | 图片显示 | 原有数据与操作 |
| --- | --- | --- |
| `HistoryDetail.vue` 的提问附件和回复图片 | 目标进入可见区域的 240px 缓冲后注册 URL；同路径只加载一次 | 原路径打开、Quick Look、附件选择与原生拖出 |
| `TodosView.vue` 新待办的已选本地图片 | 有界注册 URL；img 懒加载、异步解码 | 创建仍提交文件路径；已保存附件继续使用 128px 托管缓存 |
| `useInterjectAttachments.ts` 已选 / 恢复的可用图片（独立窗口与控制台共用） | 有界注册 URL；img 懒加载、异步解码 | 发送仍提交 `filePaths`；不可用引用可见且可移除 |

注册超限、文件不可读或 WebView 解码失败时，历史显示已有占位，两个草稿显示普通文件胶囊。
显示失败不删除源路径，用户仍可打开历史原图、提交草稿文件或移除附件。未增加加载模式设置。
剪贴板图片、Popup 回复图片运输、IM / CLI / MCP 返回编码均不在本次改动范围。

## 资源管理

- 新增 `src/lib/localImageUrls.ts`，让图片 URL 独立于提交数据。每个视图按路径去重，首次实际
  加载才创建 scope；历史由 IntersectionObserver 驱动，缺少 observer 时采用有界即时读取。
- 移除一个草稿文件只释放对应 token；其他图片保留当前 URL，不重新检查或读取。
  切换历史记录 / 待办项目、重置 Interject、清空草稿或组件卸载都撤销该拥有期的 scope。
- scope 创建和图片准备都可能晚于移除或重置；过期结果不写入当前视图，迟到的资源也会释放。
  解码错误核对事件来源 URL，旧 img 的错误不能把当前索引的另一张图片变成文件胶囊。
- 后端增加 `local_image_release_asset`。同 scope 内规范路径相同的资源共用 token 并计引用数，
  最后一个引用释放后删除资源、退还显示像素预算。整个 scope 撤销不受引用数影响。
- 复用现有单图 20 MiB / 40M 画布像素、动画 500 帧 / 80M 累计像素、SVG 2 MiB / 5,000
  节点 / 65 层限制；每个视图 scope 合计 80M 显示像素、最多 128 个资源。后台读取仍为单 worker。
  前端只持 URL，协议仍返回有界二进制响应，WebView 仍需解码内存。
- 历史拖出原文件优先使用已有系统 PNG 图标；未取到时使用内置 32px 应用 PNG。
  不把 WebView URL 交给原生拖拽插件，也不为图标重新读取原图。

## 验证

完整前端 362 Vitest + 5 Node 测试通过，Rust 1291 passed / 3 ignored，TypeScript、Rust fmt 和
all-targets Clippy 通过。新增回归覆盖去重、增量移除、迟到 scope / token 释放、同路径重加、
记录切换、可见区域加载、解码失败，以及选图继续提交原路径和粘贴继续提交既有 data URL。
后端覆盖规范路径共享引用、拥有期隔离和像素预算退还。

用户要求休息期间自行完成开发、验证和提交，本轮未要求人工验收三处窗口。
生产构建经 `./scripts/install.sh` 编译、签名和安装；已有 GUI Host 工具窗继续保护当前草稿，
关闭最后一个工具窗后按原有机制自动换新，没有强制关闭其他窗口或打断其他 agent 请求。

真实 WebView 探针复用生产模块，追加共享 token 首次释放仍能显示、最后引用释放后后端返回 404。
WKWebView 仍可能复用已解码的同 URL 像素；撤销阻止后端再次读取，不承诺立即清掉浏览器缓存。
视图清掉旧 img / URL，新拥有期分配新 token。探针分别报告 native 注册表状态与缓存观察，
并明确设置进程退出码，避免 macOS event loop 忽略 exit 参数造成失败误报成功。
正常探针退出 0；故意传入超限输入时报告 `limit` 并退出 1，已验证失败不会误报成功。
平台协议与既有 macOS 实测依据见 [Base64 审计](../investigations/base64-usage-audit.md)。
Windows / Linux 的官方机制已核查，但没有本轮三处 UI 的实机证据，随现有平台 gate 补验。
