## 实现前审核

### 入口取舍（随实现延期）

此前用户要求沿用原命令，实验因此替换 `~/.local/bin/agent` / `cursor-agent`。但第三方安装器不参与我们的锁，先核验再 rename 无法保证目标仍是核验过的文件。先移走再独占创建可以避免覆盖，却引入崩溃时原命令缺失的窗口；交换后检查也不能提供与第三方写入之间的原子条件更新。

推荐采用明确的受管入口 `AskHuman cursor [args]`，直接调用已核验的厂商安装，完全不写厂商命令入口。这同时消除第三方入口替换竞态，以及 AskHuman 删除/降级导致原始 Cursor 命令失效的问题。代价是受保护会话需要通过该入口启动，与此前原命令要求不同，需用户确认。

若继续要求透明接管原命令，必须明确接受并发冲突检测/恢复的边界，不能把更多检查或私有锁说成已严格消除竞态。

### 升级兼容

- 接纳经过验证的构建及关键发行文件指纹；未知构建继续运行原生 CLI，明确报告未保护。
- 不再仅凭模块名、源码包含 super.pull / forgetInFlight 就报告 active。
- 在独立 registry 实例上预检原生 pull/ACK 的同步和记账语义，确认后才修改真实 registry 原型。
- 旧版允许继承的 pull/ACK，包装只加在 CLI 派生原型，恢复时删除自有包装；不改共享基类。
- 运行中依赖方法被替换时退出保护并报告状态，避免调用语义已变的 ACK。
- 维护可重复运行的构建审计/验收工具；新构建需要证据后才能加入支持范围，不自动将静态匹配当成实测支持。
