# Cursor Desktop 恢复前验证

2026-10-15 用户选择“先做 Desktop 恢复前的兼容性与行为验证”。CLI 接管继续延期。

## 边界与通过标准

- 验证官方 macOS ARM64 构建 3.14.27、3.18.25、3.24.12；每个构建使用专用用户数据、扩展目录和空测试工作区。
- 使用历史 bridge/renderer 作为候选，优先一套小适配器；3.14 缺少 paired inbox 的差异需明确验证，不能只删除检查就宣布兼容。
- 仅对拥有且身份核验过的测试进程附加、注入、重载和停止；生产 AskHuman 的已撤回功能保持撤回。
- 先验证接入、服务发现、原生队列和恢复，再运行必要的真实模型检查。所有实际模型调用仅 Grok 4.7；不伪造人类的 AskHuman 结束答复。
- 旧版使用本机日期的后端服务实测，记录服务端拒绝/模型不可用等限制，不把无法执行当成功，也不无限扩展历史兼容补丁。

## 验证顺序

1. 取回官方完整旧版包，核验包内版本和签名；记录当前用户 Cursor 主进程和 Inspector 状态。
2. 逐版本普通启动隔离进程，验证 SIGUSR1 附加、provider/服务发现、guard 接入、关闭 Inspector 后控制桥存续。
3. 检查原生后台队列、ACK/Await 排除与 3.14 的无 paired inbox 路径。纯队列探针明确标为无模型证据。
4. 对能可靠接入的版本执行真实 Shell/子代理完成、Await、Stop/AskHuman 结束与手动续聊检查；记录模型请求和真实工具结果，不读取/保存模型思考内容。
5. 验证窗口重载、关闭恢复、测试进程重启；确认非测试 Cursor 和生产配置未被修改。
6. 汇总逐版本、逐路径的通过/失败/未验收矩阵，判断能否用少量适配维护；提交报告后再决定功能恢复。

## 交付边界

本轮先交付恢复前证据和建议，不将原型验证当成产品已经恢复发布。现有 3.24.12 产品安装链及真实两路径记录可复用，但会区分历史证据与本轮重验。
