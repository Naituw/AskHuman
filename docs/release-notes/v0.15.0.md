### 新增与改进

- **作答窗口 · 稍后回答**：合并窗口里暂时不想回答的请求，可以用底部「稍后回答」按钮（取消按钮旁）或侧栏行上的图标先放一边，窗口会切到下一条待答请求。所有待答请求都被放一边后，整个窗口缩成一个只显示「待答 N」的小窗，不占屏幕空间，仍遵循窗口置顶设置，也可以拖动；有需要回答的新请求，或点开小窗里的某一行时，窗口自动展开。离开 AskHuman 去别的应用后，临时展开的窗口会自动缩回小窗。macOS 上有平滑的过渡动画，Windows 和 Linux 上直接切换。
- **作答窗口 · 拖入文件**：文件可以拖到合并窗口里任意一个待答请求或问题上：悬停在小窗或侧栏某一行上稍等片刻，会自动展开或切换过去，拖到列表或正文边缘会自动滚动；松手后文件附加到鼠标下的请求（纵向多问题布局里附加到鼠标下的那个问题）。
- **作答窗口 · 拖入失败有提示**：拖入的文件没有附加成功时，现在会说明原因——无法读取、没有文件路径、落在附件预览区、该请求不接收附件、窗口正忙；macOS 上被系统保护的文件夹（桌面、文稿、下载、iCloud Drive、外置卷）拒绝读取时，还会提示去哪里授权。每次拖放也会在 `daemon.log` 里留下不含路径和文件名的诊断行（`askhuman_drop`）。
- **作答窗口 · 多问题纵向显示**：一次提出多个问题时，默认纵向平铺显示全部问题（已经保存过该选项的配置保持原来的选择），可在「设置 → 通用 → 多问题纵向同时显示」中切换。
- **作答窗口 · 标题栏显示会话标题**：macOS 在红绿灯旁淡入显示当前请求的 Agent 会话标题（合并窗口里居中于主区域）；Windows 和 Linux 在窗口标题里显示「会话标题 — AskHuman」。

### 修复

- **托盘菜单**：从托盘的待回答列表里选择一个请求时，会把合并的作答窗口带到前面，不再弹出报错。
- **作答窗口**：修复合并窗口里同时有多个请求时，后到请求底部固定的回答输入框变成空白条的问题。
- **Codex 集成**：安装 MCP 配置时改写 Codex 认可的 `default_tools_approval_mode`，不再写入会被 Codex 忽略并在启动时提示的 `approval_mode`（感谢 @dearrrfish，#16）。

### Features and improvements

- **Reply window · Answer later**: In the merged window, set a request aside with the "Answer later" button next to Cancel or with the icon on a Sidebar row; the window moves on to the next waiting request. Once every waiting request is set aside, the whole window shrinks into a small "Waiting N" list that takes almost no screen space, still follows the window pin setting, and can be dragged. A new request that needs an answer, or clicking a row in the small window, expands it again. After you switch to another app, a temporarily expanded window shrinks back by itself. macOS animates the change; Windows and Linux switch instantly.
- **Reply window · Drag files anywhere**: Drag files onto any waiting request or question of the merged window: rest over the small window or a Sidebar row to expand or switch to it, and drag to the edge of the list or the body to scroll. On drop, the files attach to the request under the pointer (the question under the pointer in the vertical multi-question layout).
- **Reply window · Drop feedback**: When a dropped file is not attached, the window now says why: an unreadable file, no file path, a drop on the attachment preview, a request that takes no attachments, or a busy window. On macOS, a folder guarded by the system (Desktop, Documents, Downloads, iCloud Drive, external volumes) also tells you where to allow access. Every drag leaves diagnostic lines in `daemon.log` (`askhuman_drop`) with no paths or file names.
- **Reply window · Vertical questions by default**: A request with several questions lists them all top to bottom by default (configs that already saved the option keep their choice). Switch it in Settings → General → "Show multiple questions vertically".
- **Reply window · Session title in the title bar**: On macOS, the Agent session title fades in beside the traffic lights (centered over the main pane in the merged window); on Windows and Linux the window title reads "<session title> — AskHuman".

### Fixes

- **Tray menu**: Picking a pending request from the tray menu now brings the merged reply window forward instead of showing an error.
- **Reply window**: Fix the pinned answer box turning into an empty bar for later requests when several requests share the merged window.
- **Codex integration**: Write the `default_tools_approval_mode` setting that Codex recognizes when installing the MCP config, instead of `approval_mode`, which Codex ignores with a startup warning (thanks @dearrrfish, #16).
